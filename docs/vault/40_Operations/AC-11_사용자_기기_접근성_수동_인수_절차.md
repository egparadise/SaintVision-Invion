# AC-11 사용자 기기 접근성 수동 인수 절차

## 1. 준비

자동 lane의 exact head SHA와 artifact를 먼저 확보한다. 사용자 기기에는 그 SHA의 배포 후보만 열고, 브라우저·보조기술의 이름과 버전을 확인한다. 원문 token, cookie, 이메일, 사용자 이름, 기기 serial은 기록 파일에 넣지 않는다.

템플릿 `docs/vault/30_Development/Evidence/ac11-accessibility-manual-session-template-v1.json.example`을 `.work/ac11-accessibility/manual-session.json`으로 복사한다. placeholder를 실제 SHA·RFC3339 시각·기기·브라우저·screen reader 관측으로 바꾸고 6개 시나리오를 모두 수행한다. 하나라도 실패하면 해당 `result`와 `overallResult`를 `FAIL`로 둔다.

## 2. GitHub provenance 내려받기

아래 식별자는 `gh run list`와 `gh api` 출력에서 복사한다. artifact ZIP은 풀지 않는다.

```powershell
py -3.12 tools/download_ac11_accessibility_inputs.py --run-id <RUN_ID> --artifact-id <ARTIFACT_ID> --output-dir .work/ac11-accessibility
```

## 3. fresh-auth 결속과 import

access token은 argv·환경 변수·JSON에 넣지 않는다. `.work` 아래 ACL로 보호한 임시 파일을 stdin으로 전달하고 import 직후 삭제한다. JWKS bundle은 공개키 묶음이며 정본 운영 파일을 사용한다.

```powershell
Get-Content -Raw -LiteralPath .work/intranet/operator-access-token.tmp | python tools/import_ac11_accessibility_evidence.py --archive .work/ac11-accessibility/artifact.zip --run-metadata .work/ac11-accessibility/run.json --artifact-metadata .work/ac11-accessibility/artifact.json --manual-session .work/ac11-accessibility/manual-session.json --access-token-stdin --tenant-id <TENANT_UUID> --issuer https://<IDP_HOST>/realms/saintvision --audience saintvision-api --client-id saintvision-web --jwks-file .work/intranet/jwks.json --output .work/ac11-accessibility/ac11-axis-evidence.json
Remove-Item -LiteralPath .work/intranet/operator-access-token.tmp
```

명령은 token을 출력하지 않으며 실패 메시지도 값 대신 분류만 출력한다. `manualAcceptanceMissingCount=0`은 exact SHA, exact scenario set, 전부 PASS, 검증된 fresh interactive auth가 모두 충족될 때만 가능하다.

## 4. 확인

```powershell
python -m pytest tests/test_import_ac11_accessibility_evidence.py -q
python tools/check_docs.py
```

Evidence의 `sourceHeadSha`, `targetRef`, `artifactSha256`, `manualAcceptance.importAuthorizationReceipt.binding`을 확인한다. `MEASURED_PASS`는 접근성 축 측정 결과일 뿐 전체 AC-11 완료나 사용자 최종 인수를 뜻하지 않는다.

## 5. Windows 및 신뢰 경계

PowerShell 5.1의 `Out-File`/`Set-Content -Encoding utf8`은 BOM을 붙일 수 있고 `>`로 binary ZIP을 받으면 byte가 변형될 수 있으므로 사용하지 않는다. 위 Python 3.12+ helper는 `gh api` stdout을 byte로 받아 UTF-8 no-BOM JSON과 검증된 ZIP을 exclusive create로 저장하며 기존 파일을 덮어쓰지 않는다.

수동 session은 target 문서 §5의 여섯 단계를 exact SHA 배포 후보에서 모두 수행한 뒤 기록한다. template의 `NOT_RUN`과 `REPLACE_WITH_` 값은 반드시 실제 관측값으로 바꾸며, 실패는 `FAIL`로 그대로 보존한다.

access token은 이 저장소가 제공하는 browser memory-only 경계 밖으로 자동 export할 수 없다. 승인된 one-time operator handoff가 `.work/intranet/operator-access-token.tmp`를 제공하기 전에는 import를 실행하지 않고 `NOT_OBSERVED`를 유지한다. DevTools, browser storage, shell history에서 token을 복사하는 절차는 금지한다. 제공된 임시 파일은 import 직후 삭제한다. trusted JWKS는 `inv.identity.trusted_file` 형식의 exact 운영 bundle이어야 한다.

fresh token은 수동 수행을 끝낸 뒤 발급받아야 한다. Evidence의 fresh-auth receipt는 수행자 identity가 아니라 **import 승인 운영자**의 검증된 세션을 뜻하며 subject는 digest로만 남는다. 이 저장소에는 운영자 subject/role registry가 없으므로 별도 사람/역할 provenance를 주장하지 않는다.
