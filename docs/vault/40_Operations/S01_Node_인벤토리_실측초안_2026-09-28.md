# S01 Node 인벤토리 실측 초안 (2026-09-28, 읽기 전용 측정)

[[S01_물리노드_인벤토리_표양식_2026-09-22]](PR #55 양식)에 **관측 가능한 사실만** 채운 초안이다. 토폴로지는 [[ADR-100 CP 호스트의 Node 겸임과 5노드 측정 경계]]가 이미 사용자 결정으로 채택한 **`cp-colocated-plus-four-workers`**(Ubuntu worker 4 + Windows CP 겸임 Node 1)이며, 이 문서는 그것을 다시 열지 않는다. 현재 사실: Ubuntu worker **3대 등록**(LAN 파일럿 private state `.work/lan-5node/node1`), Ubuntu worker **1대 미등록**(4번째 PC), Windows CP 겸임 Node **1대 미등록·BLOCKED**(Docker Desktop Engine API 1.41 < installer 최소 1.45, [[2026-09-23_06-15-00_KST_LAN-PILOT-CP-COLOCATED_Codex_구현]]). **허용 자원 상한(C1)·허용 폴더(C2)·Storage 역할(G1)·DNS(A2)·로그 정책(F2)은 사용자 결정이라 비워 둔다.** 측정하지 못한 칸은 `미확인`, 결정 칸은 `사용자 결정`으로 적고 추정값은 넣지 않는다(조용한 강등 금지).

> [!note] 문서 정책(Git에 남기는 값의 범위)
> - **Node ID**: ADR-100이 `nodeId`·공개 인증서 지문·failure-domain ID를 공개 메타데이터로 허용하므로 전체 값을 적는다.
> - **IP·hostname·machine-id·MAC**: 이 문서를 Git에 두면서 이 값들을 보존할 문서별 근거가 없으므로 값을 적지 않고 `관측됨(값은 보호 inventory)`로만 표기한다. 행 식별은 Node ID로 한다. 전체 값은 Git 밖 보호 inventory JSON(`s01-readiness-inventory:1`)에만 둔다 — 양식 §3 "값이 들어가는 순간 공개 이력" 경고와 같은 뜻이다.
> - **#122 preflight와의 범위 차이**: #122의 report guard는 결과 JSON에서 `nodeId`·`ip`·`hostname`·`fingerprint`·`path` 키/값을 전부 금지한다(보고서는 count/status만). 이 문서는 그와 **다른 산출물**로, Node ID는 남기고 나머지 식별 값은 보호 inventory로 넘긴다. "같은 redaction"이 아니다.
> - **비밀**: DSN·비밀번호·키·인증서 원문·SSH 키 지문은 적지 않는다(양식 §3). 이미지 digest는 앞 8자리만.

### 0.1 S-2 재실행 덩어리 (DSN 값은 state에서 읽고 출력하지 않음)

```python
# cwd: 저장소 루트, venv python. DSN은 private-state.json의 "adminDSN" 필드(값 미출력).
import json, psycopg
state = json.load(open(r"D:/Project/SaintVisionI-Invion/.work/lan-5node/node1/private-state.json", encoding="utf-8"))
dsn, tenant = state["adminDSN"], state["tenantId"]
with psycopg.connect(dsn, autocommit=False) as conn:
    conn.execute("BEGIN READ ONLY")                     # psycopg가 연 트랜잭션 위에 read-only 지정
    assert conn.execute("SHOW transaction_read_only").fetchone()[0] == "on"
    conn.execute("SELECT set_config('inv.tenant_id', %s, true)", (tenant,))   # RLS predicate(superuser라도 명시)
    nodes = conn.execute(
        "SELECT node_id, status, heartbeat_at, clock_skew_seconds FROM inv.nodes "
        "WHERE tenant_id = %s ORDER BY node_id", (tenant,)).fetchall()
    resources = conn.execute(
        "SELECT node_id, kind, capacity, offered FROM inv.resources WHERE tenant_id = %s ORDER BY node_id, kind",
        (tenant,)).fetchall()
    snapshots = conn.execute(
        "SELECT node_id, received_at, snapshot FROM inv.node_resource_snapshots WHERE tenant_id = %s ORDER BY node_id",
        (tenant,)).fetchall()
    now, version = conn.execute("SELECT clock_timestamp(), current_setting('server_version')").fetchone()
    conn.rollback()                                     # 어떤 경우에도 COMMIT 없음
print(json.dumps({"nodes": [list(map(str, r)) for r in nodes], "resources": resources,
                  "snapshots": [[r[0], str(r[1]), r[2]] for r in snapshots],
                  "server_now": str(now), "pg": version}, ensure_ascii=False))
```

실측 시 실제로 실행한 것은 위와 같은 SELECT 4개·`set_config`·`ROLLBACK`이며, 당시에는 `SET TRANSACTION READ ONLY`로 read-only를 지정했고 `SHOW transaction_read_only` 확인 행은 없었다(이 덩어리는 그 확인을 추가한 재실행 형태다 — 다음 실행부터 이 형태를 쓴다). 결과 요약: nodes 3행(online·online·offline, skew −0.047537 / −0.082886 / NULL), resources 0행, snapshots 2행, server_version 16.14.

## 2. 이 초안이 보여주는 것 / 못 보여주는 것

- **측정됨**: 등록 3 Node의 CP 관측값(S-2), Node-3의 하드웨어·OS·Docker·NTP 전부(S-3). Node-3는 인벤토리 ↔ capability가 CPU·RAM에서 정확히 일치한다(H2).
- **미확인**: Node-1·Node-2의 호스트 내부 사실(SSH 키가 그 호스트의 시험 계정에 승인되지 않음 — **계정명은 사용자 입력 U5의 일부**), Node-2 offline 원인, Node-4의 접근 정보(state·PG·SSH 어디에도 없음), Node-5(CP 겸임)의 하드웨어 실측과 BLOCKED 해소 경로(Docker Engine 갱신 또는 기준 완화는 ADR 범위), 모든 Node의 인증서·CA·credential(E), NIC 대역폭·지연(B5).
- **결정됨(다시 열지 않음)**: U1 토폴로지 = `cp-colocated-plus-four-workers`, A6 역할(worker 4 + CP 겸임 1) — ADR-100.
- **사용자 결정으로 비움**: A2 DNS, C1 상한, C2 폴더, F2, G1.
- **관측 한계**: `lan-observe-v1` snapshot은 `cpuCapacityMillis`·`memoryCapacityBytes`만 싣는다. GPU·storage·network capability는 `inv.resources`(offer 승인 뒤)에서만 나오므로, C1 결정 전에는 H2 대조가 CPU·RAM으로 제한된다.
