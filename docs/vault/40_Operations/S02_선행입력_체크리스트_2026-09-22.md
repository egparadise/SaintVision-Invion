# S02 착수 선행 입력 체크리스트

S01-BE·S01-ST를 닫고 S02(OIDC·mTLS 등록·Heartbeat / 실제 폴더·DataLocation)를 여는 데 **사용자만 줄 수 있는 입력**의 한 장. 항목마다 **무엇 → 어디에 넣나 → 성공 신호**. 값은 여기에 적지 않는다(비밀은 [[개발환경_이전_절차서]] §4 원칙: 재발급·미기재). S01_PENDING(`INV_NODE_MTLS_CA_BUNDLE`, `INV_OBJECT_STORE_ENDPOINT`)은 코드가 `/v1/health`의 `unresolvedSettings`로 **아직 없음**을 스스로 보고하므로, 채웠는지는 그 응답으로 확인한다.

## 0. 먼저 정할 것 (결정 1건)

| 결정 | 선택지 | 어디에 반영 |
|---|---|---|
| **5대 토폴로지** | (권고) 5대 전부 worker Node + Control Plane은 별도 호스트(이 PC) / 1대 CP 겸 Node + 4 worker / CP를 5대 중 1대에 겸임(ADR 필요) | S01-ST 인벤토리의 Node 수, mTLS 발급 대상 수, S02 인수 증거 대상 수. 근거 [[2026-09-22_Codex_PC_migration_and_5node_readiness]] §4 |

## 1. IdP (OIDC) — S01-BE·S02-BE·S02-FE 로그인

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| **issuer URL** (예: 사내 IdP realm), **audience**(이 API의 식별자), **허용 client_id 목록**(웹 포털·Studio 클라이언트) | 정본 서버: 설정 디렉터리 `api.json`의 `identity.issuer/audience/client_ids/tenant_id`(`deploy/CONFIGURED-SERVER.md` 형식) → `tools/prepare_server_config.py`로 Linux volume 생성 → `INV_CONFIG_VOLUME`. 업무 앱 단독 실행: env `INV_OIDC_ISSUER`·`INV_OIDC_AUDIENCE`·`INV_OIDC_CLIENT_IDS`(쉼표)·`INV_TENANT_ID` | `GET /readyz` ready; `GET /v1/health`의 `unresolvedSettings`에 OIDC 항목 없음; 헤더 없는 요청이 `401 WWW-Authenticate: Bearer` |
| **JWKS 공개키 묶음 파일**(IdP의 RS256 공개 JWK만; URL 아님 — 검증은 오프라인 설계) | `jwks.json` = `{ "issuer": <동일>, "expiresAt": <Unix 초>, "keys": [JWK…] }` → `api.json`의 `identity.jwks_file`(`/run/saintvision/jwks.json`) 또는 env `INV_OIDC_JWKS_FILE` | 만료 전이면 실제 IdP 발급 토큰으로 `GET /v1/session` 200; 만료·다른 issuer 토큰은 401. `INV_OIDC_JWKS_URL`은 **폐기된 이름**(넣어도 무시) |
| **웹 포털 OAuth 공개 설정**(authorize/token 엔드포인트, client_id, redirect URI) | `INV_WEB_AUTH_CONFIG` = 공개 OAuth 설정 JS 파일 경로(`docker-compose.prod.yml`이 필수로 요구) | `docker compose -f docker-compose.prod.yml config --quiet` exit 0; 브라우저 로그인 여정(S02-FE, Gemini 실측) |
| **발급 절차**(누가 client를 등록·회전하는가, 만료 정책) | 운영 문서(사용자 소유) — 절차만, 비밀 없음 | 회전 후 `jwks.json` 교체 → 재시작 없이 다음 검증부터 새 키 (실측은 S02-BE) |

## 2. CA · mTLS 인증서 — S01-BE·S02-BE Node 등록

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| **운영 CA 체인**(Node client cert를 발급한 CA; 자체 CA 가능) | `INV_NODE_MTLS_CA_BUNDLE`(PEM 경로; 현재 S01_PENDING) | `/v1/health.unresolvedSettings`에서 사라짐; 잘못된 CA로 서명된 Node cert가 거부됨(먼저 부정 시험) |
| **Node별 client 인증서 5장**: SAN/EKU(clientAuth)/단일 Control Plane URI, private key **0600/0400 일반 파일**(symlink 금지) | 각 Node의 보호 디렉터리(`inv-node` 설정; [[Codex Node mTLS 전달과 인증서 권한 계약]]); CP 쪽 `NodePeerPolicy`에 지문 allowlist(0~2개, 교체 시 old+new 겹침) | mTLS handshake 성공 → heartbeat `heartbeatSequence` 증가·`lastHeartbeatAt` 갱신(S02-BE); 폐기 지문은 거부 |
| **Control Plane 서버 TLS**(내부망 hostname SAN) | 개발은 `tools/generate_tls_cert.py --output-dir <보호 디렉터리>` + `SAINTVISION_DEV_CERT_DIR`; 운영은 사내 CA 발급본 | 브라우저 경고 없이 `https://<CP 호스트명>/readyz` |

## 3. DNS · 호스트명 — 접근성

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| **CP 엔드포인트 호스트명**(내부 DNS A 레코드), **웹 포털 호스트명**, **IdP 호스트명**(issuer와 일치) | `api.json.allowedOrigins`(포털 origin), Node 설정의 CP URI, 인증서 SAN; 리버스 프록시가 있으면 `INV_TRUSTED_PROXY_ADDRESSES` | 5대 각각에서 `nslookup <CP 호스트명>`·`curl https://<CP>/healthz` 200; 포털에서 API 호출 시 CORS 거부 없음 |

## 4. 물리 PC 5대 — S01-ST 인벤토리·S02 실장비

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| 각 장비: **IP·hostname·OS(Windows/Linux, Docker/WSL 여부)·역할(worker)·CPU/RAM/GPU(모델·VRAM)·디스크 경로·MAC/설치 식별자** | S01-ST 인벤토리 표(사용자 → Codex/Claude가 registry 증거로 기록); Node 등록 시 capability로 관측되어 `GET /v1/nodes/{id}`와 대조 | 등록 후 Node 상세의 capability(cpu millicores·memory bytes·gpu devices)가 인벤토리와 일치 |
| **허용 자원 상한**(Node가 내놓을 CPU/RAM/GPU 몫)과 **허용 폴더**(Node가 읽기 제공할 실제 경로) | 자원: Node offer(`/v1/nodes/{id}/offers`, 운영자 승인); 폴더: `storage-policy.json`(contribution_id·root_version·channel) — [[Codex Node 저장소 설정 설치와 교체 절차]] | offer가 `NodeResourceUsage`의 `offered ≤ capacity`로 보임; 폴더는 contribution 활성화 후 `/v1/storage/locations`에 나타남 |
| **Node 등록 자격**(tenant-bound discovery credential) | 운영자가 발급: `python tools/discovery_credential.py issue --tenant <UUID> --installation <ID> --apply`(`INV_DISCOVERY_ISSUER_DSN`), 원문은 Node의 `INV_DISCOVERY_BEARER_TOKEN`에만(저장소·로그 금지) | `inv-discover`가 announce → `/v1/discovery/candidates`에 후보 등장 → 운영자 admission → Node `active/online`; 다른 tenant 토큰은 403 |
| **시각 동기화 소스**(NTP/도메인 시간) — 각 PC | OS 설정(사용자) | heartbeat 후 `inv.nodes.clock_skew_seconds`가 ±5초 안 → `tools/alarm_check.py`의 `Node 시각 스큐 한도 초과` quiet(결정 #7 활성 알람) |

## 5. Storage 제품 값 — S01-ST·S02-ST

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| **오브젝트 스토어 엔드포인트**(MinIO/S3 호환 URL)·**버킷 이름** | `INV_OBJECT_STORE_ENDPOINT`(현재 S01_PENDING); 버킷·보존(Artifact/로그 90일, Evidence pin ≥1년, DB backup 35일)은 [[Codex 운영 자격증명과 Storage 계약]] | `/v1/health.unresolvedSettings`에서 사라짐; Artifact 업로드→다운로드가 `X-Content-SHA256`과 일치(S03-ST) |
| **스토어 자격증명(재발급, 옛 값 재사용 금지)** | compose 비밀 `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD`(배포 환경에만); 서비스 자격증명은 `svcred` 등록: `python tools/provision_credentials.py register --manifest <파일> --root <보호 root> --check` → `--apply`(`INV_CREDENTIAL_ADMIN_DSN`) | `--check`가 `{"status":"checked"}`, `--apply`가 `applied`; 출력에 비밀·DSN 원문 없음 |
| **Node 제공 폴더의 원본 루트**(Linux 경로; Windows 네이티브 수집은 미지원 → WSL/Docker) | `INV_STORAGE_SOURCE_ROOT`(설치 시험) / Node `--storage-policy` | storage-ready.json에 policySha256·contributionId 기록; `/v1/storage/replica-status` 관측 |

## 6. DB · 커널 (절차서 §4와 동일 — 이 PC에서 재발급)

| 준비할 것 | 어디에 넣는가 | 성공 신호 |
|---|---|---|
| 배포 전용 LOGIN(`inv_kernel` 상속, superuser/BYPASSRLS 금지) DSN, 업무 DSN, 복구 epoch | `INV_RUNTIME_DSN`·`INV_BUSINESS_DSN`(`postgresql+psycopg://`)·`INV_RECOVERY_EPOCH`(= `inv.control_epoch`) | `.venv\Scripts\python -c "import psycopg,os;psycopg.connect(os.environ['INV_TEST_ADMIN_DSN']).close();print('pg ok')"` → `pg ok`; `/readyz` ready |
| 시험·복구용 DSN 넷(`INV_TEST_ADMIN_DSN`, `INV_AUDIT_DSN`, `INV_RECOVERY_*`) | `.env`(git 제외) | 절차서 §5 전수 검증 통과 |
| `CX01_CONTAINER` | **비워 둔다**(보호 컨테이너는 옛 PC) | 관련 시험 19건 skip = 정상 |

## 7. 한 번에 확인하는 순서

1. `docker compose -f docker-compose.prod.yml config --quiet` → exit 0 (필수 env 전부 있음).
2. `GET /v1/health` → `unresolvedSettings: []` (CA bundle·object store 채워짐).
3. `GET /readyz` → ready (JWKS 신뢰 파일·비소유자 DB 역할·tenant·epoch).
4. IdP 실토큰으로 `GET /v1/session` 200, 토큰 없이 401.
5. Node 1대 먼저: discovery credential 발급 → announce → admission → heartbeat → `alarm_check` quiet → 나머지 4대.
6. Storage: contribution 활성화 → `/v1/storage/locations`에 폴더 → Artifact 왕복 SHA-256 일치.

## 이 목록이 여는 것 / 열지 못하는 것

- 1~3이 갖춰지면 **S01-BE**가, 4~5가 갖춰지면 **S01-ST**가 닫힐 조건이 되고 S02-BE/ST(+S02-FE 브라우저 여정)가 착수 후보가 된다([[사용자_결정대기_브리프_2026-09-22]] 선행 입력 표).
- 입력이 있어도 각 과제의 구현·계약·실측 증거·독립 검토·운영 인수는 별도다. 이 문서는 **입력 목록**이지 완료 판정이 아니다.
