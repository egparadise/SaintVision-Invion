# 24주 통합 실행 계획


12개 Sprint의 네 영역 작업 48개를 `docs/task-registry.json`에서 관리한다. 각 작업에 owner·reviewer·선행 작업·목표·합격 증거가 있다. 작업 계획은 문서 기준선이며 48개 작업 모두 아직 planned다.

| 단계 | 상대 주차 | 릴리스 | 게이트 | 사용자에게 보이는 결과 |
|---|---|---|---|---|
| [[S01 기준선]] | 1–2 | R0 | G0 | 완성 목표와 계약을 모든 Agent가 동일하게 해석한다 |
| [[S02 Node 관측]] | 3–4 | R1 | G0 기반 | 로그인한 사용자가 등록 Node와 제공 자원을 본다 |
| [[S03 격리 실행]] | 5–6 | R1 | G3 기초 | Workspace에서 허용 작업이 실행되고 증거가 남는다 |
| [[S04 단일 노드 여정]] | 7–8 | R1 | G3 | 승인·취소·결과 확인의 단일 노드 여정을 완료한다 |
| [[S05 자원 배치]] | 9–10 | R2 | G4 기초 | 5노드 자원을 초과 예약 없이 설명 가능하게 배치한다 |
| [[S06 개발 작업공간]] | 11–12 | R2 | G4 | 편집·터미널·Git 작업이 재시작 후 안전하게 재개된다 |
| [[S07 분산 복구]] | 13–14 | R2 | G4 | Node 손실과 분할 상황에서 낡은 실행을 차단한다 |
| [[S08 운영 통제]] | 15–16 | R2 | G5 기초 | 격리된 Build·GPU 작업을 정책과 복구 아래 수행한다 |
| [[S09 제한된 Agent]] | 17–18 | R3 | G1/G2/G6 기초 | Agent가 근거 있는 Context와 제한된 수정 루프로 일한다 |
| [[S10 AI와 MLOps]] | 19–20 | R3 | G6 기초 | 서로 다른 AI 도구와 모델 계보를 공통 계약으로 추적한다 |
| [[S11 릴리스 후보]] | 21–22 | R3 | G1~G6 종합 | 기능·보안·성능·복원이 검증된 내부망 후보를 만든다 |
| [[S12 파일럿]] | 23–24 | R4 | G0~G6 인수 | 5대 PC에서 개발부터 배포·장애 복구까지 완료한다 |

G0=문제·용어, G1=Prompt, G2=Context, G3=Harness, G4=Graph, G5=ROOF, G6=Agent. 성숙도 번호와 구현 일정은 다른 축이다. S03부터 정책·감사를 적용하며, Agent 자율 실행의 파일럿 승격 전에는 G1~G5를 모두 통과한다.

S01의 네 작업은 준비 범위를 나누어 병행한다. 이후 Sprint는 이전 Sprint의 통합 증거를 기본 의존성으로 둔다. 구체적인 조기 착수는 선행 계약·시험 환경이 준비된 TaskCard를 분리한 뒤 기록한다. 일정 단축을 이유로 보안·동시성·복원 게이트를 생략하지 않는다.

실제 날짜·장비는 아직 미확정이며 첫 30일은 S01~S02다. 기존 첫 30일에 Scheduler까지 완성한다는 목표는 이 일정으로 대체한다. 원문 백로그 ID는 삭제하지 않고 실제 착수 시 TaskCard에 `legacy_refs`로 연결한다.
