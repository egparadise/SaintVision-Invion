## 1. 개요 및 수용 목표 (OUT-11 / AC-11)

본 문서는 SaintVision 제어 평면 및 릴리스 관측 서브시스템의 **S11-FE (접근성·시각 회귀·배포 후보 화면)** 트랙을 체계적으로 검증하기 위해 수립된 **docs-only 시나리오 매트릭스 정본(v1.0.2)**이다.

S07~S10 선행 시나리오 매트릭스(PR #116, #123, #113, #144; 현재 병합 대기 중인 PR 거버넌스 상태 기준)의 체계를 계승하며, 코디네이터 지침, task-registry의 `S11-FE` 요구 증거("E2E·부하·복원·보안·접근성 결과"), Codex FE Review Map 32행("WCAG와 릴리스 후보 UI의 Chrome 증거"), S11 개발과정 History 및 `S11 릴리스 후보.md`의 수용 기준을 프런트엔드 소스코드(`apps/web`) 및 CI 워크플로(`.github/workflows/desktop-browser.yml`)와 1:1로 엄격하게 대조하여 작성되었다.

### 1.1 핵심 작성 및 거버넌스 원칙 (Zero Fake / Honest Boundary)

1. **W3C WCAG 2.1 AA 실측 대조와 정적 리터럴의 엄격한 분리**:
   - `releaseEngine.ts:93-126`에 내장된 `accessibilityAudits` 배열과 `ReleaseCandidateView.tsx:91-98`의 `WCAG 2.1 AA 접근성 적합도` 라벨(:91) 및 `{auditRate}% ({passCount}/{totalAudits} 적합)` 템플릿(:93, 렌더 결과 `"100% (5/5 적합)"`) 표기는 실제 axe-core나 Playwright 접근성 자동화 도구를 실행하여 판정한 것이 아닌 **상수 배열(Fixture-only / 정적 리터럴)**이다.
   - `releaseEngine.ts`의 5대 규칙 식별자는 전체 정본 ID(`wcag21-1.4.3-contrast-minimum`[:95], `wcag21-1.4.11-non-text-contrast`[:102], `wcag21-2.1.1-keyboard-navigation`[:109], `wcag21-2.4.7-focus-visible`[:115], `wcag21-4.1.2-name-role-value`[:121])를 갖는다.
   - `tests/release-candidate.test.ts:65-95`는 DOM을 렌더링하지 않고 `ReleaseManager`의 인메모리 객체 필드(`expect(keyboardAudit?.status).toBe('pass')`)만을 단언하므로 실질적인 접근성 검증 증거가 아니다.
   - 실제 소스코드 상에는 `Button.tsx:27`의 `outline: 'none'`으로 인한 전역 버튼 포커스 링 소멸, `MonacoWorkspaceEditor.tsx:636, :866` 및 `WebTerminal.tsx:502` 입력창의 `outline: 'none'`, `WorkspaceList.tsx:96` 카드 div의 키보드 접근성 누락 등 다수의 접근성 결함이 실재함을 본 문서에 정직하게 기록한다.
2. **시각 회귀 기준 수립 및 hosted 브라우저 job 실행 제약 정직 고지**:
   - `.github/workflows/desktop-browser.yml:57`은 워크플로 스텝 명칭(`- name: Require every canonical browser journey to execute`)이며, 실제 5대 browser journey의 실행을 단언하는 불변식 가드는 line 77(`assert journeys == expected`, hosted 실행상 step 10)에 위치한다.
   - `test_web_container.py:150`의 스크린샷(`.work/web-container-studio.png`)은 비로그인 로그인 화면(`:137`)을 transport fixture(`tests/fixtures/nginx_transport.py`) 대상으로 캡처한 것이며, hosted 브라우저 시험 파일군 전체에서 `ReleaseCandidateView` 렌더링이나 `release`/`header-tab` 진입은 0건이다.
   - `test_approval_browser.py:90`(`.work/approval-browser.png`) 및 `test_studio_browser.py:156`(`.work/studio-browser.png`)에서 스크린샷이 캡처되지만 워크플로 아티팩트 업로드 목록(`:85-88`)에는 포함되지 않는다.
   - `@playwright/test`의 `toHaveScreenshot({ maxDiffPixelRatio: 0.001 })` API는 Node 러너 전용이며, 현재 hosted CI 환경은 Python `playwright==1.62.0` 및 `pytest` 러너이고 `apps/web/package.json`에는 pixelmatch나 `@playwright/test`가 부재하다. 시각 회귀 자동 게이트 구현을 위해서는 Python 이미지 디프(PIL/numpy) 또는 Node 시각 테스팅 러너의 도입과 함께 폰트 고정 및 동적 영역 마스킹이 선행되어야 한다.
   - 본 PR head(`a08c9ce3`)의 hosted `desktop-browser` 성공 실행 ID는 `36366313817`이다.
3. **배포 후보 화면의 서버 계약 부재 및 허위 상태 표출 격리**:
   - `ReleaseCandidateView.tsx:324`의 `<span ...>{rc.isActive ? 'ACTIVE LIVE' : 'STANDBY'}</span>` 및 `:310`의 `<span ...>{rc.rollbackVerified ? '✔ 검증 완료' : '대기'}</span>`는 백엔드 제어 평면의 실제 배포/롤백 API와 연동되지 않은 **클라이언트 인메모리 배열 조작(`releaseEngine.ts:164-176`)**에 불과하다. 특히 `releaseEngine.ts:144` 초기값에 `rollbackVerified: true`가 선언되어 있어 롤백 조작 없이도 초기 화면부터 '✔ 검증 완료'가 노출되는 결함이 실재한다.
   - `ReleaseCandidateView.tsx:145`의 `"측정 환경: 5-Node 분산 클러스터 및 실제 원격 호출 계측 결과"`는 정적 모의 데이터와 정면 배치되는 허위 표기이다.
   - 관련 배포 화면인 `IntranetDeploymentView.tsx`의 정적 리터럴(DEF-S12-01~08에 포함된 :140, :207-209, :462/:474, :190 `202/202`, :543-579 및 후속 보강 대상인 :114 `100% (5/5 PASSED)`, :194 `라이브 프로브(HTTP 200) 검증 완료`, :576 `5/5 Nodes PASSED (100%)`)은 S12-FE 매트릭스(PR #156) 이관 대기 및 전담 관리 대상으로 상호 참조하며, `ModelLineageView.tsx`의 'Production Live' 등은 S10-FE 수정(PR #146)에서 치유 대상임을 명시한다.
4. **문서 전용(docs-only) 경계 및 결함 목록 격리**:
   - 본 카드는 시나리오 매트릭스 수립 문서 전용 카드이다. 본 작업 중 발견된 모든 제품 결함은 Section 4의 '발견된 제품 결함 목록(Defect Backlog: DEF-S11-01 ~ DEF-S11-19)'으로만 기록하며, 실제 소스코드(`apps/web`)의 수정은 본 매트릭스가 승인 완료된 뒤 별도의 제품 결함 치유 카드로 착수한다.

## 6. 결론 및 차기 카드 인계 사항

1. **S11-FE 영역의 현 상태 요약**:
   - `ReleaseCandidateView` 및 `releaseEngine`은 AC-11을 시뮬레이션하는 프런트엔드 프로토타입 골격을 갖추고 있다.
   - 상단 안내 배너(`release-unexposed-notice`)와 롤백 액션 알림에 백엔드 배포 API 미노출 고지가 도입되었으나, (a) 테이블 내부 배지('ACTIVE LIVE', '✔ 검증 완료'), (b) 전역 키보드 포커스 링 상실, (c) 모달 포커스 트랩 및 Esc 닫기 부재, (d) 기본 Dark 테마 버튼 색 대비 미달(3.68:1), (e) 뷰포트 반응형 결함 및 플라시보 버튼 등 총 19건의 명확한 제품 결함(DEF-S11-01 ~ DEF-S11-19)이 식별되었다.
   - Hosted `desktop-browser` CI 환경은 Playwright를 통한 실브라우저 실행 및 스크린샷 아티팩트 저장이 가능하나, 자동화된 픽셀 디프(Visual Regression) 및 접근성(axe-core) 게이트는 아직 연동되어 있지 않다.
2. **차기 카드 인계 계획**:
   - 본 매트릭스 v1.0.2에 대해 Claude UI 축 및 Codex 계약 축의 재검토를 요청한다.
   - 매트릭스 승인 완료 후, 후속 카드인 **"S11-FE 제품 결함 수정 및 접근성/시각회귀 보강(apps/web)"**을 통해 19대 결함(DEF-S11-01 ~ DEF-S11-19)의 소스코드 수정을 일괄 착수한다.
