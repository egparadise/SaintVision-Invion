# G-11 재평가 판정 (2026-09-29)

G-11 hosted CLI provision 설계(PR **#206**, `docs/vault/30_Development/G-11 hosted CLI provision 설계 v1.0.md`)는 결론을 "**지금 하지 않는다**"로 두고 §6에 "**모두 충족 시 B안으로 카드 재개**"인 네 조건을 남겼다. 이 문서는 그 네 조건을 **착지 후보 `b91ab72f`**(`origin/coord/train-land-2330`, `2026-09-28T23:28:51+09:00`)와 **G-03 2단계 #221**(`2f853a94`) 기준으로 하나씩 실측 판정한다.

**판정: 재개하지 않는다.** 조건 1은 원문의 단위(**구현 카드가 닫힘**)로 **landed 0/5**, 조건 2·3은 미충족, 조건 4는 전제만 유지된다.

**판정은 §6 원문의 문구와 수치로만 한다.** v1.0은 조건을 원문보다 강하게 바꾼 곳이 셋 있었고 독립 검토가 그것을 잡았다(§0).

설계 문서는 이 base(`1e8baf04`)에 **없으므로 wiki link가 아니라 평문**(PR 번호 + 경로)으로 인용한다.

## 2. §6 조건별 판정

### 2-1. 조건 1 — 원문 "G-01~G-05(#179 §3-1~3-4) 구현 카드가 닫힘": **미충족 (landed 0/5)**

**단위를 하나로 고정한다.** 원문이 요구하는 것은 "**구현 카드가 닫힘**"이므로 재개 판정에 쓰는 값은 **landed·카드 닫힘** 열뿐이다. 착지 후보에 구현 blob이 있다는 것은 다른 사실이고, 두 열로 나누어 같은 조건을 두 단위로 세지 않는다. 착지 후보 `b91ab72f` 자체도 **integration 착지 전**이므로 landed는 다섯 모두 아니다.

### 2-2. 조건 2 — 원문 "`workflow_dispatch` 1회 실측 … 결과를 Evidence JSON으로 남김": **미충족 (하나도 수행되지 않음)**

| 확인 | 결과 |
|---|---|
| `cli-conformance` lane | **없다**. `b91ab72f`의 `.github/workflows`는 `ac11-migration-rehearsal.yml`·`backend.yml`·`core.yml`·`desktop-browser.yml`·`docs.yml`·`frontend.yml`·`s05-legacy-staircase.yml`·`s11-storage-failure-hosted.yml` **8개**뿐이다 |
| tools/cli-conformance 디렉터리(`package.json`·`package-lock.json`) | **없다**(`git ls-tree -r`에 경로 0건). 이 경로는 **존재하지 않는 것이 이 판정의 내용**이므로 코드 인용으로 적지 않는다 |
| Evidence JSON | 설치·`--version`·로그아웃 status 관측을 담은 파일 **없다** |

**원문을 그대로 인용해 범위를 고정한다.** §6-2는 이렇게 적는다 — *"`workflow_dispatch` 1회 실측: runner에서 `npm ci`(lock 핀)로 세 패키지 설치 성공, `--version` 3건 exit 0, 로그아웃 상태 `claude auth status --json`이 JSON(`loggedIn` 키 포함)을 내고 `codex login status`가 답함 — 결과를 Evidence JSON으로 남김."*

즉 **끝이 Evidence JSON이다.** `adapter_conformance_records`에 넣으라는 요구는 **원문에 없다.** 그래서 이 조건은 **제품 DB·migration과 독립적으로 먼저 실행할 수 있다**: 별 workflow/job, secrets 0, 결과는 **artifact Evidence JSON**, 제품 DB write 0.

이 조건은 **기다려서 충족되지 않는다** — 요구하는 것이 runner 관측이므로 workflow 파일을 먼저 commit해야 성립한다. 즉 **선행 조건이 아니라 작은 측정 작업**이고, 설계 §6이 그 순환을 적지 않았다. 참고로 이 판정이 인용하는 Backend run `36436343934`도 **`workflow_dispatch` 이벤트**였다 — dispatch 전용 실행 자체는 이 저장소에서 이미 일상이다.

설계가 이 조건에 넣은 세 미관측 항목(로그아웃 상태 `claude auth status --json`의 JSON 여부, `codex login status`의 응답, runner에서의 `npm ci` 성공)은 **여전히 전부 NOT_OBSERVED**다. 이 PC에서 로그아웃 시험을 하지 않는 이유(사용자 세션을 끊는다)도 그대로다.

### 2-3. 조건 3 — 원문 "핀 갱신 담당·주기 결정(예: 월 1회, 담당 Claude)": **미충족**

`renovate`·`핀 갱신`·`pin 갱신`으로 `docs`를 훑으면 나오는 것은 **설계 문서 자신과 그 History 기록 둘뿐**이다. 결정 기록이 없다.

**그리고 이 조건의 필요성이 7시간 반 만에 실측으로 강화됐다.** 설계의 npm 조회는 `2026-09-28 17:4x KST`, 이 문서의 재조회는 `2026-09-29 01:0x KST`다.

| 패키지 | 설계 조회 | 재조회(2026-09-29) | 차이 |
|---|---|---|---|
| `@openai/codex` | `latest 0.158.0`, 버전 수 **5044** | `latest 0.158.0`, 버전 수 **5051** | **+7 버전 / 약 7.5시간**, `latest`는 그대로 |
| `@anthropic-ai/claude-code` | `latest 2.1.283`, `stable 2.1.274`, 525 | `latest 2.1.283`, `stable 2.1.274`, **525** | 변화 없음 |

### 2-4. 조건 4 — 원문 "antigravity는 정의 변경(Linux headless 호출 존재 확인) 전까지 **G-11 범위에서 제외**하고 map에 skip 1로 명시": **전제 유지, 적용은 구현 시점**

`src/saintvision/adapters/agents.py`의 `ANTIGRAVITY`는 `b91ab72f`에서도 그대로다 — `install_paths`는 **Windows·macOS 셋뿐**이고 `prompt_args=None`이며 주석이 *"A desktop application with no documented headless invocation"* 라고 적고 `capabilities=frozenset()`(빈 집합)이다.

즉 **정의 변경은 없었고 제외 전제는 유지된다. G-11의 실효 상한은 여전히 3/4다.** 다만 이 조건의 나머지 반쪽("map에 skip 1로 명시")은 **새 lane이 있어야 적용되는 것**이므로 재개 판정의 입력이 아니라 구현 시점의 요구사항이다.

### 2-5. #221이 `subject`를 DB CHECK로 못박았다 — **제품 import 쪽의 선행 조건**(측정은 막지 않는다)

카드는 "opt-in lane의 결과를 **#221의 conformance 기록 import 경로로 넣는** PR"을 B안으로 말한다. **그 경로는 오늘 존재하지 않는다.** 다만 범위를 정확히 해 둔다 — 이것은 **§6의 다섯째 조건이 아니다.** §6-2가 요구하는 것은 Evidence JSON까지이므로(§2-2) **측정은 이것 없이 먼저 할 수 있다.** 아래는 **제품 DB import(B안 완결) 쪽의 선행 조건**이다.

| 관측 | 값 |
|---|---|
| migration | `migrations/versions/0055_adapter_conformance_records.py:75-76` — `SUBJECT_ALLOWED = "subject = 'fixture-adapter'"`, `PROVENANCE_ALLOWED = "provenance = 'in-server'"` 를 **CHECK 제약**으로 건다 |
| migration 자신의 문장 | `:20-23` — `subject`·`provenance`는 **닫힌 단일 값 집합**이고 "**A wider value is refused by the CHECK until a producer exists**" |
| ORM | `src/saintvision/db/models/conformance.py:46-47`에 같은 두 `CheckConstraint` |
| 유일한 producer | `tools/record_fixture_conformance.py:1-11` — *"the **only** producer … What it measures is the product's in-process `ReferenceAdapter` — **not the CLI installed on this host**"*, 각 기록이 `subject = fixture-adapter`·`provenance = in-server`를 말하고 **"a screen reading these rows must not call the result 'the installed CLI conforms'"** 라고 적는다 |

따라서 hosted CLI 적합성 결과를 이 표에 넣으려면 **`subject`(그리고 `provenance`) CHECK를 넓히는 새 migration**과 계약 4개(`contracts/adapter-conformance-not-observed-response.schema.json`·`contracts/adapter-conformance-recorded-response.schema.json`·`contracts/conformance-status-response.schema.json`·`contracts/conformance-status-recorded-response.schema.json`) 및 producer 확장이 함께 필요하다. 이것은 B안의 비용에 **설계 v1.0에 없던 항목**을 더한다.

**그래서 §6이 아니라 "제품 import 선행 조건"으로 한 줄 추가할 것을 제안한다**: "hosted 결과를 `adapter_conformance_records`에 넣기로 **별도 결정한 경우에만**, `subject`·`provenance` 확장(예: `installed-cli`)이 설계·계약·migration 번호와 함께 승인되어 있을 것." 이 결정이 없으면 **import를 포함한** B안 PR은 착수 직후 migration 번호를 요청하며 멈춘다. 측정 전용 PR은 그렇지 않다.

**그리고 순서가 거꾸로면 안 된다.** 로그아웃 상태의 실제 출력 shape는 아직 **NOT_OBSERVED**다(§2-2). 그것을 먼저 관측해야 **`subject`·`provenance` 말고 다른 저장 계약이 필요한지**를 근거로 결정할 수 있다. 미측정 값을 예상해 `0055`의 CHECK를 먼저 넓히는 것은 추측이고, 지금의 strict CHECK는 "installed CLI producer가 없다"는 경계를 **올바르게 보존**하고 있다.

## 3. 그래서 다음 재평가 시점

두 갈래를 **분리한다.** 측정은 migration·계약과 독립이고, 제품 import는 별도 결정이 있어야 한다.

### 3-1. 측정 갈래 — 지금 바로 할 수 있다 (조건 2)

| 순 | 해야 하는 일 | 누구 | 닫는 것 |
|---:|---|---|---|
| 1 | **측정 전용 dispatch PR** — tools/cli-conformance 아래의 `package.json`·`package-lock.json`(정확 버전 + lock)과 **`workflow_dispatch` 전용 job 하나**. 본 lane 불변, `permissions: contents: read`, **secrets 0**, 설치 실패는 그 job만 red, 결과는 **artifact Evidence JSON**, **제품 DB write 0** | Claude | **조건 2** |

**이 갈래는 §2-5를 기다리지 않는다.** §6-2의 요구가 Evidence JSON까지이기 때문이고, 오히려 이 측정이 로그아웃 출력 shape(지금 NOT_OBSERVED)를 관측해 **어떤 저장 계약이 필요한지**의 근거를 만든다.

### 3-2. 재개 갈래 — 조건 1·3이 먼저다

| 순 | 해야 하는 일 | 누구 | 닫는 것 |
|---:|---|---|---|
| 1 | **#221 착지**(G-03 2단계). 그리고 landed 단위가 채워지려면 **다섯 모두 integration 착지** | 코디네이터 병합 목록 | 조건 1 |
| 2 | **핀 갱신 담당·주기 결정**(원문의 예시는 "월 1회, 담당 Claude") | 사용자·코디네이터 결정 | 조건 3 |
| 3 | 조건 4는 antigravity **정의 변경 전까지 제외**로 유지하고, 새 lane의 map에 skip 1을 적는다 | Claude(구현 시점) | 조건 4 적용 |
| 4 | 네 조건 충족 확인 뒤 **B안 구현** | Claude | 카드 재개 |
