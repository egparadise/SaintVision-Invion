# G-11 재평가 판정 (2026-09-29)

G-11 hosted CLI provision 설계(PR **#206**, `docs/vault/30_Development/G-11 hosted CLI provision 설계 v1.0.md`)는 결론을 "**지금 하지 않는다**"로 두고 §6에 "**모두 충족 시 B안으로 카드 재개**"인 네 조건을 남겼다. 이 문서는 그 네 조건을 **착지 후보 `b91ab72f`**(`origin/coord/train-land-2330`, `2026-09-28T23:28:51+09:00`)와 **G-03 2단계 #221**(`2f853a94`) 기준으로 하나씩 실측 판정한다.

**판정: 재개하지 않는다.** 네 조건 중 **셋이 미충족**이고 하나는 전제만 유지된다. 그리고 설계 v1.0 이후에 **다섯째 조건이 새로 생겼다**(§2-5) — #221이 conformance 기록의 `subject`를 DB CHECK로 못박았기 때문이다.

설계 문서는 이 base(`1e8baf04`)에 **없으므로 wiki link가 아니라 평문**(PR 번호 + 경로)으로 인용한다.

## 2. §6 조건별 판정

### 2-1. 조건 1 — "G-01~G-05 구현 카드가 닫힘": **미충족 (4/5)**

착지 후보에서 파일로 실측했다.

| 공백 | `b91ab72f`에서의 상태 | 근거 |
|---|---|---|
| **G-01** adapters HTTP 시험 | **있음** | `tests/core/test_adapters_route.py`, `tests/integration/test_adapters_route_real_pg.py` |
| **G-02** live archiver hosted 실행 | **있음** | `backend.yml:164-166`이 주석으로 **"the two live archiver cases now run here (docker exec probe, image from `INV_TEST_ARCHIVER_IMAGE`)"** 라고 적고 `backend.yml:66`이 `INV_TEST_ARCHIVER_IMAGE: postgres:16`을 준다. 예전의 "published host port 없음" skip은 사라졌다(`tests/integration/test_recovery_drill.py:194`가 그 경위를 적는다) |
| **G-03** conformance 결과 API 노출 | **1단계만** | `src/saintvision/api/v1/conformance_status.py:1`이 스스로 **"G-03 phase one"** 이라고 적고 `:66`이 "이 platform은 conformance를 저장하지 않는다"를 응답 문장으로 갖는다. **2단계(#221, `2f853a94`)는 OPEN이고 `b91ab72f`에 없다** |
| **G-04·G-05** business lane·model-registry 쓰기 route | **있음** | `src/saintvision/api/v1/`에 `context_bundles.py`·`run_records.py`·`run_seal.py`·`eval_runs.py`·`model_versions.py`·`model_verify.py`·`model_retention.py`·`model_release.py` |

**G-03 카드가 열려 있으므로 조건 1은 미충족이다.** 다섯 중 넷의 구현이 착지 후보에 들어 있다는 것까지가 지금 참인 문장이다. 그리고 착지 전이므로 **다섯 모두 병합 대기**라는 사실도 함께 적는다 — "카드가 닫힘"을 병합 완료로 읽으면 조건 1은 0/5다. 어느 읽기에서도 충족이 아니다.

### 2-2. 조건 2 — "`workflow_dispatch` 1회 실측": **미충족 (하나도 수행되지 않음)**

| 확인 | 결과 |
|---|---|
| `cli-conformance` lane | **없다**. `b91ab72f`의 `.github/workflows`는 `ac11-migration-rehearsal.yml`·`backend.yml`·`core.yml`·`desktop-browser.yml`·`docs.yml`·`frontend.yml`·`s05-legacy-staircase.yml`·`s11-storage-failure-hosted.yml` **8개**뿐이다 |
| `tools/cli-conformance/`(`package.json`·`package-lock.json`) | **없다**(`git ls-tree -r`에 경로 0건) |
| Evidence JSON | 설치·`--version`·로그아웃 status 관측을 담은 파일 **없다** |

**그리고 이 조건은 "기다리면 충족되는" 종류가 아니다.** 요구하는 것이 **runner에서의 관측**이므로, workflow 파일을 먼저 commit하지 않으면 영원히 미충족으로 남는다. 즉 조건 2는 **선행 조건이 아니라 작은 측정 작업**이다 — 설계 §6이 이 순환을 명시하지 않았다. 재평가 시점의 순서를 §3에 그렇게 적는다.

설계가 이 조건에 넣은 세 미관측 항목(로그아웃 상태 `claude auth status --json`의 JSON 여부, `codex login status`의 응답, runner에서의 `npm ci` 성공)은 **여전히 전부 NOT_OBSERVED**다. 이 PC에서 로그아웃 시험을 하지 않는 이유(사용자 세션을 끊는다)도 그대로다.

### 2-3. 조건 3 — "핀 갱신 담당·주기 결정": **미충족**

`renovate`·`핀 갱신`·`pin 갱신`으로 `docs`를 훑으면 나오는 것은 **설계 문서 자신과 그 History 기록 둘뿐**이다. 결정 기록이 없다.

**그리고 이 조건의 필요성이 7시간 반 만에 실측으로 강화됐다.** 설계의 npm 조회는 `2026-09-28 17:4x KST`, 이 문서의 재조회는 `2026-09-29 01:0x KST`다.

| 패키지 | 설계 조회 | 재조회(2026-09-29) | 차이 |
|---|---|---|---|
| `@openai/codex` | `latest 0.158.0`, 버전 수 **5044** | `latest 0.158.0`, 버전 수 **5051** | **+7 버전 / 약 7.5시간**, `latest`는 그대로 |
| `@anthropic-ai/claude-code` | `latest 2.1.283`, `stable 2.1.274`, 525 | `latest 2.1.283`, `stable 2.1.274`, **525** | 변화 없음 |
| `@google/gemini-cli` | `latest 0.61.0`, 763 | `latest 0.61.0`, **763** | 변화 없음 |

`latest`가 움직이지 않아도 **같은 태그 아래 버전이 7개 늘었다.** 핀을 정확 버전 + lock으로 잡는 설계 결정(§1-5)이 옳다는 증거이면서, **핀 갱신 담당이 없으면 lane이 곧 "예전 CLI의 모양"을 증명한다**는 비용의 증거다.

### 2-4. 조건 4 — "antigravity는 정의 변경 전까지 G-11 범위에서 제외": **전제 유지, 적용은 구현 시점**

`src/saintvision/adapters/agents.py`의 `ANTIGRAVITY`는 `b91ab72f`에서도 그대로다 — `install_paths`는 **Windows·macOS 셋뿐**이고 `prompt_args=None`이며 주석이 *"A desktop application with no documented headless invocation"* 라고 적고 `capabilities=frozenset()`(빈 집합)이다.

즉 **정의 변경은 없었고 제외 전제는 유지된다. G-11의 실효 상한은 여전히 3/4다.** 다만 이 조건의 나머지 반쪽("map에 skip 1로 명시")은 **새 lane이 있어야 적용되는 것**이므로 재개 판정의 입력이 아니라 구현 시점의 요구사항이다.

### 2-5. 새로 생긴 조건 5 — #221이 `subject`를 DB CHECK로 못박았다

카드는 "opt-in lane의 결과를 **#221의 conformance 기록 import 경로로 넣는** PR"을 B안으로 말한다. **그 경로는 오늘 존재하지 않는다.**

| 관측 | 값 |
|---|---|
| migration | `migrations/versions/0055_adapter_conformance_records.py:75-76` — `SUBJECT_ALLOWED = "subject = 'fixture-adapter'"`, `PROVENANCE_ALLOWED = "provenance = 'in-server'"` 를 **CHECK 제약**으로 건다 |
| migration 자신의 문장 | `:20-23` — `subject`·`provenance`는 **닫힌 단일 값 집합**이고 "**A wider value is refused by the CHECK until a producer exists**" |
| ORM | `src/saintvision/db/models/conformance.py:46-47`에 같은 두 `CheckConstraint` |
| 유일한 producer | `tools/record_fixture_conformance.py:1-11` — *"the **only** producer … What it measures is the product's in-process `ReferenceAdapter` — **not the CLI installed on this host**"*, 각 기록이 `subject = fixture-adapter`·`provenance = in-server`를 말하고 **"a screen reading these rows must not call the result 'the installed CLI conforms'"** 라고 적는다 |

따라서 hosted CLI 적합성 결과를 이 표에 넣으려면 **`subject`(그리고 `provenance`) CHECK를 넓히는 새 migration**과 계약 4개(`contracts/adapter-conformance-not-observed-response.schema.json`·`contracts/adapter-conformance-recorded-response.schema.json`·`contracts/conformance-status-response.schema.json`·`contracts/conformance-status-recorded-response.schema.json`) 및 producer 확장이 함께 필요하다. 이것은 B안의 비용에 **설계 v1.0에 없던 항목**을 더한다.

**그래서 §6에 조건 5를 추가할 것을 제안한다**: "`adapter_conformance_records`의 `subject`·`provenance` 확장(예: `installed-cli`·`hosted-runner`)이 **설계·migration 번호와 함께 승인**되어 있을 것." 이 조건이 없으면 B안 PR은 착수 직후 migration 번호를 요청하며 멈춘다.

## 3. 그래서 다음 재평가 시점

순서를 고정한다. **조건 2는 마지막이 아니라 조건 1·3·5가 정리된 뒤의 첫 실행**이다.

| 순 | 해야 하는 일 | 누구 | 그것이 닫는 조건 |
|---:|---|---|---|
| 1 | **#221 착지** (G-03 2단계) | 코디네이터 병합 목록 | 조건 1 |
| 2 | **핀 갱신 담당·주기 결정**(예: 월 1회, 담당 Claude, 자동 갱신 도구 도입 여부 포함) | 사용자·코디네이터 결정 | 조건 3 |
| 3 | **`subject`·`provenance` 확장 설계 + migration 번호 배정** | Claude 설계 → Codex 검토 | **조건 5** |
| 4 | **측정 전용 dispatch PR** — `tools/cli-conformance/{package.json,package-lock.json}`과 `workflow_dispatch` 전용 job 하나. 본 lane 불변, 설치 실패는 그 job만 red, 결과를 Evidence JSON으로 남긴다 | Claude | **조건 2** |

4번을 3번 뒤에 두는 이유는 하나다 — 측정 결과를 **넣을 자리가 정해진 뒤에** 측정하면 그 결과가 곧 증거가 되고, 먼저 측정하면 Evidence JSON이 표에 들어가지 못한 채 남는다.

**재평가 트리거**: 위 1·2·3이 모두 끝난 날. 그 전에는 이 판정이 유효하고, 설계 §0의 "지금 하지 않는다"를 뒤집는 새 실측은 없다.
