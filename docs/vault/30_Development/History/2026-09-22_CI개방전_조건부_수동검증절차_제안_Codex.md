# CI 개방 전 조건부 수동 교차 레인 검증 절차 제안

> **제안 전용.** Codex는 provenance/governance 정본을 수정하지 않았다. 정책 owner Claude가 검토·수용할 때까지는 정식 규칙이 아니다.

## 왜 필요한가

- `8f4d919`에서는 EvidenceViewer가 `sealed && sha256`만으로 무결성 PASS를 내는 회귀가 생겼다. Vitest만 실행하는 프런트 확인에서는 Python `tests/test_route_coverage.py`의 UI guard가 돌지 않았고, 전체 pytest를 실행한 Claude가 먼저 찾았다. Codex focused Python 재현도 해당 guard를 `1 failed`로 확인했다.
- 후속 `0b7d51e`에서 Gemini가 `verified === true` 게이트와 3-case DOM guard를 착지했다. Codex는 DOM 시험을 소스에서 확인했으며 자체 Vitest 재실행은 하지 않았다. 수정 뒤 Python focused guard는 통합 코드에서 `1 passed`로 확인했다.
- 같은 경계의 검사 양쪽에 있다. 프런트 17개 시험 파일은 backend canonical schema/공유 fixture를 읽지만 FastAPI/DB/권한 경로를 실행하지 않는다. Python/Playwright 시험은 반대로 실제 프런트 경로·요청·렌더링을 일부 검사한다. 한 레인 결과를 다른 레인의 증거로 간주하면 놓친다.
- GitHub Actions는 결제 제한으로 실제 실행이 아직 없다. 아래 절차는 그 공백 동안의 임시 운용안이며, 워크플로 YAML에 배선된 상태를 실행 결과로 취급하지 않는다.

## 제안: 변경 범위가 실행 레인을 결정한다

모든 변경마다 모든 suite를 돌리지 않는다. 변경된 경계에 직접 걸린 가장 좁은 시험을 먼저 실행하고, 더 무거운 실행은 표의 조건일 때만 추가한다. 실행들은 **동일한 최종 SHA와 clean tree**에 귀속시키고 `tools/provenance.py -- <command>`로 종료 코드·인터프리터·환경·skip을 기록한다.

| 변경 트리거 | 최소 수동 실행 | 조건부 추가 실행 | 이유 |
|---|---|---|---|
| 문서만 변경 | `tools/check_docs.py`; 변경한 task/ontology 매핑이 있으면 `tools/check_ontology.py` | Obsidian 변경/내보내기 전 `tools/sync_obsidian.py --check`; `--apply`는 승인된 동기화 작업에서만 | 제품 동작과 무관한 전체 suite 비용을 피한다. |
| `apps/web/src` 화면·상태·API 경로 변경 | 앱 작업 디렉터리에서 `npm run test`, `npx tsc -b`, `npm run build`; Python `tests/test_route_coverage.py` | endpoint 목록/configured route 또는 실제 요청 경로가 바뀌면 `tests/integration/test_vf_canonical.py` (PostgreSQL 필요) | Vitest는 화면 동작을, Python guard는 정적 UI 불변식/요청 경로를 지킨다. 최근 `EvidenceViewer` 회귀는 두 가드가 서로 대체되지 않음을 보였다. |
| canonical schema, 공유 fixture, 생성 타입, API adapter 계약 변경 | `python tools/export_schemas.py --check`, `python tools/check_contract_bindings.py`, 프런트 `npm run contracts:check` 및 전체 Vitest, 해당 `tests/core/*contract*` | 응답을 만드는 서비스/route도 변경되면 해당 PostgreSQL API integration 시험. 권한·RLS·mutation 변경은 real PostgreSQL이 필수 | fixture/schema 적합성은 실제 backend 직렬화·DB 행·권한 실행의 증거가 아니다. 양쪽 계약 consumer를 실행하고 실제 producer 변경이면 DB 경계도 탄다. |
| backend route, 상태 변경, authorization, DB/migration 변경 | 해당 focused pytest와 관련 core/API contract 시험 | DB state/role/RLS/migration이 관련되면 disposable PostgreSQL 시험; public API route/프런트 client 집합이 변하면 `test_vf_canonical.py` | 모의 서비스 반환만으로 실제 저장·권한 경로를 추정하지 않는다. |
| 로그인, 사용자 주요 여정, 브라우저 전용 API/다운로드, proxy/TLS, DOM 상호작용 변경 | Vitest 또는 focused backend 시험(위 해당 레인 포함) | `desktop-browser.yml`의 Chromium+HTTP+DB 시험; 배포 proxy/TLS 변경이면 web-container 시험. 실제 환경 인수가 요구된 변경은 별도 운영/브라우저 인수 | jsdom/Vitest와 Python TestClient는 실제 browser, TCP/proxy, wire 환경을 대체하지 않는다. |
| 여러 agent 변경의 통합, migration/schema 대량 변경, release/handoff 전 | 같은 최종 SHA에서 frontend 전체 suite와 backend/core 전체 pytest를 각각 실행하고 skip 사유 분포 기록 | browser/Go/Docker image 전용 workflow는 해당 기능이 변경됐거나 통합 인수가 요구될 때 실행. suite가 같은 DB/daemon을 공유하면 순차 실행 | 누적 착지 상호작용은 단일 patch의 focused 시험으로 보이지 않는다. 그래도 관련 없는 무거운 opt-in 인수는 매 변경마다 강제하지 않는다. |

### 결과 보고 규칙

- test lane마다 정확한 command, cwd, exit code, test/pass/fail/error/skip 수와 skip 사유를 따로 적는다. 서로 다른 interpreter나 SHA에서 나온 숫자를 합치지 않는다.
- Provenance에는 full SHA, branch/worktree, clean 여부, 절대 interpreter/tool 경로와 버전, KST, 실행자, PostgreSQL/Docker/Go/Node/browser 게이트를 포함한다.
- 한 lane의 성공을 전체 검증 완료로 쓰지 않는다. 특히 schema fixture pass는 실제 backend response pass가 아니며, Vitest pass는 Python UI guard pass나 browser acceptance가 아니다.
- prerequisite가 없어 시험을 못 돌린 경우 성공처럼 표시하지 말고 `unverified`와 사유를 남긴다. skip을 pass에 더하지 않는다.

## 임시 절차의 종료 조건

이 수동 교차 레인 절차는 **다음 조건을 모두 만족할 때만** 필수 임시 절차에서 내린다:

1. GitHub Actions 결제/계정 blocker가 해소된다.
2. 같은 integration SHA에서 `docs`, `backend`, `core`, `frontend`, `desktop-browser` 다섯 workflow가 실제 시작되어 완료된다. 단순 YAML 검사나 각 job의 존재는 충족 조건이 아니다.
3. 각 workflow가 의도한 시험을 실제 실행한 증거가 있고, 금지된 skip/error/failure가 0이다. opt-in lane은 기대 testcase 집합 및 no-skip gate가 통과해야 한다.
4. 해당 run URL/SHA와 JUnit 또는 workflow evidence를 History에 남기고, 사용자가 CI 복구를 확인한다.

이후에는 이 수동 전체 교차 실행을 반복 요구하지 않고, 각 change-trigger 표의 로컬 focused 검증과 hosted CI를 쓴다. 어느 workflow든 비활성화/누락되거나 필수 테스트가 skip되면 해당 lane 수동 실행을 다시 임시로 요구한다. 이것은 CI 전체의 품질을 보장한다는 선언이 아니라, 이 제안에서 다룬 다섯 레인의 자동 실행을 확인하는 종료 기준이다.

## 제안 상태 및 담당

- Codex가 절차안과 사용 근거를 작성했다. 공통 governance 정본은 변경하지 않았다.
- 다음 담당: Claude가 change trigger, 종료 조건, provenance/skip 규칙을 검토해 정본에 수용·수정하거나 기각한다. 수용 전까지 이 문서를 accepted policy로 인용하지 않는다.
- 작성자 검증: cross-lane inventory `2867ddbb78af0efdc46288b3c26a316e41ad719e`; 이 문서의 check_docs/ontology/sync 및 제안 내용은 작성자 검증이지 Claude 승인이나 hosted CI 검증이 아니다.
