## 작업한 것

- 실제 Docker 배포를 `saintvision.server:create_app --factory`로 고정. 커널 0038까지 보존하며 OIDC/DB/RLS/Workspace/business 정본 결합. 설정 부재/읽기 불가/잘못된 역할은 거부.
- 원격 fixture 서버와 이전 demo 서버 원문은 tests/fixtures로 옮겨 보존. src 배포 package 및 Docker image에는 fixture app 없음. 원격 apps/web 및 frontend workflow는 b9752a8 그대로 보존.
- 현재 원격 fixture의 임의 Bearer는 401. 실제 위험은 사용자가 만든 code/PKCE 조합으로 관리자 토큰 200을 발급하고 인증 없는 프로젝트 목록도 200을 반환하는 경로였음. 구성된 정본에서는 token/userinfo fixture 경로 404, 임의 Bearer로 프로젝트 접근 401.
- init-db.sql은 이미 기본 로그인 생성을 제거한 상태. Compose에는 암호의 기본값 없이 명시적 설정을 요구하고 API/PG/MinIO host publish를 127.0.0.1로 제한. 실제 기존 DB 자격증명 변경/점검은 수행하지 않음.
- 감사 정책의 기대 head만 0038로 갱신. 함수 정의 hash·grant 허용 집합은 바꾸지 않음. 기존 migration 파일 내용 및 분기 이력은 보존.
- 같은 DB에 대한 connect_timeout 차이를 별도 target으로 잘못 거부하던 비교 수정. DB host/name 및 제한된 inv_app/inv_kernel 역할 분리는 유지.
- standalone 배포/복원 도구의 kernel import 경로 보완. Windows PowerShell 시험은 7의 모듈 경로를 5에 잘못 상속하지 않도록 환경 수정.
