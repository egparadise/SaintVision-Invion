# SaintVision 개발 시작

서버 PC의 바탕화면에서 **SaintVision 개발 시작**을 두 번 클릭한다. Studio가 실행되고 Windows 사용자에게 발급된 일회용 링크로 브라우저가 로그인한다. 일반 주소는 `http://127.0.0.1:18100`이다. 로그인 만료 시 같은 바로가기를 다시 연다. 다른 PC에서 이 주소를 열면 그 PC 자신의 localhost이므로 현재 개발 Studio에 연결되지 않는다.

바로가기가 없을 때 PowerShell에서 다음 한 줄을 실행한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Project\SaintVision-Invion\agent-codex-dev-environment\deploy\studio\Start-DevStudio.ps1"
```

## 준비된 프로젝트

| 프로젝트 | 위치 | 사용할 일 |
|---|---|---|
| SaintVision-Invion | `C:\Project\SaintVision-Invion\agent-codex-dev-environment` | 통합 개발 환경 구현 checkout. 기존 원본 checkout은 보존됨 |
| ai-starter | `C:\Project\SaintVision-Workspaces\Projects\ai-starter` | Python CPU 모델 학습·평가·단위 테스트 |
| python-starter | `C:\Project\SaintVision-Workspaces\Projects\python-starter` | 일반 Python 코드 작성·실행·테스트 |

AI/일반 프로젝트에는 독립 `.venv`와 pip, Git 저장소, Agent 공통 지침이 있다. CPU 컨테이너는 Python 3.11 표준 라이브러리를 사용하고 Windows 편집 환경은 설치된 Python 3.14를 사용한다. 외부 패키지는 아직 컨테이너에 설치하지 않았다. `python -m pip`로 가상 환경을 명시하고, 패키지를 쓰는 작업은 해당 패키지를 포함한 실행 이미지를 준비해야 한다.

## 1. 프로젝트와 Workspace 선택

왼쪽에서 프로젝트를 선택한다. 혼자 수정할 때는 `main` Workspace를 사용할 수 있다. 여러 Agent와 개발할 때는 도구별 별도 Workspace를 선택한다. AI 프로젝트에는 아래 폴더가 이미 준비되었다.

- Codex: `C:\Project\ai-starter\studio-codex`
- Claude: `C:\Project\ai-starter\studio-claude`
- Gemini: `C:\Project\ai-starter\studio-gemini`
- Antigravity: `C:\Project\ai-starter\studio-antigravity`

다른 프로젝트에서는 도구 이름을 선택하고 **Workspace 준비**를 누른다. Orca가 별도 Git worktree를 만든다. 최초 생성은 커밋된 HEAD 기준이므로 main의 미커밋 수정이 자동 복사되는 것으로 생각하지 않는다. 각 도구의 수정은 별도 branch에 남고, 통합은 Git diff를 검토한 뒤 진행한다.

## 2. 개발 도구 열기

선택한 Workspace에서 Orca·Codex·Claude·Gemini CLI·Antigravity 버튼을 누른다. **이 서버 Windows에** 해당 도구 창이 열린다. Orca는 해당 README를 열며 Codex/Claude/Gemini/Antigravity는 개발 터미널을 연다. Antigravity 연결은 설치된 `agy` CLI를 사용한다. Antigravity GUI의 프로젝트 자동 연결은 확인되지 않았다.

각 도구의 기존 로그인을 사용한다. Codex ChatGPT 로그인과 Claude 로그인은 확인됐고, Gemini/Antigravity 모델 요청·과금·로그인 성공을 이번 설정에서 시험하지 않았다. 로그인 화면이 나오면 본인이 해당 공급자에 로그인한다. 계정이나 API key를 Studio에 붙여 넣지 않는다.

처음 AI 프로젝트에 다음처럼 요청할 수 있다.

> AGENTS.md와 README.md를 읽고 src/train.py의 학습·평가 흐름을 설명해 줘. CSV 입력 검증을 추가하고 tests에 잘못된 입력 사례를 넣어 줘. 실제 테스트 결과를 확인하고 변경한 파일을 알려 줘.

Orca는 프로젝트/작업 정리, Codex는 실행·아키텍처·무결성, Claude는 서비스·데이터 처리·테스트, Antigravity/Gemini는 UI·시각화에 배분하면 된다. 버튼을 누르는 것만으로 작업을 다른 Agent에게 전달하거나 검토가 완료되지는 않는다.

## 3. 실행 자원 선택

초기 한도는 동시 1개, CPU 0.5코어, RAM 256 MiB, 최대 120초다. 자원 한도 변경에서 CPU 0.25–1코어, RAM 128–512 MiB, 최대 300초를 설정할 수 있다. 실행 중에는 한도 변경을 거절한다. 이는 새 개발 컨테이너의 제한이며 Windows 전체나 AI 도구의 메모리를 제한하는 설정은 아니다.

서버 PC의 기존 업무를 보존하기 위한 작은 시작 한도다. 두 컴퓨터의 RAM/VRAM을 하나의 큰 메모리로 합치지 않는다. 현재 GPU·원격 Node·대규모 데이터 작업은 활성화되지 않았다.

## 4. 테스트·학습 실행

`ai-starter`에서 **단위 테스트** 또는 **CPU 학습·평가**를 누른다. `python-starter`에서는 **단위 테스트** 또는 **프로그램 실행**을 누른다. 선택한 Workspace의 src/tests/data 파일을 고정해서 Linux 컨테이너로 전달한다. 파일 변경 후 같은 버튼을 다시 누르면 새 소스로 새 작업을 만든다.

AI 예제는 합성 데이터 101행 중 51행으로 선형 모델을 400 epoch 학습하고 50행으로 평가한다. 일반 학습 파이프라인을 시작하기 위한 실제 CPU 실행 예제이며 업무 데이터나 대규모 모델 학습 성과는 아니다.

컨테이너에는 프로젝트 입력과 tmpfs 출력만 있고 호스트 폴더·Docker 소켓·계정 자격 증명·네트워크가 없다. 코드에서 결과는 `SV_OUTPUT_DIR` 아래에 쓴다. 출력은 최대 2 MiB/50개다. 로컬 폴더에 파일을 쓰는 코드가 실제 PC 전체를 수정하는 것은 아니다.

## 5. 결과 확인과 이어서 개발

**실제 개발 작업 기록**에서 작업을 펼친다. 종료 코드, stdout/stderr, 실제 적용 자원, 소스 SHA-256, 출력 파일 SHA-256이 나온다. 모델 `model.json`, 평가 `metrics.json`, 학습 곡선용 `loss.csv`를 내려받을 수 있다. 저장된 파일을 바꿔 해시가 달라지면 다운로드를 거절한다.

실행 기록은 `C:\Project\SaintVision-Workspaces\.studio\jobs`에 보존된다. 직접 지우지 않는다. 실패 원인을 고치고 다시 실행하면 이전 기록과 새 기록을 비교할 수 있다. 원격 제품 Run/Evidence와는 별도 개발 기록이다.

## 취소·중단·재시작

실행 중인 작업의 **작업 취소**를 누르면 그 작업의 컨테이너만 정리한다. Studio 프로세스가 끊겼다면 시작 바로가기를 다시 연다. journal에서 미완료 작업을 찾아 소유한 컨테이너를 정리하고 `중단 후 정리됨`으로 남긴다. 파일을 보존하며 자동 재실행하지 않는다. 정지 확인 실패는 `복구 확인 필요`로 표시하고 새 작업을 막는다. Docker Desktop을 먼저 켠 뒤 다시 확인한다.

원격 Node 조회 서비스까지 서버 재시작 후 켜려면 다음을 실행한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Project\SaintVision-Invion\agent-codex-dev-environment\deploy\lan\Start-LiveConsole.ps1"
```

Node 화면은 `http://localhost:3000`, 다른 PC에서는 `http://192.168.45.99:3000`이다. 현재 실제 원격 Node는 192.168.45.225 한 대이며 관측 전용이다. 로컬 CPU 개발 환경이 준비됐다는 사실을 두 PC 분산 실행·GPU 시험 통과로 해석하지 않는다.

## 기존 프로젝트 추가

원본 폴더를 복사·초기화하지 않고 등록한다. 이름과 폴더 경로를 자신의 프로젝트에 맞춰 실행한다.

```powershell
& "C:\Project\SaintVision-Invion\.venv\Scripts\python.exe" "C:\Project\SaintVision-Invion\agent-codex-dev-environment\tools\dev_studio.py" register "내 프로젝트" "C:\Project\내프로젝트"
```

기존 프로젝트는 개발 도구 열기를 제공한다. 실행 명령·패키지·입력 경로를 검토하기 전에는 임의 명령을 웹 실행 버튼으로 자동 등록하지 않는다.
