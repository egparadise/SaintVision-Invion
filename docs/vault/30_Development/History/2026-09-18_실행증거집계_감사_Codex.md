# 실행 증거 집계와 CI gate 표본 감사

## 방법과 실측

Evidence/verification-boundary-audit/aggregation-audit.py는 실제 VF main을 임시ROOT에서 호출한다. Docker/PG/pytest subprocess 경계만 stub으로 대체하고 XML 파일은 실제 파싱한다. workflow Python heredoc gate도 원문 추출 후 임시파일로 실행했다. 실제 CI/DB/Docker/운영 네트워크0. 명령 `python .../aggregation-audit.py . .../aggregation-results.json` exit0; JSON에8 runner 조건·9 gate조건·selection 직접/전이 및 root부재 대조, sourceHashes를 기록했다. 스크립트 exit0는 관측 수집 성공이지 제품 합격이 아니다.

추가 실제 pytest 최소재현: 임시 test_probe에 assert False를 두고 --collect-only/--junitxml 실행 → exit0,Junit testcase0,본문 미실행. collect-only-result.json 참조. 이는 VF 외부 child0/빈XML stub 조건이 가능한 pytest 모드임을 보이는 대조이며 실제 VF Docker 실행은 아니다.

## VB-AGG-01 / P2 — 이전 XML의 PASS가 현재 실패 실행에 붙음

VF runner는 고정prefix-tests.xml을 제거하거나 새 run namespace로 만들지 않는다. timeout/exit1 뒤에도 파일이 있으면 읽어 tests를 집계한다. 이전1PASS XML을 둔 채 새child timeout을 주입하니 JSON exit124/tests.passed1, childexit1이면 exit1/tests.passed1이었다. 새 성공exit0이 XML을 만들지 않는 stub도 이전PASS를 가져왔다.

종료코드 실패는 보존되므로 timeout이 exit0으로 바뀐 것은 아니다. 문제는 현재 실행에 도달하지 않은 과거 PASS를 현재 proof에 귀속하는 증거 오염이다. 수정 조건: 실행별 고유 XML/JSON namespace, 새로 생성된 artifact의 run 결속, 불완전 실행의 부분증거 표시. 이전파일을 무조건 운영경로 삭제하는 방식 대신 고유 private run 경로가 안전하다. owner Codex, reviewer Claude; 이번 감사에서는 미수정.

## VB-AGG-02 / P2 — child exit0만으로 증거 생성 완료를 대체

VF main에 childexit0+XML없음/빈XML/잘린XML을 각각 주입해 모두 exit0이었다. 없음은 tests도 없고, 빈XML은passed0, 잘린XML은testReport=incomplete만 추가한다. 필요한 증거가 미완료여도 runner 완료코드는 성공이다. 일반0수집 childexit5는5로 보존된다. 1개만 가진 부분XML+exit0도1PASS로 보고하며 필수case집합 계약은 없다.

수정 조건: subprocessExitCode와 evidenceStatus를 분리하고 실행증거를 만들지 못한 경우 distinct nonzero/unverified로 처리한다. collect-only는 실행 인수 모드에서 거부하거나 별도scope로 분리한다. 통상 정상 pytest는 JUnit을 남긴다는 가정만으로 미완료를 성공으로 처리하지 않는다. 전체선택 임의변경/일부case 실행이 전체인수로 쓰이지 않도록 요청선택·실제case ID를 저장한다. owner Codex, reviewer Claude; 미수정.
