## 3. schema 1.5 evidence 필드와 랩 준비표 vs 실제 파일럿

- **schema 1.5는 실재**한다: `tests/integration/test_placement_benchmark.py` 361행 `report["schemaVersion"] = "1.5.0"`, 302행 `lockHold`, 346/351/356행 `legacyLockWait`·`limitRowWait`·`lockAcquireWait`, 271행 `sqlDiagnostics`, 363행 `serverSideLockWaitSeparatelyMeasured=False` — lane이 나열한 필드·boolean 그대로. `services/control-plane/src/inv/db.py:218` `lockHoldMs`가 원천. 다만 **`tools/placement_benchmark.py` CLI 단독 JSON은 `schemaVersion "1.1.0"`**(288행)이고 1.5 필드는 integration test가 tool 결과 위에 증강해 만든다(관찰 O1).
- 카드 18 요약 evidence `s05-symmetric-metrics-card18.json`는 별도 요약 schema(`postAcquireLockHoldP95Ms`·`lockAcquireElapsedP95Ms`·`lockAcquireMeasurement`·`rawEvidenceSha256`)이며 lane이 이를 1.5라고 부르지는 않는다. 정합.
- **실제 파일럿 상태**(코디네이터 `.work/lan-5node/node1` state, 값은 IP·flag만 읽음): Node 3건 `.143`(online, 코디네이터 #89 실검증)·`.222`·`.210`(provisioned, CSR 미등록 대기), server `.74`, Node별 `public/nodes/<id>/worker.zip` 3개, CP 겸임 Windows Node 미등록. lane 준비표 "실행 Node 5개/물리 host 5대 … 5개 미만이면 중단"과 **모순 없음** — lane은 준비 완료를 주장하지 않고(파일럿 상태 언급 0건, History "로컬/물리 시험 미실행"), 현재 상태는 차단 조건 2에 해당. 추가로 파일럿 state의 `nodes[]`에는 `hostId`·`failureDomainId`·`coLocatedWithControlPlane`·`measurementEligible`이 없으므로 lane의 `LAB_INVENTORY_PATH`(revision 고정 inventory)는 파일럿 state와 **별도 파일**이어야 한다 — lane이 이미 그렇게 정의하므로 정합(구현 카드 유의).
