# 노드 정적 용량 vs 동적 사용률 엄격 분리, 텔레메트리 부재 정직 반영 및 클러스터 생존성 보존

> **수행 요약**:
> 백엔드 HTTP 라우트 실측 검증(Codex/Claude/User 합의)에 따라, 노드 인벤토리 및 상세 응답에 실시간 평면 텔레메트리(CPU/RAM/스토리지/GPU 동적 사용률)가 일체 노출되지 않는 현실을 화면 계약에 정직하게 반영하였다.
> 1. **클러스터 조용한 전멸 방지 (`App.tsx`)**: 백엔드가 평면 텔레메트리를 반환하지 않을 때 `measuredNodes` 필터링으로 인해 노드가 0대로 전락하던 결함을 치유(`nodes={nodes}` 전달)하여 클러스터 물리 노드 생존성을 보존하였다.
> 2. **정적 용량(Capacity) vs 동적 실시간 사용률(Utilization) 엄격 분리 (`ResourceExplorer.tsx`, `virtualFabric.ts`)**: 결측된 동적 점유량을 `0 Cores`나 `0 B`로 왜곡하여 100% 유휴 상태라는 착시를 주지 않고, `LogicalResourceSummary`를 nullable(`number | null`)로 전환하여 `미제공 (API 미노출)`으로 명확히 고지하였다.
> 3. **엄격한 3분할(Tri-Distinction)**: "0 (없음: 0대)" vs "모른다 (미확인: unobserved/NaN)" vs "미제공 (unprovided: HTTP API 미노출)"의 3분할을 확립하고, NaN 결측 시 `formatBytes`가 `'NaN undefined'`를 내뿜지 않도록 방어하였다.
> 4. **Tab 4 Capabilities 표 상단 고지**: 등록(Enrollment) 시점의 정적 하드웨어 총용량(Total Capacity)과 실시간 동적 사용량의 HTTP 미제공 상태를 못 박는 안내 배너(`role="status"`)를 배치하였다.
> 5. **DOM 단위 테스트 및 3대 돌연변이 실측 사살 (전수 KILLED)**: `node-telemetry-capacity-distinction.test.tsx`를 신설하여 6/6 test passed 및 M1/M2/M3 돌연변이를 실측 사살하였다.

## 1. 백엔드 소스 실측 정합 결과 (사실 관계)

- **`GET /v1/nodes` (리스트 producer `_node_body`)**:
  - `schemas.NodeResponse`(`Strict`, `extra="forbid"`)가 방출하는 필드는 `nodeId`, `hostname`, `osType`, `osVersion`, `agentVersion`, `status`, `enrolledAt`, `lastHeartbeatAt`, `heartbeatSequence`, `labels`뿐임.
  - 평면 동적 텔레메트리(`cpuUsagePercent`, `memoryUsedBytes`, `storageTotalBytes`, `storageUsedBytes`, `gpuVramUsedBytes` 등)는 0건 방출.
  - 백엔드 DB models (`src/saintvision/db/models`) 전수 검색 결과 동적 사용률 컬럼 0건(전무).
- **`POST /v1/nodes/{id}/heartbeats`**:
  - `ObservationPayload`(`capabilityId`, `usedQuantity`, `unit`)로 capability별 사용량을 수집·기록(`record_observations`, 쓰기 전용)하여 placement 엔진이 내부적으로만 읽고 있음.
  - **이 수집된 사용량을 클라이언트가 조회할 수 있는 HTTP GET 라우트가 전무(미노출)**함.
- **`GET /v1/nodes/{id}` (상세 producer)**:
  - `NodeDetailResponse`의 `capabilities`(`NodeCapability`)는 `totalQuantity`만 있는 **정적 하드웨어 총용량(Total Capacity)** 선언이며, `usedQuantity`는 미포함.
- **화면의 유일한 정직한 상태**:
  - 정적 용량(등록 신고치)은 표시하되, 실시간 동적 사용률은 "0"이 아닌 **"미제공 (HTTP 읽기 경로 부재)"**로 표기해야 사용자가 "용량 여유가 100% 있다"는 치명적 오해를 하지 않는다.

## 2. 주요 구현 및 화면 정직성 강화 내역

### ① 클러스터 조용한 전멸 방지 (`apps/web/src/app/App.tsx`)
- 기존:
  ```tsx
  const measuredNodes = nodes.filter(node => !node.telemetryUnavailable);
  // ...
  <ResourceExplorer nodes={measuredNodes} ... />
  <PlacementSimulator nodes={measuredNodes} />
  ```
  - 백엔드가 평면 텔레메트리를 방출하지 않으므로 `observedNode`는 모든 노드를 `telemetryUnavailable: true`로 마킹.
  - 결과적으로 `measuredNodes.length === 0`이 되어 `ResourceExplorer`가 "등록된 노드가 없습니다"(`storage-no-nodes-notice`) 및 0개 노드를 렌더링, 정상 동작 중인 클러스터가 완전히 죽은 것으로 오인되는 중대한 화면 결함 발생.
- 개선:
  ```tsx
  <DeveloperStudio nodes={nodes} ... />
  <ResourceExplorer nodes={nodes} ... />
  <PlacementSimulator nodes={nodes} />
  ```
  - `nodes={nodes}`를 직접 전달하여 텔레메트리가 없더라도 등록된 물리 노드들이 토폴로지에 그대로 유지되며, 상태와 정적 총용량이 정상 표출되도록 보존.

### ② 정적 용량 vs 동적 실시간 사용률 엄격 분리 (`apps/web/src/contracts/virtualFabric.ts`, `apps/web/src/features/desktop/ResourceExplorer.tsx`)
- 계약 타입 확장 (`virtualFabric.ts`):
  ```typescript
  export interface LogicalResourceSummary {
    totalCores: number;
    allocatableCores: number;
    usedCores: number | null; // 동적 사용률 부재 시 null
    totalMemoryBytes: number;
    allocatableMemoryBytes: number;
    usedMemoryBytes: number | null;
    totalGpuCount: number;
    totalGpuVramBytes: number;
    usedGpuVramBytes: number | null;
    totalStorageBytes: number;
    usedStorageBytes: number | null;
    onlineNodeCount: number;
    totalNodeCount: number;
    disclaimer: string;
  }
  ```
- 결측치 0 왜곡 제거 및 `null` 반환 (`ResourceExplorer.tsx`):
  - `(node.cpuUsagePercent || 0)` 식을 제거하고, `Number.isFinite`와 `!node.telemetryUnavailable`이 충족될 때만 실시간 점유량을 합산.
  - 유효 관측치가 없을 경우 `usedCores: null`, `usedMemoryBytes: null`, `usedStorageBytes: null`을 명시적으로 반환.
- 논리 풀 요약 카드 JSX 렌더링:
  - `logical-vcpu-used`: `{logicalSummary.usedCores !== null ? `${logicalSummary.usedCores} Cores` : '미제공 (API 미노출)'}`
  - `logical-ram-used`: `{logicalSummary.usedMemoryBytes !== null ? formatBytes(logicalSummary.usedMemoryBytes) : '미제공 (API 미노출)'}`
  - `logical-storage-used`: `{logicalSummary.usedStorageBytes !== null ? formatBytes(logicalSummary.usedStorageBytes) : '미제공 (API 미노출)'}`

### ③ 엄격한 3분할(Tri-Distinction) 및 NaN 포맷팅 방어
- **GPU 3분할**:
  - `typeof node.gpuCount === 'number' && Number.isFinite(node.gpuCount)`:
    - `0`인 경우: `GPU: 없음 (0대)` (0: None)
    - `>0`인 경우: `GPU: ${node.gpuName} (${node.gpuCount}대)`
  - 결측치/NaN인 경우: `GPU: 장치 미확인` (모른다: Unknown)
- **CPU 용량 방어**:
  - 유효 숫자: `${node.cpuCores}C`
  - 결측치/NaN: `용량 미확인`
- **`formatBytes` NaN 방어**:
  - `if (bytes === null || bytes === undefined || !Number.isFinite(bytes)) return '미확인';`
  - 기존에 `NaN`이 전달되면 `Math.log(NaN)` 계산으로 인해 `'NaN undefined'`라는 흉측한 문자열이 렌더링되던 문제를 원천 차단.
- **물리 노드별 실시간 사용률 배너 (`role="status"`)**:
  ```tsx
  <div
    data-testid={`node-utilization-status-${node.id}`}
    role="status"
    style={{ ... }}
  >
    📊 자원 사용률: {node.telemetryUnavailable ? '미제공 (HTTP 읽기 경로 부재)' : `CPU ${node.cpuUsagePercent ?? 0}% · RAM ${formatBytes(node.memoryUsedBytes)}`}
  </div>
  ```

### ④ Tab 4 Hardware Capabilities 고지 배너
- 노드 상세 capabilities 원장 표 바로 상단에 고지 배너 신설:
  ```tsx
  <div
    data-testid="capabilities-static-capacity-notice"
    role="status"
    style={{ ... }}
  >
    ℹ️ <strong>정적 용량과 사용률 구별 고지</strong>: 아래 원장의 수량은 노드가 등록(Enrollment) 시점에 신고한 <strong>정적 하드웨어 총용량(Total Capacity)</strong>입니다. 실시간 동적 사용량(Used Quantity)은 백엔드 내부에서만 수집되며 현재 외부에 노출되는 HTTP 읽기 라우트가 부재(미제공)하여 표시되지 않습니다.
  </div>
  ```

## 3. DOM 단위 테스트 및 돌연변이 실측 사살 (KILLED)

`apps/web/tests/node-telemetry-capacity-distinction.test.tsx` (happy-dom & createRoot 기반 harness):
1. **클러스터 생존성 단언**: `telemetryUnavailable: true` 노드가 주어졌을 때 카드가 렌더링되고 빈 목록 안내문이 나타나지 않음 검증 (PASS).
2. **논리 자원 점유율 `미제공 (API 미노출)` 단언**: `logical-vcpu-used`, `logical-ram-used`, `logical-storage-used`가 `0 Cores`나 `0 B`를 포함하지 않고 정직하게 `미제공 (API 미노출)`을 렌더링함 검증 (PASS).
3. **GPU 3분할 단언**: `0대` 노드는 `없음 (0대)`, `NaN` 노드는 `장치 미확인`, `2대` 노드는 `NVIDIA RTX 4090 (2대)`를 렌더링함 검증 (PASS).
4. **용량 부재 시 NaN 방어 단언**: `CPU: 용량 미확인`, `RAM: 미확인`, `스토리지: 미확인` 표출 확인 (PASS).
5. **노드 사용률 배너 `role="status"` 단언**: `📊 자원 사용률: 미제공 (HTTP 읽기 경로 부재)` 확인 (PASS).
6. **Tab 4 정적 용량 고지 배너 단언**: `capabilities-static-capacity-notice` 표출 및 안내 문구 확인 (PASS).

### 돌연변이 실측 사살 기록
- **Mutation 1 (M1: 결측 사용률을 0으로 기본화)**:
  - 주입: `usedCores: hasKnownUsedCores ? Math.round(usedCores * 10) / 10 : 0`
  - 결과: `AssertionError: expected '0 Cores' to be '미제공 (API 미노출)'` -> **KILLED (사살)**.
- **Mutation 2 (M2: GPU NaN을 0대로 오인)**:
  - 주입: `node.gpuCount > 0 ? ... : '없음 (0대)'`
  - 결과: `AssertionError: expected 'GPU: 없음 (0대)' to be 'GPU: 장치 미확인'` -> **KILLED (사살)**.
- **Mutation 3 (M3: formatBytes NaN 방어 제거)**:
  - 주입: `if (bytes === null || bytes === undefined) return '미확인';`
  - 결과: `AssertionError: expected 'RAM: NaN undefined' to be 'RAM: 미확인'` -> **KILLED (사살)**.
