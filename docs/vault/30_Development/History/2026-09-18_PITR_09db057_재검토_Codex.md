## R1-03: 단일 writer 논거는 조건부 타당

PG16 기본 shell archiver는 system(archive_command) 완료를 기다린다. 제안의 동기식 cp/mv를 단일 서버가 전용 아카이브에서 실행하고 다른 writer/수동 실행이 없다면 fixed tmp에 남은 부분파일은 다음 cp로 덮어쓰고 최종mv 전에 공개되지 않는다. 이 제한된 조건에서 '고정 tmp 자체가 무조건 결함'이라는 판정은 하지 않는다.

그러나 이 직렬성은 공유 저장소 전체의 직렬성이 아니다. PG16 공식문서 §27.2.9는 primary/standby가 같은 아카이브를 공유하며 동시에 같은 파일을 보낼 때 race-free여야 한다고 명시한다. archive_mode=always인 standby, 다른 cluster/인스턴스, 별도 수동 publisher에는 각자의 실행 흐름이 있다. 따라서 모든 설정에서 하나의 전역 archiver라는 전제는 성립하지 않는다.

또한 $$는 호출 프로세스 기준 이름일 뿐, 여러 host/container/PID namespace에서 전역 고유성을 보장하지 않는다. unique temp만으로도 최종 if-not-exists→mv 덮어쓰기 경합은 해결되지 않는다. 이 리허설이 현재 실제 두 writer 충돌을 겪었다고 주장하지는 않는다.

## 직접 실행한 archive 명령 대조

후보 override의 실제 archive_command를 추출해 경로만 private temporary directory로 치환, Git Bash에서 실행했다. Docker/PG/운영볼륨 접근0이다.

| 조건 | exit / 최종 bytes | 판정 |
|---|---|---|
| 대상 부재 | 0/A | 순차 생성 성공 |
| 기존 동일A | 0/A | idempotent 성공 |
| 기존 상이B | 1/B | 덮어쓰기 거부 |
| stale tmp만 존재 | 0/A | 재시도 복구 |
| cp 후 mv 전에 다른 writer가 최종B를 게시하는 순서를 주입 | 0/A | 나중mv가 B를 덮음; 단일writer 가정 밖 경합 |

마지막은 cp wrapper가 정상 복사 직후 최종목적지에 B를 쓰게 한 결정적 interleaving 시험이며 실제 동시 PostgreSQL 구성 실행이 아니다. Evidence/pitr-review/09db057-archive-command.json에 후보SHA/원명령/범위/결과를 기록했다.

수정·범위 조건: Tier-A를 전용 namespace·단일 writer로 한정하고 다른 서버/복원 인스턴스가 같은 경로에 쓰지 않는 계약을 명시·적용하거나, 잠금/덮어쓰기 없는 원자 게시와 동일성 재검사를 갖춘 구현으로 공유writer를 지원해야 한다. 현재 override의 외부volume 이름만으로 exclusivity가 강제되는 것은 아니다. fsync 없는 crash내구성은 문서화된 Tier-A 한계로 남길 수 있으나, 이를 운영RPO 보장으로 사용할 수 없다. 제한된 준비안 착지와 운영 인수는 계속 분리한다.
