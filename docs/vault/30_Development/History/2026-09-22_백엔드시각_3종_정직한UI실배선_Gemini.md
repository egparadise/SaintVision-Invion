# 백엔드 내구성 시각 필드 3종 정직한 UI 실배선 및 신선도 오독 차단 보고서

## 1. 개요 및 배경

- **트랙 목적**: Codex의 백엔드 응답 시각 정합 커밋 [`f1d95466`](https://github.com/egparadise/SaintVision-Invion/commit/f1d95466) 및 설계 문서 `2026-09-22_response_freshness_asof_Codex.md`를 프론트엔드에 완전하고 정직하게 반영.
- **백엔드 추가 3대 시각 필드의 의미와 화면 표현 원칙**:
  1. **`RunResultView.stateUpdatedAt`** (required `Timestamp`): `inv.runs.updated_at` 기반. 실행 상태가 마지막으로 DB에 갱신된 시각 (HTTP read time 아님). ➔ 고유 라벨: **`실행 상태 갱신`** (`data-testid="run-state-updated-at"`).
  2. **`ShardObservation.stateAsOf`** (nullable `Timestamp`): 응답에 포함된 parent 및 member Run들의 최신 `updated_at`. ➔ 고유 라벨: **`샤드 상태 기준`** (`data-testid="shard-state-as-of"`). "단일 공통 스냅샷이나 조회 시각이 아닙니다"라는 한정된 의미 명시.
  3. **`RunArtifactList.completedAt` & `RunLogView.completedAt`** (nullable `Timestamp`): `inv.result_completions.completed_at` 기반. 결과가 커밋된 실행 완료 시각. ➔ 고유 라벨: **`실행 완료 시각`** (`data-testid="artifact-completed-at"`, `data-testid="log-completed-at"`).
- **엄격한 금기 사항 및 오독 방지 규칙**:
  - `completedAt`을 "로그 수집 시각", "로그 캡처 시각", "산출물 다운로드 시각", "화면 마지막 확인 시각", "신선도 갱신 시각"으로 오인시키는 라벨링 엄격 금지 (없는 신선도를 지어내지 않는다).
  - `stateAsOf`를 "단일 공통 스냅샷" 또는 "동일 시점 스냅샷"으로 둔갑시키지 않는다.
  - 세 시각 필드를 "갱신됨"이나 "최종 확인" 같은 모호한 단일 어휘로 뭉뚱그리지 않고 출처를 담은 고유 라벨을 부여한다.
  - `DeveloperStudio.tsx`에서 `completedAt`이 없을 때 `new Date().toISOString()`을 위조하던 합성 로직 완전 소거.

## 2. 세부 구현 및 UI 실배선 내역

### A. API 헬퍼 및 런타임 계약 검증 보강
1. **`apps/web/src/shared/api/runArtifactObservation.ts` 신규 작성**:
   - `fetchRunArtifacts(projectId, runId)`: `/v1/projects/{project}/runs/{run_id}/artifacts` 정본 커널 엔드포인트 호출.
   - `RunArtifactList` 계약 런타임 검증: `source === 'execution-kernel'`, `runId`, `artifacts` 배열, `count`, `verifiedCount`, `completedAt` (nullable Timestamp) 검증.
   - `getArtifactDownloadUrl(projectId, runId, path)`: 실제 커널 산출물 바이너리 스트림 다운로드 URL 생성기 제공.
2. **`apps/web/src/shared/api/runLogObservation.ts` 보강**:
   - `RunLogView.completedAt` nullable Timestamp 런타임 타입 검증 추가.
3. **`apps/web/src/contracts/types.ts` 보강**:
   - `RunItem`에 `stateUpdatedAt?: string;` 및 `completedAt?: string | null;` 추가.

### B. `apps/web/src/features/runs/RunDetail.tsx` 실배선
1. **Header / Overview**:
   - `run.stateUpdatedAt` 또는 `runResult?.stateUpdatedAt`: `실행 상태 갱신: {formatTime}` (`data-testid="run-state-updated-at"`).
   - `runResult?.completedAt` 또는 `run.completedAt`: `실행 완료 시각: {formatTime}` (`data-testid="run-detail-completed-at"`).
2. **Tab 2 (실시간 로그)**:
   - `logView?.completedAt` 존재 시:
     `ℹ️ [실행 완료 시각] {formatTime} (커널 결과 완료 커밋 시각이며, 실시간 로그 캡처나 화면 갱신 시각이 아닙니다)` (`data-testid="logs-freshness-banner"`, `data-testid="log-completed-at"`).
     헤더 뱃지: `완료 커밋: {formatTime}` (`data-testid="log-completed-at-badge"`).
   - 부재 시: 기존 `[화면 확인 기준]` 스냅샷 고지 유지.
3. **Tab 3 (산출물 목록)**:
   - 더미 목록을 소거하고 `fetchRunArtifacts` 실제 API 실배선.
   - `artifactList?.completedAt` 존재 시:
     `ℹ️ [실행 완료 시각] {formatTime} (커널 결과 완료 커밋 시각이며, 파일 다운로드 또는 화면 조회 시각이 아닙니다)` (`data-testid="artifacts-freshness-banner"`, `data-testid="artifact-completed-at"`).
   - 실제 산출물 행 렌더링 (`data-testid="artifact-row-${art.path}"`), 파일 크기, SHA-256, 증거 식별자 표출.
   - 다운로드 버튼: `getArtifactDownloadUrl`로 실제 커널 엔드포인트 연동 (`data-testid="download-artifact-${art.path}"`).
   - 사전 로드된 `run.artifacts`가 있는 경우의 fallback 호환성 보존.
4. **Tab 5 (분산 샤드 원장)**:
   - `shardObservation?.stateAsOf` 존재 시:
     `ℹ️ [샤드 상태 기준] {formatTime} (포함된 Run 행들의 최신 DB 갱신 시각 기준이며, 단일 공통 스냅샷이나 조회 시각이 아닙니다)` (`data-testid="shards-freshness-banner"`, `data-testid="shard-state-as-of"`).
   - Aggregate Manifest Card에 `샤드 상태 기준 (stateAsOf)` 카드 추가 (`data-testid="shard-state-as-of-card"`).
   - 부재 시: 기존 `[화면 확인 기준]` 스냅샷 고지 유지.

### C. `apps/web/src/features/runs/RunList.tsx` 실배선
- 테이블 각 행의 날짜/시각 셀에 `run.stateUpdatedAt` 표출 (`data-testid="run-state-updated-at-${run.id}"`, `상태 갱신: {formatTime}`).
- `run.completedAt` 존재 시 `실행 완료: {formatTime}` (`data-testid="run-completed-at-${run.id}"`)로 정직화.

### D. `apps/web/src/features/studio/DeveloperStudio.tsx` 실배선
- `artifactData`에 `stateUpdatedAt?: string;`, `completedAt?: string | null;` 추가.
- `RunResultView` 조회 시 `res.completedAt || new Date().toISOString()`으로 현재 시각을 지어내던 결함 완전 소거 ➔ 백엔드가 준 `res.completedAt` 그대로 보존.
- Step 4 실행 세션 헤더:
  - `currentRun?.stateUpdatedAt || artifactData?.stateUpdatedAt` ➔ `실행 상태 갱신: {formatTime}` (`data-testid="studio-run-state-updated-at"`).
  - `artifactData?.completedAt` ➔ `실행 완료 시각: {formatTime}` (`data-testid="studio-run-completed-at"`).
- JSON 인스펙터에 `stateUpdatedAt`, `completedAt` 정본 필드 포함.
