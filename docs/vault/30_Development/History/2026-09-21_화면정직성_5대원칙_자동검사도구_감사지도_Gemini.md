# 화면 개발 정직성 5대 원칙 수립, 자동 검사 도구 구축 및 전체 감사 지도 완료 보고서

## 1. 개요 및 배경

백엔드(Codex/Claude)가 fail-closed 보안 경계(권한 없는 호출자 거절, 테넌트 불일치 403, 가짜 commandId 거절)를 구축하더라도, 화면이 임의의 자리표시자나 가짜 데이터를 합성하거나 실패를 조용히 숨기면 시스템 전체의 무결성이 훼손된다. 사용자 지시에 따라 오늘 하루 동안 확립한 판단 기준을 5대 정직성 원칙으로 집약하고, 이를 구조적으로 집행하는 정적 자동 검사 도구 `tools/check_frontend_integrity.py`를 제작했으며, 전체 화면 감사 지도 및 Codex 운영자 CLI 자격증명 발급과의 연동 예측을 명문화하였다.

---

## 2. 작업 내역 및 실증 결과

### 2.1 화면 개발 정직성 5대 핵심 원칙과 실제 사례집 완성
거버넌스 정본 문서 `docs/vault/40_Governance/화면_개발_정직성_지침_및_사례집.md`를 신설하고 다음 5대 원칙과 실제 코드베이스 내 사례를 상세히 정리했다:
1. **원칙 ①: 백엔드가 주지 않는 것을 만들지 않는다 (Never Synthesize)**
   - `mlopsEngine.ts` 가짜 모델 정확도 0.812 합성 제거 (`TEST_FIXTURE_LINEAGES`를 테스트 fixture 디렉터리로 격리).
   - `StorageObservationView` 반-합성 가드 (`currentHealth: "unknown"`, `operationalAcceptanceAssessed: false` 강제).
   - `RunDetail.tsx`의 가짜 SSE 실시간 로그 스트림(`wsp-saint-pilot`, `단위 테스트 48/48 통과`, `exit code 0`) 전면 소거 및 정직한 빈 상태 표시(`run-logs-none`) 대체.
   - `DeveloperStudio.tsx`의 실행 세션 fallback `run_01JABCDE0001` 제거 -> `미지정`.
2. **원칙 ②: 부를 근거가 없으면 부르지 않는다 (0-Network Calls Without Basis)**
   - `ResourceExplorer.tsx:420` 하드코딩 테넌트 UUID 제거 및 세션 테넌트 누락 시 0회 호출 가드 (`discovery-tenant-required-notice` 노출, 브로드캐스트 버튼 disabled).
   - `WebTerminal.tsx` 가짜 commandId(`11111111-1111-4111-8111-111111111111`) 티켓 발급 요청 0회 차단 (`isAuthorizedCommandId` 가드).
   - `ModelLineageView.tsx` `approvalInput` 빈값 기본값 및 `planRunId` 빈값 가드.
   - `DeveloperStudio.tsx` `activeRunId` 부재 시 영수증 조회 버튼 disabled 및 0-call 가드.
3. **원칙 ③: 일어나지 않은 일을 일어났다고 표시하지 않는다 (No Premature Success Display)**
   - `WebTerminal.tsx` WebSocket 실제 연결(`onopen`) 전 초기 출력의 `Connected via secure WebSocket` 조기 표출 결함 수정.
   - `WebTerminal.tsx` 일회용 티켓 값의 console 로깅 원천 차단 (Zero-Leak Invariant).
   - `InvFileExplorer.tsx` 클라이언트 타이머 기반 가짜 레플리카 복구 시뮬레이션 제거 (어댑터 부재 시 정직한 거절).
   - `ModelLineageView.tsx` `apr_01JXYZ889900` 사전 입력 제거.
4. **원칙 ④: 검증 못 함과 검증 통과를 같게 표시하지 않는다 (Strict Tri-State: unverified ≠ verified)**
   - `InvFileExplorer.tsx` 실제 커널 체크아웃 바이트 SHA-256 일치 시에만 `verified`, 불일치 시 `mismatch`, 바이트 미연결/데모 시 `unverified` 유지 (3갈래 엄격 분리).
   - `ModelStudioView.tsx` 검증 라우트 부재 시 임의 통과 없이 `RES-MODEL-404` 정직한 거절 표시.
5. **원칙 ⑤: 실패를 캐시나 이전 결과로 가리지 않는다 (Never Mask Fresh Failures)**
   - `DeveloperStudio.tsx` 아티팩트 다운로드 시 404 경로 부재만 레거시 폴백 허용하고, 500/401/네트워크 에러는 즉시 alert 경고 및 캐시 다운로드 차단.
   - `InvFileExplorer.tsx` 재검증 시 503 서버 에러 발생 시 이전 `verified` 뱃지를 즉시 지우고 `error` 배너 표시.

### 2.2 자동화 검사 도구 제작 및 회귀 방지 (`tools/check_frontend_integrity.py`)
Claude의 `check_contract_bindings.py`와 동일한 거버넌스 철학으로, 프런트엔드 정적 구조를 자동 검사하는 스캐너를 제작했다:
- **[RULE-1 Placeholders]**: `apps/web/src/` 내 금지된 하드코딩 자리표시자(`00000000-0000-0000-0000-000000000001`, `run_01JABCDE0001`, `rcp_01JABCDEF`, `apr_01JXYZ889900`, `prj_01JABCDE` 등) 검출.
- **[RULE-2 Zero-Call Guard]**: 테넌트/식별자 누락 시 API 호출을 차단하는 가드 존재 여부 확인.
- **[RULE-3 Premature & Credential Logging]**: 소켓 연결 전 초기 상태의 `Connected` 선언 검출 및 console 로깅에서의 민감 티켓(`ticketData.ticket`, `bootstrapToken`) 노출 검출.
- **[RULE-4 Tri-State]**: `InvFileExplorer.tsx`의 엄격한 3상태(`verified`, `mismatch`, `unverified`) 유지 확인.
- **음성 대조(Negative Control) 실측**: `--test-negative` 플래그를 통해 고의 돌연변이(자리표시자, 조기 연결, 티켓 로깅) 주입 시 즉시 감지하여 exit 1로 사살함을 실증.

### 2.3 전체 화면 감사 지도 및 디스커버리 CLI 연동 예측
- **감사 지도 확정**: 감사 완료 영역(`ResourceExplorer`, `WebTerminal`, `InvFileExplorer`, `DeveloperStudio`, `ModelLineageView`, `RunDetail`, `mlopsEngine`)과 미감사 영역(`AdminSecurityConsole`, `MonacoWorkspaceEditor`, `IntranetDeploymentView`, `ReleaseCandidateView`)의 경계를 명확히 수립.
- **디스커버리 화면 연동 예측**: 현재 `tenantId` 부재 시 `discovery-tenant-required-notice` 및 0건 시 `discovery-empty-state`가 동작 중이며, Codex의 운영자 CLI(`saint operator issue-grant`) 연동 시 빈 상태에서 실제 후보 카드 및 일회용 부트스트랩 토큰 카운트다운으로 유기적으로 전환되도록 시퀀스 다이어그램과 연동 흐름을 설계함.
