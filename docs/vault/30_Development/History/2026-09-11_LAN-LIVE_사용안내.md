# 지금 사용하는 방법

현재 사용할 수 있는 것은 실제 Node 연결 현황과 실행 검증 기록 조회다. 일반 프로젝트 생성·코드 편집·작업 제출·GPU 분산 실행이 사용자용 화면까지 연결됐다는 뜻은 아니다. 기존 예시 화면의 가상 5대·예시 작업을 기본 진입 화면에서 제외했다.

## 1. 접속

- 서버 PC: 브라우저 주소창에 `http://localhost:3000` 입력.
- 같은 네트워크의 다른 PC: `http://192.168.45.99:3000` 입력.
- 이전 화면이 남아 있으면 `Ctrl+F5`로 새로고침.
- 서버의 3000 포트 실제 화면과 API를 Edge에서 검증했다. 다른 PC 브라우저에서 주소를 직접 열어 보는 검증은 별도다. 기존 Node.js Public TCP 방화벽 허용 규칙을 확인했으며 방화벽 설정을 바꾸지 않았다.

## 2. 전체 현황 읽기

현재 정상 기준은 온라인 1 / 등록 1대다. 서버 PC 192.168.45.99는 관리·관측 서버 역할이며 실행 Node로 등록하지 않았다. 192.168.45.225가 실제 등록된 원격 Node다. 따라서 컴퓨터가 두 대여도 Node 숫자는 한 대로 표시한다.

‘관측 CPU’와 ‘관측 메모리’는 Node가 접근하는 Linux/Docker 환경의 실측값이다. 현재 관측된 CPU는 논리 16코어, 메모리는 약 7.68 GiB이며 사용량은 계속 변한다. Windows 전체 메모리·GPU 사양이나 제공 승인된 실행 용량으로 해석하지 않는다. 물리 PC의 메모리가 하나로 합쳐지는 기능도 아니다.

‘제공 승인된 실행 자원’ 0은 일반 프로젝트에 제공하도록 등록한 자원이 없다는 뜻이다. 연결 실패를 의미하지 않는다. GPU·VRAM·디스크는 아직 미수집이며 임의 숫자를 채우지 않는다.

## 3. 연결된 Node 확인

‘연결된 Node’를 누르면 IP, Node ID, ONLINE 상태, 마지막 heartbeat와 자원 관측 시각을 볼 수 있다. 화면은 5초마다 서버를 조회한다. 20초보다 오래된 snapshot은 현재 가용 용량에 포함하지 않으며, 60초보다 오래되면 OFFLINE으로 표시한다. 인증서가 폐기·만료되거나 관측 API가 실패해도 과거 온라인 상태를 현재 상태로 보이지 않는다.

다른 PC는 Windows이지만 Node가 Docker/WSL 안에서 실행되므로 실행 환경은 Linux로 표시된다.

## 4. 실행·복구 기록 확인

‘실행·복구 기록’에서 시험 항목을 누르면 수행 시각, 실행 식별자, 종료 코드·사유, 프로세스 종료 확인, 출력 SHA-256, 실제 표준 출력·오류를 확인할 수 있다.

준비된 시험은 프로세스 격리·자원 제한, 실제 출력 수집·해시, exit 7 실패 감지, 3초 제한 종료·정리, 송신 프로세스를 exit 17로 중단한 뒤 새 프로세스가 기존 Node 영수증만 조회하는 복구다. 합성 시험 작업은 CPU 0.5코어·메모리 64 MiB, 일반 사용자 UID, 네트워크 없음, 사용자 폴더 mount 없음으로 실행한다. Node에만 로컬 Docker 실행 연결을 사용하며 작업 컨테이너에 Docker socket을 제공하지 않는다.

통과는 해당 시험의 기대 결과와 실제 결과가 일치했다는 뜻이다. 의도적 실패 시험의 exit 7은 예상 결과여야 통과한다. 복구는 같은 영수증 확인과 duplicate 응답이 있어야 통과하며 작업을 재실행하지 않는다. 이 시험은 일반 사용자 Run·승인·Lease·Evidence 전체 통합 시험과 구분해 표시한다.

문서 작성 시 다른 PC의 실행 준비 완료 결과를 기다리고 있다. 따라서 실제 실행·복구 시험을 아직 통과했다고 보고하지 않는다. 화면의 ‘대기 중’이 현재 정확한 상태다.

## 5. 다른 PC의 실행 시험 준비

다른 PC PowerShell에서 다음 명령으로 전달받은 배포 파일을 검증하고 실행한다. 개인키·journal·기존 volume을 유지하며 관측용 기존 container는 멈춘 backup으로 보존한다. 새 구성 시작이 실패하면 기존 관측 container를 다시 시작한다.

```powershell
$svRoot = Join-Path $env:USERPROFILE 'Downloads\SaintVision-LAN'
$svZip = Join-Path $svRoot 'worker.zip'
$svUrl = 'http://192.168.45.99:18081/worker.zip'
$svHash = 'f9167bb15402dffc3ba00dc08e8effca7bf0cf4124229ba39f0931240cc3cdd1'
Invoke-WebRequest -UseBasicParsing -Uri $svUrl -OutFile $svZip
if ((Get-FileHash $svZip).Hash -ne $svHash) { throw '해시 불일치' }
$svDir = Join-Path $svRoot 'worker'
Expand-Archive -LiteralPath $svZip -DestinationPath $svDir -Force
$svSetup = Join-Path $svDir 'Enable-ExecutionTests.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $svSetup
```

마지막 공개 JSON 결과에는 수신 Docker에서 확인한 `executionImage`가 나온다. 이 값을 운영자에게 전달하면 운영자가 서버의 `tools/lan_execution.py --state <기존 state> run --image <검증된 executionImage>`로 한정 시험을 수행한다. 개인키를 전달하지 않는다. 일반 사용자 승인자를 임의로 만들거나 정책 승인을 실제 사용자 승인처럼 기록하지 않는다.

## 6. 서버 재시작 후 화면 열기

양쪽 Docker Desktop이 실행 중이어야 한다. 서버 PC의 PowerShell에서 다음을 실행한다.

```powershell
$svScript = 'C:\Project\SaintVision-Invion\.worktrees\codex-lan-live\deploy\lan\Start-LiveConsole.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $svScript
```

이 스크립트는 기존 파일럿 DB·관측 프로세스·콘솔을 확인하고 필요한 것만 시작한다. 기존 DB를 초기화하거나 사용자 작업을 실행하지 않는다. Docker 자체가 정지한 경우에는 먼저 Docker Desktop을 실행한다. 자동 로그인·Windows 부팅 시 자동 시작·인증서 갱신은 아직 구성하지 않았다.

## 아직 남은 사용 기능

일반 사용자가 프로젝트/Workspace를 선택해 코드·파일·명령을 보내려면 실제 로그인/프로젝트 권한, 승인된 제공 자원, Workspace 작업 제출 및 결과 API를 UI와 연결해야 한다. 이후 실제 사용자 흐름으로 Run·Evidence·취소·복구를 확인해야 한다. 현재 이 기능을 예시 화면에서 클릭했다는 이유로 실행됐다고 판단하지 않는다.
