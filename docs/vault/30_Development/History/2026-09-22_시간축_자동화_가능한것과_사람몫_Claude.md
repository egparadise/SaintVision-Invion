# 시간 축 자동화

되살림이 시간 축에 약하다(시험이 한순간 실행 → 없는 observedAt이 t=0엔 멀쩡). 그럼 무엇이 듣나. 소스검토·독립검토는 사람 몫 — **자동은 어디까지 되나** 밀어봤다.

## 시계 조작 기제 (먼저 확인)
- **freezegun/time-machine 미사용.** 대신 **`now` 주입**(`get_now` 의존성 + 서비스 `now=` 인자).
- staleness 컷오프는 **Python**: `cutoff = now - timedelta(...)`(nodes·discovery·pools·locality·pilot). → `now`를 전진시키면 컷오프가 움직인다.
- **그러나 행-단위 비교(`ts < cutoff`)는 SQL에서** 실행(`mark_lost_nodes` 등). → 종단 staleness 동작은 **실 PG 필요**. monkeypatch 시계만으론(PG 없이) 못 돌린다.
- **순수 결정 함수는 PG 없이 시계전진 가능**: 예 `alarm_check.partition_alarm(bound, now)` — `now`만 전진하면 remaining 축소.

## 자동으로 되는 것 (만듦)
1. **구조 검사 `tools/check_response_freshness.py`(report-only, PG-free)** — 신선도-중요 응답이 **시각 필드를 선언하는가**를 **독립 pinned map**으로 확인(rule 6: 표현값이라 스키마에서 유도 안 함 — 유도하면 필드 삭제가 제 기대까지 지움). 실 결과: **5/6 present**, `ShardObservation.observedAt` **MISSING**(알려진 갭 표면화). "필드 삭제"와 "갭"을 다 보여줌(항상 "다 ok"라 말하지 않음 = 무게 있음). report-only(갭이 있어 게이트 불가).
2. **시계전진 시험(순수 함수, PG-free)** — `test_alarm_check`에 추가: **고정 bound에서 `now`만 전진**하니 quiet→P1 firing. 되살림이 한순간이라 못 만드는 **시간 경과를 시험이 만든다.** 시간을 무시하는 도구는 조용한 채 이 시험에 실패한다.

## 자동으로 안 되는 것 (경계와 이유)
- **종단 staleness 동작**(node lost·candidate expire): 비교가 **SQL clock 파라미터**라 실 PG 필요 → 로컬 unit 아닌 **CI/PG-tier**. monkeypatch 시계로는 컷오프만 움직이고 행 비교는 못 함.
- **"이 값이 신선도-중요한가 / 시각 필드가 필요한가"** = **사람 판단.** 새 응답을 map에 안 넣으면 **조용히 미검사**로 남는다 — 마이그레이션 prior 목록과 **같은 forgets-limitation.**

## 결론 — 시간 축은 부분 자동, 나머지는 사람 (언제 볼지 정함)
- **자동(floor)**: 시각 필드 존재(check_response_freshness) + 순수 함수 시계전진.
- **PG-tier**: SQL-side staleness 동작(CI에 PG 있을 때).
- **사람(ceiling)**: 어떤 응답이 신선도-중요인지의 **큐레이션.** 이건 자동이 안 된다(축 자체의 결론). → **주기 검토 필요.**
  - **언제**: (a) 새 서빙 응답을 결속할 때 freshness map 갱신 여부 판단, (b) 릴리스 게이트에서 map 검토.
  - **한계(같이 적음, 오늘 내가 prior 목록에 단 것)**: **사람이 기억해야 하는 것은 잊힌다.** "map에 추가"를 자유 기억에 두지 말고 **응답-결속 체크리스트에 묶어**(행위에 결속) 새 freshness-중요 응답이 결속되는 순간 map 갱신을 강제하는 게, 릴리스 때 회상하는 것보다 낫다. Codex의 prior-list 릴리스체크리스트와 같은 대응이되, 그 약점(회상 의존)을 줄이는 방향.

## 배선
`check_response_freshness.py`는 stdlib·report-only → docs.yml에 `- run: python tools/check_response_freshness.py` 추가 가능(YAML=Codex). 게이트 아님(갭 표면화용).
