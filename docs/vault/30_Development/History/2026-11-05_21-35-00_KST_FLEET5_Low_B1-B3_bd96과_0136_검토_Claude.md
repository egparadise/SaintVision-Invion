## B1 — Git mode 120000

- `build()`는 SHA를 확인한 직후 `ls-tree -rz --full-tree`로 mode를 검사한다.
  - `blob`이 아니거나 `100644`/`100755`가 아니면 `ValueError`를 낸다.
  - 이 검사는 `.work` 확인, `mkdir`, `git archive`보다 **먼저** 한다. 원래 있던 `expected` 생성 코드를 이 위치로 옮긴 것이고, 의미는 그대로다.
- 작성자 test는 진짜 Git index fixture를 쓴다(`update-index --cacheinfo 120000`, OS symlink 없음). 확인하는 것:
  - `.work`가 없음
  - link가 만들어지지 않음
  - 바깥 sentinel이 바뀌지 않음
  - 644와 755의 blob bytes와 packet readback
- **내 probe** (commit하지 않음, sha256 `fc3a0985…`): 모두 통과했다.
  - 깊은 경로의 `120000` → 출력 전에 거부
  - `160000` gitlink → 출력 전에 거부
  - 한글과 공백이 든 경로의 755 파일(CRLF가 섞인 bytes)과 644 파일이 섞인 tree → mode와 blob이 정확히 왕복한다
- **red 확인:** 같은 test를 `18293b54`의 builder로 돌리면 실패한다. 출력이 만들어진 뒤에야 거부하거나 받아들인다.
- **참고:** UTF-8이 아닌 경로 이름은 `ValueError`가 아니라 `UnicodeDecodeError`로 멈춘다. 그래도 출력 전이므로 fail-closed다. 결함은 아니다.
