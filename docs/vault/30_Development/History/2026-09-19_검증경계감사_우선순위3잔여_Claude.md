# 검증 경계 감사 — 우선순위 3 잔여

검증 경계 감사 종합의 우선순위 3 잔여(나머지 DB·credential fixture의 `raises` 범위, cleanup, 동시성, 실 driver 오류. 그동안 핵심 표본만 봤고 전수 미완)를 **전수**로 수행했다. 기준은 이번 세션의 네 형태:
① `except Exception`이 의도 외 원인까지 삼켜 내부 결함을 정상 거부로 위장 · ② `pytest.skip`=`Skipped`=BaseException이라 `except Exception`에 안 잡히는 비대칭 · ③ `finally`가 앞 실패로 뒤 정리를 건너뜀 · ④ `pytest.raises` 범위 과다(`match` 없으면 같은 타입 아무 예외나 통과).

**방법**: 3개 슬라이스(핵심 fixture / credential·registry 통합 테스트 / credential·migration 도구·src)를 병렬 카탈로그한 뒤, 모든 REAL-DEFECT를 **내가 소스로 직접 재확인**했다. 값은 옮기지 않고 경로·성격·짧은 해시만 기록한다. 통합 tip 기준(`origin/integration/all-agents-unified` 병합 상태)에서 판정했다.

## 형태별 REAL-DEFECT 집계 (전수)
| 슬라이스 | ① | ② | ③ | ④ |
|---|---|---|---|---|
| 핵심 fixture (db_login/db_provision/conftest×2/credential_conformance/vf_docker + 회귀 6) | 0 | 0 | 0 | 0 |
| credential·registry 통합 테스트 (11파일) | 0 | 0 | 0(1 borderline) | **1 high** + 7 low-rank |
| 도구·src (10파일) | **2** | 0 | 0(4 noted) | — |

핵심 fixture는 전 형태 0 — 내 기존 수정(db_login·db_provision의 `ExceptionGroup` 정리, vf_docker의 `run`이 skip 대신 분류 결과 반환)과 credential_conformance의 `raises`는 모두 후속 불변식(`backend_reads`/`calls`/`count`/메시지 동일성)으로 공허성이 닫혀 있다.

## 적용한 수정 (소스 검증. 실행 경계 명시)
1. **`tools/check_migration_upgrade.py`** 최상위 핸들러 (형태 ①) — `except Exception`이 AssertionError(진짜 검증 실패)와 KeyError/psycopg 오류(내부 결함)를 모두 "validation failed"로 보고하던 것을, `except AssertionError`(검증 실패)와 `except Exception`(내부 오류, `type(exc).__name__`만 표기)으로 분리. **전파·값누출 불변**(둘 다 SystemExit로 변환·값 억제 유지) — 메시지 카테고리만 보존. `py_compile` OK. *[Claude-실행: 구문]*
2. **`tests/integration/test_credential_backend.py:296`** (형태 ④ high) — `pytest.raises(psycopg.Error)`(base) → `pytest.raises(psycopg.errors.CheckViolation, match="immutable record")`. 의도된 실패는 append-only 트리거 `inv.immutable_record()` 뿐인데(직접 확인: `services/control-plane/src/inv/migrations/0001_core.sql:116` = `RAISE EXCEPTION 'immutable record' USING ERRCODE='23514'` → 23514=CheckViolation), base 타입이라 InsufficientPrivilege(42501)·UndefinedColumn·연결오류가 "불변성 강제"로 위장 통과할 수 있었다. 형제 `test_provisioning_integrity.py:94`가 이미 `CheckViolation`을 쓰던 것과 정합. **strictly tightening + break-when-vacuous**(트리거가 사라지면 UPDATE 성공→DID NOT RAISE 실패; 권한 회귀는 InsufficientPrivilege→이제 실패).
3. **`tests/integration/test_provisioning_integrity.py:94`** (형태 ④ 강화) — 기존 `CheckViolation`에 `match="immutable record"` 추가(self-enforcing). 같은 트리거·소스 검증. 그 테이블의 다른 CHECK(reason 길이/grant_scope/jsonb)가 미래에 걸려도 불변성 단언으로 위장 못 하게.

**실행 경계(정직)**: 2·3은 실 PostgreSQL 필요(`@pytest.mark.postgres`/`INV_TEST_ADMIN_DSN` 게이트)라 이 환경에서 **수집조차 불가**(`jsonschema` 미설치 + PG 없음). 따라서 **소스 검증만 수행**했고 런타임 통과는 **PG 환경 대기**다 — 조용한 통과 아님(reason-visible skip 그대로). `psycopg.errors.CheckViolation` 접근성·`23514→CheckViolation`은 별도로 실측 확인.

## 기록·인계 (직접 수정 안 함 — 소유 경계)
`provision_credentials.py`·`plan_lan_migration.py`는 credential/migration **보안·복구 도구**이고, 올바른 수정이 **전파 의미(무엇이 crash/deny 되는지)**를 바꾼다. CLAUDE.md상 고난도 보안 변경은 Codex 계약이므로 **수정안과 함께 인계**한다(값누출 방어를 내가 약화시키지 않기 위해서다).

- **`tools/provision_credentials.py:301` (형태 ① 주)** — `provision()`의 `except Exception: raise ProvisioningDenied() from None`가 전 트랜잭션을 감싸 (a) DB-down/연결실패 (b) `fetchone()[...]`가 None일 때의 TypeError/KeyError (c) `psycopg.Error` (d) 의도된 `ProvisioningDenied`를 한 "denied"로 붕괴하고 `from None`으로 원인을 지운다. 정확히 calibration 패턴("factory 내부 오류가 의도된 거부로 위장"). **형제 `provision_account.py:244-257`이 정답 형태**(typed `ProvisioningRefused` vs `psycopg.Error`, catch-all 없음). 수정안: `ProvisioningDenied`는 그대로 전파, `psycopg.Error`는 별도 inconclusive 결과(`sqlstate`만), 그 외는 재전파(또는 `type(exc).__name__`만). 외곽 `main():334`가 credential-free 경계를 유지하므로 값누출 없이 카테고리 보존 가능.
- **`tools/plan_lan_migration.py:66` (형태 ① 중)** — `main()`의 `except Exception`이 `gap_plan`의 의도된 `ValueError`(불일치 메타)를 DB-down·버전파일 부재(`OSError`)·내부 버그와 한 exit-2 메시지로 붕괴. 수정안: `psycopg.Error`/예상 `ValueError`를 구분 메시지로, 그 외는 재전파/타입명 표기.

## 자동수정 안 한 형태 ④ low-rank (권고. 이유 명시)
파라미터 funnel형(여러 원인→하나의 generic 도메인 예외, `match` 없음): `test_credential_provision.py:192`(10 case), `test_provisioning_integrity.py:172`(7), `test_model_registry_binding.py:66`(6), `test_model_registry_revalidation.py:61`(5), `test_model_registry_runtime.py:118`(4 stage), `test_model_execution_registry.py:39`(5, `MODEL-0008` 구체 오원인 경로 존재), `test_sandbox_contracts.py:62`(11 field). broad `ValueError` borderline: `test_model_execution_registry.py:51`, `test_model_registry_config.py:31`, `test_sandbox_contracts.py:95`(모두 정상경로/성공테스트 대조로 현재 위장통과 없음).

**자동수정 보류 이유**: 올바른 수정은 case별 discriminating `match=`(도메인 오류 코드)인데, 각 코드가 실제로 그 case에서 발화하는지는 **실 PG 실행으로만 확정**된다. 검증 못 하는 `match` 문자열을 수십 case에 일괄 주입하면 **실제 통과를 거짓 실패로 바꿀** 위험이 있다(사용자 원칙: 억지 통과 금지이자, 그 역방향으로 미검증 강화로 깨뜨리기도 금지). 따라서 참조 정답(`test_sandbox_contracts.py:85` `match="SANDBOX-0002"`, `:123` `AUTH-0014`)을 명시하고, PG 환경에서 case별 코드 확인 후 착지할 항목으로 **기록**한다. 이들은 타입 자체가 도메인의 지정 거부이고 다수가 상태 불변식(`count==0` 등)을 동반해 severity가 낮다.

## ACCEPTABLE-with-note (저위험, 참고)
- 부분 `finally` os.close 누수: `provision_credentials.py:124`, `linux_file.py:130`(`root_fd`가 앞 close 실패 시 누수 — exotic), `test_migration_role_guard.py:64`(DROP DATABASE 실패 시 DROP ROLE skip — 컨테이너 `docker rm -f`로 backstop). `test_credential_backend.py:173` temp-dir `rmdir` skip(fixture tmp, 저위험).
- conformance 메타테스트 `test_credential_conformance.py:114/119`: broad `pytest.raises((AssertionError, pytest.fail.Exception))`이나 clean-harness 양성대조(`TestCredentialContractModel`)가 항상-실패 메서드를 잡아 공허성 차단. 대조가 제거되면 공허해지므로 case별 `match=`나 인라인 양성대조로 self-enforcing화 권고.
- `linux_file.py:66`의 `except BaseException: os.close(fd); raise`는 순수 fd 정리 중 재전파라 **정답**(광범위 catch가 옳은 유일 지점).
