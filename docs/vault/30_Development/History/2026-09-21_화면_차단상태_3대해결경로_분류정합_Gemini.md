# 화면 차단·미검증·미노출 상태의 3대 해결경로 분류정합 보고

## 1. 개요 및 목적

정직한 거절(Honest Rejection)과 계약 정합성 강화 과정에서, 프런트엔드는 무결성 미검증, 복제본 수복 불가, 샤드 건강도 미수복, 모델 재검증 불가, 계보 미노출, 디스커버리 후보 부재 등 다수의 영역을 차단(Disabled/Blocked)하거나 미검증/미노출 상태로 전환했다.

그러나 화면 전체가 차단 상태로 채워질 경우, 사용자는 (1) 왜 차단되었는지, (2) 차단을 풀기 위해 무엇이 필요한지, (3) 그 조치의 책임자가 누구인지를 구별하지 못하고 "시스템 전체가 고장났다"고 오인할 위험이 있다.

본 작업은 사용자의 승인된 트랙 지침에 따라, 시스템 전반의 모든 차단·미검증·미노출 상태를 전수 점검하여 다음 **3대 해결경로(Resolution Pathways Tri-Classification)**로 엄격히 분류·표기하도록 UI를 고도화했다:

1. **[사용자 조치 필요]**: 로그인/테넌트 선택, 유효한 ID(`runId`, `approvalId`, `commandId`, `checkoutId`) 입력, 슬라이더 변경 등 사용자가 화면에서 직접 해결 가능한 경로. 화면 내 입력 위치와 해결 방법을 구체적으로 안내.
2. **[운영자 조치 필요]**: 기계 온보딩, 운영자 자격증명 발급(`saint operator issue-grant`), 노드 런북 절차, 리스 연장(`AUTH-0070`) 등 사용자가 직접 풀 수 없고 인프라/보안 운영자의 행정 조치가 필요한 경로. 문서화된 운영 런북 절차로 연결하며, **존재하지 않는 사용자 셀프서비스 버튼을 날조하지 않음**.
3. **[제품 기능 미제공]**: 온디맨드 복제본 수복 API, 온디맨드 샤드 복구 API, 모델 계보 HTTP 서빙 라우트, 원격 HTTP 모델 검증 라우트 등 현재 백엔드 제품 사양에 엔드포인트 자체가 구현되지 않은 경로. "현재 제품 사양에 미제공 (백엔드 API 부재)"임을 투명하게 못 박고, 일시적 장애나 "곧 제공/재시도"로 위장하지 않음.
