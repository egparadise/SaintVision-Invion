# PR15 중간 병합 CI의 관찰 경쟁 실패

2026-09-10 21:48:30 KST에 #15 merge SHA `bb27909786d84ceb8ae146269808ded9fe7d5a02`의 [Core Build 34478520766](https://github.com/egparadise/SaintVision-Invion/actions/runs/34478520766)이 exit 1로 끝났다. `test_competing_prepared_plans_commit_only_one_replacement`에서 예상한 `NODE-0064` 또는 `RES-0007` 대신 `NODE-0030`이 발생했다. 앞선 7개 테스트는 통과했고 이 단계는 첫 실패에서 중단됐다. 병합 전 해당 head의 Core 941개 통과 기록과 이 실패 기록은 모두 보존한다.

직접 확인한 로그에서 실패 위치는 `NodeTLSClient._request`의 heartbeat HTTP 응답 상태/content-type 검사다. 연결 타임아웃이나 DB 중복 복구 commit 실패라는 증거는 없다. 예외는 Node 관찰 단계에서 발생하여 해당 요청의 최종 승인 소비·예약 transaction으로 진입하지 않았다. 실패 로그는 정확한 HTTP status 값을 출력하지 않으므로 특정 응답 코드를 관측했다고 단정하지 않는다.

코드상 동시 heartbeat는 Node의 단일 control slot에서 HTTP 429를 받을 수 있다. #15 코드는 이 응답도 `NODE-0030`으로 분류한다. 따라서 관찰 capacity 경쟁이 가장 유력한 원인이라는 판단은 코드와 동시 실행 조건에서의 추론이다.

이미 요청 순서의 다음 PR #16에 다음 보완이 포함돼 있다. diff `4290467fec203c0e8f290bd816c5d30ca1bd34bd..990f3f3a89cef6f6e8c7dd1236d8f2518041fc4f`를 직접 확인했다.

- heartbeat/snapshot의 HTTP 429를 `NODE-0050`, status 503, retryable로 분류한다.
- 관찰 supersession 409와 capacity 503만 새 nonce로 최대 3회, 짧은 backoff를 두고 재관찰한다.
- 실행 permit 전달의 불확실한 결과에 대한 자동 재실행 권한은 추가하지 않는다.
- `test_node_observation_retries_with_fresh_nonces_and_a_hard_bound`에 capacity 거부와 재시도 상한 사례가 추가돼 있다.

최종 #18 merge SHA `6bc890349297d9a16b66f71e199ab9a440250c4f`에는 이 수정이 포함된다. [최종 Core 34478582423](https://github.com/egparadise/SaintVision-Invion/actions/runs/34478582423)은 success다. artifact `10152945484`의 JUnit을 직접 읽어 샤드 복구 21개 및 전체 Python 1,008개가 각각 실패/오류/건너뜀 0임을 확인했다. #16·#17 merge의 Core도 success다. 중간 브랜치의 실패를 재실행 통과로 덮거나 결과를 삭제하지 않으며, 중간 #15 브랜치를 단독 운영 후보로 취급하지 않는다.

관련 보고: [[2026-09-10_21-46-00_KST_PR13-PR18-MERGE_Codex_검토와병합]]. 다음 담당은 Codex이며, 최종 통합에서도 같은 문제가 재현되면 HTTP 상태를 안전하게 관측할 수 있는 진단과 제한된 관찰 정책을 추가 검토한다. 실제 장비 시험은 사용자 일정에 따른 별도 범위다.
