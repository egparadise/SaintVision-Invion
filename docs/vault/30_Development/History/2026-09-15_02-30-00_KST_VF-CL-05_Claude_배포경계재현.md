## 실측 결과

### P0-1 canonical app — 미해결 (Codex 몫)

- `deploy/Dockerfile.backend`는 **여전히 fixture `saintvision.server:app`을 배포**(`PYTHONPATH=/app/src`, 커널 경로 없음).
- `deployment_surface.py --dockerfile deploy/Dockerfile.backend`: obtainable, **76 route**, credential 없이 `/v1/approvals`·`/v1/runs`·`/v1/projects`·`/v1/nodes`·**`/v1/admin/audit-logs`** 5개 200 응답, `/readyz`가 무설정인데 `"status":"ready","executionDispatcher":"active"`(날조), DB 미참조, auth 미선언. exit 1.
- 안전한 canonical 후보 **둘**이 fail-closed 확인:
  - 커널 `inv.app:app`(module-level `create_app()`): 무설정 시 `/readyz` 503, `/v1/projects` 503, `/healthz` 200. (내 `deployment_surface.py`는 이 checkout에서 `inv`를 import 못 해 INCONCLUSIVE·exit 1 — **도구 한계 finding**; 수동 PYTHONPATH로 확인.)
  - `saintvision.api.app:create_app`: `engine/settings/verifier` 없이 빌드 거부, DB 참조, "nothing serves without configuration", exit 0.
- **인계**: Codex가 `Dockerfile.backend`를 실 app으로 재지정하고 컨테이너 PYTHONPATH에 커널을 포함해야 한다. 두 후보 모두 무설정 서빙을 거부하므로 canonical 선택은 Codex 계약이다.

### P0-2 auth negative — 코드 건전 (거부 정상)

- 무설정 커널은 verify 이전에 503(fail-closed)이라, 검증기 자체는 **configured 상태로 직접** exercise:
  실제 RS256 키쌍 + JWKS 신뢰 번들로 `AccessTokens` 구성 후 `verify()` 호출.
- 결과: valid RS256 **ACCEPTED**; `alg:none` 위조·wrong issuer·wrong audience·expired·missing `inv.api` scope·unknown client_id·**HS256 alg-confusion** 전부 **REJECTED AUTH-0050/401**.
- 즉 **인증 코드는 건전**하다. 위험은 "어느 app을 배포하는가"이지 auth 로직이 아니다(fixture는 아무 Bearer나 허용, 실 커널은 모두 401).

### P0-3 기본 credential — 아티팩트 청정, 라이브는 운영자

- `deploy/init-db.sql`은 `inv_app`을 LOGIN으로 pre-create하지 않음(NOLOGIN 그룹 주석), 커밋된 password 없음.
- `deploy/remediate-shared-app-role.sql`: `inv_app` 세션 잔존 시 예외로 거부 → `ALTER ROLE inv_app NOLOGIN PASSWORD NULL`.
- **인계**: 아티팩트 결함(B-9)은 해소. 라이브 클러스터의 `inv_app` 약화 여부는 **운영자 remediation**(blocked, 코드 아님).

### P0-4 PITR readiness — 미구성 (운영/배포 결정)

- 기본 `postgres:16`: `archive_mode=off`, `archive_command=(disabled)`, `wal_level=replica` → **시점 복구 없음**. 로드맵 P0 '미구성 PITR' 재확인.
- `--require-operational-rpo` 게이트 도구(`recovery_drill.py`)는 `review/claude-account-results`에 있고 **integration에는 없다**(integration엔 `operations_pilot.py` 모델만). **인계**: 도구 integration 반영 또는 PITR 매체 결정은 운영/배포 사안.

### P0-5 route 정합 — fixture가 실 갭을 가림

- served-set을 명시해 재측정(상세 registry `aad3d2b`): fixture 포함=0 unserved(hollow), 실 백엔드(kernel10+api19)=17, CX-01 목표 wb kernel(58r)=13.
