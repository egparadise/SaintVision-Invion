## 2. 브라우저 여정 정본 고정값 감사 결과 (Codex 감사 지침 대조)

### ① 질문: "이 값이 계약을 표현하는가 아니면 계약에서 계산되는가?"
- **대상**: `.github/workflows/desktop-browser.yml`의 5대 canonical browser journey 목록.
- **분석 결과**:
  - `desktop-browser.yml:63-70`의 `expected`는 시험 파일에서 개수를 세거나(`len(cases) == 5`), 테스트 파일 목록을 glob으로 긁어서 동적으로 유도하지 않고, **독립 정본 집합으로 고정**되어 있음:
    ```python
    expected = {
        'test_actual_browser_quorum_snapshot_and_no_duplicate_vote',
        'test_actual_browser_stale_run_and_revoked_review_are_rejected',
        'test_browser_real_catalogue_owner_scope_and_revocation',
        'test_browser_real_committed_model_and_current_permission',
        'test_full_studio_login_project_approval_and_logout',
    }
    assert journeys == expected, f'browser journey set drifted: {journeys ^ expected}'
    ```
  - **판정**: 5대 canonical browser journey는 브라우저 인수(Browser Acceptance)의 **수용 범위 계약 자체를 표현**하는 집합이다.
  - **이유**: 이를 시험 대상 소스/실행 파일에서 유도하면, 누군가 시험 하나를 슬그머니 지웠을 때 기대 집합도 같이 줄어들어 CI 게이트가 조용히 통과(Silent Pass)해버리는 치명적 결함이 발생한다. 따라서 **독립 고정 목록**으로 유지하는 것이 완벽히 정당하다.
- **잔여 위험**:
  - 향후 신규 브라우저 여정 추가 또는 시나리오 분리 시, `.github/workflows/desktop-browser.yml`의 `expected`를 함께 갱신하지 않으면 게이트 실패(`journeys ^ expected`)가 발생한다.
  - 이는 침묵하는 회귀를 방지하기 위해 의도된 안전 비용이며, 릴리스/CI 체크리스트에서 명시적 리뷰를 요구한다.
