# 화면 접근성 상태 역할 분리, 비색상 단서, 비활성 버튼 고지 및 DOM 검증

## 1. 개요 및 사용자 지시

본 작업은 화면 내 상태 표출(미검증·검증됨·불일치·차단·빈 상태 등)과 차단 버튼에 대해 보조공학기기(스크린 리더) 및 색각 이상 사용자를 위한 웹 접근성(WCAG 2.1 AA 및 WAI-ARIA)을 체계적으로 실장하고 검증한 기록이다.

사용자의 명시적 지시에 따라 다음 6대 과제를 이행했다:
1. **스크린 리더 상태 역할 엄격 분리**:
   - `role="alert"` (`aria-live="assertive"`): 즉각적 주의가 필요한 방해/차단 상태(해시 불일치/변조 감지, 테넌트/권한 차단 barrier, 네트워크 장애, 노드 부재, 필수 컨텍스트 누락 등).
   - `role="status"` (`aria-live="polite"`): 일반적인 상태 전이, 정상 검증 통과(`verified`), 로딩 중, 정상 빈 상태(`empty-state`).
   - 무결성 검증 뱃지(`integrity-badge`)의 동적 역할 전이: `unverified` 시 `role="status"`, 해시 불일치(`mismatch`) 및 오류(`error`) 시 `role="alert"`, 검증 통과(`verified`) 시 `role="status"`.
2. **색상만으로 구별되는 요소 방지 (Non-color-only Defense)**:
   - 초록/빨강 색각 이상(적록색맹 등) 사용자가 색상 차이 없이도 상태를 명확히 인지할 수 있도록, 뱃지 및 상태 표시에 텍스트 라벨(`[저하]`/`[정상]`, `[VERIFIED]`, `[TAMPERED]`, `[UNVERIFIED]`) 및 보조공학기기용 `aria-label`을 병행 제공.
3. **비활성화(Disabled) 버튼 이유 전달**:
   - 조건부 차단된 액션 버튼에 `aria-disabled="true"`, `aria-describedby="<notice-id>"`, 마우스 호버 및 포커스 툴팁용 `title` 속성을 연동하여 초점을 이동하는 스크린 리더 사용자에게 비활성화 원인과 해결 경로를 고지.
4. **DOM 테스트 고정**:
   - 16건의 종합 접근성 단위 테스트(`apps/web/tests/accessibility-status-and-guards.test.tsx`)를 구축하여 100% 통과 실증.
5. **스캐너 규칙 반영성 및 한계 명시**:
   - 정적 스캐너(`check_frontend_integrity.py`)로 자동화 가능한 영역과 불가능한 영역(AST/DOM 런타임, CSS 색상 대비, 육안 확인 필요 항목)을 명확히 문서화.
6. **점검 범위 명시**:
   - 감사 완료 화면 컴포넌트와 미감사 영역을 투명하게 구분하여 기록.

## 4. 정적 스캐너(`check_frontend_integrity.py`) 한계와 육안 감사 필요 목록

정적 검사 도구(`tools/check_frontend_integrity.py` 등)와 보조공학기기 접근성 감사 간의 구조적 관계를 명확히 기록한다:

### 4.1 정적 스캐너로 검사 가능한 것
- 특정 `data-testid`를 가진 엘리먼트 소스 코드에 정적인 `role="alert"` 또는 `role="status"` 속성이 문자열로 명시되어 있는지 여부.
- 하드코딩된 위험 토큰(가짜 UUID 등) 감지.

### 4.2 정적 스캐너로 검사 불가능한 것 (런타임 DOM & 보조공학기기 감사 필수)
1. **동적 역할 전이 (Dynamic Role Transitions)**:
   - 예: `InvFileExplorer.tsx`의 무결성 뱃지처럼 `integrityState.status`에 따라 `role`이 `'status'`에서 `'alert'`로 전환되는 조건부 삼항 연산식은 정적 정규식으로 안전성을 검증할 수 없다. 이는 happy-dom / jsdom 상태 머신 단위 테스트로만 검증된다.
2. **`aria-describedby`와 타깃 ID의 실제 DOM 참조 유효성**:
   - 버튼의 `aria-describedby="checkout-context-warning"`가 실제 동일 렌더링 트리에 존재하는 요소의 `id`와 결속되는지는 컴포넌트 렌더링 시점에만 알 수 있다.
3. **색상 대비 비율 (WCAG 2.1 AA Contrast Ratio)**:
   - CSS 배경색(알파 블렌딩된 `rgba(...)`)과 전경색 간의 대비(4.5:1 이상)는 브라우저 레이아웃 엔진이 픽셀을 렌더링하고 계산해야 측정할 수 있다.
4. **스크린 리더 오디오 발화 순서와 타이밍**:
   - `aria-live="polite"`와 `"assertive"`가 실제 NVDA, VoiceOver, JAWS 등 보조공학기기에서 기존 발화를 끊고 즉각 낭독하는지 여부는 실제 운영체제 및 브라우저 환경에서 청각적으로 확인해야 한다.
