## Blocking finding

- **K2-M1 — PRESENT head의 fresh witness 획득 경로가 닫히지도, HOLD로 명시되지도 않았다.**
  - K1 current에는 현재 challenge와 HELD operation 아래의 신선한 M2 두 개가 필요하다. 나이 상한은 최대 120s다.
  - 그 M2를 만들려면 challenge 발급과 observer ExecCreate/Start가 필요하다. 둘 다 K2B effect다.
  - K2B admission은 "K1 current where available"만 말한다. 대체 권한은 ABSENT head용 D-PREPUBLICATION뿐이다.
  - head가 PRESENT인데 witness가 만료되면 결정 규칙이 없다. 미정의 권한이 숨어 있거나, 120s 뒤 CurrentView를 영구히 못 얻는다.
  - 8874 A36 green은 "terminal seal + fresh common normal:3 lease"를 이후 observation의 권한으로 이름 붙였다. K2B 설계는 이를 이어받지도, HOLD로 두지도 않았다.
  - K1 Challenges map key는 operation+scope다. operation·Node마다 challenge가 하나뿐이어서, UNKNOWN 뒤 재시도 규칙이 비어 있다.
- **K2-M2 — `MigrationOperationID`의 current/history 분류가 틀렸다.**
  - P12는 이 field를 "현재 활성 operation registry"에 두었다.
  - eb32에서는 operationId가 없는 plan 증명의 alias fallback이다. history 검증 때는 History.Operations에서 찾는다.
  - K1 durable two-epoch fixture는 이 값을 만료된 epoch1 operation으로 둔다.
  - 검토자 scratch Go test(eb32 git-archive 복사본, 제품 아님)에서 P12대로 current operation을 넣었다. Verify와 Current 모두 "proof signed for different current operation"으로 거부했다.
  - 처음 실패하는 plan 증명 경로는 map 순서에 따라 달라진다. 오류 종류는 같다.
  - facts.migrationOperationId만 바꿔도 noOverlap subject 불일치로 거부된다.
- **K2-M3 — A01–A40 requiredTask 배정이 read-only K2A에 effect green을 넣었다.**
  - A05, A15, A29, A33, A36(K2A-CURRENT)과 A32(K2A-TRUST)가 해당한다.
  - 원래 green이 M2 생성, inventory publish, renewal cycle, ExecID 기록, observation admission, Node signer를 요구한다.
  - read-only grant의 범위를 이 표로 정할 수 없다.

## code grant 전 수정

- **K2-L1:** K1은 Now 하나로 평가한다. 구간 보수 검증의 방법이 정해지지 않았다.
  - 가능한 방법 하나는 구간 양 끝점 평가다. 검사한 eb32 시간 조건은 모두 반직선 또는 반열린 구간이었다.
  - 값과 출처는 Root의 D-CLOCK 선택이다. 검토자가 정하지 않았다.
- **K2-L2:** contract 본문의 REPLAY_OR_SCOPE_MISMATCH, NO_CURRENT_HEAD, TRUST_UNKNOWN이 닫힌 errorCatalog 밖에 있다.
- **K2-L3:** owner field census는 regex 기반이다.
  - hash를 다시 고정하면 embedded field 두 종류와 Now 타입 약화가 통과한다(V01c–V03c).
  - 향후 gate에는 go/types census가 필요하다.
  - V06–V09처럼 의미 배치와 label 변조도 통과한다. static 도구의 본래 한계다.
- **K2-L4:** NewVerifier는 export돼 있고 internal/ 밖에 있다. DTO 위조 방지의 Go 강제 수단이 없다.
  - unexported field, import 경계 test, K2B의 caller 값 불신을 명시해야 한다.
- **K2-L5:** VerifierPublication을 실제 실행 중인 verifier의 측정 digest와 묶는 요구가 없다.

## 닫혔거나 올바르게 HOLD인 공격

- 순환 권한과 자기 등록은 막혀 있다. plan hash는 등록 hash와 같아야 하지만 등록을 고르지 못한다.
- status key 범위, 부분 readback, fixture 승격은 막혀 있다.
- 쓰기 주체가 중재되지 않으면 두 번 읽어도 안전하지 않다고 정직하게 적었다. 이는 D-COHORT-FENCE HOLD다.
- ABSENT head에서는 BootstrapPhaseAuthorization이 named method 전용이고 CurrentView가 아니다.
- effect 상태 기계가 맞다.
  - REFUSED_NO_EFFECT, INTENT_COMMITTED, UNKNOWN의 순서를 지키고 exactly-once를 주장하지 않는다.
  - PC2→PC4 순서이고, DB lock을 잡은 채 I/O하지 않는다.
- generation이 보존된다. binary 전환에서 P/H/C/R을 유지하고, normal-v2는 P+1/P+2, C+1, R 유지다.
- Engine 1.45/1.41 차이와 VM 97%/482MiB snapshot은 새 측정 없이 과거 맥락으로 남았다.

## Root 결정 목록 (검토자가 선택하지 않음)

- **D-TRUST-INSTALL:** anchor, custody, CA, registry 인증, reviewer grant, K2 package·lock·설치 receipt.
- **D-COHORT-FENCE:** cross-migration cohort registry와 모든 mutator의 중재.
- **D-CLOCK:** 인증된 clock 출처와 불확실성 상한, 그리고 L1의 평가 방식.
- **D-PREPUBLICATION:** ABSENT head bootstrap phase 권한.
- **D-OBSERVATION(신규, M1):** PRESENT head witness 재획득 admission과 재시도 규칙. 정하지 않으면 명시적 HOLD로 둔다.
