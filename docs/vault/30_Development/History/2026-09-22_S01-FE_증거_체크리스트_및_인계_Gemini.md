### 4.2 DeveloperStudio Run API 3곳 정본 생성 타입 전환 및 계약 경계
- **기존 문제**:
  - `apps/web/src/features/studio/DeveloperStudio.tsx` 3개소(Line 230 수동 새로고침, Line 247 폴링, Line 402 POST 디스패치)에서 API 호출 시 수기 ViewModel인 `RunItem`을 제네릭 응답 타입으로 지정 (`apiClient<RunItem>`)하고 `data.id` / `res.id`를 직접 참조함.
  - 실제 와이어에서는 커널 정본 필드인 `runId`가 반환되므로 타입-와이어 간 괴리가 존재했음.
- **프런트엔드 조치 완료**:
  - `packages/contracts-ts`의 정본 생성 타입인 `ControlRunView`를 `apps/web/src/contracts/kernel-observation.ts` 및 `DeveloperStudio.tsx`에 import.
  - 3개소 호출부를 모두 `apiClient<ControlRunView>`로 전면 전환.
  - 와이어 정본 필드인 `res.runId` 및 `data.runId`를 정확히 취득하여 UI ViewModel `RunItem`의 `id` 필드로 정합 투영(`effectiveRunId`).
  - 게이트 실측: `npx tsc -b` (0 errors), `npm run build` (4.31s 빌드 성공), Vitest 75개 파일 653/653 passed 100%.
- **백엔드 정본 스키마 및 서빙 앵커 규명 (Codex 계약 소유 영역 인계)**:
  - 1) `POST /v1/projects/{project}/runs`: 와이어 응답 객체는 `core.schema.json`의 `$defs/ControlRunView`와 100% 일치하나, `services/control-plane/src/inv/control.py`의 `control.create`에 `validate_contract("ControlRunView", result)` 서빙 앵커가 누락되어 있음.
  - 2) `GET /v1/projects/{project}/runs/{run_id}`: `control.get`은 `{**public(row), "resourceReleasePending": bool(active)}`를 반환함. 현재 `core.schema.json`의 `ControlRunView`는 `additionalProperties: false`이며 `resourceReleasePending` 필드가 없어, 단일 Run 조회 전용 정본 스키마가 `core.schema.json`에 미정의 상태이며 서빙 앵커도 부재함.
  - 지침 준수: 정본 스키마 정의 및 커널 `validate_contract` 서빙 앵커는 Codex의 고유 소유권이므로, 프런트엔드 호출부를 `ControlRunView`로 수렴한 뒤 해당 계약 갭을 Codex에게 정식으로 인계함.
