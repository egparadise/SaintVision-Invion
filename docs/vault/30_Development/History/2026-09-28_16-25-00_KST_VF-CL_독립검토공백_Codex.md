## 3. VF-CL-02 `c75201af` model shard resolution

`resolve_model()`은 model URI와 등록 version을 먼저 확인하고, 주입된 `ManifestReader(tenant_id, model_id, version)` 결과를 strict shape로 검사한 뒤 shard index와 `locationId/locationVersion`을 tenant-scoped catalog 및 ready replica에 결속한다. reader가 없을 때 `shards=None`, `manifest_source=unavailable`, `fully_materialisable=false`로 말하므로 빈 성공으로 강등하지 않는다.

`tests/test_model_uri_resolver.py`의 PostgreSQL 7건은 dataset URI 거부, 미등록 version 404, reader 부재의 unavailable, location version drift, manifest unavailable/stale replica, 타 tenant location 비노출·누락 shard, malformed manifest 거부를 각각 직접 단언한다. 현재 integration의 후속 운영 reader는 observation identity/project/auth shape와 reader scope 재검사를 더하며, 그 후속 경계는 Card 44의 원 커밋보다 강하다.

- 판정: **승인**. `c75201af-model-shard-resolution-not-independently-reviewed` 공백을 닫는다.
- 실행 강도: 로컬 PG 시험은 NOT_RUN; 대장의 hosted 7 passed 근거를 재사용하되 Card 44의 PG-free 결과로 위장하지 않는다.
- 잔여 관찰: 원래 raw injected manifest 경로의 shape 검사는 manifest 자체의 `modelId/version`을 요청값과 다시 비교하지 않는다. 지금 제품 경로는 strict observation reader이고 injected callable은 내부 신뢰 경계지만, 새 외부 provider가 raw reader를 사용하게 되면 identity 결속 시험을 먼저 추가해야 한다.

## 5. VF-CL-04 `3e267b05` archive retention tool

retention planner의 핵심 불변식은 retained backup들의 가장 이른 WAL start segment부터 WAL을 지우지 않는 것이다. oldest-by-time backup의 segment만 쓰도록 되살린 mutation은 property 시험이 잡았다.

```text
pytest -q tests/test_pitr_archive_retention.py
# 9 passed, exit 0

pytest -q tests/test_pitr_archive_retention.py -k property_retained_window
# mutation: 1 failed, exit 1 (expected boundary 0E, got 1D)
```

그러나 새 차단 finding **F-VFCL04-01**을 발견했다. `parse_backup_label()`은 `START TIME` 필드가 존재하지만 세 지원 형식 모두로 파싱되지 않아도 오류를 내지 않고 directory mtime인 `fallback_time`을 그대로 반환한다. 따라서 내용상 유효하거나 최근인 backup도 조작되었거나 오래된 directory mtime으로 expired 판단되어, newest가 아닌 경우 backup과 그 복구 지점을 삭제 후보로 만들 수 있다. 오염된 시각은 `newest` 선택도 바꿀 수 있다. 다만 retained로 남은 backup의 WAL boundary는 start segment의 최솟값으로 계산되므로, 이 결함이 그 retained backup들까지 복원 불가로 만든다는 뜻은 아니다. 기본 dry-run이라 자동 삭제가 아니라 운영자에게 잘못된 적용 계획을 제시하는 결함이다. 현재 9개 시험에는 malformed/unsupported `START TIME` 반례가 없다.

```text
parse_backup_label("... START TIME: definitely-not-a-time", 2000-01-01T00:00:00Z)
# ('000000010000000000000003', 2000-01-01T00:00:00Z), exit 0
```

필요 수정은 `START TIME`이 존재하면 parse 실패를 fail-closed 오류로 만들고, 누락 시 fallback을 허용할지 별도 명시하는 것이다. 최소 회귀 시험은 malformed time + 오래된 directory mtime이 deletion candidate가 되지 않음을 확인해야 한다.

owner 재검토에서 별도 차단 finding **F-VFCL04-02**도 확인했다. PostgreSQL backup label은 서버 timezone을 쓸 수 있지만 `%Z`는 CPython 실행 환경이 아는 제한된 이름만 받고, 성공하더라도 대개 timezone-aware instant를 만들지 않는다. 현재 코드는 그런 naive 값을 UTC로 붙이므로 비-UTC 명명 timezone이 파싱 실패로 F-VFCL04-01 경로에 들어가거나 실제 instant를 잘못 계산한다. 숫자 offset과 명시적 UTC/GMT만 정확히 받고, 알 수 없는 명명 timezone은 UTC로 둔갑시키지 않는 별도 수정과 회귀 시험이 필요하다.

- 판정: `0043` pin fix는 승인하지만 `3e267b05` 도구는 **수정 요청**이다.
- registry에는 기존 검토 공백 blocker 대신 `archive-retention-invalid-start-time-falls-back-to-directory-mtime`과 `archive-retention-start-time-timezone-misparsed`를 서로 독립된 blocker로 제안한다.
- PR #126 hosted Core skip 전환과 retention/readiness의 운영 gate 미배선 blocker는 이 검토와 무관하므로 유지한다.
