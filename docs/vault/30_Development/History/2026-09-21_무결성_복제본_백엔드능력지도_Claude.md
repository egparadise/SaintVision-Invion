# 백엔드 무결성 검증·복제본 복구 능력 지도

Gemini의 VF-GM-03(무결성)·VF-GM-04(복제본)가 **없는 것을 지어내고 있다**(파일 바이트 대신 URI+contentHash 해시 = 순환; 복구 callback 없으면 healthy 합성; 백엔드가 unknown인데 화면이 healthy 복제본 합성). 진짜 능력이 무엇이고 무엇이 없는지를 못 박아 합성을 멈춘다.

## 훑은 범위 (명시 — "없음"이 무엇에 대한 없음인지)
- 고정 SHA `b49b38d`. **두 백엔드 트리 모두**: ① `services/control-plane/src/inv/`(커널, `core.schema.json` + `validate_contract`), ② `src/saintvision/api/`(개별 `contracts/*.schema.json` + pydantic `schemas.py` model_validate).
- HTTP 표면: `inv/app.py` 라우트 전량 + `saintvision/api/v1/storage.py` 라우터. 검증 함수: `grep def (verify|recover|reclaim|repair|replica)` 전량 추적, 각 함수의 호출자를 라우트까지 사슬 추적(이름 유사 아닌 **실 호출경로**).
- 대상 도메인: 무결성 검증(파일/모델/샘플 바이트) + 복제본 상태/복구. (터미널·인가 등 보안경계는 Codex라 범위 밖.)

## 진짜 능력 (실측: 서버에 있다, 프런트가 지어낸 게 아니다)
- `inv/storage.py:82 verify_content(path, expected_hash, expected_size)` — **실제 파일 바이트를 sha256 스트리밍 해시**해 기대값·크기와 비교. (URI/contentHash 순환 아님.)
- `inv/model_manifest.py:112 verify(manifest, snapshots)` — 모델 manifest 바이트 검증.
- `inv/storage_sampling.py:251 verify_sample(challenge, envelope, certificate_der)` — 샘플링 소유증명 검증.
- `inv/workspace_files.py:355 _verify(...)`, `inv/workspace_editor.py:_view` — 체크아웃 내용 `hashlib.sha256(raw)` 실 해시.

## ② 내부 함수는 있으나 엔드포인트가 없음 (Gemini는 부를 것이 없다)
- **`model_manifest.verify`(실 모델 무결성)**: `model_commit.py`·`model_locality.py`가 **내부 호출**. 프런트가 부를 라우트 없음. 결과의 *일부*만 ModelCommitObservation.`requiresExecutionRevalidation`로 노출(=아직 재검증 안 됨 신호). → 프런트는 "검증됨"을 주장 못 함, "재검증 필요"만 표시.
- **`verify_content`**: `runs.py:172` 내부(artifact 서빙 시). 결과는 artifact `verified`로 노출(①). 별도 "검증 실행" 엔드포인트 없음.
- **`verify_sample`**: `storage_commit.py`·`storage_view.py` 내부. 결과는 StorageObservationView(①, 미소비).
- **복구**: `reclaim_unclaimed`(reservations.py) / `require_recovery_admission`(shard_recovery.py) — **상태전이 시 내부 실행**. **"복제본/자원 복구를 실행하고 결과를 반환하는 엔드포인트가 없다.**" → VF-GM-03의 "복구 callback 없으면 healthy 합성"은 여기서 비롯. 부를 복구 API가 없으므로 프런트는 healthy를 합성하면 안 되고 "복구 불가/미수행"을 표시해야 한다.

## ③ 아예 없음 (설계상 백엔드가 거부하는 것)
- **복제본 "healthy" 건강 판정**: 백엔드는 `recordedStates` 카운트 + `currentAvailability:"unknown"` + `requiresExecutionRevalidation:true`만 준다. **healthy/degraded를 단언하지 않는다**(의도적). → 프런트가 healthy 복제본을 합성 = 백엔드가 명시적으로 거부하는 것을 지어내는 것.
- **온디맨드 무결성/복구 콜백(성공 결과 반환)**: 없음. verify_*는 내부 부수효과이지 "지금 검증/복구해서 결과 줘" API가 아니다.
- **샤드별 복제본 목록/건강**: ShardObservation은 샤드 실행 상태(evidenceId 등)만. per-shard 복제본 건강은 없음(VF-GM-04).

## Gemini 인계 (합성 금지 → 정직한 상태)
- **VF-GM-03 File Explorer 무결성**: `WorkspaceEditView.sha256`(실 바이트 해시)·`snapshot.files[].sha256`를 **소비**하라. URI+contentHash 해시는 순환이니 폐기. 지금 MonacoWorkspaceEditor는 하드코딩 `INITIAL_FILES`(EditorFile)라 이 엔드포인트를 안 부름 → 배선 전까지 무결성은 "미검증" 표시, "검증됨" 합성 금지. (fixture: `contracts/fixtures/workspace-edit-view-response.json`.)
- **VF-GM-04 복제본**: `ReplicaObservationResponse`의 `recordedStates` 카운트 + `currentAvailability:"unknown"` + `requiresExecutionRevalidation:true`를 **그대로** 표시. healthy 합성 금지, 샤드별 복제본 건강은 ③(없음).
- **복구**: 복구 실행/결과 API 없음(②/③). "복구 callback 없음 → healthy 합성"을 "복구 불가 → 사용 불가/미검증"으로.

## 엔드포인트 신설이 필요하면 누구 소관 (경계)
- 스토리지 샘플 무결성(StorageObservationView)·체크아웃 무결성(WorkspaceEditView)·모델 lineage 관측 = **Claude 레인**(계약 결속 완료/가능). 커널 view 응답.
- 복제본 관측/복구(ReplicaObservation, replica-repair)·분산복구(reclaim/recovery admission)·소유증명(verify_sample 서명)·보안경계 = **Codex**. (replica는 이미 Codex tests 존재.)
- 모델 `verify`를 HTTP로 노출할지 = 모델 registry/lineage는 Claude 트랙이나 실제 verify는 워커·보안 인접 → Codex와 조율.
