## 1. 실측 감사 배경 및 목적

오늘 밤 프론트엔드 전반에서 합성 제거, 죽은 방어 살리기, 캐시 은폐 차단, 가짜 식별자 소거, 조기 성공 차단, 쓰기 실배선, 시간 신선도 지표화, 허위 미구현 소거 등 10대 축의 무결성 작업이 완결되었다.

이에 대해 **"추가된 시험들이 실제로 회귀 결함에 대해 실질적 방어력(무게)을 지니는가?"**를 검증하기 위해, 역방향 실측 감사를 수행하였다.
- **실측 감사 방법론 (Inverse Mutation & Skip Analysis)**:
  1. 각 핵심 영역에 치명적 회귀 결함(Defect D1 ~ D4)을 주입.
  2. 해당 기능을 검증하기 위해 작성된 신규 테스트를 임시로 건너뜀(`it.skip`).
  3. 전체 69개 테스트 파일(622개 테스트)을 실행하여, **다른 기존 테스트 중 어느 하나라도 그 결함을 잡아내는지** 확인.
  4. **판정 기준**:
     - 다른 시험이 결함을 잡아내면 ➔ **중복 방어 (Redundant / Multi-layered Defense)**: 다층 보호망으로 기능하므로 삭제 금지.
     - 다른 어떤 시험도 잡지 못하고 전체 PASS로 넘어가면 ➔ **유일한 방어 (Sole Defense)**: 해당 결함을 막는 시스템 내 유일무이한 방어선. 향후 어떤 리팩터링에서도 **절대 임의 수정·삭제·약화 금지**.

## 3. 유일한 방어(Sole Defense) 상세 등록부

### 1) Sole Defense #1: 워크스페이스 에디터 커널 저장 실배선 단언
- **보호 대상 코드**: `apps/web/src/features/editor/MonacoWorkspaceEditor.tsx` (커널 `saveWorkspaceEditView` 호출부)
- **유일 방어 테스트**: `apps/web/tests/monaco-workspace-editor-wiring.test.tsx`
  - `Priority 6-A: MonacoWorkspaceEditor 파일 저장 단축키(Ctrl+S) 누를 때 saveWorkspaceEditView 실제 API가 호출된다`
  - `Priority 6-B: 에디터 저장 실패 시 role=alert DOM 에러 배너를 표출하고 가짜 성공 토스트를 띄우지 않는다`
- **실측 증거**:
  - 이 테스트를 스킵하고 API 호출을 우회하면 69개 테스트 파일 전체가 성공으로 무사통과함.
  - 계약 테스트(`workspace-edit-view-contract.test.ts`)는 스키마 구조만 볼 뿐 UI 컴포넌트의 실제 호출 여부를 보지 못함.
  - 따라서 이 테스트는 **프론트엔드 편집기 실배선 무결성을 지키는 유일한 방패**임.

### 2) Sole Defense #2: RunDetail 산출물 다운로드 실배선 및 허위 미구현 방지 단언
- **보호 대상 코드**: `apps/web/src/features/runs/RunDetail.tsx` (Tab 3 아티팩트 목록의 `getArtifactDownloadUrl` `<a>` 태그)
- **유일 방어 테스트**: `apps/web/tests/dashboard-runlist-freshness-wiring.test.tsx`
  - `Priority 19: 아티팩트 탭에서 다운로드 클릭 시 브라우저 alert 대신 인라인 고지(role=status)를 표출한다` (다운로드 `<a>` 태그, `href`, `download` 속성 단언)
- **실측 증거**:
  - 실제 커널 엔드포인트(`/v1/projects/:id/runs/:id/artifacts/content?path=...`) 연결을 제거하고 이전의 'API 미노출' 버튼으로 회귀시켜도, 이 테스트 외에는 아무도 감지하지 못함.
  - 따라서 이 테스트는 **사용자가 실제 산출물을 다운로드할 수 있는 권리를 보장하는 유일한 방패**임.

### 3) Sole Defense #3: ShardObservation.stateAsOf 스냅샷 왜곡 방지 한정 고지 단언
- **보호 대상 코드**: `apps/web/src/features/runs/RunDetail.tsx` (Tab 5 분산 샤드 `stateAsOf` 안내 배너)
- **유일 방어 테스트**: `apps/web/tests/response-freshness-wiring.test.tsx`
  - `2. ShardObservation.stateAsOf: Tab 5 분산 샤드 상태 기준 표출 및 스냅샷 왜곡 차단`
  - `expect(banner?.textContent).toContain('단일 공통 스냅샷이나 조회 시각이 아닙니다')`
  - `expect(container.textContent).not.toContain('단일 공통 스냅샷입니다')`
- **실측 증거**:
  - `truth-time-and-freshness-axis.test.tsx`는 화면 조회 시점(`observedAt`)만 검사할 뿐, 샤드 상태 기준 시각의 의미 왜곡 방지 고지는 검사하지 않음.
  - 이 테스트가 스킵되면 개별 샤드 갱신 시각의 비동기성을 단일 스냅샷으로 속이는 왜곡이 무사통과함.
  - 따라서 이 테스트는 **시간 정보의 의미론적 무결성을 지키는 유일한 방패**임.

### 4) Sole Defense #4: 대시보드 노드 통신 장애 은폐 차단 단언
- **보호 대상 코드**: `apps/web/src/features/dashboard/ClusterOverview.tsx` (`nodesState === 'error' && nodes.length === 0`)
- **유일 방어 테스트**: `apps/web/tests/dashboard-runlist-freshness-wiring.test.tsx`
  - `Priority 13-16: 동기화 실패(nodesState=error) 시 노드가 0대일 때 정상 빈 상태로 둔갑하지 않고 cluster-overview-fetch-error(role=alert)를 표출한다`
- **실측 증거**:
  - `node-fetch-error-workspace-wiring.test.tsx`는 `ResourceExplorer`의 에러 배너를 검사하고, `truth-time-and-freshness-axis.test.tsx`는 과거 캐시가 있는 상태에서의 경고만 검사함.
  - 노드가 0대인 상태에서 통신 실패가 났을 때 정상 클러스터로 둔갑시키는 치명적 은폐를 잡는 것은 이 테스트가 유일함.
  - 따라서 이 테스트는 **클러스터 장애 시 운영자 오판을 방지하는 유일한 방패**임.

## 4. 중복 방어(Redundant Defense / Multi-layered) 식별 결과

중복 방어는 결코 낭비가 아니며, 서로 다른 계층과 맥락에서 회귀를 막아주는 **다층 방어망**으로 입증되었다:

1. **과거 캐시 보유 중 동기화 실패 경고 (`cluster-stale-warning`)**:
   - `tests/dashboard-runlist-freshness-wiring.test.tsx` (P13-16)
   - `tests/truth-time-and-freshness-axis.test.tsx` (TC-TRUTH-01)
   - ➔ **2중 방어선**: 대시보드 개요 맥락과 진실 시각 축 맥락 양쪽에서 교차 검증됨.
2. **과거 작업 목록 보유 중 동기화 실패 경고 (`run-stale-warning`)**:
   - `tests/dashboard-runlist-freshness-wiring.test.tsx` (P17-18)
   - `tests/truth-time-and-freshness-axis.test.tsx` (TC-TRUTH-05)
   - ➔ **2중 방어선**: 작업 목록 신선도와 승인 센터 신선도 양쪽에서 교차 검증됨.
3. **`alert()` 호출 원천 소거 검증**:
   - 정적 분석 게이트: `tools/check_frontend_integrity.py` (Rule 4: no unhandled alert/confirm/prompt)
   - 동적 런타임 단언: `tests/developer-studio.test.ts`, `tests/dashboard-runlist-freshness-wiring.test.tsx`
   - ➔ **정적·동적 2계층 방어**: CI 게이트에서 AST 레벨로 1차 차단하고, 컴포넌트 렌더링 시 DOM 배너로 2차 보장.

## 5. 결론 및 향후 관리 지침

1. **Sole Defense 4개 항목의 보존 의무**:
   - 상기 명시된 4대 Sole Defense 테스트는 **"단 하나의 방패"**이므로, 코드 리팩터링 시 테스트를 주석 처리하거나 단언 강도를 낮추는 행위를 엄격히 금지한다.
2. **중복 방어의 가치 인정**:
   - 중복 방어 테스트는 삭제 대상이 아니며, 한쪽 테스트가 변경될 때 다른 쪽이 기준점을 잡아주는 안전망 역할을 수행한다.
3. **테스트 스위트 건전성**:
   - 전체 69개 테스트 파일, 622개 테스트 모두 정상 동작(100% Pass)을 유지하고 있으며, 게이트 도구(`check_frontend_integrity.py`, `check_contract_bindings.py`) 전원 통과 상태를 유지한다.
