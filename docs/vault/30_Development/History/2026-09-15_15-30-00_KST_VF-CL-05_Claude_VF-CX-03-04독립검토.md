# VF-CL-05 VF-CX-03/04 locality·runtime recovery 독립 검토 (Claude)

## 범위

Codex 커널의 model locality/placement(VF-CX-03 `bc8797c`)와 runtime input freeze/replacement-node retry(VF-CX-04 `a42178a`)를 **소스 수준 독립 검토**. 이 둘은 내 VF-CL-04 replica_repair(node-loss)·resolver(locality)와 직결된다. 코어 concurrency/recovery(Codex 도메인)이므로 수정하지 않고 finding으로 인계. 브랜치 미체크아웃 — 소스 정독.

## VF-CX-03 (locality → placement) — verdict: 견고

- `migrations/0040 model_run_inputs`: PK(tenant,run_id) → **run당 model input 1개**. FK runs·model_manifests·nodes. RLS ENABLE+FORCE, `GRANT ... TO inv_kernel`만(inv_app REVOKE), immutable 트리거, forward-only.
- `model_locality.LocalModelObservation`: 내부 provider 결과(HTTP 입력·실행 permit 아님). scope/epoch 결속(불일치 403), **신선도 15s**(초과 409), 커밋된 `model_manifests.manifest_sha256` 재검증. `revalidate`는 **PlacementStore가 이미 잠근 노드만**(`verified_nodes & selected_pool`) 사용해 **lock 순서 보존**(deadlock 회피), 재-capture 동일성으로 TOCTOU 차단. mode="single-node"(auto-split 안 함 — 아키텍처 정합).
- `placement.py`: model_observation은 typed 신뢰 관측만. GPU/vram 요청은 versioned config 없이 거부. **deterministic placement explain** 제공(`modelLocality.localBytes`, `unavailableReplicas`, `rejected[node]=사유`, `requiresExecutionRevalidation:True`) — 로드맵 VF-CX-03 합격("deterministic placement explain") 충족.
- 각 replica 노드 online·recovery_epoch·heartbeat 15s·project_nodes enabled·public active를 FOR SHARE로 펜싱.

## VF-CX-04 (runtime freeze + bounded retry) — verdict: 견고

- `migrations/0042 model_retry_lineage`: `generation BETWEEN 2 AND 3` → **최대 3 Run**, PK(tenant,parent), UNIQUE(child)·(root,generation), parent≠child·root≠child. RLS·kernel-only·immutable·forward-only. **bounded 재시도 사슬**.
- `model_retry.ModelRetryStore`:
  - **failed Run만** 재시도(아니면/generation>3 → MODEL-0007). root→parent lock 순서.
  - **물리 자원 release 후에만**: 미해제 `resource_leases` 있으면 LEASE-0003 — 실패 노드의 double-execution 방지(핵심 correctness).
  - parent당 retry 1개(MODEL-0003). frozen input의 fencingToken이 **현재 recovery_epoch** 접두여야 함(아니면 LEASE-0004 epoch reconciliation) — stale-epoch 입력 거부.
  - double-transaction(capture→observe 밖→재-capture 동일성 `_scope != captured → 409`)로 TOCTOU 차단. child는 새 frozen input·현재 policy·독립 승인·Node admission(permit 전이·취소 override 없음), lineage/lease/outbox atomic commit.

## 내 VF-CL 카드와의 정합 (핵심 소득)

- **node-loss가 저장-side와 실행-side로 상보적으로 처리됨**: 내 `replica_repair.mark_node_replicas_unavailable`은 이탈 노드의 replica를 `stale`로(데이터 가용성, manifest 불변). Codex retry는 **lease release를 기다린 뒤** 교체 노드에 fresh run(실행 복구). 두 경계가 충돌 없이 맞물린다.
- placement의 `verified_nodes`는 내 replica_repair의 "ready replica" 개념과 일치(검증된 bytes만 usable). resolver의 `ready_replica_nodes`가 그 후보 집합의 저장-side view.

## Finding (수정 아님, Codex 인계)

- **차단 결함 없음.** VF-CX-02와 일관된 fencing/recovery 규율. 
- (정합성 확인) VF-CX-03/04는 single-node runtime까지. 아키텍처의 multi-node 실행 모드(request-routing/data-parallel/tensor·pipeline)는 여기 없음 — 의도적 후속(VF-CX-04 docstring "single-node", 확장은 별도). 내 replica_repair의 replica factor(정책 기본 2)는 이 single-node 단계에서 가용성 보강용으로 정합.
- (앞선 finding 유지) VF-CX-02 검토의 finding 2(커널 model_manifests vs S10 model_versions 두 개념)와 shard 상한(finding 1)은 여전히 Codex 결정 대기.
