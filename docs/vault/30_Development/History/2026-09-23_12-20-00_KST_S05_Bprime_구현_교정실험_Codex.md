# S05 Card24 B-prime 구현과 h 교정 실험

## 구현 결과

Claude PR #108의 조건부 승인을 반영해 candidate의 `project_resource_limits ... FOR UPDATE` 한 statement에만 private lock budget을 적용했다. 기본값은 500ms, 허용 범위는 정수 1~1900ms이며 `bool`은 거부한다. production `INV_API_CONFIG`에는 새 key를 노출하지 않았고 benchmark가 flag-on 실험값을 명시적으로 전달한다.

성공 경로는 limits lock 전에 `current_setting('lock_timeout')`을 캡처하고 획득 직후 다음 resource lock 전에 그 caller 값을 복원한다. 실패·stale 경로는 savepoint rollback이 값을 복원한다. `BoundDatabase`의 700ms caller 값, budget 초과 `55P03`, 이어지는 attempt 2, 응답·replay·fencing·RLS·rollback 불변식을 실제 PostgreSQL 단일 파일에서 확인했다. 공개 표면은 계속 `RES-0007`/503/retryable이며 migration·route·응답 schema 변경은 없다.

구현 고정 SHA는 `4c8a736334ad97813d7f5ea422f4ec079d23a760`이다. PG-free focused는 **15 passed / exit 0**, 최종 실 PG focused는 **17 passed / 16.59s / exit 0**이다. 첫 worktree 실행은 `.env` 경로 오인으로 17 skipped여서 실측으로 세지 않았다. 첫 실제 PG 실행은 16 passed/1 failed였는데 0.8초 holder의 client-observed wait가 681.737ms로 500ms를 넘겨 기능 목표를 충족했음에도 임의의 `>=700ms` assertion이 실패한 시험 결함이었다. 이를 목적 그대로 `>500ms`로 교정한 새 SHA에서 최종 focused를 다시 통과시켰다.

## observer 포함 상한 해석과 1900 arm 생략

경합 중 candidate hold P95 중앙 `767.708ms`를 사양의 근사식 `20−⌊B/h+2⌋`에 넣으면 B=1500 예상 실패는 17건이고 실제 **16/16/17**과 수치상 정합한다. 그러나 Claude 카드 28 F-1 검토로 이 값을 제품 고유 `h`의 교정값이라고 부른 해석을 철회한다.

이 세 wave는 `pg_stat_activity`와 `pg_blocking_pids` queue sampler를 함께 켰다. 검토자가 evidence에서 다시 계산한 실제 sampler interval은 legacy depth-1에서 약 21ms, candidate depth-19에서 약 67~89ms로 3~4배 느려졌다. `pg_blocking_pids`는 lock 파티션 LWLock을 사용하므로 observer가 holder의 후속 lock 획득을 지연했을 가능성을 배제할 수 없다. sampler가 없던 카드 16/18 candidate hold는 117~171ms였다. 따라서 `767.708ms`는 **observer 포함 상한**이며, 실패 수와의 정합은 자기 일관성이지 인과 교정 완료 증거가 아니다.

후속 sampler-off candidate 1500×1은 SHA `6c389a1d`에서 20/20, timeout 0, hold p50/p95/max 55.469/155.873/234.974ms였다. observer-on P95 767.708ms와 611.835ms·약 4.925배 차이라 observer 포함 상한 정정은 지지됐지만, 단일 wave 변동을 전부 `pg_blocking_pids` 비용으로 확정하지 않는다. 이번 세 observer-on wave가 확정한 것은 B′의 세 승격 조건 실패와 그 조건의 raw 결과다. N 산출은 sampler-off max를 보수적으로 사용해 첫 옵션 B 실험값 4로 정했으며 실제 semaphore 20×3 전 zero-timeout은 미확정이다. [[s05-card25-sampler-off-6c389a1d.json]].

세 wave가 같은 방향이어서 코디네이터 승인에 따라 1900 arm은 `NOT_RUN`으로 닫았다. `B+h>2000ms`여서 1900 arm은 `55P03` 개선보다 `statement_timeout`의 `57014`를 섞어 h 교정 해석을 흐릴 위험이 있다. 이를 실행하지 않은 사실과 이유를 evidence에 명시했다.

## 다음 카드 B 착수 근거

다음 설계 대상은 **project별 bounded semaphore**다. budget 확대가 FIFO 깊이 19와 holder 길이를 줄이지 못했으므로, DB 원자성을 바꾸기 전에 lock 진입 동시성을 제한하는 B를 사양화한다. 다음 카드에는 최소한 tenant+project 격리, permit 누수 0, exact replay 재진입, cancel/exception 반환, queue 상한 초과의 기존 `RES-0007`/503/retryable 표면, process-local 한계와 다중 CP 비주장, 기본 off·즉시 rollback을 포함한다. B 구현·부하는 Claude 카드 28 검토와 코디네이터의 별도 승인 전 시작하지 않는다.

## 정직성 경계

이 결과는 B′의 **h 교정 실험**이지 승격·throughput 해결·AC-05 충족 증거가 아니다. production flag는 off이고 기본 500ms는 유지된다. 1900·50동시·5노드는 미실행이다. 실측 뒤 긴급 hosted Backend 수집 hotfix는 별도 R1 `41f899b3`으로 먼저 착지해 카드 24 제품 변경과 분리했다.
