# Go 미검증 표면 지도

## 왜 (검증 밀도 차이 명시)
오늘 백엔드(Python)·프런트는 여러 층으로 파고들었다(계약 결속·서빙 앵커·돌연변이·되살림). **Go는 한 번도 실행 검증을 못 했다** — 이 호스트에 Go 컴파일러가 없어(측정: `which go` 부재) Claude·Codex 둘 다 **소스 읽기로만** 봤다. 언어별 검증 밀도가 크게 다르다. 명시하지 않으면 전체가 같은 수준으로 검증됐다고 착각한다.

## 범위 (측정)
- 고정 SHA `15dfa66`. 오늘(세션, 8c12449 이후) 바뀐 Go = **정확히 3파일**(전부 fb2ba31; PTY 9728556은 node-agent Go 미변경):
  `services/node-agent/cmd/inv-discover/main.go`, `services/node-agent/discovery/announce.go`, `services/node-agent/discovery/announce_test.go`.
- 이 호스트: **Go 없음** → 컴파일·`go test` 실행 불가. 아래 "주장"은 소스 읽기 기반이며 실행으로 확인한 것이 아니다.

## 파일·함수·주장·검증 필요 (컴파일 / 단위시험 / 실서버)
| 파일·함수 | 주장 | 검증에 필요한 것 |
|---|---|---|
| `main.go run()` | `INV_DISCOVERY_BEARER_TOKEN` env를 읽어 빈 값·CR/LF면 "credential unavailable"로 실행 거부, `"Bearer "+bearer`를 Send에 전달 | **컴파일**(구문/타입/`os`·`strings`·`fmt` import) + **단위시험 필요**(run()의 env 읽기·거부 로직은 현재 미시험 — cmd main) |
| `announce.go Send()` | `authorization` 인자 추가; `Bearer ` 접두·비공백(trim 후)·CR/LF 금지 검증; `Authorization`+`X-Inv-Tenant` 헤더 설정 | **컴파일** + **단위시험**(일부만 존재, 아래) |
| `announce_test.go` | 헤더 전송(양성)·빈 authorization 거부·TLS·redirect | CI `go test`가 **실행**(이 파일 자체가 검증 수단) |

## CI 검증 경로 (core.yml, setup-go 1.27.1 / go.mod 1.23 요구)
- `go build ./cmd/inv-discover`(line 61)가 **main.go + discovery 패키지(announce.go)를 컴파일** → CI 열리면 **두 변경 파일의 컴파일은 잡힌다.**
- `go test -race ./...`(55)·`go test ./...`(142)가 **announce_test.go를 실행** → 그 시험이 커버하는 것은 CI가 잡는다.
- (CI 트리거는 integration push/PR. 현재 CI 실행·통과 여부는 저장소로 미측정 — 외부 상태.)

## CI가 해소하는 것 vs 남는 것 (남는 것이 진짜 구멍)
**CI 열리면 해소(컴파일):** main.go·announce.go 구문/타입/import. (지금은 CI 미실행이면 이것조차 미검증.)
**CI가 announce_test.go로 해소(단위):**
- Send가 `Authorization: Bearer <token>` 헤더를 실제로 붙여 보냄(양성 시험이 서버에서 헤더 확인).
- **빈** authorization 거부(`TestAnnouncementRequiresTenantAuthentication`, `""`).
- TLS 신뢰·redirect 거부(기존).

**CI로도 남는 것 (진짜 갭):**
1. **announce.go Send의 보안 검증 분기 중 미시험**: CR/LF 주입 거부(`ContainsAny(auth,"\r\n")`), `Bearer ` 뒤 공백만인 경우 거부, 비-Bearer 접두(비공백, 예 `"Basic x"`) 거부 — announce_test.go는 `""`만 거부 시험. 이 **헤더 주입 방지 분기들이 컴파일만 되고 시험되지 않는다**(보안 관련이라 더 문제).
2. **main.go run()의 env 로직 미시험**: 토큰 부재·CR/LF 거부, Bearer 접두 구성 — cmd main이라 단위시험 없음. 컴파일만.
3. **교차언어 e2e 부재**: inv-discover(Go)가 env를 읽어 Bearer를 붙여 보내고 → Python 서버(pools.announce)가 tenant를 대조해 403/수락하는 **전 경로를 잇는 시험이 없다**. Python `test_discovery_announcement_tenant_boundary.py`는 서버측만(Python이 만든 요청, Go 클라이언트 아님). Go 헤더 구성과 서버 검증이 **한 번도 함께 실행된 적 없다**.

## 필요한 시험 — 무엇을·누가·언제 (돌릴 수 없는 시험은 지금 안 만든다)
오늘 우리가 계속 경계한 것: 못 돌리는 시험을 올리면 통과하는지 모른 채 쌓인다. 이 호스트에 Go가 없으므로 Go 시험을 **지금 만들지 않는다**. 대신 명세만 남긴다.
- **T1 (단위, announce.go)**: `Send`에 (a) 비-Bearer 접두, (b) `Bearer `+공백만, (c) CR/LF 포함 authorization → 각각 "discovery configuration rejected" 반환 확인. **누가**: node-agent 소유·보안 경계 = Codex(또는 Go 툴체인 보유 에이전트). **언제**: Go 툴체인/CI 가용 시(작성 즉시 `go test`로 통과 확인 가능해야).
- **T2 (단위, main.go)**: `run()`을 test 가능하게(env 주입) 하여 토큰 부재·CR/LF 거부·Bearer 구성 확인. **누가/언제**: 동일.
- **T3 (통합, 교차언어)**: inv-discover 바이너리를 실 tenant 자격으로 test 서버에 대고 announce → 서버가 tenant 대조·후보 row 기록까지 확인. **누가**: Codex(보안·분산). **언제**: test 서버/CI 통합 하니스 가용 후 — CI가 열린 뒤가 맞다.
- 우선순위: T1(보안 분기, 작음) > T2 > T3(하니스 필요, 큼).

## 요약 판정
- 오늘 Go 3파일은 **실행 검증 0**(소스 읽기만). CI 열리면 **컴파일 + 헤더전송/빈토큰거부**까지 해소. **CR/LF·공백·비-Bearer 주입 방지 분기, main.run() env 로직, 교차언어 e2e**는 CI로도 남는다.
- 이 셋이 보안(헤더 주입·자격 처리)에 닿으므로, 위 T1~T3를 소관·시점과 함께 남긴다. **못 돌리는 Go 시험은 만들지 않았다.**
