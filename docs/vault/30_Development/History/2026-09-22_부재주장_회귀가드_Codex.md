# 부재 주장 회귀 가드

## 목적과 범위

사용자 요청은 앞선 두 부재 판정이 새 코드가 들어온 날 조용히 낡지 않도록 시험으로 고정하는 것이었다. 제품 구현이나 상태기계 계약을 새로 바꾸지 않고 시험만 추가했다.

- 일반 failed Run 재실행 경로가 없다는 판정의 근거인 `failed` terminal 성질을 고정한다.
- 오늘 역검토에서 외부 입력/확장 가능성이 있으나 미지원 값은 fail-closed여야 한다고 판정한 기존 capability kind, Node OS, placement strategy 도메인을 고정한다.
- 오늘 좁힌 세 status 도메인은 사용자 요청대로 다시 조사하거나 변경하지 않았다.

## 구현한 보호

`tests/test_run_state.py::test_failed_run_is_terminal_and_cannot_enter_a_retry_transition`는 `failed`가 terminal인지, 나가는 간선이 없는지, `scheduled`·`running`·`recovering`으로의 전이를 거부하는지 확인한다. 이는 자동 재시도가 좋은지 나쁜지를 영구 결정하지 않는다. 재시도 기능을 추가하려면 상태기계와 이 시험, 재시도 제품 경로 감사 및 브리프를 함께 갱신하도록 의도적으로 깨지는 경계다.

새 `tests/core/test_external_closed_domain_guards.py`는 세 도메인 각각에서 현재 지원값을 계속 허용하고, 미지원 sentinel을 거부한다. Capability kind와 placement strategy는 request와 대응 response 양쪽을 검사한다.

- Capability kind: `cpu/gpu/ram/disk` 허용, `npu/tpu/future-accelerator` 거부.
- Node OS: `windows/linux` 허용, `freebsd/macos/future-os` 거부. 경로 처리기가 해당 OS 의미를 구현하기 전에는 API 계약을 통해 새 OS를 받지 않는다.
- Placement strategy: `single_node/data_parallel/sharded` 허용, `automatic/pipeline/future-strategy` 거부. 새 전략은 알고리즘·배치/샤드 제약·DB와 wire 계약을 함께 구현해야 한다.

이 시험은 “외부 값은 언제나 닫혀 있어야 한다”는 전역 규칙이 아니다. 알 수 없는 제어 입력을 현재 의미로 조용히 해석하지 않는 좁은 방어다. 새 기능이 지원값을 확장할 때에는 해당 입력의 의미·DB CHECK·생성 스키마/타입·실행 처리가 함께 바뀌어야 하므로 sentinel 기대값도 같은 변경에서 갱신한다.
