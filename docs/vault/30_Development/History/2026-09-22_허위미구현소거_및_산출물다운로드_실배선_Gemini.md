# 허위 미구현(Class 3) 표기 전수 재감사 및 산출물 다운로드 실배선

## 1. 배경 및 목적
- Claude의 백엔드 대조 감사 보고서(`2026-09-22_미구현목록_백엔드대조_남은구현범위_Claude.md`, commit `52a3eea4`) 확인:
  - 프론트엔드에서 "미구현 / API 미노출"로 분류해 차단하거나 모의 안내를 하던 항목들이 실제로는 백엔드 라우트에 실재하고 있었음 (진짜 누락 0건).
  - "없는 기능이라 막아둔 것인데 실은 있는 기능이었으면 지금 화면의 표시는 거짓"이라는 거버넌스 원칙에 따라, 프론트엔드 내 허위 미노출/모의 표기를 전수 감사하고 실배선 및 상태 정직화를 단행함.

## 2. 작업 내용

### 1) `RunDetail.tsx` Tab 3 Fallback 아티팩트 다운로드 실배선 및 허위 문구 완전 소거
- **문제점**:
  - `(run as any).artifacts` fallback 목록의 다운로드 버튼이 `[모의 고지] ... (서버 아티팩트 파일 스트림 다운로드 API 미노출 상태)` 안내 배너를 띄우고 버튼 텍스트가 `다운로드 (API 미노출)`로 표시됨.
  - 실제 백엔드 커널에는 `GET /v1/projects/{project}/runs/{run_id}/artifacts/content?path={path}` (`app.py:413`, `result_view.py:200`)가 완벽하게 실재하며 파일 스트림을 제공함.
- **수정**:
  - `getArtifactDownloadUrl(run.projectId, run.id, art.name)`을 통해 실제 백엔드 다운로드 링크(`<a>` 태그, `download` 속성)로 실배선.
  - `[모의 고지]` 및 `(API 미노출)` 허위 텍스트 전면 소거 ➔ 정직한 `📥 다운로드` 버튼으로 상단 실배선 분기와 일관성 확보.
  - `run.projectId`가 없는 극단적 비정상 상태일 때만 `프로젝트 ID 부재 (컨텍스트 필요)` 인라인 안내 제공.

### 2) `MonacoWorkspaceEditor.tsx` 백엔드 저장 라벨 정직화
- **문제점**:
  - 상단 안내문과 저장 버튼에 `인메모리 워크스페이스 에디터 (백엔드 저장 API 미노출)`이라고 표기되어 있었음.
  - 실제로는 `POST /v1/projects/{projectId}/runs/{runId}/checkouts/{checkoutId}/files` (`saveWorkspaceEditView`)가 실재하며 `projectId && runId && checkoutId` 바인딩 시 서버 영속 저장이 수행됨.
- **수정**:
  - "백엔드 저장 API 미노출" ➔ "체크아웃 컨텍스트 미연결 (로컬 브라우저 인메모리 버퍼 샌드박스 · 커널 영속 저장 시 runId/checkoutId 컨텍스트 필요)"로 정직하게 정정.

### 3) 기타 "API 미노출" 항목 검토 및 확인
- `ResourceExplorer.tsx`: Logical vCPU/RAM/스토리지 점유율의 `미제공 (API 미노출)`은 백엔드에 화면용 HTTP 읽기 엔드포인트가 없는 상태임이 Claude 감사로 확인되었으며, 조작된 0 숫자 대신 정직한 미제공 상태를 유지하고 있음.
- `NodeList.tsx`: 에이전트 설치 안내는 물리 노드 CLI 실행 대역외(Out-of-band) 안내로 이미 정직하게 표기됨.
- `DeveloperStudio.tsx`: 실행 중 다운로드 비활성화는 "API 미노출"이 아닌 "실행 진행 중 상태 가드(조건 미충족)"로 올바르게 표기됨.
