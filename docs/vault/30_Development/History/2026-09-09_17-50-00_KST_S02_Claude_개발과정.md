### S02-BE — OIDC·mTLS 등록·Heartbeat

`/v1` REST. `POST /nodes`, `POST /nodes/{id}/heartbeats`, `GET /nodes`, `GET /nodes/{id}`, `/v1/health`, `/v1/readiness`.

- **부트스트랩 토큰 1회성**: 평문은 반환 시 한 번만 존재하고 SHA-256만 저장한다. 소비는 `consumed_at IS NULL` 조건이 붙은 단일 `UPDATE ... RETURNING`이라 동시 등록 두 건 중 하나만 성공한다. 검사 후 갱신하는 2문장 방식은 경합에서 둘 다 통과한다.
- **heartbeat 재생 차단**: sequence가 증가하지 않으면 적용하지 않는다. 캡처한 heartbeat로 제거된 노드를 살아 있게 유지할 수 없다(ADR-007).
- **오류 계약**: RFC 9457 + `code`·`category`·`retryable`·`traceId`·`causeRef`·`evidenceId`. category는 code 접두사에서 파생되므로 둘이 어긋날 수 없고, `retryable`은 category의 성질이다.
- **인증 실패 기록**: AUTH/SEC 분류 오류는 요청 트랜잭션과 **별개 트랜잭션**으로 audit에 남긴다. 같은 트랜잭션에 쓰면 거부에 따른 rollback이 기록까지 지운다.
- **OIDC**: issuer·audience·JWKS가 S01-BE 미결이므로 `OidcPrincipalVerifier`는 생성 시 예외를 던진다. 개발용 `StaticPrincipalVerifier`는 `INV_ENV=dev|test`가 아니면 생성되지 않는다. **그럴듯한 issuer를 하드코딩하지 않았다.**
- **project 권한**: RLS는 tenant 격리만 준다. 같은 tenant의 모든 사용자가 RLS를 통과하므로 "다른 project 정보 접근 차단"은 서비스 계층 검사로 별도 구현했다.

### S02-ST — 제공 폴더·DataLocation 카탈로그

- **경로 안전성**(`storage/pathsafe.py`): 반복 percent-decode, NFC 정규화, 절대경로·UNC·`\\?\` 장치 네임스페이스·드라이브 상대경로·ADS·예약 장치명(CON/COM1…)·`..`·보호 디렉터리를 OS별로 검사한다. **구문 검사와 실제 해석을 분리**했다: `resolve_within`은 노드에서 심볼릭 링크·junction까지 따라간 뒤 다시 포함 여부를 검사한다. `link/secret.txt`는 `..`가 없어 구문 검사를 통과하지만 해석 후 탈출이 드러난다.
- **URI 문법**(ADR-010): namespace별로 다르다. artifact는 `runId/artifactId`, dataset/model은 `name@version`. 하나의 문법으로 합치지 않았다.
- **`ready`의 의미**: 존재가 아니라 checksum 검증 완료다. `NOT ready OR (checksum IS NOT NULL AND verified_at IS NOT NULL)` 제약으로 고정해 서비스 경로가 우회할 수 없게 했다. ETag·클라이언트 metadata는 받지 않는다(ADR-011).
- **object store 제품 미결**: MinIO archive 확인으로 전송 경로는 S01-ST 대기다. 카탈로그·URI·무결성 필드는 제품과 무관하므로 제품명을 쓰지 않고 구현했다.

### CI가 잡은 결함 2건

로컬 DB가 없어 CI를 검증 경로로 썼고, 첫 실행(run `34331523722`)이 **failure**로 실제 결함 2건을 드러냈다. `24 failed, 116 passed`. 두 건 모두 논증만으로는 찾지 못했을 것이다.

**결함 1 — Python 버전 차이로만 드러나는 오류.** `errors.py`의 `@dataclass(slots=True)` 안에서 인자 없는 `super().__init__()`을 호출했다. `slots=True`는 데코레이터가 클래스를 새로 만들기 때문에 `__class__` 셀이 원본을 가리켜 `TypeError`가 난다. Python 3.13에서 고쳐진 동작이라 **개발 기계(3.14)에서는 통과하고 CI(3.12)에서만 실패했다.** 모든 `InvError` 발생 경로가 죽었으므로 오류 계약 전체가 동작하지 않는 상태였다. `Exception.__init__(self, ...)` 직접 호출로 수정했다.

- 재발 방지: CI에 `python-version: ['3.12', '3.14']` matrix를 넣었다. 한 버전만으로는 신뢰할 수 없다는 것이 이번에 증명됐다.

**결함 2 — 스키마 설계 오류.** `nodes.certificate_fingerprint`에 `UNIQUE NULLS NOT DISTINCT`를 걸었다. PLAN-DB-001의 "NULL 중복까지 막는 제약"을 잘못 적용한 것이다. 여기서 NULL은 "아직 등록 미완료"라는 **정상 상태이고 여러 노드가 동시에 가질 수 있다.** 이대로면 플랫폼 전체에서 미등록 노드가 한 대만 존재할 수 있어 동시 등록이 깨진다. 실제로 다른 tenant의 노드 2대를 넣는 테스트가 제약 위반으로 실패하며 드러났다.

수정: `WHERE certificate_fingerprint IS NOT NULL` 부분 unique 인덱스로 바꿨다. 지문이 있으면 유일하고, 없으면 제약하지 않는다. **`NULLS NOT DISTINCT`는 `node_capabilities(node_id, kind, device_index)`에는 그대로 둔다** — 거기서는 NULL이 "전체 호스트 자원"이라는 의미이므로 NULL 중복이 진짜 중복이다.

마이그레이션 `0001`을 직접 수정했다. 어떤 환경에도 적용된 적이 없고(CI는 매 실행 schema를 drop한다) 초기 리비전이므로, 배포된 적 없는 제약을 고치는 데 `0002`를 추가하는 것보다 옳다.

테스트도 함께 고쳤다. 기존 테스트는 **틀린 동작을 단언하고 있었다**: 미등록 노드 2대가 거부되는 것을 정상으로 봤다. 지금은 (1) 미등록 노드 여러 대 허용, (2) 같은 지문 2대 거부를 각각 단언한다.
