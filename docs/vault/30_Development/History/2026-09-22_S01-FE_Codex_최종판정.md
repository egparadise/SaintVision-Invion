## 두 차단 사유의 재검증

1. **Vitest 수치:** 이전 653 대 652 차이는 SHA별 시험 추가로 설명됐다. 최신 통합 SHA `5180a737`에서 직접 실행한 값은 655다. PlacementSimulator 시험 2건이 추가되어 수치가 증가했으며, 명령·SHA·Node `v24.17.0`·시각을 함께 기록했다.
2. **수기 RunItem:** DeveloperStudio의 API 응답은 `ControlRunDetail`/`ControlRunView`와 `observedRun` 어댑터를 사용한다. 생산 코드에서 `apiClient<RunItem|NodeItem|WorkspaceItem|ProjectItem|ApprovalItem>` 호출은 0건이다. `RunItem`은 화면 ViewModel로만 남아 있다.

추가 확인:

- `apiClient<unknown>`은 terminal ticket 한 곳뿐이며, 반환 즉시 `parseTerminalTicketResult`가 정본 필드·UUID·경로·티켓 형식을 검증한다.
- `fabricControlApi`의 `PlacementPreviewResponse`는 API wire 타입이 아니라 canonical `PlacementPreviewWireResponse`를 UI용으로 투영한 타입이다. raw 응답 모양을 별도로 정의한 잔여 수기 계약으로 세지 않았다.
