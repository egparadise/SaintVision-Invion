# 실행 증거 집계 오류 수정

base 933209a, task VB-AGG-01/02, owner Codex, reviewer Claude(대기), branch agent/codex/model-registry-binding. agent-delivery1.1.0/core-reliability1.0.0 적용. 공통판1.0.97/Codex1.0.64/검증지도1.3.0 기준. 사용자 수정 승인에 따라 두 P2 finding을 구현하고 로컬 검증했다.

## 수신 근거의 범위

사용자 네 실행 coord-postfix-determination/coord-final-determination/coord-business-retry/postod-quiet-determination은 서로 다른 prefix였다. 보고된 수치의 이전 XML 오염 증거는 없으며 도구가 격리를 강제했던 것은 아니다. coord-business-retry는 tests 키/XML 없이 exit1로 끝났다는 사용자 확인을 수신했다. 실제 미생성 경로의 근거이며 거짓 성공 사례로 바꾸지 않는다. 원인 당시 Docker 호출 TimeoutExpired는 이번 오프라인 시험에서 실제 호스트 재현하지 않았다.

## 변경 계약

- `.work/vf-runs/<prefix>-<uuid>/`를 독점 생성하고 이 실행의 tests.xml/private.log/proof.json만 사용한다. 이전 prefix-tests.xml은 읽거나 삭제하지 않는다. 기존 `<prefix>.json`은 마지막 완료 실행 요약의 atomic replace이며 각 고유 proof는 보존된다. 동시 실행의 요약은 마지막 게시자 기준이지 이력 목록이 아니다.
- subprocessExitCode는 자식 미시작 null/실제 종료코드/timeout124, evidenceStatus는 not-run/rejected-mode/missing/invalid/empty/partial/inconsistent/no-executed-tests/complete다. child0이라도 증거가 complete가 아니면 runner exit2. child 실패/124/5 및 harness125는 그대로 보존한다. partial의 PASS는 부분 관측이며 lane 합격이 아니다.
- complete는 현재 invocation의 읽을 수 있는 비공허 JUnit에 실행된 성공 case가 있고 실패/오류가 없다는 뜻이다. 필수 suite 완주나 무skip 보장은 아니다. 선택 command·runId·UTC 시작/끝·XML hash·private case identity hash를 남긴다. 민감한 parameter ID가 가능한 실제 case 목록은 private 파일에 보존하고 safe JSON/CI artifact에는 hash만 둔다.
- CLI --co/--collect-only는 Docker 전 exit2로 거부한다. pytest plugin도 최종 설정 collectonly를 검사하므로 env PYTEST_ADDOPTS/config addopts 우회는 nonzero다. 기존 docker_host 기본 제외 설정은 유지한다.
- desktop-browser CI gate는 subprocess0/evidence complete와 기존6passed/0skip/cleanup을 모두 요구한다. 기존 source SHA/필수 case identity의 완전한 provenance 계약 보강은 이번 두 finding 수정 범위 밖이며 이번 runId/hash를 SHA 증명으로 부르지 않는다.
- 격리 kernel snapshot exact allowlist에 새 시험의 runner/guard/node selection 의존성을 추가했다. private XML/log는 CI 업로드하지 않는다.
