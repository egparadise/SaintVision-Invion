# S05 Card22 B-prime candidate limits 잠금 예산 구현 사양

## 결과

Card21의 `HYPOTHESIS_SUPPORTED`와 결정 문서 v1.4의 B′ 우선순위를 구현 가능한 docs-only 카드로 분해했다. [[S05 B-prime candidate limits 잠금 예산 구현 사양]]은 candidate limits `FOR UPDATE` 한 statement에만 기본 500ms·실험 1500ms를 적용하고 성공 직후 공통 500ms로 복원하도록 경계를 고정한다.

공개 route·schema·ProblemDetails는 바꾸지 않는다. limits 한 wait segment의 예산 초과 `55P03`과 동일 statement 누적 2초의 `57014`는 계속 `RES-0007`/503/retryable로 매핑하며, SQLSTATE는 evidence에서만 구분한다. 1500ms는 transaction 전체 timeout 확대가 아니고 후속 Node/Resource lock은 500ms다.

## 시험·판정·롤백

- PG-free: 기본 500, 유효 범위, flag-off 격리, `BoundDatabase` 전달, production config 무변경, 비밀 0건.
- 실 PG 단일 파일: default parity, 500 실패/1500 획득 경계, 1500 초과 55P03, 2초 57014 관계, 성공/재계획 뒤 500 복원, replay/fencing/no-overbooking/RLS/rollback.
- 승인 뒤 성능 wave: legacy와 candidate 1500을 20동시 각 3회 비교하고 외부 timeout 합계 비증가, request P95 중앙값 비악화, post-acquire hold P95 중앙값 비악화를 모두 요구한다.
- rollback: 실험 인자를 제거해 500ms로 복귀하고 flag off를 유지한다. migration·DB cleanup은 없다.
