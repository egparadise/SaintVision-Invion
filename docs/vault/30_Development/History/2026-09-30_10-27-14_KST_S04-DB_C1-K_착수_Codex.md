## 가장 앞 카드로 고른 근거

`docs/task-registry.json`과
`docs/vault/30_Development/57.81퍼센트 이후 단일 가상 컴퓨터 보강 로드맵.md`를
대조했다. 고난도 Codex 범위 중 S04-DB가 가장 앞선 sprint이며, 현재 core
collector가 의도적으로 제외한 kernel C1-K는 복구 epoch와 bound run version,
dispatch/execution 결속을 검증하는 보안·동시성 경계다.

이 작업은 추가 PC 2대, CP 호스트 결정, hosts 적용 없이 제품 schema와 hosted
PostgreSQL로 구현·검증할 수 있다. 반면 S05-DB와 S07-DB의 남은 합격 증거는
물리 5노드 부하·장애 반복에, S08-DB의 남은 합격 증거는 보존 결정과 off-device
backup/PITR 자원에 주로 차단돼 있다. 따라서 외부 전제 없이 실제 제품 진전을
만드는 첫 카드로 C1-K를 선택했다.

## 착수 범위

1. `services/control-plane/src/inv/approvals.py`와 실제 migration을 기준으로
   C1-K의 입력·불변식·판정 경계를 먼저 고정한다.
2. 운영 행이 없거나 필요한 producer 결속이 없으면 PASS가 아니라
   `NOT_OBSERVED`로 내리는 read-only collector를 만든다.
3. stale recovery epoch, bound run version 불일치, 승인과 dispatch/execution의
   결속 불일치를 fail-closed로 보존한다.
4. DSN·tenant/run/approval 식별자·payload·raw 오류를 출력하지 않는다.
5. PG-free 부정 시험과 hosted Core 실 PostgreSQL 단일 파일로 검증한다.

공개 계약과 migration 변경은 현재 범위에 없다. 분석 중 migration이 필요해지면
구현을 멈추고 번호 배정을 요청한다. 이 문서는 착수 기록이며 아직 측정 완료나
S04-DB 승격을 주장하지 않는다.

## 구현 결과

- 계약 문서 [[S04-DB_C1-K_kernel_승인_결속_Evidence_계약]]을 먼저 고정했고, current policy decision ID가 승인 당시 ID와 같지 않다는 제품 의미를 v1.0.1 `8a506612`에 정정해 collector의 criteria source로 결속했다.
- `tools/collect_s04_kernel_approval_evidence.py`는 한 REPEATABLE READ·READ ONLY snapshot에서 다음을 재계산한다.
  - K1: approval→dispatch→claim의 scope·command·digest·policy version·epoch·시간 결속. claim 직전 current policy decision ID는 독립 durable peer가 없어 `RECORDED_ONLY`다.
  - K2: delivery permit의 strict base64/UTF-8/duplicate-key JSON과 DB claim exact field set 결속. 공개키 provenance가 없으므로 signature는 형식만 확인하고 `RECORDED_ONLY`다.
  - K3: scheduled=`bound_run_version+1`, running=`bound_run_version+2`, run attempt와 execution attempt 및 시간 순서 결속.
  - K4: 실행 당시 control epoch history producer가 없으므로 `NOT_REGISTERED`다. 현재 epoch를 과거 실행 시점 증거로 대체하지 않는다.
- 행이 없거나 producer가 없으면 PASS가 아니며, 기록 불일치·누락·파싱 실패는 `MEASURED_FAIL`이다. 따라서 현재 전체 verdict는 위반 시 `FAIL`, 그 외에는 K4 때문에 `NOT_OBSERVED`이고 acceptance claim은 false다.
- Evidence에는 aggregate count와 hash만 남긴다. DSN·host·database 이름 원문·tenant/project/run/node/approval/command/claim 식별자·payload·signature·raw 오류는 남기지 않는다.
- 구현 commit은 `fc08a856`, fail-closed scope·missing-row 변이 보강과 Black 정렬은 `b0ff6b69`, count reason 집합·합계·status를 validator가 다시 계산하도록 고정한 commit은 `26448c94`다. 공개 계약·migration·task-registry status 변경은 0건이며 S04-DB는 `review`를 유지한다.

## Claude 독립 검토 조치

- F1: 실 PG 모듈이 `gateway`의 선행 `approval` fixture를 함께 import하도록 고쳤다.
- F3: permit `notAfter`는 UTC 문자열이 아니라 timezone-aware instant로 비교하고 `+09:00` 동치 시험을 추가했다.
- F4: 모든 대상 relation의 `FORCE RLS` 경계를 지키기 위해 `row_security=off`와 실행 role의 `rolsuper`/`rolbypassrls`를 확인한다. 전체 snapshot 권한이 없으면 부분집합을 evidence로 만들지 않고 exit 2로 거부한다.
- F5~F8: evidence validator가 REPEATABLE READ·READ ONLY·완전한 RLS visibility와 재계산 status를 고정하고, 중복 scheduled/running event 및 재승인 attempt를 시험한다.
- F10: `sort_keys=True`로 저장한 JSON도 다시 검증할 수 있도록 reason 집합은 순서가 아니라 exact key set으로 검사한다.
- 위 의미 정정은 criteria v1.0.2 commit `6d677d4e`에 먼저 고정했다. 공개 API 계약·migration·task-registry status는 바꾸지 않았다.
