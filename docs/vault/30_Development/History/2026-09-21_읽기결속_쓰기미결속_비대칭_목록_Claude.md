# 읽기 결속·쓰기 미결속 비대칭 목록

작업공간 생성에서 본 것: 같은 파일에서 GET은 `response_model`로 묶였는데 POST는 안 묶였다. **쓰기가 더 위험한데 그쪽이 안 묶여 있다.** 같은 비대칭이 어디 또 있는지 훑는다. **전부 묶자는 것이 아니라 목록·위험도만.** 반환이 없거나 204인 것은 대상 아님(아래 전부 body 반환 확인).

## 범위·기제 (중요)
- **response_model 비대칭은 saintvision 전용 문제다.** saintvision(`src/saintvision/api/v1`)은 FastAPI `response_model`로 응답을 검증한다.
- **커널(`services/control-plane/src/inv`)은 `response_model`을 전혀 쓰지 않는다**(전 파일 grep 0건). 대신 `validate_contract(...)`를 서빙 경로에서 호출한다(app.py 15회 등). → 커널 write를 "response_model 없음"으로 나열하면 **전부 걸리는 오탐**이 된다. 커널의 등가 질문 = "write 응답이 validate_contract(서빙 앵커)를 거치는가"이고, 그건 [[2026-09-21_서빙앵커_감사_3갈래_Claude]]의 3-버킷 감사가 다룬다. 여기선 **saintvision만** 목록화하고 커널은 그 감사를 가리킨다.
- 측정 tip `7d75f810`.

## saintvision write 라우트 — 결속 여부
**이미 묶임(대조군)**: `POST /pools`(PoolCreatedResponse)·`PUT /pools/{}/members/{}`(PoolMemberResponse)·`DELETE /pools/{}/members/{}`(PoolMemberRemovalResponse)·`POST /pools/{}/plans`(DistributedPlanResponse) — 전부 Codex 계약작업. **`POST /projects/{}/workspaces`(WorkspaceSummaryResponse)** — 오늘 내가 결속.

**미결속(전부 body 반환 → 대상). 위험도순:**

### HIGH — 권한·용량·admission을 부여하는 쓰기 (응답 드리프트가 "무엇이 부여됐나"를 오보)
| 라우트 | 반환 | 왜 위험 |
|---|---|---|
| `POST /projects` create_project (201) | 생성된 project body | **create_workspace와 정확히 같은 비대칭**(GET 목록은 `ProjectListResponse`로 묶임). 생성 응답 드리프트가 id/코드/상태를 오보. **가장 싸게 묶을 후보**(내가 workspace에서 한 것과 동형). |
| `POST /discovery/candidates/{id}/admission` admit (201) | admitted 후보/노드 dict | **보안**: 운영자가 미검증 노드를 fabric에 들인다. 응답이 무엇을 들였는지 오보하면 운영자 판단이 틀린다. |
| `PUT /projects/{id}/members/{user}` set_member_role | result | **권한 부여**: 누가 무엇을 할 수 있는지. 응답 드리프트가 부여된 역할을 오보. |
| `PUT /capabilities/{id}/offer` set_resource_offer | result | **placement 입력**: 제공 용량. Codex가 resource-offer-integrity 하드닝했으나 응답 미결속 — 드리프트가 offered capacity 오보→배치. |

### MED-HIGH — 상태·자원 등록 쓰기
| 라우트 | 반환 | 비고 |
|---|---|---|
| `PUT /workspaces/{id}/status` set_workspace_status | status dict | provisioning→ready→… 상태기계. 생성 결속과 짝. |
| `PUT /users/{id}/status` set_user_status | {userId,status} | suspend/activate. |
| `POST /storage/contributions` register_contribution (201) | contribution body | 저장 기여 등록. |
| `POST /nodes` enroll_node (201) | {"node": _node_body} | 내부 `_node_body`는 NodeResponse 모양이나 라우트 래퍼 미검증. |

### MED — 수정/해제 응답을 화면이 읽음
| 라우트 | 반환 | 비고 |
|---|---|---|
| `PUT /workspaces/{id}/tool` set_workspace_tool | body(선택+사용가능성) | 도크스트링이 화면이 이 응답으로 실행가능성 판단한다고 강조 — 드리프트가 실행가능 오판. |
| `PUT /projects/{id}/status` set_project_status | {projectId,status} | |
| `DELETE /projects/{id}/members/{user}` remove_member (200) | {…,removed:true} | 멤버십 제거 수령증. |
| `DELETE /discovery/candidates/{id}` decline | {announcementId,state} | 후보 거절 수령증. |
| `POST /storage/contributions/{id}/activation` activate_contribution | {contribution} | |
| `DELETE /storage/contributions/{id}` revoke_contribution | {contribution} | |

### LOW — 기계-대-서버 수령증 (화면 비의존)
| 라우트 | 반환 | 비고 |
|---|---|---|
| `POST /nodes/{id}/heartbeats` (202) | result(applied/sequence) | 하트비트 수령증. |
| `POST /nodes/liveness-sweeps` (200) | sweep dict | 운영 스윕 결과. |
| `POST /discovery/announcements` announce (202) | {accepted,state} | 공지 수령증(테넌트 강제 로직은 Codex 하드닝). |

## 판정·권고 (전부 묶지 않는다)
- **비대칭 실재**: saintvision은 읽기(GET)를 대부분 묶고 **쓰기(POST/PUT/DELETE)를 대부분 안 묶었다**(pools 계열·내 create_workspace만 예외). 쓰기가 더 위험하다.
- **주의(있다≠묶임)**: 일부 미결속 라우트는 내부에서 `_contribution_body`/`_node_body`/`schemas.X.model_validate`로 body를 만든다. 그러나 **라우트에 response_model이 없으면 FastAPI가 최종 응답을 검증·정리하지 않는다** — 여분 키 미제거, 드리프트 미포착. 내부 헬퍼가 스키마를 닮은 것과 응답이 계약-강제되는 것은 다르다.
- **권고 우선순위(결정 대기)**: HIGH 4건부터. 그중 **create_project는 create_workspace와 동형이라 가장 싸다**(반환 project body에 맞는 기존/신규 응답 모델 한 줄). admit·set_member_role·set_resource_offer는 보안·권한·placement라 값이 크다. MED-HIGH/MED는 배선 필요도에 따라. LOW는 후순위(화면 비의존).
- **커널**: 위 기제 절대로 revisit — response_model 아닌 validate_contract. write 응답 앵커는 서빙앵커 3-버킷 감사 소관(ShardObservation 부재→Codex 보강 등 이미 처리). 여기 재나열 안 함(오탐 방지).
