# 세 축 종합

아침의 6층("있다≠작동한다")은 **어떻게** 실패하는지(미시 모드)다. 오늘 밤 다룬 세 축은 **무엇이** 참이어야 하는지(거시 차원)다. 6층은 각 축이 깨지는 방식이다.

## 세 축 (한 줄씩)
- **쓰기 실물성**: 쓰기가 진짜 대상을 만드는가. (작업공간 생성이 가짜 id 합성·POST 미호출 → 실물 없음. response_model로 결속하면 반환이 검증된 실물.)
- **읽기 정직함**: 읽기가 있는 그대로 말하는가 — 지어내지도, 숨기지도, 오류를 빈 목록으로 바꾸지도 않는가. (LegacyProjectCatalog=서빙 없는 계약; dead contract; telemetry "미제공" vs 가짜; throw→role=alert vs 조용한 빈 목록.)
- **시간 신선도**: 값이 언제 참이었는지를 함께 주는가. (observedAt/lastHeartbeatAt; 조회 시각을 진실 시각처럼 붙이지 않기.)

## 관계 — 나열이 아니라 전제 사슬
**쓰기 실물성 → 읽기 정직함 → 시간 신선도.** 아래가 위의 전제다.
- 실물이 없으면(가짜 id) 읽을 진짜가 없다 → **읽기 정직함이 무의미**(허구를 읽음).
- 읽기가 정직해야 신선도가 의미 있다 → **부정직한 값에 신선도 스탬프를 붙이면 최악**(허구에 거짓 확신을 더함). 시각 필드가 있다고 값이 현재라는 뜻이 아니다(복제본 observedAt=재검증 필요이지 "지금 건강" 아님).
- **점검 순서 = 사슬 아래부터**: 실물성 먼저. 아래가 깨졌으면 위 축들의 발견은 무의미하거나 오히려 해롭다.

## 축별로 무엇이 잡나 (도구가 다르다)
| 축 | 잘 잡는 도구 | 약한 도구 |
|---|---|---|
| 쓰기 실물성 | **되살림**(response_model/가드 제거→시험 깨짐, 항상-울림/201 노출) + **실측**(반환 dict ↔ 스키마, 프런트가 실제로 POST하나) | — |
| 읽기 정직함 | **대조군·실측**(전수 grep→측정; 실제 경로 추적: throw인가 role=alert인가 빈 목록인가) + **되살림**(서빙앵커 제거→시험) + **report-only 검사**(dead-contract·single-source) | 초록 카운트만 보기(도달 안 함) |
| 시간 신선도 | **소스 스키마-검토**(시각 필드 유무·기록 유무=알고있음 vs 미기록) + **독립검토**(시각의 *의미*) | **되살림 약함** — 시험이 한순간에 돌아 시간 경과를 못 만든다. 없는 observedAt이 t=0엔 멀쩡해 보인다 |

## 다음 사람에게
- **순서**: 쓰기 실물성 → 읽기 정직함 → 시간 신선도. 아래가 성립해야 위가 의미 있다.
- **도구 선택**: 실물성·읽기엔 **되살림**을 먼저(무게를 지는지 직접 깨 봐라). 신선도엔 **되살림 말고 소스 스키마-검토**(시각 필드가 응답에 있나, 백엔드가 기록은 하나) — 되살림은 시간 축을 못 잡는다.
- **미시 대조**(6층): 초록≠도달·배선≠통과·통과했으나 다른 이유·방어가 엉뚱·계약있으나 서빙 없음·앵커있으나 무게 없음 — 세 축이 깨지는 방식들. [[2026-09-21_이어가기_상태와규칙_Claude]] §2·§6.
