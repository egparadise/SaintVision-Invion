# S08-BE 단일 GPU 측정·격리·회수 결속

- Card 175, owner Codex, reviewer Claude, branch
  `agent/codex/s08-be-single-gpu`, base `3059c97868f237bac291c70bb89464b6ea8077c7`
  (#274 승인 head) 위에 쌓았다.
- 승인된 `S08-BE ROOF·BuildKit·단일 GPU 구현 설계` v1.1.0(`ecb43d4d`)의 구현
  순서에서 Build 계약·ROOF 결속·admitted adapter 다음인 **단일 GPU 경계**를 선택했다.

  공개 route, registry 상태·점수는 변경하지 않았다.

## 구현 경계

- `contracts/v1alpha1/core.schema.json`에 strict `GPUDeviceObservation`과
  `GPUAllocation`을 추가했다. `NodeResourceSnapshot.gpuDevices`는 선택 필드라 provider가
  없으면 기존 CPU 경로는 변하지 않고 GPU 요청만 닫힌다. 생성 Python·TypeScript·Go·Node
  schema도 같은 source에서 재생성했다.
- `services/control-plane/src/inv/gpu.py`는 discovery의 claimed `gpuCount`를 읽지 않는다.
  authenticated Node channel, online 상태, heartbeat·snapshot 15초 freshness, certificate,
  recovery epoch, profile, clock skew, device observation digest와 exact GPU resource/lease를
  모두 확인해야 한 장치 allocation을 만든다.
- `services/control-plane/src/inv/placement.py`는 `gpuCount=1`만 허용하고 strict snapshot의
  장치 ID·VRAM과 device별 `inv.resources(kind='gpu')` offer를 함께 만족하는 후보만 고른다.
  final commit에서 GPU resource row를 CPU·memory와 같은 canonical lock 집합에 넣고 active
  합계를 다시 계산한다. 같은 device의 두 번째 예약은 허용하지 않는다.
- `services/control-plane/src/inv/tooling.py`와 `services/control-plane/src/inv/sandbox.py`는
  exact live lease가 없는 GPU launch를 claim 전에 거부하고, allocation 전체를 서명되는
  launch plan과 `planDigest`에 넣는다.
- `services/node-agent/runtime/permit.go`는 permit의 GPU resource·lease·fencing token·Node·
  recovery epoch·profile을 exact match한다. `services/node-agent/runtime/docker.go`는
  `nvidia` driver의 특정 device ID 한 개와 `gpu` capability만 전달하며, inspect read-back에서
  all-device·다른 device·추가 capability·option을 거부한다. privileged, bind, broad `/dev`
  노출 금지는 기존 격리 조건 그대로다.
- `services/control-plane/src/inv/node_transport.py`는 GPU permit이 channel admission을 지난 뒤
  exchange, stop receipt 저장 또는 lease release를 확정하지 못하면 모든 lease를 유지하고
  Node를 quarantine한다. audit에는 resource·lease·observation digest·정본 오류 code만 남기며
  원문 오류나 비밀은 남기지 않는다.

## 되살림 방지와 검증 경계

| 변이·실패 | 고정한 시험/판정 |
|---|---|
| provider 없음, stale snapshot, digest drift | `tests/integration/test_tool_admission.py`에서 claim 0과 `RES-0003/RES-0008` |
| GPU 2개, count/VRAM 불일치, profile drift, VRAM 부족 | `tests/core/test_single_gpu_contract.py`에서 fail closed |
| unhealthy/non-exclusive/runtime-incompatible, wildcard device, broad driver | strict schema 부정 시험 |

| 다른 resource의 두 번째 device 대체, 한 lease에 장치 둘 | CP helper 실 PG 반례에서 exact resource 선택과 exact-one 거부 |
| all-device·다른 device·broad capability | `services/node-agent/runtime/docker_test.go` read-back 거부 |
| 같은 GPU를 두 Run이 예약 | `tests/integration/test_placement.py`에서 첫 lease 1건, 두 번째 예약 거부 |

로컬 환경에는 Go toolchain이 없어 Go compile·runtime 시험과 실 PG 3개 파일은 실행했다고
주장하지 않는다. PR의 `run-core` exact-head hosted 결과에서 Go와 real-PG JUnit을 확인한다.

## 비주장 경계

- synthetic measured provider는 contract·placement·fencing·exact Docker request·회수 실패
  경계를 검증하지만 실 GPU workload 성공 증거가 아니다.
- Linux 단일 GPU 장비의 driver/toolkit, 실제 device output, cancel 뒤 detach·재할당 인수는
  외부 전제이며 계속 `NOT_OBSERVED`/`BLOCKED_EXTERNAL`이다.
- GPU 없는 기본 provider는 none이고 기존 CPU launch 경로에는 `gpuAllocation`이 없다.
  S08-BE done·점수 승격·물리 인수 PASS를 주장하지 않는다.
