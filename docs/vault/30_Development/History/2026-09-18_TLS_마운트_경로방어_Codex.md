# TLS 인증서 마운트 및 경로 방어 구현

## 작업한 것

- `docker-compose.prod.yml`의 인증서·키 bind를 long syntax로 전환하고 `bind.create_host_path: false`를 적용했다. 소스 파일이 없을 때 Compose가 파일 대상 위치에 디렉터리를 자동 생성하지 않고 명시적으로 실패한다.
- `tools/deploy_intranet.ps1`는 정확한 인증서·키 경로가 디렉터리이면 해당 경로만 제거한 뒤 생성하고, 이후 검사는 `Test-Path -PathType Leaf`로 파일 형태를 요구한다.
- `tools/generate_tls_cert.py`는 동일한 두 출력 경로에 남은 파일·심볼릭 링크·디렉터리를 생성 전에 정리한다. 저장소의 인증서 파일 삭제, `.gitignore` 변경, Git 이력 재작성, 저장소 공개 설정 변경은 수행하지 않았다.

## 확인한 것

- `python -m pytest -q tests/core/test_deployment_credentials.py::test_tls_file_mounts_never_create_host_directories tests/test_deploy_intranet_preflight.py::test_cert_directory_collisions_are_removed_before_generation` → **2 passed**.
- `python -m pytest -q tests/test_deploy_intranet_preflight.py` → **11 passed**.
- `yaml.safe_load(docker-compose.prod.yml)` → **compose-yaml-ok**.
- `git diff --check` → 오류 없음.
- 생성기 직접 실행은 현재 기본 Python 환경에 `cryptography`가 없어 `ModuleNotFoundError`로 실행하지 못했다. 생성기 경로 방어 자체는 PowerShell preflight 회귀 시험으로 확인했다.

## 다음 담당

새 개발 인증서 발급과 외부 주입 전환, 공개된 개발 키의 회전·폐기, 저장소 비공개 전환 여부는 사용자 결정 대기다. 이 변경은 그 결정 전에도 빈 bind 대상 디렉터리와 디렉터리-파일 충돌을 조기에 실패·복구하도록 하는 독립 방어선이다.
