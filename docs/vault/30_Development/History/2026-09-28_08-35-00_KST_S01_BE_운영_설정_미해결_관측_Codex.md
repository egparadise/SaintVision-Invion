# S01-BE 운영 설정 미해결 관측 계약과 route 구현

## 결과

정본 운영 factory에 `GET /v1/operations/configuration-readiness`를 추가했다. 기존 `/v1/health.unresolvedSettings`는 다른 app factory의 표면이라 운영 배포 증거가 될 수 없었다. 새 경로는 Bearer와 현재 tenant operator grant를 요구하며, `S01_PENDING` 이름만 반환하고 값은 반환하지 않는다. `/readyz` 의미와 공개 오류 코드는 바꾸지 않았다.

정본 provider는 `create_configured_app()`에서만 명시 주입한다. 따라서 control-plane wheel을 단독 import할 때 루트 `saintvision` 패키지에 import-time 결합하지 않으며, provider가 없는 factory에서 이 경로는 추정 빈 목록 대신 `SYS-0001/503`으로 fail-closed한다.

## 계약·결속

- `ConfigurationReadinessView`를 canonical JSON Schema에 추가하고 Python/TypeScript/Go/packaged/Node schema를 재생성했다.
- 공유 fixture, generated model strictness, serving `validate_contract` anchor, route coverage를 함께 추가했다.
- `AUTH-0050`, `AUTH-0062/403`, `SYS-0001/503`은 기존 ProblemDetails funnel을 재사용한다.
- [[S01_BE_운영_설정_미해결_관측_결정]]에 (a)/(b)/(c) 비교, 비밀 경계, PR #122/#125 후속 정정을 기록했다.
