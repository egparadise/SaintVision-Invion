# S01-BE 운영 설정 미해결 관측 계약과 route 구현

## 결과

정본 운영 factory에 `GET /v1/operations/configuration-readiness`를 추가했다. 기존 `/v1/health.unresolvedSettings`는 다른 app factory의 표면이라 운영 배포 증거가 될 수 없었다. 새 경로는 Bearer와 현재 tenant operator grant를 요구하며, `S01_PENDING` 이름만 반환하고 값은 반환하지 않는다. `/readyz` 의미와 공개 오류 코드는 바꾸지 않았다.

정본 provider는 `create_configured_app()`에서만 명시 주입한다. Claude 1차 검토의 수정 요청대로 단순 process env 존재 검사를 폐기하고 `api.json.configurationReadiness`를 기존 read-only `server_config` volume에 결속했다. CA는 읽을 수 있는 bounded PEM 안에 CA 인증서가 하나 이상 있어야 하고 endpoint는 자격증명 없는 HTTP(S) URL이어야 한다. provider가 없는 factory에서 이 경로는 추정 빈 목록 대신 `SYS-0001/503`으로 fail-closed한다.

## 계약·결속

- `ConfigurationReadinessView`를 canonical JSON Schema에 추가하고 Python/TypeScript/Go/packaged/Node schema를 재생성했다.
- 공유 fixture, generated model strictness, serving `validate_contract` anchor, route coverage를 함께 추가했다.
- `AUTH-0050`, `AUTH-0062/403`, `SYS-0001/503`은 기존 ProblemDetails funnel을 재사용한다.
- `tools/prepare_server_config.py`가 `nodeMtlsCaBundle` 참조 파일만 기존 설정 volume에 복사하며 Compose는 그 volume을 이미 `/run/saintvision`에 read-only로 전달한다. endpoint는 같은 `api.json`에 있어 관측용 env drift가 없다.
- 1개만 유효하거나 1개만 미해결인 경우에도 `blocked`임을 고정해 `len(unresolved) < 2` 생존 변이를 죽였다. 없는 파일·깨진 PEM·CA가 아닌 leaf cert·잘못된 URL도 `ready`가 되지 않는다.
- [[S01_BE_운영_설정_미해결_관측_결정]]에 (a)/(b)/(c) 비교, 비밀 경계, PR #122/#125 후속 정정을 기록했다.
