# 미구현 목록 백엔드 대조 + 남은 구현 범위

Gemini가 alert 18개소를 3분류(오류·성공·미구현)하고 **미구현(Class 3) 4개소**를 집계했다. 각각 작업공간 생성에서 한 구별(있는데 안 부름 vs 아예 없음)로 백엔드를 대조했다.

## Gemini Class-3 4건 대조 — 전부 백엔드 존재, 진짜 누락 0
| # | 화면 위치 | 백엔드 | 판정 | 레인 |
|---|---|---|---|---|
| 1 | NodeList Node Agent 부트스트랩 안내 | 에이전트 설치는 **대역외**(운영자가 물리 노드에서 CLI 실행), 이후 등록은 `POST /v1/nodes`(nodes.py:48) **존재** | **누락 아님**(안내이지 API 액션 아님) | Gemini(안내), 등록 백엔드는 이미 있음 |
| 2 | DeveloperStudio 실행중 아티팩트 결과 다운로드 | `GET /v1/runs/{id}/artifacts`(app.py:408) **존재** | **누락 아님** — running 중엔 아티팩트가 아직 없어 비활성이 옳음(조건 미충족) | Gemini(상태 가드, 완료됨) |
| 3 | DeveloperStudio 실행중 원시 파일 바이트 다운로드 | `GET /v1/runs/{id}/artifacts/content`(app.py:414) **존재** | **누락 아님** — 동일(running 중 미가용, 비활성 옳음) | Gemini(상태 가드) |
| 4 | DeveloperStudio NodeStopReceipt 영수증 조회 | `RunResultView.stopReceipt`에 **임베드 서빙**(node_execution.py가 발행) **존재** | **누락 아님** — "미발행"은 정상 빈 상태(치명 에러 아님) | Gemini(상태 표기, 완료됨) |

**결론(이 배치)**: 4건 모두 **백엔드 라우트 존재.** "미구현/뒤가 없는 기능"이라는 라벨이 부정확했다 — 실제로는 **조건 미충족(running 중 미가용)·대역외 안내·정상 빈 상태(영수증 미발행)** 였다. Gemini가 그걸 정직하게(사전 비활성·인라인 안내) 고친 것이 옳고, **이 배치에서 새로 구현할 백엔드 기능은 0.** 흉내를 걷어내니 "그 자리에 없는 것"이 아니라 "그 자리에 이미 있으나 조건/상태였던 것"으로 드러났다.

## 그러나 — 세션이 실제로 드러낸 남은 구현 범위 (레인별)
이 배치는 0이지만, 오늘 밤 축 작업이 드러낸 **진짜 pending**은 따로 있다(흉내 걷어낸 자리의 실제 공백):
| 항목 | 상태 | 레인 |
|---|---|---|
| **node 자원 사용량 읽기 계약** | 사용량(usedQuantity)은 heartbeat로 수집·placement가 읽으나 **화면용 읽기 HTTP 없음**. 계약 신설 + capability별 vs 평면 metrics 모델 선택 미결 | **Codex**(커널/계약) + 사용자 결정 |
| **응답 관측시각(신선도) 필드** | ShardObservation.stateAsOf·RunResultView.stateUpdatedAt·RunArtifactList/RunLogView.completedAt — Codex `f1d95466`로 노출 **진행 중**(check_response_freshness 5/9, 4 pending) | **Codex**(커널) |
| **set_workspace_status 응답 결속** | 날 dict `{…, allowedNext}` 미결속(응답이 다음 전이 입력) | **Claude**(saintvision 백엔드, 작음) |
| **artifact-content 응답 계약 결속** | 라우트는 있으나 응답 계약 미결속(Codex 맵 지적) | **Codex**(커널) |
| **Go inv-discover T1/T2/T3 · 실 PG integration** | 이 호스트 툴체인 부재로 미검증 | **Codex** + 인프라 |

- 이 배치의 화면 4건은 Gemini가 이미 정직화 완료 → **추가 배선 불요**(백엔드 존재). 다음 착수 우선순위는 위 pending 표: 작은 것부터면 **set_workspace_status(Claude)**, 신선도 4필드(Codex 진행 중), node 사용량 계약(Codex+결정).

## 방법 메모
"있는데 안 부름 vs 아예 없음"을 라우트 존재로 갈랐다(작업공간 생성과 동일). 화면의 "미구현" 라벨은 **조건 미충족·대역외·빈 상태**를 포함하므로, 라벨을 그대로 남은-범위로 읽으면 안 되고 **백엔드 라우트 존재를 실제 대조**해야 한다 — 이 배치가 그 예(라벨 4, 진짜 누락 0).
