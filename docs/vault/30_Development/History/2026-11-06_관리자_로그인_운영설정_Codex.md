사용자가 지정한 계정으로 관리자 로그인이 가능하도록 설정하고 init, commit, push, build, Obsidian report, deploy를 수행한다. 비밀번호·DSN·토큰·개인 키는 소스·명령 인자·공개 로그·문서에 저장하지 않는다.

시작 기준은 정본 Index1.0.452/Codex1.0.413, base05b8d2bc666690a82a6268f744e78fbbc2294406이다. owner는 Codex다. 원래 작업 checkout의 local auth-config 변경을 보존하고 Orca child worktree admin-login-20261106, branch agent/codex/admin-login-20261106을 준비했다. 새 저장소 init은 하지 않는다.

읽기 전용 점검에서 로컬 포털3100은200이나 session 경로500, 구성된 backend8080은 연결 거부였다. 기존 로컬 Keycloak은 검증된 HTTPS discovery200이고 프로젝트3개 중 현재 포털 프로젝트는 active다. 요청 계정은 business DB에 없었다. 프로젝트 관리자 권한은 기존 DB의 owner membership과 원래 kernel account provisioning 경로로 설정하며 인증·권한 검사를 우회하지 않는다.

계정·실제 로그인·관리자 API 검증과 build/deploy는 아직 수행 전이다. 기존5대 FLEET 작업과 운영 인수 상태는 변경하지 않는다. 후속 기록에는 실제 명령·exit·환경·소스·CI·배포 결과를 비밀 없이 남긴다.


## 실제 계정·백엔드 복구와 로그인 검증

기존 로컬 IdP의 해당 계정 부재와 현재 active 포털 프로젝트를 확인했다. 비밀번호는 숨김 stdin으로만 받아 IdP reset-password JSON stdin에 전달했고 argv·소스·보고서·토큰 파일에 저장하지 않았다. 기존 OIDC subject 변환과 tools/provision_account.py 경로를 사용해 새 business user·project owner membership·request-and-approve 연결을 transaction으로 적용했다. account_provisioning_events 감사 기록과 연결 완료를 확인했다. 다른 사용자·프로젝트·Node 권한은 바꾸지 않았다.

원래 포털3100과 인증 서버8443은 보존하고 내려간 backend8080을 이 source checkout의 기존 saintvision.server production entrypoint로 복구했다. 로컬로만 listen하며 비밀은 private 기존 manifest에서 process 환경으로 전달한다. 원래 수정된 auth-config.js와 별개8000서비스도 그대로다.

18:49:53KST 실제 HTTPS SSO authorization-code/PKCE S256 로그인·토큰 교환200·포털 proxy를 거친 session200·동일 사용자 프로젝트 owner/canAdminister/canRequest/canApprove true·members200을 확인했다. 비인증 session은401이다. 토큰·비밀번호는 저장하지 않았다. 이는 실제 로컬 계정·API 검증이며 전체5대 운영 인수나 미완료FLEET 계약 수락은 아니다.

다음 행동은 이 기록의 normal commit/push와 exact Docs/Frontend build CI, 빌드 산출물 hash 확인·정본 Obsidian 보고 뒤 로컬 production frontend 배포와 사후 로그인 검증이다. 계정 설정은 실제 완료했고 frontend production artifact 배포는 아직 pending이다.
