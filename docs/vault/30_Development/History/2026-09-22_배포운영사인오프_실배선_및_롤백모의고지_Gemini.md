# 화면 결함 5대 부류 4차 치유 보고: IntranetDeploymentView 운영자 행위자 실배선/미인증 차단 및 ReleaseCandidateView 롤백 모의 고지

## 1. 개요 및 배경

사용자의 화면 결함 5대 부류(합성, 죽은 방어, 캐시 은폐, 가짜 식별자, 조기 성공 표시) 전수 점검 및 치유 지시에 따라, 과거 작성된 내부망 배포 뷰(`IntranetDeploymentView.tsx`)와 릴리스 후보 관리 뷰(`ReleaseCandidateView.tsx`)의 잠재 결함을 전수 감사하고 치유했다:
1. **`IntranetDeploymentView`: 하드코딩된 가짜 운영자 식별자 제거 및 세션 실배선 ("가짜 식별자" 치유)**:
   - 기존 `const [operatorId, setOperatorId] = useState('usr_operator_lead');`에 박혀 있던 하드코딩 식별자를 전면 제거.
   - `props`로 `currentUser`를 전달받아 `currentUser?.id`로 실배선하고, `App.tsx` 최상위 세션 컨텍스트와 결속.
   - 미인증 세션(또는 `currentUser === null`) 상태에서는 `data-testid="deployment-auth-required-notice"` (`role="alert"`) 경고 배너를 표출하고, 서명 버튼을 `disabled` 및 `aria-disabled="true"`로 원천 비활성화하여 비인가자 서명을 방어.
2. **`IntranetDeploymentView`: 내부망 배포 시뮬레이터 백엔드 미노출 정직 고지 ("합성 & 조기 성공 표시" 치유)**:
   - 실제 물리 장비 기동 및 Nginx TLS 실서버 바인딩은 CI/CD 파이프라인에서 수행됨을 못 박는 `data-testid="deployment-unexposed-notice"` (`role="status"`)를 상단에 배치.
   - 상단 메트릭 카드의 "5대 노드 전수 여정"을 `[AC-12 기준 규격]`으로 정직 표기하여 실시간 물리 노드 5대 통과 착시를 방지.
   - 서명 완료 통지문을 `✔ [모의 시뮬레이션] 최종 프로덕션 릴리스 ... 로컬 시뮬레이션 승인되었습니다. (백엔드 배포 API 미노출)`로 정직화.
3. **`ReleaseCandidateView`: 롤백 모의 고지 및 허위 축하 배너 소거 ("조기 성공 표시" 치유)**:
   - 상단에 `data-testid="release-unexposed-notice"` (`role="status"`, "릴리스 후보(RC) 및 무중단 롤백 제어기 (백엔드 배포 API 미노출)")를 신설.
   - 롤백 클릭 시 표출되던 과거의 `✔ AC-11 롤백 검증 완료! ... 캐시 무효화 및 무중단 상태가 확인되었습니다.` 허위 축하 문구를 완전 소거하고, `✔ [모의 시뮬레이션] AC-11 롤백 절차 검증 완료: ... (백엔드 릴리스 제어 API 미노출 상태로 실제 인프라 및 CDN 캐시 미반영)`으로 정직하게 고지.
4. **신규 DOM 단위 테스트 구축 및 2대 돌연변이(M9, M10) 실측 사살**:
   - `apps/web/tests/deployment-release-integrity-wiring.test.tsx`를 작성하고 고의 돌연변이 M9(미인증 경고 억제)과 M10(롤백 허위 완료 배너 회귀)을 실측 사살했다.

## 2. 세부 구현 및 컴포넌트 수정

### 2.1 `IntranetDeploymentView.tsx`
- `IntranetDeploymentViewProps`에 `currentUser?: { id: string; name: string; role: string } | null` 확장.
- `operatorId` 초기값 및 `useEffect` 동기화 로직 적용:
  ```typescript
  const [operatorId, setOperatorId] = useState<string>(currentUser ? currentUser.id : '');
  useEffect(() => {
    if (currentUser?.id) {
      setOperatorId(currentUser.id);
    }
  }, [currentUser]);
  ```
- 서명 버튼 가드:
  ```tsx
  <Button
    data-testid="deployment-signoff-btn"
    disabled={manifest.operatorSignOff || !operatorId.trim()}
    aria-disabled={manifest.operatorSignOff || !operatorId.trim() ? 'true' : 'false'}
    title={!operatorId.trim() ? '운영자 계정 로그인이 필요합니다' : '...'}
  >
  ```
- `App.tsx:558`에서 `<IntranetDeploymentView clusterNodes={nodes} currentUser={currentUser} />`로 실배선.

### 2.2 `ReleaseCandidateView.tsx`
- 상단 `release-unexposed-notice` (`role="status"`) 신설:
  ```tsx
  <div role="status" aria-live="polite" data-testid="release-unexposed-notice">
    ℹ️ 릴리스 후보(RC) 및 무중단 롤백 제어기 (백엔드 배포 API 미노출)...
  </div>
  ```
- `handleRollback` 성공 메시지를 `[모의 시뮬레이션]` 규격으로 정직화.
