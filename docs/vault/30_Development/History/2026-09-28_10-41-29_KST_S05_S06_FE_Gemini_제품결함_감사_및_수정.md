## 1. 작업 개요 및 목적

본 작업은 S07~S10 트랙에서 완결된 '시나리오 매트릭스 수립 → 제품 결함 후속 감사 및 수정' 거버넌스 프로세스를 **S05-FE(자원배치 미리보기·Explain UI)** 및 **S06-FE(Workspace 복원·원격 WS/PTY 콘솔 UI)** 트랙에 완결 적용하는 카드이다.

S05 매트릭스(v1.2.2)와 S06 매트릭스(v1.1.2), 그리고 PR #151의 S05 결정(bounded semaphore 라인은 공식 폐쇄되었으며 `/v1/pools`, `/v1/pools/{id}/placement-preview`, `/v1/pools/{id}/plans`의 legacy 배치 경로가 정본)에 입각하여 현재 `apps/web` 제품 코드를 심층 전수 감사하고, 발견된 7대 결함(허위 상태 표기, 모의 데이터의 실제 위장, 서버 계약에 없는 비정본 필드 폴백, 모달 Escape/포커스 트랩 부재, 키보드 접근성 결함)을 치유하였다.

또한 Claude UI 축 독립 검토(issuecomment-5862081355) 지적 사항인 **차단 결함 4건(F-1~F-4) 및 중간 결함 5건(F-5~F-9)**을 전수 반영하여 회귀 없는 정본 코드를 확정하였다.

## 2. 결함 감사 및 조치 내역 (Claude UI 지적 F-1~F-9 및 r2 조건 C-1~C-4 전수 조치 포함)

### 1) [S05-DEF-A] `PlacementExplainView.tsx` 로컬 시뮬레이션 고지 및 점수 분해 성격 명시
- **결함 내용**: `PlacementExplainView.tsx:26, :32-34`가 클라이언트 결정론적 휴리스틱 계산 결과를 아무런 단서 없이 `"후보 노드 평가 및 제외 Explain 원장 (AC-05)"`, `"정책: {policyVersion}"`, `"스냅샷: {snapshotVersion}"`으로 표출하여 백엔드 제어 평면이 세부 다면 평가 점수(지역성 40%, 가용여유 30%, 네트워크 30%)를 반환한 것처럼 오인 유발.
- **조치 내용**:
  - 헤더 영역에 `data-testid="placement-explain-simulation-badge"` 배지 추가: `[로컬 시뮬레이션 (UNVERIFIED · 모의)]`.
  - 안내 문구 보강: "클라이언트 결정론적 가중치 시뮬레이션 (서버 API 점수 분해는 미측정 · Hard Filter 탈락 사유 추적)".
  - 점수 라벨을 `data-testid="placement-explain-score-label"`로 래핑하고 `로컬 모의 점수 (미측정)`으로 명확히 표기.
  - `PlacementExplainResult` mock에 정본 필수 필드인 `runId` 보강.

### 2) [S05-DEF-B] `PlacementSimulator.tsx` 비계약 가짜 풀 용량 필드 접근 제거, 시험 전용 props 롤백 및 동기화 useEffect 제거 (F-4, F-6, F-8, C-3)
- **결함 내용**:
  - `PlacementSimulator.tsx:367-390`에서 `poolCapacity`가 로드되지 않았을 때 `(activePool as any).availableCores !== undefined` 등 비계약 가짜 필드에 접근하여 렌더링을 시도함.
  - Claude F-4: 시험 편의를 위해 추가되었던 `nodes?`, `activePool?: any`, `allPools?: any[]`, `projectId?: string` 및 임의 폴백이 제품 계약에 침투함 (실제 운영 호출처는 `App.tsx:814 <PlacementSimulator nodes={nodes} />` 1곳).
  - Claude F-6: `!poolCapacity && activePool` 조건으로 인해 loading 및 error 상태에서도 `pool-capacity-pending` 배너가 동시 렌더링됨.
  - Claude C-3 (N-1): 시험 편의를 위해 추가되었던 props→state 동기화 `useEffect` 3개(`initialPoolCapacity*`)가 제품 코드에 잔존함.
- **조치 내용**:
  - `(activePool as any).availableCores` 등 비계약 필드 접근 블록 전면 제거.
  - 시험 전용 props(`nodes?`, `activePool?`, `allPools?`, `projectId?`) 및 `effectiveInitialPools` 폴백을 전면 제거하고 `nodes: NodeItem[]` 필수 props로 복원.
  - props→state 동기화 `useEffect` 3개를 전면 제거하여 시험 전용 런타임 코드를 완전히 배제 (C-3).
  - 시험(`s05-s06-defect-fixes.test.tsx`)에서는 unmount 후 새 root로 error 상태를 fresh 렌더링하도록 교정.
  - `pool-capacity-pending` 표출 조건을 `poolCapacityState === 'idle'`로 엄격히 제한하여 오류 상태에서의 거짓 배너 표출 차단.
  - `/v1/pools` 응답 mock을 계약 형태인 `{ items: [...], count: 1 }`로 정합화하고, 레거시 비계약 필드(`availableCores: 8, totalCores: 16`)가 주어져도 DOM에 `8 / 16 Cores`가 렌더되지 않음을 단언하고, 공허 단언(`undefined/NaN Cores`)을 삭제 (C-2).

### 3) [S05-DEF-C] `ResourceExplorer.tsx` 후보 노드 여유 자원 정밀 렌더링 (F-5)
- **사유 정정**: `ResourceExplorer`의 `placementPreview`는 UI view(`fabricControlApi.ts:62-72`)이며 어댑터가 `spare.*`를 `availableCpuMillicores`로 정규화하므로 NaN 위험은 사실이 아님.
- **결함 내용**: `c: any`로 타입 안전성을 무력화하고 서버가 실측한 유효 0값을 `> 0 ? ... : '미측정'`으로 변환하여 허위 '미측정' 라벨을 생성함.
- **조치 내용**:
  - `c: any`를 제거하고 엄격한 정본 타입 `c`로 복원.
  - 0 코어 가용 자원을 정직하게 `0C 가용`으로 표출하고, '미측정'으로 왜곡하지 않음.
  - 가용 GPU가 0인 경우 `0 GPU`로 정직 표출.
  - 후보 노드 여유 자원이 0일 때 `0C 가용`이 렌더링되고 '미측정'이 출력되지 않음을 단언하는 시험 추가.

### 4) [S06-DEF-D] `WorkspaceCreateModal.tsx` Escape 닫기, 포커스 트랩, 포커스 복원 및 포커스 탈취 방지 (F-2)
- **결함 내용**:
  - `[isOpen, onClose]` effect 의존성 때문에 `App.tsx`의 5초 폴링 재렌더 시마다 cleanup이 `previousActiveElement.focus()`를 호출하여 모달 입력 중 포커스가 5초마다 오프너로 튐.
  - 모달 오픈 시 초기 포커스가 부여되지 않고, Escape가 window 전역 리스너에 바인딩됨.
- **조치 내용**:
  - `onClose`는 `useRef(onClose)`로 최신 ref를 추적하고, opener 저장/복원은 `useLayoutEffect`/`useEffect`의 `[isOpen]` 변경에서만 수행.
  - 모달 오픈 시 `nameInputRef.current?.focus()`로 초기 포커스를 안전하게 부여 (`autoFocus` 제거).
  - Escape 및 Tab 포커스 트랩을 dialog 컨테이너 요소의 `onKeyDown`으로 한정하여 전역 윈도우 간섭 차단.
  - 열린 상태에서 새 `onClose` 함수로 재렌더되어도 포커스가 입력칸에 온전히 유지됨을 단언하는 시험 추가.

### 5) [S06-DEF-E] `WorkspaceList.tsx` 작업공간 카드 키보드 접근성 및 Studio 버튼 키보드 격리 (F-1, F-8)
- **결함 내용**: 카드 `div`의 `onKeyDown`이 `e.target !== e.currentTarget` 검사 없이 `preventDefault()` 및 `onSelectWorkspace()`를 실행하여, 카드 내부의 `⚡ Studio에서 열기` 버튼에서 Enter/Space를 누를 때 Studio가 열리지 않고 작업공간 선택이 가로채지는 키보드 회귀 발생.
- **조치 내용**:
  - 카드 `onKeyDown`에 `if (e.target !== e.currentTarget) return;` 가드 부여.
  - `⚡ Studio에서 열기` 버튼에 독립적인 `onKeyDown` 핸들러를 부여하여 Enter/Space 입력 시 `e.stopPropagation()` 및 `onOpenStudio(wsp.id)`를 직접 실행.
  - `WorkspaceList`에 정본 필수 prop인 `nodes={[]}` 전달 및 `onCreateWorkspace` prop 명칭 정합화.
  - Studio 버튼에서 Enter 키 발생 시 `onOpenStudio`가 호출되고 `onSelectWorkspace`는 호출되지 않음을 단언하는 시험 추가.

### 6) [S06-DEF-F] `TerminalSessionView.tsx` PTY 티켓 인증 방식 설명 명시 (F-7)
- **결함 내용**: 사용자가 입력한 `activeCommandId` 문자열만 보고 "30초 암호학적 1회용 PTY 티켓 (mTLS 격리)"를 표출하여 티켓 발급이 완료된 것으로 오인하게 함.
- **조치 내용**:
  - 라벨을 '인증 방식'으로 명시:
    - 명령 ID 존재 시: `30초 암호학적 1회용 PTY 티켓 인증 연동 (mTLS 격리)`
    - 명령 ID 부재 시: `승인 명령 ID 대기 중 (인증 대기 · mTLS)`
  - 실제 발급/연결 완료와 인증 메커니즘을 명확히 구분.

### 7) [S06-DEF-G] `DesktopWindow.tsx` 윈도우 한정 Escape 처리, 터미널/입력 격리 및 시작 메뉴 오버레이 우선순위 연동 (F-3, F-8, C-1, C-2)
- **결함 내용**:
  - `globalThis.addEventListener('keydown')` 전역 Escape 리스너 제거 후, 윈도우 루트 `onKeyDown`에서 `e.stopPropagation()`을 호출하여 포커스가 활성 창 안에 있을 때 시작 메뉴를 닫으려는 Escape가 `DesktopShell`의 `window` 리스너에 도달하지 못해 창만 닫히고 메뉴가 열린 채 남는 회귀(C-1).
  - 시험 mock의 `appId: 'system-monitor'`가 `AppId` 유니온에 없고, workspace mock에 `status: 'active'` 및 `updatedAt` 비정본 필드 포함(C-2).
- **조치 내용**:
  - `DesktopWindowComponent`에 `isOverlayOpen?: boolean` prop 추가 및 `handleKeyDown`에 `if (e.defaultPrevented || isOverlayOpen) return;` 가드 부여 (C-1).
  - `DesktopShell.tsx:664`에서 `isOverlayOpen={isStartMenuOpen || isNotifOpen}`을 전달하여 시작 메뉴/알림창이 열려 있을 때는 창 닫기를 억제하고 이벤트 버블링을 허용하여 시작 메뉴만 우선 닫히도록 연동.
  - 닫기 버튼 타이틀에서 `(Esc)` 표기 제거 (`title="창 닫기"`).
  - `appId: 'terminal'`로 유효한 `AppId` 적용, `WorkspaceItem` mock의 `status: 'ready'` 정합 및 `updatedAt` 제거 (C-2).
  - 회귀 시험 `[S06-DEF-G-C1]` 추가: 시작 메뉴가 열린 상태에서 활성 창 내부 Escape 입력 시 시작 메뉴만 닫히고 창은 닫히지 않으며, 메뉴가 닫힌 뒤 다시 Escape를 눌러야 창이 닫힘을 실단언.
