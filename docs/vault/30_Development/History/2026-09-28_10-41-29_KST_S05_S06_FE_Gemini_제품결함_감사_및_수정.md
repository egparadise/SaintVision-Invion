## 1. 작업 개요 및 목적

본 작업은 S07~S10 트랙에서 완결된 '시나리오 매트릭스 수립 → 제품 결함 후속 감사 및 수정' 거버넌스 프로세스를 **S05-FE(자원배치 미리보기·Explain UI)** 및 **S06-FE(Workspace 복원·원격 WS/PTY 콘솔 UI)** 트랙에 완결 적용하는 카드이다.

S05 매트릭스(v1.2.2)와 S06 매트릭스(v1.1.2), 그리고 PR #151의 S05 결정(bounded semaphore 라인은 공식 폐쇄되었으며 `/v1/pools`, `/v1/pools/{id}/placement-preview`, `/v1/pools/{id}/plans`의 legacy 배치 경로가 정본)에 입각하여 현재 `apps/web` 제품 코드를 심층 전수 감사하고, 발견된 7대 결함(허위 상태 표기, 모의 데이터의 실제 위장, 서버 계약에 없는 비정본 필드 폴백, 모달 Escape/포커스 트랩 부재, 키보드 접근성 결함)을 치유하였다.

## 2. 7대 결함 감사 및 조치 내역

### 1) [S05-DEF-A] `PlacementExplainView.tsx` 로컬 시뮬레이션 고지 및 점수 분해 성격 명시
- **결함 내용**: `PlacementExplainView.tsx:26, :32-34`가 클라이언트 결정론적 휴리스틱 계산 결과를 아무런 단서 없이 `"후보 노드 평가 및 제외 Explain 원장 (AC-05)"`, `"정책: {policyVersion}"`, `"스냅샷: {snapshotVersion}"`으로 표출하여 백엔드 제어 평면이 세부 다면 평가 점수(지역성 40%, 가용여유 30%, 네트워크 30%)를 반환한 것처럼 오인 유발.
- **조치 내용**:
  - 헤더 영역에 `data-testid="placement-explain-simulation-badge"` 배지 추가: `[로컬 시뮬레이션 (UNVERIFIED · 모의)]`.
  - 안내 문구 보강: "클라이언트 결정론적 가중치 시뮬레이션 (서버 API 점수 분해는 미측정 · Hard Filter 탈락 사유 추적)".
  - 점수 라벨을 `data-testid="placement-explain-score-label"`로 래핑하고 `로컬 모의 점수 (미측정)`으로 명확히 표기.

### 2) [S05-DEF-B] `PlacementSimulator.tsx` 비계약 가짜 풀 용량 필드 접근 제거
- **결함 내용**: `PlacementSimulator.tsx:367-390`에서 `poolCapacity`가 로드되지 않았을 때 `(activePool as any).availableCores !== undefined` 조건을 검사하며 `(activePool as any).availableCores`, `totalCores`, `availableMemoryBytes` 등 서버 정본 스키마(`PoolListItemResponse`: `{ poolId, projectId, name, status, memberCount }`)에 존재하지 않는 허위 필드에 접근하여 렌더링을 시도함.
- **조치 내용**:
  - `(activePool as any).availableCores` 및 메모리/GPU 가짜 필드 접근 블록 전면 제거.
  - `!poolCapacity && activePool` 상태일 때 `data-testid="pool-capacity-pending"` 배너 표출: `"풀 3원 용량 조회 대기 중 (미측정 · GET /v1/pools/{activePool.poolId}/capacity)"`.
  - `test_route_coverage.py`의 필수 불변식 가드 문자열(`"UNVERIFIED: 로컬 시뮬레이션 전용"`, `"preview-error-banner"`, `"pools-error-banner"`, `"서버 어드미션 미검증: 가짜 샤드 상태를 생성하지 않습니다"`, `role="alert"`)을 100% 보존.

### 3) [S05-DEF-C] `ResourceExplorer.tsx` 후보 노드 여유 자원 와이어 스키마 대응 및 후보 순위 명시
- **결함 내용**: `ResourceExplorer.tsx:1810-1815`에서 `placementPreview.candidates`를 렌더링할 때 `c.availableCpuMillicores / 1000`에 직접 접근하여 와이어 응답(`PlacementPreviewCandidateResponse`: `c.spare.cpuMillicores`, `c.headroom`)과 불일치 시 `NaN`을 출력할 위험이 있었으며, 샤드 할당이 완료된 것처럼 보일 수 있는 모호성 존재.
- **조치 내용**:
  - `c.spare?.cpuMillicores ?? c.availableCpuMillicores ?? 0`로 안전하게 폴백하여 와이어 계약과 UI 어댑터 모두 수용.
  - `data-testid="placement-preview-results"` 컨테이너를 부여하고 후보 노드 타이틀 우측에 `[서버 유휴 우선 후보 순위 · 샤드 미할당]` 명시.

### 4) [S06-DEF-D] `WorkspaceCreateModal.tsx` Escape 닫기, 포커스 트랩, 포커스 복원 구현
- **결함 내용**: 모달 오픈 시 키보드 Escape 키 닫기 미지원, 마지막 입력/버튼에서 Tab 키 입력 시 배경 화면으로 포커스 누출(Focus Trap 부재), 모달 닫힘 시 트리거 버튼으로 포커스 복원 부재, `aria-labelledby` 누락.
- **조치 내용**:
  - `role="dialog"`, `aria-modal="true"`에 `aria-labelledby="workspace-create-title"` 및 제목 `id` 추가.
  - `useEffect` 내 `keydown` 리스너를 통해 `e.key === 'Escape'` 시 `onClose()` 호출.
  - `e.key === 'Tab'` 시 모달 내부의 첫 번째와 마지막 포커스 가능 요소 간 순환 잠금(Focus Trap) 구현.
  - 모달 언마운트 시 이전 활성 엘리먼트(`previousActiveElement.focus()`) 복원 구현.

### 5) [S06-DEF-E] `WorkspaceList.tsx` 작업공간 카드 키보드 접근성(role="button", tabIndex=0, Enter/Space) 부여
- **결함 내용**: `WorkspaceList.tsx:96-107`의 작업공간 카드 `div`에 `onClick`만 바인딩되어 있어 키보드 사용자가 Tab 키로 도달할 수 없고 Enter/Space로 진입 불가.
- **조치 내용**:
  - `role="button"`, `tabIndex={0}`, `aria-label={`작업공간 ${wsp.name} 선택`}` 속성 부여.
  - `onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); onSelectWorkspace(wsp.id); } }}` 추가.

### 6) [S06-DEF-F] `TerminalSessionView.tsx` PTY 티켓 발급 상태 조건부 렌더링
- **결함 내용**: `activeCommandId`가 전달되지 않았거나 빈 값인 상태에서도 상단 바의 `pty-ticket-badge`가 무조건 `"30초 암호학적 1회용 PTY 티켓 (mTLS 격리)"`를 표출하여 티켓이 이미 발급된 것으로 오인하게 함.
- **조치 내용**:
  - `activeCommandId.trim()` 존재 여부에 따라 분기:
    - 명령 ID 존재 시: `'30초 암호학적 1회용 PTY 티켓 (mTLS 격리)'` (`#fbbf24`)
    - 명령 ID 부재 시: `'승인 명령 ID 대기 중 (티켓 미발급 · mTLS)'` (`#94a3b8`)

### 7) [S06-DEF-G] `DesktopWindow.tsx` 활성 윈도우 한정 Escape 키 닫기 구현
- **결함 내용**: 닫기 버튼에 `title="창 닫기 (Esc)"`가 표기되어 있으나 실제 Escape 키다운 핸들러가 부재함.
- **조치 내용**:
  - `isActive && window.isOpen && !window.isMinimized` 조건 하에서만 Escape 키 입력을 감지하여 `onClose()` 호출 (비활성 창 및 다중 창 일괄 닫힘 원천 차단).
