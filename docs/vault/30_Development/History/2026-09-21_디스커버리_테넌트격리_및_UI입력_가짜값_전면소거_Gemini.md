# 디스커버리 테넌트 격리 실배선, 네트워크 0호출 가드 및 UI 전수 가짜 식별자 소거

## 1. 작업 개요

- **촉발 배경**:
  - Codex가 `POST /v1/discovery/announcements` 엔드포인트에 인증 주체(principal)와 일치하는 테넌트 경계(`X-Inv-Tenant == principal.tenant_id`) 검증을 도입하여, 테넌트 불일치 시 `403 AUTH_TENANT_SCOPE` ProblemDetails를 반환하도록 보안 태세를 전환함.
  - Claude의 가짜 값 감사(`2026-09-21_계약이_못잡는_가짜값_목록_Claude.md`) 및 사용자 지시에 따라, `ResourceExplorer.tsx:420`에 하드코딩되어 있던 가짜 테넌트 UUID `'00000000-0000-0000-0000-000000000001'`를 실제 인증 세션의 `currentUser.tenantId`로 배선하고, 테넌트 부재 시 무단 네트워크 요청을 일절 발생시키지 않는 0-call 가드를 확립함.
  - 아울러 사용자가 승인 번호 없이도 통과하던 `ModelLineageView`의 `'apr_01JXYZ889900'` 사전 채움 결함을 비롯하여, UI 전반(5대 대상)에 잔존하던 하드코딩된 자리표시자/데모 식별자(`nod_01JABCDEF01`, `run_01JABCDEF_DEMO`, `prj_01JABCDE`, `wsp_0123456789ABCDEFGHJKMNPQRS`)를 전수 소거하고, 필수 입력/노드 부재 시 조작 버튼 비활성화 및 정직한 안내 배너를 구축함.

## 3. 실측 돌연변이 사살 및 에러 내역 (Measured Mutation Failures)

1. **디스커버리 테넌트 가드 돌연변이 사살 (`tests/resource-explorer-dom.test.tsx`)**:
   - 돌연변이: `tenantId`가 누락되었을 때 `handleBroadcastAnnouncement`가 기존의 하드코딩된 `'00000000-0000-0000-0000-000000000001'`로 백엔드 호출을 진행하도록 되돌림.
   - 실측 사살 에러:
     ```
     AssertionError: expected "broadcastAnnouncement" to have been called 0 times, but got 1
     at tests/resource-explorer-dom.test.tsx:778:29
     ```
   - 결과: 테넌트 식별자가 없는 상태에서의 무단 호출이 0회로 정확히 차단됨을 확증함.

2. **모델 배포 게이트 가드 돌연변이 사살 (`tests/model-lineage.test.ts`)**:
   - 돌연변이: `approvalInput`을 다시 `'apr_01JXYZ889900'`로 초기화하거나, 빈 문자열일 때 배포 버튼을 활성화(`disabled={false}`)하도록 변조.
   - 실측 사살 에러:
     ```
     AssertionError: expected false to be true // deployBtn.disabled === false
     at tests/model-lineage.test.ts:180:31
     AssertionError: expected 'apr_01JXYZ889900' to be ''
     at tests/model-lineage.test.ts:175:27
     ```
   - 결과: 승인 식별자 입력 없이는 배포 시도가 원천 차단됨을 확증함.

3. **작업 사본(Run ID) 계획 수립 가드 돌연변이 사살 (`tests/resource-explorer-dom.test.tsx`)**:
   - 돌연변이: `planRunId`를 `'run_01JABCDEF_DEMO'`로 초기화하거나 버튼 활성화 유지.
   - 실측 사살 에러:
     ```
     AssertionError: expected 'run_01JABCDEF_DEMO' to be ''
     at tests/resource-explorer-dom.test.tsx:817:32
     ```
   - 결과: 유효한 승인 Run ID가 입력되지 않으면 계획 생성 버튼이 비활성화됨을 확증함.
