# 화면 결함 5대 부류 치유 — 노드 에러 은폐, 작업공간 실배선, 자연어 KPI/조기성공

> 사용자 명시 승인 트랙에 따라 5대 결함 부류(합성, 죽은 방어, 캐시 은폐, 가짜 식별자, 조기 성공 표시) 중 위험도가 높은 최우선 3개 항목(노드 에러 은폐 치유, 작업공간 생성 실배선 및 가짜 ID 제거, 자연어 99% 가상 KPI 및 허위 성공 배너 치유)을 연속 실행으로 완결하였다.

## 1. 개요 및 3대 결함 치유 항목

| 순위 | 대상 화면 및 결함 | 결함 부류 | 원인 및 위험도 | 치유 결과 (Before vs After) |
|---|---|---|---|---|
| **Priority 1** | `ResourceExplorer.tsx`, `App.tsx` (노드 API 실패 시 에러 은폐) | **캐시/오류 은폐** (Concealment -> Empty State Illusion) | `fetchNodes`의 `catch` 블록에서 `setNodes([])`만 호출하고 에러를 기록하지 않아, 제어 평면 장애 발생 시 5개 노드가 전부 증발한 것으로 오인하여 불필요한 인시던트 대응 유발 | **Before**: API 실패 시 빈 배열 `[]`만 남아 0대 빈 상태 및 0 Cores 표시.<br>**After**: `nodesState`(`idle`/`loading`/`success`/`error`), `nodeError` 신설. `nodesError` 시 `nodes-fetch-error-banner`(`role="alert"`)와 재시도 버튼 표출, 상단 논리 요약 카드에 `조회 실패` 명시, 정상 0대일 때만 `nodes-empty-state`(`role="status"`) 표출. |
| **Priority 2** | `WorkspaceList.tsx`, `App.tsx`, `projectObservation.ts` (작업공간 가짜 ID 합성 및 미배선) | **가짜 식별자 합성 & 조기 성공 표시** (Fake ID Synthesis & Early Success) | 백엔드에 `POST /v1/projects/{projectId}/workspaces`가 실재함에도 프런트가 이를 부르지 않고 클라이언트 로컬에서 `wsp_${Date.now()}`와 `status: 'active'`를 날조 합성 | **Before**: 백엔드 미호출, 새로고침 시 증발, 가짜 'active' 상태 부여.<br>**After**: `createProjectWorkspace(projectId, name)` 실배선(POST 호출). 서버가 부여한 실물 ID와 `status: 'provisioning'`을 수신하여 `WorkspaceList`에 정직하게 `프로비저닝 중 (Provisioning)`으로 표기. 작업공간 0개 시 `workspaces-empty-state`(`role="status"`) 렌더링. |
| **Priority 3** | `NaturalLanguageRunView.tsx` (가상 KPI 99% 달성 합성 및 조기 성공 배너) | **합성 & 조기 성공 표시** (Synthetic KPI & Premature Success Banner) | 백엔드에 자연어 에이전트 라우트(`/v1/agent/*`)가 없음에도 100건 중 99건 성공(99.0%) 모의 픽스처를 프로덕션 지표인 양 표출하고, Diff 적용 시 파일시스템 기록 없이 "Diff가 성공적으로 승인 및 적용되었습니다" 허위 배너 노출 | **Before**: 가상 99% 달성 배너, 허위 성공 축하 배너.<br>**After**: `agent-unexposed-notice`(`role="status"`) 신설(에이전트 API 미노출 명시), KPI 카드를 `[AC-09 픽스처]`, `(로컬 시뮬레이션)`으로 정직 고지, Diff 적용 시 파일시스템에 기록되지 않았음을 고지하는 안내문(`role="status"`)으로 전환. |

## 2. Before vs After 코드 대조

### ① Priority 1: 노드 API 실패 시 에러 은폐 치유
- **App.tsx Before**:
  ```ts
  const fetchNodes = React.useCallback(async () => {
    if (!currentUser) return;
    const scope = scopeRef.current;
    try {
      const page = await apiClient<NodePageResponse>('/v1/nodes');
      if (scopeRef.current === scope) setNodes(page.items.map(observedNode));
    } catch {
      if (scopeRef.current === scope) setNodes([]); // 에러 은폐!
    }
  }, [currentUser]);
  ```
- **App.tsx After**:
  ```ts
  const fetchNodes = React.useCallback(async () => {
    if (!currentUser) { setNodesState('idle'); return; }
    const scope = scopeRef.current;
    setNodesState('loading'); setNodeError(null);
    try {
      const page = await apiClient<NodePageResponse>('/v1/nodes');
      if (scopeRef.current === scope) {
        setNodes(page.items.map(observedNode));
        setNodesState('success'); setNodeError(null);
      }
    } catch (err: any) {
      if (scopeRef.current === scope) {
        setNodes([]);
        setNodesState('error');
        setNodeError(err?.message || '노드 목록을 확인하지 못했습니다.');
      }
    }
  }, [currentUser]);
  ```
- **ResourceExplorer.tsx After**:
  - 논리 자원 카드: `nodesError ? <span style={{ color: '#f87171' }}>조회 실패</span> : ...`
  - 물리 노드 영역: `nodesError` 시 `<div role="alert" data-testid="nodes-fetch-error-banner">...</div>` 및 재시도 버튼 노출. `!nodesError && filteredNodes.length === 0`일 때만 `nodes-empty-state`(`role="status"`, "등록된 물리 노드가 없습니다 (정상 조회 결과: 0대)") 표출.

### ② Priority 2: 작업공간 가짜 ID 합성 제거 및 백엔드 실배선
- **App.tsx Before**:
  ```ts
  onCreate={async (newWsp) => {
    const created: WorkspaceItem = {
      ...newWsp,
      id: `wsp_${Date.now().toString(36)}`, // 가짜 ID 클라이언트 합성!
      createdAt: new Date().toISOString(),
    };
    setWorkspaces((prev) => [created, ...prev]);
  }}
  ```
- **App.tsx After**:
  ```ts
  onCreate={async (newWsp) => {
    try {
      const created = await createProjectWorkspace(projectId, newWsp.name);
      await fetchWorkspaces();
      setSelectedWorkspaceId(created.workspaceId);
    } catch (err: any) {
      setWorkspaceError(err?.message || 'Workspace 생성 실패');
      throw err;
    }
  }}
  ```
- **WorkspaceCreateModal.tsx After**:
  - 백엔드 `WorkspaceCreateRequest(extra=forbid)` 스키마(`name` 2–128자)에 맞춰 폼을 단일화.
  - 생성 시점에 결정되지도 않으면서 사용자를 속이던 가짜 노드 선택기(`<select>`), 가짜 CPU/RAM 슬라이더, 가짜 허용 경로 폼 완전 소거.
  - 상단에 `data-testid="workspace-create-phase-notice"` (`role="status"`) 신설:
    > "📌 생성 단계 안내 (Phase Notice): 작업공간 생성(POST /v1/projects/.../workspaces)은 **프로비저닝(provisioning)** 초기 레코드만 등록합니다. 물리 노드 배치, CPU/RAM 자원 할당, 실행 도구 바인딩 및 파일 체크아웃은 생성 스키마에 포함되지 않으며, 생성 완료 후 **실행(Run) 준비(prepare) 커널 단계**에서 수행됩니다."
- **WorkspaceList.tsx After**:
  - `statusConfig['provisioning']`: `프로비저닝 중 (Provisioning)` (색상: warning)
  - `wsp.targetNodeId`: `null`일 때 `미할당 (Unassigned)` 표기.
  - `workspaces.length === 0`: `data-testid="workspaces-empty-state"`, `role="status"`, "등록된 작업공간이 없습니다 (정상 조회 결과: 0개)" 표출.

### ③ Priority 3: 자연어 뷰 가상 KPI 99% 달성 합성 및 허위 성공 배너 치유
- **NaturalLanguageRunView.tsx After**:
  - 상단에 `data-testid="agent-unexposed-notice"` (`role="status"`):
    > "ℹ️ 자연어 에이전트 실행 및 골든 평가 제어기 (API 미노출). 현재 SaintVision 백엔드에는 자연어 에이전트 자율 실행 및 코드 diff 자동 패치 엔드포인트(/v1/agent/*)가 배선되어 있지 않습니다. 아래 표시된 수치는 백엔드 실측 관측치가 아닌 AC-09 클라이언트 테스트 픽스처 모의 수치입니다."
  - KPI 카드 라벨: `Prompt 100건 유효율 (AC-09 픽스처)`, `목표: ≥99% (로컬 시뮬레이션)`
  - 코드 Diff 적용 액션: "🎉 코드 Diff가 성공적으로 승인 및 적용되었습니다!" 허위 배너를 제거하고, "ℹ️ 코드 Diff 모의 적용 완료: 백엔드 코드 패치 API가 미노출 상태이므로 실제 작업공간 파일시스템에는 기록되지 않았습니다." 고지로 교체.
