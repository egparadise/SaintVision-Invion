## 실행 공백과 CI 경계

- **현재 임시 공백:** GitHub Actions는 결제 제한으로 실제 실행이 차단돼 있다. 따라서 지금은 담당자가 수동으로 Python route/source guards, Vitest/schema suite, 필요한 DB/browser lane을 각각 실행하고 SHA와 결과를 함께 남겨야 한다. 프런트 전용 Vitest green을 전체 프런트/backend 경계 검증으로 읽으면 안 된다. 이번 EvidenceViewer 가드는 Claude가 Python 전체 회귀에서 발견했고 focused 실행에서도 실패했다.
- **CI가 열리면 자동으로 줄어드는 공백:** 현재 YAML상 `backend.yml`과 `core.yml`은 일반 pytest를 돌려 `test_route_coverage.py` 및 `test_vf_canonical.py`를 수집한다. `frontend.yml`은 Vitest 및 generated contract/build checks를 돌린다. `desktop-browser.yml`은 real-browser/browser-proxy 시험을 별도 lane에서 실행한다. 그러므로 프런트 source guard가 “frontend job에서 안 돈다”는 구조는 남지만, 통합 SHA마다 backend job도 성공적으로 실행되면 CI가 그 검사를 대신 실행한다.
- **CI만으로 증명되지 않는 것:** 로컬 변경 중간에 돌지 않은 시험은 CI 시작 전까지 신호를 주지 않는다. 또한 workflow가 실제 해당 SHA에서 실행·성공하기 전에는 YAML 배선이 있다는 사실을 실행 증거로 세지 않는다. PG/browser 전용 workflow의 예상 testcase와 no-skip gate도 실제 Actions 실행 전에는 준비 상태일 뿐이다.
