# 디스커버리 3대 빈 상태 분리, 운영자 자격 규칙 고지 및 DOM 돌연변이 실측 사살 보고

## 1. 개요 및 목적

Codex가 디스커버리 엔드포인트(`POST /v1/discovery/announcements`)에 테넌트 경계를 강화함에 따라, 인증된 principal의 tenant와 일치하는 자격증명을 부여받지 못한 미인가 노드의 안내 방송은 403(`AUTH_TENANT_SCOPE`)으로 엄격히 거부된다. 이로 인해 신규 설치 머신이 자격증명 없이 후보로 등록될 수 없으며, 현재 패브릭 디스커버리 후보 목록(`GET /v1/discovery/candidates`)은 0대로 조회된다.

본 작업은 사용자의 승인된 트랙 지침에 따라, 프런트엔드(`ResourceExplorer.tsx` Tab 5 `discovery`)에서 후보 노드가 표출되지 않는 상황을 **세 가지 서로 다른 독립적 비-후보 상태(3대 빈 상태)**로 엄격히 분리(Tri-Partition)하고, 왜 현재 후보가 비어 있는지에 대한 **시스템 아키텍처 규칙(운영자 CLI `saint operator issue-grant` 자격증명 필수 요건)**을 운영자에게 정직하게 고지하는 화면 UX를 확립했다. 아울러 이 3대 상태가 상호 배타적으로 유지되고 임의의 상태 축소가 발생하지 않도록 DOM 단위 테스트를 작성하고 3대 돌연변이 실측 사살(KILLED)을 완결했다.

## 2. 디스커버리 3대 빈 상태 분리 (Discovery Empty-State Tri-Partition)

`ResourceExplorer.tsx`의 디스커버리 탭(Tab 5)에서 다음 3가지 상태를 완벽히 격리하여 렌더링하도록 정합했다:

```
+-----------------------------------------------------------------------------------------+
|                                Discovery Screen State Space                              |
+-----------------------------------------------------------------------------------------+
|                                                                                         |
|  [State 3: 세션 테넌트 미식별 차단 (Session Tenant Missing Barrier)]                      |
|   - 조건: (!tenantId || !tenantId.trim())                                               |
|   - UI: data-testid="discovery-tenant-required-notice"                                  |
|   - 동작: 안내 방송 전송 버튼 disabled, 클릭 시도 시 네트워크 0회 호출 가드 (0 network calls)  |
|                                                                                         |
|  [State 2: 디스커버리 서비스 연결 실패 (Query Failure Banner)]                             |
|   - 조건: candidatesState === 'error' (500, 503, 네트워크 단절)                          |
|   - UI: role="alert" data-testid="discovery-error-banner" & discovery-retry-btn         |
|   - 동작: 이전 잔여 후보 및 조작 버튼 완전 소거, 빈 상태 안내 배너 억제                     |
|                                                                                         |
|  [State 1: 정상 조회 빈 상태 (Clean Zero Candidates with Architectural Rule Notice)]    |
|   - 조건: candidatesState === 'success' && candidates.length === 0                      |
|   - UI: data-testid="discovery-empty-state"                                             |
|   - 내용: 1) 승인 대기 중인 디스커버리 후보가 0대임을 명시                                    |
|          2) 시스템 아키텍처 규칙 고지: saint operator issue-grant 일회용 자격증명 요건       |
|          3) 신규 머신 부트스트랩 및 안내 방송 수신 대기 중 / 새로고침 재조회 안내            |
|                                                                                         |
+-----------------------------------------------------------------------------------------+
```

### 2.1 State 1 (정상 조회 빈 상태: Clean Zero Candidates)
- **발생 조건**: 백엔드 API(`/v1/discovery/candidates`) 호출이 성공(`candidatesState === 'success'`)했으나 후보 배열이 비어 있는 경우(`candidates.length === 0`).
- **DOM 식별자**: `data-testid="discovery-empty-state"`
- **표출 내용 및 정직성 원칙**: 가상의 대기 상태나 유령 머신 관측을 날조하지 않고, **시스템 정본 아키텍처 규칙**을 투명하게 안내:
  - *헤더*: `ℹ️ 승인 대기 중인 디스커버리 후보가 없습니다. (0 Candidates Pending)`
  - *아키텍처 규칙 고지*: `후보 목록이 비어 있는 이유 (시스템 아키텍처 규칙): 테넌트 격리 및 무단 노드 오염 방지 정책에 따라, 운영자 CLI(saint operator issue-grant)를 통해 일회용 자격증명을 부여받은 노드만 디스커버리 안내 방송이 승인되어 목록에 나타납니다.`
  - *후속 행동 안내*: `신규 머신 부트스트랩 및 안내 방송 수신 대기 중 · 상단 '새로고침' 버튼으로 갱신 가능`
- **상호 배제**: 에러 배너(`discovery-error-banner`) 및 테넌트 미식별 경고가 존재하지 않아야 함.

### 2.2 State 2 (디스커버리 서비스 연결 실패: Query Failure)
- **발생 조건**: 백엔드 장애, 500/503 HTTP 오류, 네트워크 단절 시(`candidatesState === 'error'`).
- **DOM 식별자**: `role="alert" data-testid="discovery-error-banner"` 및 `data-testid="discovery-retry-btn"`.
- **정직성 원칙**: 서비스 실패를 캐시된 빈 상태나 가짜 정상으로 덮지 않으며, 에러 상세 메시지와 명시적 재시도 버튼을 제공.
- **상호 배제**: 빈 상태 안내문(`discovery-empty-state`) 및 잔여 후보 카드/승인 버튼이 화면에 결코 노출되지 않도록 전면 억제.

### 2.3 State 3 (세션 테넌트 미식별 차단: Session Tenant Missing Barrier)
- **발생 조건**: 인증 세션의 테넌트 식별자가 없는 경우(`!tenantId || !tenantId.trim()`).
- **DOM 식별자**: `data-testid="discovery-tenant-required-notice"`.
- **정직성 원칙**: "부를 근거가 없으면 부르지 않는다 (0-Calls Without Basis)". 임의의 테넌트 UUID를 합성하지 않고, 안내 방송 전송 버튼(`data-testid="broadcast-announcement-btn"`)을 `disabled` 처리하며, 클릭 시도 시 네트워크 요청을 1건도 보내지 않는 0-call 가드를 집행.

## 5. 운영자 CLI 완성 대비 연동 상태 (Operator CLI Readiness)

현재 디스커버리 화면은 빈 상태(State 1)에서 운영자에게 `saint operator issue-grant`를 통한 자격증명 주입 필요성을 명확히 인지시키고 있다. 향후 Codex 트랙에서 운영자 CLI(`saint operator issue-grant` 및 노드 부트스트랩 인가 절차)가 착지하여 노드가 유효한 자격증명으로 안내 방송을 송출하면:
1. 백엔드 `/v1/discovery/announcements`가 201 수락 처리되고,
2. 프런트엔드의 상단 `새로고침` 버튼(`discovery-refresh-btn`) 또는 주기적 폴링을 통해 `/v1/discovery/candidates`에 신규 행이 반환되며,
3. `ResourceExplorer.tsx`가 State 1(빈 상태)에서 실시간 후보 목록 카드(`candidatesState !== 'error' && candidates.length > 0`)로 부드럽게 전이되어, 일회용 부트스트랩 토큰 발급(`handleAdmitCandidate`) 및 노드 거절(`handleDeclineCandidate`) 기능이 즉시 활성화된다.
