## 새 지적

- **B7-M1 (MEDIUM): CANCEL과 RECEIPT_OBSERVE의 continuation 정책.**
  - 문제: 모델은 두 kind에 TERMINAL_FRAME의 `_parent_current`를 그대로 적용한다. 이 조건은 QUARANTINE/RETIRE fact가 없고, lease와 notAfter가 살아 있고, workload가 활성일 것을 요구한다.
  - 72028 동작: `snapshot(observation_only=True)`(node_channels.py:124-139)는 containment 검사와 online/heartbeat 검사를 건너뛴다. dispatch.py:166-184는 start authority를 잃은 뒤에 cancel을 선택하고, 이때 lease는 receipt가 올 때까지 유지한다.
  - 반례: C1/C2(QUARANTINE, lease 만료 상태의 CANCEL)와 C3/C4(같은 조건의 RECEIPT_OBSERVE)가 모두 거부된다. 대조군 C5(offline)와 C6(parent UNCERTAIN)은 허용된다.
  - 영향: 격리되었거나 lease가 만료된 run은 OP 물리 복구로만 끝난다. 이는 B6-M1이 막으려던 일상적 operator escalation이고, 공유 procedure를 통해 plain 동작도 바뀐다.
  - 해결: kind별 continuation 표를 둔다. CANCEL/RECEIPT_OBSERVE는 정확한 parent/command/identity/epoch/generation/C/DER와 observe scope를 요구하되, DRAIN·QUARANTINE·offline·lease 만료에서도 허용한다. claim은 원래 terminal receipt까지 유지한다.
- **B7-M2 (MEDIUM): critical 21개의 missingPorts 757건이 분석 의무와 진짜 port를 구분하지 않는다.**
  - 규모: 646건(85%)이 분석 전용이다. 대표 항목은 기존 source 타입(DomainError 등 153건), 이미 기록된 DB 호출 결과의 `.fetchone`(132건), builtin method, jsonschema/x509 같은 라이브러리, ContextVar, SQLAlchemy builder다.
  - 진짜 인터페이스: external IO 32, 주입 runtime 36, getattr 22, DB 접속/role 14, DI 3, DB function 2, SQL scope 1.
  - 7개 entry는 진짜 의존이 0이다.
  - Root가 요구한 `runtime(state)` 반환 owner는 아직 해소되지 않았다. `from lan_pilot import runtime` 4곳이 미해소이고, 그 때문에 `NodeChannels.snapshot:125` → `deliver`가 묶여 있다.
  - constructor 주입 join은 parameter 이름에서 멈춘다. 그래서 `self.db.transaction` 92곳이 미해소다.
