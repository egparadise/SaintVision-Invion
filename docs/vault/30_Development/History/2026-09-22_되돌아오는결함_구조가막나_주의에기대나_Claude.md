# 되돌아오는 결함 — 구조가 막나, 주의에 기대나

EvidenceViewer 가짜 PASS는 예전에 고쳤고(`5630d1fc`) 가드까지 만들었는데(`341c0350`) 오늘 되돌아왔다(`597ef148`), 그리고 다시 고쳐졌다(`0b7d51ed`, 재검증 GREEN). **가드는 있었는데 그 가드를 돌리는 사람이 없었다**(파이썬 시험인데 화면 레인이 안 돌림). 그래서 두 가지를 봤다. (재검증 초록 확인 후 작성 — 순서상 이게 나중.)

## 판단 기준
- **되돌아오기 쉬움 = 주의 의존**: 고침이 작고, 지키는 것이 사람의 주의뿐. 되돌려도 **조용하다**(아무 게이트도 안 움).
- **안 되돌아옴 = 구조 강제**: 되돌리면 **타입이 막거나 시험이 죽거나 게이트가 운다.**
- **3번째 범주(오늘 드러남): 가드는 있으나 소유자 레인이 안 돌리는 것.** 구조가 있어도 실행되는 레인에 없으면 주의 의존과 같다. (장치가 몇 개인지 셈은 Codex.)

## Part A — 오늘 고친 것 가르기
### 구조가 막는 쪽 (되돌리면 시험이 죽음)
- **response_model 앵커 결속**(Codex contribution lifecycle·workspace tool·저위험 7·write-response): `test_all_low_risk_write_routes_keep_their_response_model_anchor`가 부착을 단언 → 떼면 **시험 죽음**. 고위험은 무효 주입→500. **좋은 형태.**
- **계약 fixture 유효성**(노드 fixture `active`): 스키마가 tight인 한 틀린 fixture는 계약시험에서 **죽음**(impossible `"online"`이 그렇게 잡힘). 단 **스키마 tight 유지가 전제**(아래).

### 주의에 기대는 쪽 (되돌리면 조용함) — 다음에 되돌아올 자리
- **⚠ 내 계약 좁힘 자체(str→Literal): node·workspace·contribution status/mode.** 다시 `str`로 풀면 **완전히 조용하다** — export --check·contracts:check·계약시험 모두 통과(str이 다 받음), tsc는 잡을 죽은 분기가 없음. **"이 필드는 Literal이어야 한다"를 단언하는 게이트가 없다.** 죽은-분기 보호는 tight일 때만 있고 tight 유지를 강제하는 것은 없다. → **EvidenceViewer와 정확히 같은 모양(작은 고침+주의만).** rule 7의 산출물이 rule 7이 경고한 함정에 스스로 놓임.
- **조용한 강등 정직화**(Gemini nodeObservation active→unknown): unknown-not-fake를 단언하는 vitest가 없으면 주의 의존. (Gemini 레인 — 가드 시험 유무 확인 권고.)
- **canon 규칙(rule 7·예외·축)**: 문서라 본질상 사람이 읽어야 적용.

**구조화 후보(전부 지금 할 값어치는 아님, 짚어둠)**: 가장 값진 하나 = **응답 필드 타입을 원천 도메인(DB CHECK 등)에 묶는 검사**(rule→검사) — "폐쇄 도메인인데 str로 둔 응답 필드"에 게이트가 울게. 그러면 내 좁힘 셋이 주의→구조로 넘어가고 모양을 **한 파일이 아니라 전 모델**에서 덮는다.

## Part B — EvidenceViewer는 한 번짜리인가 부류인가 : **부류다**
- **확정된 같은-자리 재발**: 가짜 PASS = `5630d1fc` 고침(+`341c0350` 가드) → `597ef148` 되돌아옴 → `0b7d51ed` 재수정. 1건 확정.
- **모양이 부류라는 증거**:
  1. **정직성 스캐너가 5→7 규칙으로 반응 성장**(`5ea8ba32`→`995f7cf5`) = 같은 fake-value 모양이 **새 파일로 계속 새서** 규칙을 자꾸 덧댐.
  2. 여러 파일 반복 제거: `a9294bce`(ResourceExplorer fake mock)·`2a51c703`(lineage fake score)·`c6dc9156`(priority6 fake fallback)·`cc504c6e`(storage mock)·`e7cbc51f`(placeholder id).
  3. 오늘 밤도 같은 family: nodeObservation·workspaceEdit 조용한 강등.
- **왜 되돌아오나(고치는 방식의 문제)**: 스캐너(맞는 레인·게이트)의 tri-state/verified 규칙(Rule 4·5)은 **컴포넌트 지정** — 스캐너 자체 한계 #3: "Rule 4는 `InvFileExplorer`만, Rule 5는 `ResourceExplorer`만 검사." **EvidenceViewer는 지정 밖**이라 스캐너 0위반 통과하는데도 가짜 PASS를 담았다. 그 가드는 대신 **파이썬 시험**(test_route_coverage)에 있었고 화면 레인은 파이썬을 안 돌린다. **즉 가드가 (a)모양이 아니라 파일을 겨냥하거나 (b)소유자가 안 도는 레인에 있어서, 새 파일로 샌 같은 모양을 아무도 안 잡는다.**
- **결론**: 이 프로젝트는 **같은 모양(가짜 초록·가짜 PASS·조용한 강등)을 여러 번, 여러 파일에서** 고치고 있다. 한 번짜리 사고 아님. 고치는 방식의 문제 = 가드가 **모양을 전 파일에서, 소유자 레인에서** 덮지 않고 파일별·타 레인에 흩어짐.
