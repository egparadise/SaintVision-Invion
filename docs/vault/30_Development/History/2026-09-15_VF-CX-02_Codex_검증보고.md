# VF-CX-02 모델 무결성 검증

## 작업한 것

ModelManifest/Shard/Replica schema 및 생성 Python/TS/Go, plaintext full-byte streaming verifier, 기존 DataLocation FK를 갖는 immutable model commit, 두 단계 current grant/Run/fence/epoch/catalog 검증을 구현했다. 새 0039_model_manifest는 0038 뒤에 추가했고 기존 migration 파일은 수정하지 않았다. 감사 정책은 기대 revision만 0039로 전진시키고 definer definition hash/권한 허용은 보존했다. 새 mdl/version URI를 추가하면서 legacy name@version 의미는 유지했다.

## 확인한 것

- Windows Python 3.14 + 임시 PostgreSQL16: model commit/definer/URI/contract/경계 66 passed, 0 failures/errors/skips, exit 0. 실제 파일 사용, Node 실행 상태는 커널 transition으로 만든 fixture이며 실장비 실행 주장은 아니다.
- Linux Python3.12 + 내부 Docker network/신규 PG16: model commit/definer/기존 migration 업그레이드 49 passed, exit 0, cleanup 성공. 0037/0038 출발 시 실제 Lease 행 및 fencing sequence를 만들어 head 업그레이드/replay 후 그대로 보존됨을 검사했다.
- missing/stale/expired fence, 취소·Run version·grant·epoch·catalog/root version·Node offline 변경을 file I/O 사이에 넣어 commit 거부 확인. 동시 같은 key는 manifest/outbox 하나, 다른 key의 같은 version은 충돌, 손상/누락/초과 파일은 불가.
- 다른 tenant SELECT 0, unauthorized read 거부, runtime 직접 DELETE 거부, 참조된 DataLocation DELETE FK 거부. mutation 중 기존 Lease를 임의 반환하지 않음.
- TypeScript strict tsc exit 0; Go contracts와 Node wire compile exit 0 (해당 패키지는 test files 없음). 문서/ontology/19 export schema 검사 exit 0. 생성 계약은 동일 Schema에서 출력.
- 초기 migration의 Python 문자열 delimiter 때문에 SQL quote가 손상된 문제와 잘못된 fixture 상태전이를 실제 실패로 확인하고 수정했다. DB guard를 제거하거나 migration history를 바꾸지 않았다.
- JSON 증거: Evidence/vf-cx-02/windows-model-security.json, linux-model-upgrade.json. Linux 결과는 base SHA+dirty=true+정확한 sourceHashes이며 commit 후 delivery SHA를 덧붙인다.
