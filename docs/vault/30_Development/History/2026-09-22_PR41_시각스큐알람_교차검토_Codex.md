## 판정

**수정 요청.** 실행 판정과 라우팅은 정합하지만, accepted 규격이 실제 구현을 "동일 함수가 제어하므로 어긋날 수 없음"으로 잘못 기술한다. 현재 값이 같다는 사실과 앞으로도 구조상 어긋날 수 없다는 보장은 다르므로, 정본 문서의 이 모순을 병합 전에 고쳐야 한다. PR 코멘트: https://github.com/egparadise/SaintVision-Invion/pull/41#issuecomment-5773731159

## 1. 커널 가드와 알람 판정

- `inv.scheduler`는 `clock_skew_seconds is None`, 비유한 값, `abs(value) > 5`를 `clock_unmeasured_or_skewed`로 제외한다.
- `inv.leases`, `inv.dispatch`, `inv.containment`, `inv.tooling`은 SQL의 `abs(clock_skew_seconds) <= 5`를 readiness 조건으로 둔다. SQL `NULL`은 조건을 만족하지 않고, 비유한 numeric의 절댓값도 `<= 5`를 만족하지 않는다. `inv.placement`는 scheduler 후보 판정을 소비한다.
- `tools/alarm_check.py::skew_outside_limit`는 `None`·비유한 값·`abs(value) > 5`를 outside로 판정한다. `evaluate()`는 `status='online'` 행만 넘기므로 offline 노드는 제외된다. 정확히 `-5`, `5`는 quiet이고 `5.0001`, `-5.5`는 firing이다.
- 따라서 현재 런타임 값과 경계는 정합하고 같은 원인에 대한 별도 중복 알람도 추가되지 않았다. Node 이탈 알람은 heartbeat 지연, 시각 스큐 알람은 online 노드의 스큐/미측정을 다루므로 조건과 설명이 구분된다.

### 수정 요청 근거

`ERR-DESIGN-007` v2.0.0 제4조 2항은 커널 가드와 알람이 **동일한 함수** `tools/alarm_check.py::skew_outside_limit`로 제어되어 어긋날 수 없다고 단언한다. 실제 커널은 scheduler의 Python 술어와 여러 파일의 인라인 SQL 술어를 사용하고, 알람만 별도 `CLOCK_SKEW_LIMIT_SECONDS`와 `skew_outside_limit`를 사용한다. 도구 주석도 알람 상수를 바꾸면 커널과 불일치한다고 명시한다. Claude 구현 이력의 "경계가 한 곳에만 산다/어긋날 수 없다"도 같은 과장이다. 정본을 "독립 미러이며 드리프트 가능"으로 정정하고 양쪽 계약을 함께 고정하는 검증을 두는 것이 필요하다.

작은 인용 오류도 있다. `clock_skew_alarm` docstring의 발화/해제 근거는 제4조 3항/4항으로 적혔지만 실제 v2.0.0에서는 제4조 2항/3항이다.

## 2. 라우팅·규격 정합과 문서 정직성

GOV-ALERT-001 v1.1.0과 ERR-DESIGN-007 v2.0.0은 `Node 시각 스큐 한도 초과`, P2, 인프라 1차, Backend 백업, 기록 채널, 자동 조치 없음, 재알림 없음, 다음 평가에서 자동 해제라는 점에서 일치한다. 채널과 실제 수신자는 계속 `unknown`이며 도구는 전달기가 아니라 평가기라는 한계를 명시한다.

ERR 문서 아래쪽의 옛 `governance-gated` 판정은 제목에 `채택 전 기록`이라고 명시되어 현재 상태를 가장한 허위 완료 표현으로 보지 않았다. 구현 이력도 실 PostgreSQL 시험과 파일럿 실장비 미검증을 구분한다. 다만 위 "동일 함수" 서술은 이력 표지가 아니라 현재 accepted 조항의 사실 오류이므로 차단 finding이다.
