## 설계 원칙 하나 — 기록이 일어난 것보다 더 주장하지 못하게

여기의 모든 제약은 같은 규칙이다.

### 목표와 측정은 다른 컬럼이다

`target_rpo_seconds`/`target_rto_seconds`와 `measured_rpo_seconds`/`measured_rto_seconds`를 분리했다. 계획의 RPO 15분·RTO 1시간은 **목표**이고 훈련은 **측정**한다. 하나로 두고 둘 다라고 부르는 것이 목표가 조용히 결과가 되는 방식이다.

`met_targets`는 호출자가 주는 값이 아니라 측정값에서 계산하고, CHECK 제약이 숫자와 어긋나는 플래그를 거부한다. **복원은 성공했는데 시간을 초과한 훈련은 pass로 기록되고 목표 미달로도 기록된다.** 목표를 측정값에 맞춰 고쳐 쓰는 것이 파일럿이 갖지 않은 성공을 보고하는 방식이다.

### 복구 훈련은 fencing을 확인해야 통과한다 — 제 검토 지적을 강제로

[[ERR-DESIGN-006 백업 복원이 fencing 단조성을 파괴]]는 제가 HO-DOC-CLAUDE-001 교차 검토에서 제기했고 **아직 Codex의 ADR 판단 대기**다.

PITR 복원은 fencing sequence를 되감지만 **토큰을 받아 간 Node Agent는 DB 밖이라 함께 되감기지 않는다.** 복원 후 정상 명령을 stale로 거부하거나, 반대로 오래된 토큰을 다시 수락한다.

그래서 `scope='database'` 훈련은 `fencing_verified` 없이 pass할 수 없게 했다. 서비스가 거부하고 DB CHECK도 거부한다. **미결 설계 질문은 성공 주장을 막아야지 조용히 가정되면 안 된다.** 검토 지적이 문서에 남는 것과 코드가 강제하는 것은 다르다.

`scope='workspace'`는 이 검사를 요구하지 않는다 — fencing 문제는 sequence 자신의 DB를 복원할 때만 생긴다.

### 그 밖의 거부 규칙

| 규칙 | 이유 |
|---|---|
| pass에 측정값 필수 | "잘 됐다"는 정량 목표의 증거가 아니다 |
| pass에 checksum 검증 필수 | 데이터가 **있는 것**과 **맞는 것**은 다르다 |
| failed는 측정값 없이 기록 가능 | 실패도 결과이고 기록 가능해야 한다 |
| `off_site`는 경로에서 추론하지 않고 별도 컬럼 | ADR-018이 로컬 durability와 장애 영역 밖 복구를 구분한다. 보호 대상 옆에 있는 백업이 그 구분이 존재하는 이유다 |
| checksum 불일치 1건이면 폴더는 unhealthy | **손상된 바이트는 멀쩡한 바이트에 표결로 지지 않는다** |
| 한 달 전 healthy + 이후 미점검 = 주의 필요 | 실패한 것과 운영상 같은 의미다 — 지금 아무도 모른다 |
| conditional 인수에 제한사항 필수 | 없으면 그냥 인수에 헤지를 입힌 것이다. AC-12가 "알려진 제한" 기록을 요구한다 |
| 인수자는 `users` FK | **시스템이 자기 인수에 서명할 수 없다** |
| 인수는 본 manifest 해시를 고정 | "R4를 인수"하고 구성이 다른 R4를 내보내는 것을 막는다 |

### pilot_readiness는 판정이 아니라 공백을 돌려준다

무엇이 기록되지 않았는지를 `blockers`로 반환한다. 파일럿이 좋은지 판정하지 않고 **보여줄 수 있는지**만 본다. `knownLimitations`를 초록 플래그에 흡수시키지 않고 계속 보이게 두고, **통과했지만 목표를 못 맞춘 훈련**도 별도로 보고한다.
