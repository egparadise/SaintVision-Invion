# 부류 훑기 — 느슨한 계약 열거가 가린 화면 죽은 분기

오늘 결함(WorkspaceSummaryResponse.status를 `str`로 둬서 화면이 계약이 못 내는 `'active'`에 분기 = ready가 회색)이 **한 건인가 부류인가**를 훑었다. 방법: 응답 계약의 느슨한 열거-후보 필드(열거로 좁힐 수 있는데 plain `str`) 전수 + **각 필드마다 화면이 그 값으로 무엇을 하는지**(계약 참 도메인 밖 리터럴에 분기하는가). 참 도메인은 DB CHECK를 정본으로 삼았다. 훑기만 했고 고치지 않았다.

## 결과 요약
- **부류는 외톨이가 아니다.** 같은 병의 **두 번째 사례 발견 = 노드 status**(아래 §A). 오늘 workspace보다 피해가 크다(색 하나가 아니라 노드 헬스 표시 전체).
- 나머지 느슨한 필드 8종은 **결함 아님**(§B에 하나씩): 화면이 도메인 **안** 값에만 분기하거나(contribution·run state), 아예 분기 안 함(kind·role·project status·readiness check·admission.next).
- 공통 뿌리(§C): 프런트가 백엔드 계약보다 **풍부한 status 어휘를 상상**한다(WorkspaceItem에 active/terminating/reclaimed, NodeStatus에 online/degraded/offline). 계약엔 없는 값이다.

## §A 발견 — 노드 status 어휘 불일치 (오늘과 같은 부류, live 실결함)
- **계약(내 레인)**: `NodeResponse.status: str`(느슨). `_node_body`가 `node.status`를 **raw DB 값 그대로** 낸다. DB CHECK(`0001_s02_baseline.py:176`) = `{enrolling, active, draining, lost, retired}`. 서비스가 실제로 `status="active"` 설정(`services/nodes.py:120`), `mark_lost`로 `lost` 설정(`:305`). 즉 **정상 가동 노드 = `active`, 죽은 노드 = `lost`.**
- **화면(Gemini 레인)**: `NodeStatus = 'online'|'degraded'|'offline'|'draining'|'enrolling'|'retired'`(`contracts/types.ts:33`). `App.tsx:130`이 `/v1/nodes`(NodePageResponse 계약)를 받아 `observedNode`로 매핑. `observedNode`(`shared/api/nodeObservation.ts`)는 raw.status가 그 6-집합이 아니면:
  - `status → 'enrolling'`으로 강등, `telemetryUnavailable → true`, `schedulable → false`.
- **불일치 두 방향**:
  1. 계약이 내는 `active`·`lost`가 `NodeStatus`에 **없다** → **정상 active 노드가 영구 `enrolling`·텔레메트리 없음·스케줄 불가로 표시**된다. lost 노드도 enrolling으로 표시.
  2. 화면이 기대하는 `online`·`degraded`·`offline`을 백엔드가 **어디서도 안 낸다**(전 src grep: 노드 status로 online/offline 0건, `degraded`는 app.py:163 파티션 헬스로 노드 아님). → NodeList:185/187·NodeDetail:205-209·ClusterOverview:202/504·ResourceExplorer:186·ModelStudioView·InvFileExplorer:289의 `status==='online'/'degraded'` 분기는 **실데이터로 도달 불가**(healthy 초록 포함).
- **오늘과 같은 부류**: 화면이 계약이 못 내는 값에 분기. **다른 점**: `observedNode`가 의도적으로 `object`(계약 타입 아님)를 받아 "legacy row와 NodeResponse 둘 다" 처리하므로 **tsc로는 안 잡힌다**(NodeResponse.status를 좁혀도 매퍼가 타입을 우회). 그래서 오늘처럼 좁혀서 드러나는 게 아니라 **매퍼 읽기+DB 도메인+백엔드가 online/degraded/offline 미발행+서비스가 active 설정 확인**으로 잡았다.
- **고침(사용자 지시대로 다음 단계)**: 어휘 결정 필요 — (a) 백엔드가 heartbeat 신선도로 계산한 liveness(online/degraded/offline)를 별도 노출할지, 아니면 (b) 프런트가 계약 어휘(active/lost/...)로 표시를 맞출지. 결정 후: 백엔드 절반=`NodeResponse.status`를 `Literal[enrolling,active,draining,lost,retired]`로 좁힘(내 레인, DB CHECK와 일치, 계약 명시화); 프런트 절반=`NodeStatus`/`observedNode` 어휘 정합(Gemini). **cross-lane 설계 결정이라 이번 턴엔 고치지 않음.** 노드 파일은 Codex의 저장소/다운로드와 겹치지 않음.

## §B 결함 아닌 느슨한 필드 (하나씩 — "없으면 없다고 적어라")
- `ContributionResponse.status`({pending,active,revoked}): ResourceExplorer `status==='active'` = 도메인 안. 결함 아님. (`StorageObservationView.status`의 `'recorded'`는 다른 계약, {pending,expired,recorded} 안이고 매퍼가 도메인 밖이면 **throw**로 거부 — 죽은 분기 아님.)
- `ContributionResponse.mode`({read_only,read_write}): `mode==='read_write'` 도메인 안. 결함 아님.
- `DataLocationResponse.kind`({dataset,model,artifact,workspace}): 프런트에 `.kind ===` 분기 **없음**. 느슨하나 무해.
- `ProjectListItemResponse.status`/`ProjectCreateResponse.status`({active,archived}): `projectObservation`이 status를 **버림**(ProjectItem에 status 없음), 분기 없음. 무해.
- `MemberRoleResultResponse.role_code/project_status/user_status`: 프런트에 해당 분기 **없음**. 무해.
- `ExecutionReadinessCheckResponse.check`: `.check ===` 분기 **없음**(그대로 렌더). 무해.
- `DiscoveryAdmissionResponse.next`: `.next ===` 분기 **없음**. 무해.
- `DiscoveryCandidateResponse.claimed_os_type`: **의도적 느슨**(자기보고·미검증, 화면이 claimed/unverified로 표시). 결함 아님.
- (참고) 저장소 계약 2종은 Codex 활성 영역이라 **읽기만** 했다. 위 판정은 소스 열람 기반.

## §C 공통 뿌리와 권고
- 병: **프런트가 계약보다 풍부한 status 어휘를 상상**한다. `WorkspaceItem.status`(types.ts:93)는 아직 `active|terminating|reclaimed|string`을 나열(오늘 고친 건 화면의 계약-타입 비교였고, 이 UI 타입의 잉여 어휘는 지금 아무것도 분기 안 하는 **휴면 어휘** — 정리 권고). `NodeStatus`는 online/degraded/offline을 나열(§A, 활성 피해).
- 권고 순서(고침은 사용자 지시 후): ①노드 어휘 결정(§A) — 활성 피해라 우선. ②휴면 어휘 정리(WorkspaceItem 잉여 멤버 제거, Gemini). ③선택: 계약 명시화로 `NodeResponse.status` 좁힘(내 레인). 검토에서 남겨둔 경미 잔여 2건(미결속 쓰기 raw dict, activation/revoke 비대칭)은 지시대로 **보류**(Codex 파일과 겹침).
