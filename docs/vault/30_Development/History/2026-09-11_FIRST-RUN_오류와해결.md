# FIRST-RUN 오류와 해결

- 기존 첫 업무 검증은 recovering Run과 과거 checkout을 미리 구성했다. 새 draft 입력·startId·attempt 1·실제 결과 checkpoint 경로를 구현했다. 기존 recovery 계약은 별도로 유지한다.
- 작업 중 최초 17개 시험은 통과했고 업무 연결 추가 검증은 18개 통과 뒤 시험 코드에서 실패했다. `count` helper는 inv schema 전용인데 public.workspace_edit_locks를 조회하려 해 UndefinedTable이 발생했다. 실제 업무 실행은 성공한 상태였고 fixture의 조회를 public schema로 수정한 뒤 최초 실행/업무 연결 41개가 통과했다.
- 승인 소비를 별도 호출하면 예약/queue와 분리될 수 있는 첫 실행 경계를 발견했다. 첫 실행에는 원자 admission 표시가 있는 내부 트랜잭션만 approval dispatch/Lease/claim을 수행하도록 보완하고 별도 호출 거부를 시험했다.
- Node·CPU/메모리 자원 ID·profile/policy 버전을 승인 입력에 고정했다. 승인 후 runtime/권한/제공량 변경은 rollback한다.
- 일부 조회에서 존재하지 않는 src/inv·tests/unit·시험 파일명을 지정해 읽기 명령이 실패했다. 실제 파일 목록을 확인해 정정했으며 사용자 파일 변경은 없었다.
- 확정 코드 b6301a9의 통합 159개·core 260개·Windows Go는 통과했다. GitHub build 3개는 모두 계정 결제/spending 제한으로 job 시작 전 차단됐다. 계정 변경이나 반복 재시도 없이 CI API 원문을 공개 Evidence로 보존했다.
- 외부 Obsidian 인덱스 변경 때문에 최초 sync check가 충돌을 반환했다. Gemini 정정 보고와 인덱스 원문을 first-run-sync-proposals.json에 보존하고 실제 코드 3e671e7을 검토했다. 보고 범위 정정 및 일부 수정은 확인했고 남은 3개 P1/배포 P2를 별도 기록했다. 보존 SHA 일치를 확인한 해당 인덱스의 sync 기준만 갱신해 최종 328개 hash 일치/충돌 0을 확인했다.

private 원문 로그에는 합성 DB credential/JWT가 포함될 수 있어 접근 제한된 `.work/sv-kernel-6edc4fda3d6a/runs/0da18ba0705e`에 보존했다. 공개 문서에는 결과·코드/이미지/출력 hash를 사용한다. CI·sync 및 확정 SHA의 결과는 [[2026-09-11_FIRST-RUN_Codex_검증보고]]에서 기록한다.
