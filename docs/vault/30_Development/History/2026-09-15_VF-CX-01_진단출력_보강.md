## 작업한 것

- import/factory/probe 예외의 원문과 readiness/bearer 응답 본문을 Evidence에서 제거했다. readiness는 허용된 status만, 임의 bearer 성공은 HTTP status와 byte 수만 기록한다. 위험 판정은 유지한다.
- 후보 앱의 Python stdout/stderr를 devnull로 보내 CLI JSON 오염과 로그 유출을 차단했다. 이는 subprocess/native 출력까지 통제하는 OS sandbox가 아니며 신뢰하지 않는 임의 프로그램을 안전 실행한다는 뜻이 아니다.
- readiness 부가 필드의 문자열 ready를 실제 ready 상태로 오인하지 않는다. probe 예외/5xx는 점검 성공으로 처리하지 않는다.
- `--dockerfile --json`은 설명 배너 없이 단일 JSON 문서를 출력한다.
- 점검 중에만 INV 설정을 제거하고 finally에서 원래 환경을 복원한다. 후보가 추가한 INV 설정도 제거하여 후속 통합 시험의 DB 설정을 보존한다. 이 진단 API는 동기 CLI용이며 같은 프로세스의 병렬 운영 요청에서 사용하지 않는다.
