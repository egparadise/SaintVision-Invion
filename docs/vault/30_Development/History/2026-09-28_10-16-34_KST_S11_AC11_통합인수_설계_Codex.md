# S11-BE·S11-DB AC-11 통합 인수 설계

## 결과

- S11-BE의 장시간·부하·security·rollback과 S11-DB의 migration·restore·SLO 집계를 하나의 fail-closed release evidence 모델로 설계했다.
- migration은 가역 revision의 `forward → downgrade → forward`와 비가역 revision의 `forward → verified snapshot restore → forward`를 분리했다. 현재 head `0046_model_manifest_readiness`는 비가역이고 reversible tail이 0개라, 기존 `target == head` 출력을 rollback PASS로 세지 않는다.
- restore는 PR #126 final-head Core run `36355139230`의 18 pass/2 honest skip을 disposable CX01 증거로만 재사용하고 실제 PITR·RPO/RTO로 승격하지 않는다. VF-CL-04 readiness·retention도 실제 복구와 분리하며 CX-09는 외부 결정 대기다.
- SLO는 run/head/artifact/환경/target commit을 고정하고 결과를 보기 전 목표를 등록한다. S05 run `36362386530`(#115 제품 tree)과 `36363327477`(clean integration compatibility)은 서로 다른 비교군으로 보존한다.
- hosted에서 가능한 migration/restore/합성 부하/정적 보안/E2E와 5노드·실장비가 필요한 PITR/물리 부하·복구/장시간 soak를 분리했다.
- Claude 독립 검토의 수정 요청을 반영해 verdict enum을 닫고, 필수 8축 allowlist와 집계기 재계산을 도입했다. 모든 축 `NOT_APPLICABLE`, 임의 `PASS`, 축 누락은 done이 아니라 `INVALID_RUN`/미완료다.
- 사전 등록 목표를 `d74e82ec`의 AC-05 P95 2초·RPO 15분·RTO 1시간·보존 35일에 결속했다. hosted 합성-node rung은 AC-05 참고값일 뿐 합격 판정이 아니며, VF-CL-04 7일과 35일의 불일치를 숨기지 않는다.
- migration에는 forward 후 sentinel, `lossy-reversible` 등급(0001~0007·0009·0010·0025 fixture), 기준 DB catalog fingerprint를 추가했다. security allowlist v0는 repo-native 3개 threat만 고정하고 dependency/static scanner 0건은 `NOT_OBSERVED`로 남겼다.
- 출처 PR #126/#148/#151은 모두 OPEN이며 artifact digest·만료·후보 evidence blob을 `Evidence/s11-ac11-source-baseline.json`에 고정했다. CX01은 run-specific committed JSON이 없어 만료 전 보존되지 않으면 `INVALID_RUN`이다.

## 정직한 현재 상태

구현·hosted 실행·실 PG·Docker·5노드·PITR은 수행하지 않았다. `S11-BE`, `S11-DB`, `AC-11`의 registry 상태는 `planned` 그대로이며, 실제 PITR·5노드·장시간·완전한 security/accessibility evidence가 없어 AC-11은 완료가 아니다.
