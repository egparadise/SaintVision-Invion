## 1. 작업 개요 및 배경

1. **지시 배경**:
   - 실브라우저 인수 시험(`tools/run_real_browser_acceptance.py` Invariant 6: line 1131-1150)에서 '트리거로 focus 복귀'(`focus_is_trigger`)가 PARTIAL로 관측되어 옴.
   - 원인: `DesktopShell.tsx`에서 시작 메뉴 및 알림 센터 드로어를 Escape 또는 닫기로 해제할 때, React 상태(`setIsStartMenuOpen(false)`)만 토글하고 호출 트리거 버튼(`button[aria-label="SaintVision 시작 메뉴"]`, `button[aria-label="알림 센터"]`)으로 포커스를 복원하는 로직이 누락되어 `document.activeElement`가 `<body>`로 유실됨.
2. **카드 174 수행 목표**:
   - (1) 대화상자·드로어·오버레이 닫을 때 트리거로 focus 복귀 결함을 `apps/web`에서 수정.

   - (3) 각 항목에 대해 되돌리면 실패하는(revert-fail / revert-kill) 단위/통합 시험 작성 및 게이트 검증.
   - (4) 측정 수집기/워크플로(`tools/run_real_browser_acceptance.py`)는 Codex 소유이므로 직접 수정하지 않고 필요한 측정 심(seam)을 명시적으로 인계 요청.

## 2. 결함 분석 및 해결 내역

### 2.1 트리거 포커스 복원 (`focus_is_trigger`) 및 포커스 트랩 치유
- **발생 원인**:
  - `DesktopShell.tsx` 내 시작 메뉴 dropdown 및 알림 센터 drawer 닫기 시 트리거 엘리먼트에 대한 참조가 유지되지 않았음.
  - React 렌더링 생명주기상 `setIsStartMenuOpen(false)` 호출 직후 동기적으로 포커스를 주더라도 자식 DOM 노드가 unmount되면서 포커스가 `<body>`로 리셋되는 브라우저 레이스 컨디션 존재.
- **해결 방안**:
  1. `startMenuTriggerRef` (`button[aria-label="SaintVision 시작 메뉴"]`) 및 `notifTriggerRef` (`button[aria-label="알림 센터"]`) 생성 및 바인딩.
  2. Escape 키 및 닫기 버튼 이벤트에서 동기적 포커스 복원(`startMenuTriggerRef.current?.focus()`)을 수행함과 동시에, React reconciliation 이후 확실하게 포커스를 보장하는 `useEffect` (`prevStartMenuOpenRef`, `prevNotifOpenRef` 상태 감지) 훅 추가.
  3. `DesktopShell.tsx`의 시작 메뉴 및 알림 센터 drawer 내부에 W3C WCAG 2.4.3 표준 Tab / Shift+Tab 포커스 트랩(첫 요소와 마지막 요소 간 순환) 구현.
  4. WAI-ARIA 규격 강화:
     - 시작 메뉴 버튼: `aria-haspopup="menu"`, `aria-controls="desktop-start-menu-dropdown"`, `aria-expanded={isStartMenuOpen}`
     - 시작 메뉴 컨테이너: `role="menu"`, `aria-labelledby="desktop-start-menu-trigger"`, `tabIndex={-1}`
     - 알림 센터 버튼: `aria-haspopup="dialog"`, `aria-controls="desktop-notification-drawer"`, `aria-expanded={isNotifOpen}`
     - 알림 센터 드로어: `role="dialog"`, `aria-modal="true"`, `aria-labelledby="desktop-notification-trigger"`, `tabIndex={-1}`
  5. `useModalA11y.ts`: 모달 닫힘 시 명시적 `triggerRef` 옵션을 허용하도록 `UseModalA11yOptions` 인터페이스 확장 및 unmount 시 안전한 포커스 복원 콜백(`restoreFocus`) 보강.

## 4. 검증 시험 및 되돌림 실패(Revert-Kill) 보증

신규 생성된 `apps/web/tests/desktop-shell-a11y.test.tsx`의 5대 시험:
1. `Start Menu: Escape key closes Start Menu and restores focus to trigger button (focus_is_trigger)`:
   - 시작 메뉴 오픈 후 Escape 입력 시 메뉴가 닫히고 `document.activeElement`가 `button[aria-label="SaintVision 시작 메뉴"]`로 복원됨을 검증.
   - 복원 로직을 제거할 경우 `document.activeElement`가 `<body>`가 되어 단언 실패 (Revert-Kill).
2. `Notification Center: Escape key closes drawer and restores focus to notification trigger button`:
   - 알림 센터 오픈 후 Escape 입력 시 드로어가 닫히고 `document.activeElement`가 `button[aria-label="알림 센터"]`로 복원됨을 검증.
3. `Notification Center: Close button (×) closes drawer and restores focus to notification trigger button`:
   - 알림 센터 닫기 버튼 클릭 시 포커스가 트리거 버튼으로 복원됨을 검증.
4. `Start Menu: Focus Trap cycles inside menu (Tab & Shift+Tab)`:
   - 메뉴 내부 마지막 요소에서 Tab 입력 시 첫 번째 요소로 순환, 첫 번째 요소에서 Shift+Tab 입력 시 마지막 요소로 순환함을 검증.
   - 포커스 트랩 로직을 제거할 경우 순환하지 않아 단언 실패 (Revert-Kill).
5. `useModalA11y: restores focus to explicit triggerRef when provided`:
   - 명시적 `triggerRef` 옵션 전달 시 언마운트/닫힘 후 해당 요소로 포커스 복원 검증.

## 6. 인계 및 측정 심(Measurement Seam) 요청 사항

- **Codex 인계 (측정 수집기 Invariant 6 승격)**:
  - `tools/run_real_browser_acceptance.py:1146`에서 이미 `focus_is_trigger`를 아래와 같이 측정하고 있음:
    ```python
    focus_is_trigger = bool(page.evaluate('() => document.activeElement && document.activeElement.getAttribute("aria-label") === "SaintVision 시작 메뉴"'))
    ```
  - 이제 `DesktopShell.tsx`의 트리거 포커스 복원 구현으로 인해 실브라우저 실행 시 `focus_is_trigger`가 `True`로 반환됨.
  - 따라서 수집기 소유자인 Codex 측에 `tools/run_real_browser_acceptance.py:1449`의 하드코딩된 `"triggerFocusRestored": False`를 `"triggerFocusRestored": focus_is_trigger`로 바인딩하여 Invariant 6을 PARTIAL에서 FULL PASS로 승격 반영해 줄 것을 요청함.
