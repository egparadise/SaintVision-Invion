# 공개 제안 스냅샷 DSN 비밀번호 마스킹

- 기준: `agent/codex/discovery-candidates-contract`, 시작 SHA `5d34adcc577c868f4717e1eeaa6fae7279afb719`.
- 사용자가 알려준 22개 추적 `proposal-3.txt`를 대조했다. 그중 14개에 같은 PostgreSQL DSN 비밀번호가 각각 두 번, 총 28회 들어 있었다.

## 전체 추적 파일 검색의 나머지 결과

현재 추적 파일에서 DSN 인증정보 형태를 찾는 정적 검색은 제안 14개 파일 28회 외에 18개 파일 27회를 찾았다. 그중 위 JUnit 2회와 runbook 1회는 실행 증거 또는 운영 절차여서 마스킹했다. 나머지 24회는 `.env.example`, 일회용 Postgres GitHub Actions 서비스, 테스트의 합성 DSN, 경로 경계 시험 및 `deploy_intranet.ps1`의 로컬 개발 기본값에 있다. 어느 것도 노출된 제안 비밀번호와 일치하지 않았다. 이 문자열들은 실행/시험 계약의 고정 입력이므로 이번 문서 증거 수정에 섞어 바꾸지 않았다. 특히 `.env.example` 및 로컬 기본값을 실제 운영 비밀번호로 재사용하지 않아야 한다.

이 검색은 알려진 PostgreSQL URI 인증정보 문법에 대한 현재 추적 파일의 정적 탐색이다. URI 형식이 아닌 임의 비밀번호, 런타임 secret store, 미추적 로컬 파일, Git 과거 이력 전체의 비밀 부재를 증명하지 않는다.

## 출처와 재발 방지

`git log --follow`에서 이 파일들은 자동 evidence 생성 도구가 만든 산출물이 아니라 외부 제안 및 Agent 보고를 보존한 문서 커밋으로 들어왔다. `tools/sync_obsidian.py`는 `docs/vault`를 목적지로 동기화할 뿐 proposal을 생성하지 않으므로 그 단계에서 원본을 자동 마스킹할 생성 경로는 없다. 앞으로 외부 evidence를 `docs/vault`에 편입하기 전에 credential scan을 거치도록 `tools/check_docs.py`에 문서 전체의 비밀번호 포함 PostgreSQL URI 거부 검사를 추가했다. GitHub Docs workflow도 이 검사를 실행한다. 회귀 시험은 실제 값 대신 합성 문자열과 `***` 마스크를 사용한다.

## 노출 한계 및 후속 판단

- 현재 파일에서 비밀번호를 가려도 공개 저장소의 이전 commit에는 원문이 남아 있다. 이 작업은 이력 재작성이나 저장소 공개 설정 변경을 하지 않았다. 과거 commit을 통한 취득 가능성은 끝나지 않았고, 복제된 사본 회수도 보장할 수 없다.
- DSN이 유효한지, 어느 데이터베이스에 접속되는지, 현재 권한이 살아 있는지는 확인하지 않았다. 값의 유효성은 비밀정보라 재현하거나 출력하지 않았다.
- 유효성 확인은 회전 결정을 미루는 이유가 아니다. DB 소유자가 대상·권한·운영 영향을 확인한 뒤 유효 가능성이 있으면 자격증명 회전, 연결 구성 갱신, 구 자격증명 폐기 및 접속 감사 로그 확인을 판단해야 한다. 이력 재작성은 이미 공개된 사실을 되돌리지 않으므로 별도 비용/노출범위 판단이다.
