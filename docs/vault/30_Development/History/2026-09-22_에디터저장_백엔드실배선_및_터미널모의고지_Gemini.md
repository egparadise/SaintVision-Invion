# 화면 결함 5대 부류 3차 치유 보고: MonacoWorkspaceEditor 커널 체크아웃 파일 저장 실배선, 인메모리 은폐 차단 및 PTY 모의 고지

## 1. 개요 및 배경

사용자의 5대 결함 부류 전수 점검 및 3차 치유 지시에 따라 `MonacoWorkspaceEditor`의 파일 저장과 PTY 시뮬레이션을 점검하고 정직한 운영 체계로 치유했다:
1. **파일 저장의 "캐시/로컬 은폐(False Persistence)" 결함 해소**:
   - 기존 에디터는 저장을 누르면 로컬 브라우저 상태만 갱신하고 "Save File" 성공 상태를 암묵적으로 시사하여, 사용자가 서버에 영속 저장된 것으로 오해하고 창을 닫으면 작업 내용이 소실되는 중대한 결함이 존재했다.
   - 백엔드 커널에 실재하는 파일 저장 경로(`POST /v1/projects/{project}/runs/{run_id}/checkouts/{checkout_id}/files`)를 확인하고 프런트엔드 API 클라이언트(`saveWorkspaceEditView`)를 구축하여 실배선했다.
   - 체크아웃 컨텍스트(`runId`/`checkoutId`)가 연결되지 않은 단독 에디터 실행 환경에서는 네트워크 0회 호출 가드를 집행하고, `role="alert"` 경고 배너(`editor-context-notice`)를 표출하여 "서버에 영속 저장되지 않고 로컬 브라우저 샌드박스 메모리에만 임시 보존됨"을 투명하게 고지했다.
2. **PTY 터미널의 "합성 & 조기 성공 표시(Synthetic PTY)" 결함 해소**:
   - `MonacoWorkspaceEditor` 내장 터미널은 실제 웹소켓 원격 PTY가 아닌 `SessionRecoveryManager` 로컬 시뮬레이션 엔진으로 구동되고 있었다.
   - 터미널 헤더에 `[로컬 에뮬레이션 · 독립 PTY 미연결]`(`role="status"`, `editor-terminal-mock-notice`) 뱃지를 상시 표출하여 사용자가 실제 원격 셸 환경으로 오인하지 않도록 조치했다.
3. **낡은 에뮬레이터 단위 테스트 극복 및 2대 돌연변이(M7, M8) 실측 사살**:
   - 기존 `tests/editor-session.test.ts`는 로컬 에뮬레이터 로직만 단언하는 한계가 있었으므로, 신규 DOM 단위 테스트 `apps/web/tests/monaco-workspace-editor-wiring.test.tsx`를 작성하고 돌연변이 2종을 실측 사살했다.

  - 로컬 메모리 버퍼 갱신 후 `editor-context-notice` (`role="alert"`, `⚠️ 체크아웃 컨텍스트(runId/checkoutId)가 연결되지 않아 서버에 영속 저장되지 않았습니다. (로컬 브라우저 샌드박스 메모리에만 임시 보존됨)`) 즉각 노출.
- PTY 헤더 고지:
  - `editor-terminal-mock-notice` (`role="status"`, `[로컬 에뮬레이션 · 독립 PTY 미연결]`) 마크업 배치.
