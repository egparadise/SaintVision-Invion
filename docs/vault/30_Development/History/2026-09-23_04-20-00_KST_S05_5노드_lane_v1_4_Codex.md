# S05-DB 5노드 lane v1.4

## 결론

[[Codex 5노드 랩 opt-in lane 정의]]를 v1.4로 갱신해 [[ADR-100 CP 호스트의 Node 겸임과 5노드 측정 경계]]와 카드 18 결정 (b)를 한 실행 계획으로 결합했다. 등록 Node identity는 5개지만 S05 timed wave의 candidate와 P95 분모는 CP에서 독립적인 Ubuntu 4대뿐이다. Windows CP 호스트의 Docker Desktop Node는 all-five topology smoke에만 포함하며, 결과를 만든 뒤 사후 샘플 삭제로 제외하는 방식은 금지한다.

현재 승인 범위는 inventory-bound adapter와 all-five preflight가 준비된 뒤 **legacy 20동시 × 3회 선측정 계획**까지다. `placementShortCommit=false`, S05-DB `review`, candidate와 50동시는 미승인 상태를 유지한다. 이 문서는 계획만 정리했으며 workflow·runner·제품 코드·계약·registry·ontology를 바꾸거나 로컬/물리 시험을 실행하지 않았다.

## v1.4 변경

- manifest가 `registeredNodeCount=5`, `physicalExecutionHostCount=5`, `cpIndependentWorkerHostCount=4`, `cpColocatedNodeCount=1`, `eligibleNodeCount=4`, `excludedNodeCount=1`을 함께 남기도록 했다.
- Claude의 ADR-100 독립 검토 관찰을 반영해 inventory 선언만 신뢰하지 않고 CP/Node host·machine identity와 Docker VM parent에서 co-location을 유도해 `coLocationValidation`을 대조하도록 했다. mismatch 또는 unmeasured이면 timed wave를 차단한다.
- inventory의 `measurementEligible.s05=false`, `exclusionReason=cp-host-colocation`을 timed candidate 구성 전에 적용하고 Explain의 겸임 Node 선택 0을 확인한다. CP host utilization과 Docker throttling은 같은 timeline에 남긴다.
- `decision_sha=9dafbf09...`, `candidate_authorized=false`, `fifty_authorized=false`를 기본 실행 권한으로 고정했다. Claude 카드 20은 P1/P2와 결정 (b)를 승인했지만 candidate/50 실행 승인으로 자동 승격하지 않는다. 후속 candidate 검토에는 도착 timeline·holder/waiter chain·`wait_event`·queue depth·server lock-wait 관측을 요구한다.
- 실행 단계를 all-five smoke → legacy 20동시 canary → 승인된 경우에만 candidate 20동시 → 별도 승인된 경우에만 50동시로 분리했다. 미승인 wave는 빈 값이나 0이 아니라 `UNAUTHORIZED/NOT_RUN`으로 남긴다.
- evidence를 benchmark schema 1.5에 맞춰 post-acquire `lockHold`, client elapsed `lockAcquireWait`·`legacyLockWait`·`limitRowWait`, parameter-free `sqlDiagnostics`로 갱신했다. acquire elapsed를 server wait_event 시간으로 오인하지 않도록 `serverSideLockWaitSeparatelyMeasured=false`를 유지한다.
- 카드 14의 1526→117ms hold 감소는 비대칭 계측이라 승격 근거에서 철회하고, 카드 18의 대칭 289.365→170.766ms도 candidate 성공 8개 survivor 표본이라 방향성 참고값으로만 둔다. candidate 외부 timeout 0→12 악화가 결정 (b)의 차단 근거다.

## 실행 전 차단 조건

1. inventory-bound S05 wrapper/workflow는 아직 미구현이다. 합성 Node benchmark는 물리 증거가 아니다.
2. 등록 Node 5개·서로 다른 인증서/epoch, 물리 host 5대(Windows 1 + Ubuntu 4), NTP·mTLS·resource snapshot·active Lease 0·disposable PG·redaction preflight가 모두 필요하다.
3. 겸임 Node를 timed candidate에서 사전 제외하지 못하거나 CP utilization timeline을 수집하지 못하면 legacy canary도 시작하지 않는다.
4. candidate와 50동시는 각각 별도 코디네이터 승인 SHA가 현재 `code_sha`의 조상일 때만 허용한다.
5. legacy 20동시 결과만으로 AC-05, candidate 채택, 5개의 독립 worker 성능을 주장하지 않는다.
