# ADR-100 CP 호스트 Node 겸임과 5노드 측정 경계

## 결론

사용자가 선택한 토폴로지 B를 [[ADR-100 CP 호스트의 Node 겸임과 5노드 측정 경계]]로 고정했다. Windows 물리 호스트 1대는 Control Plane과 Docker Desktop Linux 실행 Node 1개를 함께 운영하고, 별도 Ubuntu 물리 호스트 4대가 실행 Node 4개를 맡는다. 등록 실행 Node identity는 5개지만 Control Plane에서 독립적인 worker host는 4개다.

registry의 S05/S07 “5대”는 별도 `nodeId`·mTLS 인증서·epoch·heartbeat·offer/lease 경계를 가진 등록 실행 Node 5개라는 뜻으로 유지한다. `docs/task-registry.json`과 ontology는 변경하지 않았다. 다만 실행 Node 수가 CP 장애 독립성이나 성능 표본 독립성을 뜻하지 않으므로 모든 artifact에서 `registeredNodeCount=5`, `physicalExecutionHostCount=5`, `cpIndependentWorkerHostCount=4`, `cpColocatedNodeCount=1`을 함께 기록하게 했다.

## 측정 편향과 적용 규칙

| 영역 | 겸임 Node의 편향 | 채택한 경계 |
|---|---|---|
| S05 scheduler P95·결정성 | CP와 CPU/RAM/disk/NIC/host clock/Docker runtime을 공유하고 loopback·가상 NAT 경로도 달라 더 빠르거나 느릴 수 있음 | 5-Node topology smoke에는 포함하되 20/50 동시 timed candidate와 P95 분모에서는 사전 제외. Ubuntu 4대만 `measurementEligible.s05=true` |
| S07 이탈 감지·복구율 | Windows host outage가 observer인 CP와 Node를 동시에 제거해 감지 timeline 자체가 끊김 | 기본 20회는 Ubuntu 4대에 5회씩 배분. 겸임 process loss와 CP+Node host loss는 별도 scenario이며 95% 분모와 합치지 않음 |
| 시각·NTP | Windows CP와 Docker VM Node의 clock은 같은 host/virtualization 영향 | 둘 다 관측하되 독립 NTP 표본 두 개로 세지 않음 |
| 인증·fencing | 같은 host라도 Node identity 경계는 별도여야 함 | 겸임 Node도 고유 nodeId·certificate·epoch을 사용하고 private key 공유 금지 |

S05에서 겸임 Node 샘플을 실행 후 제거하는 방식은 금지했다. inventory eligibility를 candidate 구성 전에 적용하고 Explain 선택 0을 증명해야 한다. S07에서 Windows 전체 host loss의 감지 시간을 재려면 외부 monotonic observer 또는 별도 CP가 먼저 필요하며, 없으면 `UNMEASURED`/exit 3이다.

## 파일럿 provenance와 비주장

03:05 KST 코디네이터 보고 기준으로 첫 Ubuntu 후보는 `192.168.45.143`, 준비 state는 `.work/lan-5node/node1`, 예약된 node identity는 `nod_01M353DAR7EM8TETZN1FKRNPRG`이며 서버 측 init/bundle/serve 단계가 수행됐다. 이 정보는 사용자/코디네이터 보고를 문서화한 것이고 Codex가 원격 호스트를 독립 관측한 결과가 아니다. 이후 클라이언트 다운로드·CSR/enrollment·mTLS heartbeat·online·resource snapshot은 이 카드에서 확인하지 않았으므로 첫 Node 연결 완료도 주장하지 않는다. IP·state 경로는 운영 정본 inventory가 아니라 파일럿 추적 정보이며 private key·certificate 원문·DSN·token은 기록하지 않았다.

현재 Ubuntu 4대와 Docker Desktop 겸임 Node의 등록 완료, five-node inventory-bound wrapper/workflow, 20/50 동시 물리 부하, S07 20회 장애·복구는 모두 **미구현 또는 미실행·미측정**이다. 따라서 AC-05/07 통과, 5노드 운영 인수, P95≤2초, 감지≤60초, 복구율≥95%를 주장하지 않는다.

## 다음 인계

reviewer Claude는 다음을 독립 검토한다.

1. registry의 5대 수량을 유지하면서 CP 상관 장애를 과장하지 않는지.
2. S05 eligibility가 사후 sample 삭제가 아니라 candidate 선택 전 exclusion인지.
3. S07 기본 20회 denominator와 co-located/correlated scenario가 분리됐는지.
4. lane의 미구현 wrapper와 미실행 물리 증거가 완료로 표현되지 않았는지.

검토 뒤 카드 15의 inventory-bound 5노드 lane 구현 계획으로 복귀한다. 실제 workflow·adapter·lab run은 별도 카드와 승인 대상이다.
