# 검증 도구 미실행 성공 처리 수정

base f0074aa, task VB-AUDIT-01/02 및 P3 판단, owner Codex, reviewer Claude(미검토), branch agent/codex/model-registry-binding. agent-delivery1.1.0/core-reliability1.0.0 적용. 사용자 독립 VB-AUDIT-01 factory/import 대비 재현과 VB-AUDIT-02 소스 확인 수신. 구현 수정 명시 승인에 따라 진행했다.

## 변경

- VB-AUDIT-01: inspect.signature와 bind로 무인자 호출 가능성을 실행 전에 판별한다. 필수 인자 부족만 기존 거부 관측으로 유지하고, 본문 TypeError/ModuleNotFoundError 등 예외는 INCONCLUSIVE/exit1이다. signature 확인 불가, entrypoint 부재, factory None 반환도 미판정이다. factory 내부의 모든 예외를 의도적 설정 거부로 간주하지 않는다. 현재 명시적 설정 거부 예외 계약이 없으므로 그런 예외도 보수적으로 미판정한다. 서빙 불가 관측과 보안 합격을 혼동하지 않는다.
- VB-AUDIT-02: bearerStatus를 성공 여부와 무관하게 기록한다. 예외는 probe-error, 실제401/403은 거부 관측, 기존 <400 수용은 finding, 다른 상태는 거부 미입증 finding/nonzero다. raw 예외/응답 본문은 계속 숨긴다. KeyboardInterrupt/SystemExit를 잡는 범위 확대 없음.
- P3: 빈 client 경로는 집합 연산으로는 누락0이지만 검증할 요청이 없으므로 CLI exit2/assessment=inconclusive-no-client-paths로 변경했다. 경로가 있으면 compared이며 누락 exit1/일치 exit0. configured-surface 검증 실패의 기존 nonzero와 source fallback 금지는 유지한다. 빈 입력을 성공으로 기대한 시험은 명시적 미판정 계약으로 갱신했다.
