## 외부 Provider 활성화 전 후속 보완

다음은 현재 HTTP/worker 경로에서 호출되지 않는 `src/saintvision/services/eval_execution.py`의 후속 항목이다. `src` 호출 검색 결과 정의와 모듈 내부 호출만 존재한다. 따라서 이번 병합을 막는 운영 회귀로 분류하지 않았으나 실제 Provider 연결의 합격 증거로 삼아서는 안 된다. 담당은 Claude이며 완료 후 Codex가 취소·무결성 경계를 검토한다.

- `execute_case`의 `timeout_seconds` 인자가 사용되지 않는다. 외부 호출 전 실제 deadline 및 취소 결과 기록을 구현하고 `completed=False` 응답의 실행 잔존 여부도 정리해야 한다. 현재 수집 예외 경로에는 취소 시도가 있다.
- `MODEL_PINNING` capability 선언만 검사하므로 실제 handle/result의 모델 식별자 존재·일치 및 suite 정책을 실행 시에도 검증해야 한다. 별도 adapter conformance 검사의 존재가 각 실행 검증을 대신하지 않는다.
- 잘못된 금지 패턴 정규식의 `re.error`는 현재 `InvError` 처리에 들어가지 않는다. EvalCase 등록 검증 또는 결과의 errored 변환으로 나머지 케이스와 기록을 보존해야 한다.

## 보고서 검증·동기화·인계

명령과 결과의 기계 판독 영수증은 작업 디렉터리 `.work/merge-chain/`에 보관한다. `git fetch origin`, 격리 worktree 생성, 순차 ready/merge API 실행, 각 merged 상태·tree 동일성 확인은 exit 0으로 끝났다. GitHub 인증 정보는 출력·기록하지 않았다.

보고서 브랜치에는 PR19의 이미 작성된 최신 문서 7개만 정본 커밋 `33e6510d4410639ac7bf1252f1a0c232b1659cbe`에서 보존했다. Obsidian에 있던 최신 ADR·진행 상태를 오래된 버전으로 되돌리지 않기 위한 문서 통합이며 PR19의 제품 코드와 workflow는 가져오지 않았다. 문서 정본과 Obsidian 사본을 구분하고 알 수 없는 외부 편집은 덮어쓰지 않는다.

로컬 `python tools/check_docs.py`, `python tools/check_ontology.py`, `git diff --check`, `python tools/sync_obsidian.py --check`는 exit 0이었다. 완료 시 보고서 commit/push, 보고서 SHA의 CI, Obsidian check→apply→check를 수행한다. 이 보고서의 제품 검증 SHA는 위 최종 merge SHA이며 보고서 자신이 속할 미래 commit SHA를 예측해 쓰지 않는다. 별도 최종 영수증과 Git history/Actions가 보고서 commit 및 sync 결과를 증명한다.
