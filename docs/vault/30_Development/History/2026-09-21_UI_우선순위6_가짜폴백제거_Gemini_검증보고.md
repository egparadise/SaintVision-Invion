## 작업 내용 (UI-FB Remediation Details)

### 1. UI-FB-01: `ResourceExplorer.tsx` 합성 후보 및 가짜 자원 역량 폴백 제거

1. **합성 디스커버리 후보 초기값 제거**:
   - `useState` 기본 초기값에 하드코딩되어 있던 `ann_node06_unverified` (`Node-06-EdgeWorker`)를 완전히 제거하고 `initialCandidates || []`로 정직하게 초기화.
   - 백엔드 오프라인 또는 후보 부재 시 임의의 머신 등록 승인 버튼이 노출되던 결함 원천 해소.
2. **엄격한 4-상태 수명주기 및 대기/성공 빈 상태 분리**:
   - `candidatesState`를 `idle | loading | success | error`로 관리.
   - `idle` 상태에서는 대기 안내(`data-testid="discovery-idle-state"`)를 표시.
   - `success`이며 항목이 0개일 때만 정상 빈 상태 안내(`data-testid="discovery-empty-state"`)를 렌더링.
   - `error` 상태(`data-testid="discovery-error-banner"`)에서는 실제 오류 메시지와 재시도 버튼(`data-testid="discovery-retry-btn"`)을 렌더링하며, 후보 카드 및 `승인 & 토큰 발급` / `거부` 운영 버튼을 절대 렌더링하지 않음.
3. **자원 풀 용량 조회 실패 시 합성 수치 제거**:
   - `getPoolCapacity` 실패 catch 블록에서 48코어/192GiB/3GPU를 합성 주입하던 가짜 fallback을 완전 제거하고 `setPoolCapacity(null)`, `setPoolCapacityState('error')`로 전면 전환.
   - 화면에 에러 배너(`data-testid="pool-capacity-error"`)와 재시도 버튼(`data-testid="pool-capacity-retry"`) 렌더링.
4. **노드 상세 조회 실패 시 합성 역량 제거**:
   - `getNodeDetail` 실패 시 `DDR4/DDR5`, `AMD/Intel`, `NVIDIA` 역량을 합성하던 코드를 폐기하고 에러 배너(`data-testid="node-detail-error"`)와 재시도 버튼(`data-testid="node-detail-retry"`) 렌더링.
5. **스토리지 기여 및 데이터 위치 오류 표면화**:
   - `loadStorage` 실패 시 `storageError`가 조용히 무시되어 빈 상태 문구로 오인되던 구조를 수정하고, 오류 배너(`data-testid="storage-error-banner"`)와 재시도 버튼(`data-testid="storage-retry-btn"`)을 렌더링하며 빈 목록 안내(`data-testid="storage-empty-state"`)와 엄격히 분리.

### 2. UI-FB-02: `PlacementSimulator.tsx` 로컬 경험적 시뮬레이션 경계 및 서버 어드미션 분리

1. **로컬 결정론적 평가 명시적 라벨링**:
   - 상단 헤더에 `[로컬 결정론적 평가 (UNVERIFIED: 로컬 시뮬레이션 전용)]` 뱃지(`data-testid="local-simulation-badge"`)를 고정 노출하여 클러스터 서버 스케줄러의 실제 어드미션과 혼동되지 않도록 물리적 경계 명시.
2. **자원 풀 연동 상태 수명주기**:
   - `poolsState`(`idle | loading | success | error`), `poolsError` 상태를 신설.
   - 풀 연동 실패 시 `data-testid="pools-error-banner"`와 재시도 버튼 노출.
   - 풀 쿼리 대기 시 `data-testid="pools-idle-banner"`, 정상 빈 풀 응답 시에만 `data-testid="pools-fallback-banner"` 렌더링.
3. **서버 배치 미리보기 실패 시 가짜 샤드 조작 방지**:
   - `previewState`(`idle | loading | success | error`), `previewError` 상태 관리.
   - 배치 미리보기 401/403/500/네트워크 실패 시 서버 샤드를 즉시 비우고 `data-testid="preview-error-banner"` 렌더링 (`"서버 어드미션 미검증: 가짜 샤드 상태를 생성하지 않습니다"`). 가짜 합격 샤드를 절대 합성하지 않음.
4. **디스커버리 후보 목록 실패 상태 관리**:
   - `candidatesState`(`idle | loading | success | error`), `candidatesError` 관리 및 `data-testid="candidates-error-banner"` 연동.

### 3. UI-FB-03: `DeveloperStudio.tsx` 정본 ResultView 쿼리 및 엄격한 unmapped-404 폴백 제한

1. **`isRouteNotFoundError` 기반 정밀 폴백 가드**:
   - `@/shared/api/client`의 `isRouteNotFoundError(err)` 유틸리티를 임포트하여 오직 매핑되지 않은 라우트(HTTP 404 Route Not Found 또는 `NET-404`)에서만 `/artifacts` 폴백을 허용.
2. **2xx 응답 및 비-404 오류에 대한 광범위 폴백 차단**:
   - 200 OK 응답이지만 산출물이 미생성된 경우(`/result`에 output 부재)에는 `/artifacts`로 폴백하지 않고 산출물 미생성 상태(`artifactData: null`)로 정직하게 유지.
   - 401 Unauthorized, 403 Forbidden, 500 Internal Server Error, 네트워크 장애, JSON 파싱 오류 시에는 폴백을 전면 금지하고 `data-testid="artifact-error-banner"`와 실시간 ANSI 콘솔 로그(`[ResultView] 조회 실패`)에 실제 오류 메시지를 여과 없이 투명하게 표면화.
3. **폴백 적용 지표 표면화**:
   - 합법적인 404 폴백이 발동하여 `/artifacts` 데이터를 표시하는 경우 `data-testid="artifact-fallback-badge"` (`404 호환 폴백: /artifacts`)를 렌더링하여 정본 ResultView PASS와 명확히 구분.
