## PITR-R2-02 잔여 — 전체브랜치 보류

0da140e가 round-trip 무차별재시도를 없애고 물리복원 선행조건 fault5종을 추가한 것은 소스확인했다. 새6실행 매트릭스는 Claude 보고이며 Codex 실PG 재실행은 없다. RPO를 archive_timeout만으로 보장하지 않는 설명 정정도 확인했다. 하지만 다음 잔여가 있다.

1. cleanup의 `docker ps ... 2>/dev/null || true`는 조회실패를 빈목록과 같은 성공으로 만든다. 원본 shell prefix/functions를 추출하고 docker ps exit23을 주입했을 때 cleanup exit0, WARN0이었다. 제거대상이 없다는 관측을 얻은 것이 아니다.
2. rm 실패는 WARN만 출력하고 cleanup은 성공으로 끝난다. 첫run timeout→ps owned ID→rm exit23→두번째run 순서를 원본 start_probe에서 재현했다. '제거 성공 후에만 create 재시도' 조건을 강제하지 않는다. 합성 두번째run은0으로 설정했으므로 실제Docker에서 중복컨테이너가 생겼다는 주장이 아니다. 같은 NAME의 이름충돌이 생성을 막을 수 있지만 미확정 정리를 성공 전제로 재시도하는 경계는 남는다.
3. LABEL 값이 무작위nonce가 아니라 `pitr-probe-$$`다. PID 재사용/다른PID namespace 등에서 과거실행과 같을 수 있으므로 주석의 unique owner를 전역적으로 보장하지 않는다. 현재 label-filter 결과에 rm-f를 적용한다. 임의 다른label 컨테이너를 삭제하는 기존 blind-name 문제는 줄었지만 독립실행 식별자 요건은 아직 충족하지 않는다. 이번에 실제 외부컨테이너를 삭제한 적은 없다.
