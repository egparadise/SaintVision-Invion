# 실제 오류와 해결

1. 로컬 Docker 20.10 BuildKit이 Dockerfile FROM의 `sha256:...`를 registry 이름으로 해석해 build exit 1. 검증된 로컬 base image ID에 content-addressed local tag를 붙이고 `--pull=false`로 빌드, 최종 image의 base layer 배열을 비교했다. 최종 image `sha256:5efa1fae77f5d8bc330fd75ff4e03d35c95bef84ab5fca7852001a2e8ad781f9`, build exit 0.
2. 로컬 log driver의 compression 기본값과 max-file=1 조합에서 컨테이너 시작 exit 128. `json-file`, max-size=4m, max-file=1로 변경했다. 이전 실패 2건은 작업 기록에 보존했고 후속 학습/테스트가 exit 0으로 끝났다.
3. venv Python launcher의 자식 프로세스 command line 끝 공백 때문에 최초 재시작 탐지식이 매칭되지 않았다. 정확한 script path와 `serve` 뒤 공백을 허용하는 조건으로 해당 서비스만 식별했다. 다른 Python/Node/PACS 서비스는 중단하지 않았다.
4. 구현 중 serve 함수 들여쓰기 오류가 py_compile/시작 단계에서 발견됐다. 즉시 수정 후 compile·pytest·실제 API/브라우저 실행을 재검증했다.
5. npm ci를 저장소 루트에서 호출해 lockfile 없음 exit 1. apps/web에서 기존 lockfile로 `npm ci --ignore-scripts --offline`, TypeScript/Vite build exit 0.
6. 초기 조사 시 오래된 디렉터리 추정 경로·지원하지 않는 Orca worktree open을 조회했다. 실제 파일 목록과 버전 일치 help로 경로/명령을 확인했고 `orca file open README.md --worktree path:...` 성공을 확인했다.

원격 Worker의 `lan-observe-v1`, GPU 미검증, CI 결제/사용 한도 차단은 이 오류 해결로 해소되지 않는다. 로컬 CPU 개발 범위를 실제로 검증했으며 분산 업무 전체 완료로 보고하지 않는다.
