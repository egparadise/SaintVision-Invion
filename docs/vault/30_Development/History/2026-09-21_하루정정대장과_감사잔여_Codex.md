## API mock/backend 계약 설계 제안

현재 `tools/export_schemas.py`는 `src/saintvision/api/schemas.py`의 Pydantic `Strict` 모델에서 `contracts/*.schema.json`을 생성하고 backend workflow가 drift를 검사한다. 이를 신규 framework로 교체하지 말고 endpoint 응답까지 확장하는 안을 권고한다. 현재 `/v1/discovery/candidates`는 `dict` 응답이며 frontend `DiscoveryCandidate`는 수기 타입이다. `test_route_coverage.py`의 해당 테스트는 source 문자열/필드 선언을 대조하지만 serialized route body의 검증은 아니다.

단계안: (1) 후보 row 및 `{items, note}` envelope를 strict response model로 선언하고 FastAPI `response_model`에 지정, (2) 기존 exporter에서 canonical JSON Schema 및 drift check, (3) frontend type 또는 runtime fixture validator를 동일 schema/OpenAPI에서 생성, (4) DB 의존 없이 dependency override/TestClient로 실제 handler serialization을 provider contract test에서 검증, (5) adapter test는 canonical fixture를 소비하면서 adapter 변환/오류 처리를 검사한다. live DB가 없어도 schema generation/provider serialization은 CI에서 실행 가능하게 둔다. `route_coverage.py`는 기존 한계처럼 path shape 전용이며, method/response payload coverage는 별도 인접 gate로 추가한다. 이는 proposal이고 코드·task assignment는 만들지 않았다. 세부: [[2026-09-21_UI_FB_contract_readiness_review_Codex]].

- 공개 저장소의 현재 DSN evidence 비밀번호는 마스킹됐고 regression guard가 추가됐다. 과거 공개 Git commit의 원문은 남는다. DB 소유자가 자격증명 유효성과 회전 필요성을 확인하는 일은 별도 외부 항목이다.

- `sync_obsidian.py`의 공용 state, 줄바꿈 비교 정규화, 명시 경로 충돌 해소가 구현됐다. 마감 기록의 export는 7개, 보정 문서 6개, 최신 provenance 보고서 1개 순서였다. 각 `--apply`에서 목적지 hash가 일치했고, 마지막 결과는 1397 managed/0 pending/0 conflicts였다.

### 협업 회고 — Codex 관점

가장 효과적이었던 것은 사실·추정, 코드 작성자·독립 검토자, 실행·브랜치 시점을 나눠 보고하고 반례와 되돌림 대조를 서로 제공한 점이다. Codex는 보안·도구·공통 계약을 수정했고, Claude는 복구 도구와 전체 회귀의 독립 검토·실행 증거를 더했으며, Gemini는 UI 구현과 사용자 전달 경로를 맡았다. 사용자는 고정 SHA에서 여러 결과를 직접 재현했고, 자신의 초기 측정이 잘못된 전제에 기대었을 때도 공개 정정했다. 세 Agent도 수정 위치와 시험이 실제로 고정하는 경계를 서로 확인해, UI 소유권을 침범하거나 다른 Agent의 승인을 가장하지 않았다. 반면 처음부터 branch/SHA/worktree/interpreter와 skip 분포를 결과에 붙이지 않아 같은 검사를 반복했고, JUnit 없는 batch 집계, 잘못된 Python, 시점이 다른 링크 오류 귀속이 추가 확인을 낳았다. Windows PowerShell 경유 비ASCII 쓰기는 산문까지 손상시켰다. 다음 사이클은 fixed-SHA와 mutation/negative-control 증거, 전체 실행 환경, skip 분포를 처음 보고할 때부터 포함하고 검증된 UTF-8 파일 쓰기를 사용해야 사용자 중계와 재실행을 줄일 수 있다.

이 회고는 Codex 작성자 시점이다. Claude의 별도 마감/통합 검사 대조 문서는 Claude 작성자 시점이다. Claude는 Codex와 다른 clean worktree에서 같은 `cb505f6` 검사 집합 및 skip 분포를 재실행해 일치를 보고했다. 그 기록은 이 문서의 독립 대조 근거이지만 협업 회고 자체에 대한 상호 승인은 아니다.
