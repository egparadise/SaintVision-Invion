# 개발 TLS 인증서 외부 주입 전환 준비

이 문서는 절차만 준비한다. 현재 `deploy/certs/saintvision.crt`와 `saintvision.key`를 삭제하지 않았고, `.gitignore`, Compose 경로 주입, Git 이력 재작성도 변경하지 않았다.

## 1. 새 개발 인증서 발급 준비

인증서 생성기는 `cryptography`를 사용한다. 선언 위치는 `requirements-core.txt`의 `cryptography==50.0.1`이며 `requirements-test.txt`가 이를 포함한다. 기본 전역 Python에 설치하지 않고 저장소별 가상환경을 사용한다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-core.txt
.\.venv\Scripts\python.exe -c "import cryptography; print(cryptography.__version__)"
```

현재 `tools/generate_tls_cert.py`의 CLI는 `deploy/certs`를 고정 출력 경로로 사용한다. 외부 디렉터리에 새 인증서를 만들려면, 경로를 명시해 동일 함수를 호출한다.

```powershell
$ExternalCertDir = 'C:\SaintVision\secrets\saintvision-dev'
New-Item -ItemType Directory -Force $ExternalCertDir | Out-Null
.\.venv\Scripts\python.exe -c "from pathlib import Path; from tools.generate_tls_cert import generate_certificates; generate_certificates(Path(r'$ExternalCertDir'))"
```

생성 후 다음을 확인한다. 값 자체를 로그나 문서에 복사하지 않는다.

```powershell
Get-Item "$ExternalCertDir\saintvision.crt", "$ExternalCertDir\saintvision.key" |
  Select-Object FullName, Length, Mode
```

운영 전환 전에 인증서와 키의 공개키가 일치하는지, SAN에 필요한 개발 호스트가 있는지 별도 검증한다. 이 단계는 파일 존재·크기만 확인하는 현재 preflight보다 강한 검증이다.

## 2. Clone 후 개발자 초기 설정

현재 Compose의 인증서 source는 `./deploy/certs/...`로 고정되어 있다. 따라서 파일을 저장소에서 제거한 뒤에는 외부 디렉터리만 준비해도 Compose가 자동으로 그 위치를 찾지 않는다. 외부 주입을 완성하려면 다음 중 하나를 먼저 구현해야 한다.

1. **권장**: Compose의 두 `source`를 환경변수 기반 외부 경로로 바꾸고, clone 후 개발자가 해당 환경변수를 설정한다.
2. **임시 호환 경로**: 외부 보관 디렉터리에서 로컬 작업 트리의 `deploy/certs`로 파일을 공급한다. 이 경로는 파일을 저장소에 다시 추가하지 않도록 ignore 정책과 preflight를 함께 준비해야 한다.

권장 경로가 구현된 뒤 clone 후 순서는 다음과 같다.

```powershell
git clone <repository-url>
Set-Location SaintVision-Invion
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-core.txt
$env:SAINTVISION_DEV_CERT_DIR = 'C:\SaintVision\secrets\saintvision-dev'
Test-Path "$env:SAINTVISION_DEV_CERT_DIR\saintvision.crt" -PathType Leaf
Test-Path "$env:SAINTVISION_DEV_CERT_DIR\saintvision.key" -PathType Leaf
```

이 초기 설정 안내는 README의 개발 시작 절차와 배포 runbook 양쪽에 연결한다. README에는 clone 후 한 단계가 늘어난 사실과 환경변수 이름을, runbook에는 권한·검증·롤백 절차를 둔다.

## 3. 전환 검증 순서

삭제 승인 후에는 새 외부 파일을 먼저 준비하고, 고정 SHA의 별도 clean clone에서 다음 순서로 검증한다.

1. 외부 주입 경로와 파일·키 일치 검사를 실행한다.
2. `tools/deploy_intranet.ps1`를 실행해 인증서 생성 분기와 `Test-Path -PathType Leaf` preflight가 통과하는지 확인한다.
3. 인증서 파일을 의도적으로 없는 상태로 만든 별도 임시 clone에서 `docker compose -f docker-compose.prod.yml up --no-start web`를 실행한다. `create_host_path: false` 때문에 host 디렉터리를 만들지 않고 명시적으로 실패해야 한다. 이 검증은 실제 Docker 환경에서만 판정한다.
4. 외부 인증서를 복구한 뒤 같은 Compose 명령이 통과하는지 확인한다.
5. `python -m pytest -q tests/test_deploy_intranet_preflight.py`와 Compose mount 경계 시험을 실행한다.
6. 실제 HTTPS 접속과 인증서·키 공개키 일치, SAN, TLS handshake를 별도 기록한다. preflight 통과만으로 TLS handshake 성공을 주장하지 않는다.

판정에 필요한 기록은 명령, exit code, 고정 SHA, 외부 인증서 디렉터리 식별자, Docker/OS 환경이며 개인키 값은 포함하지 않는다.

## 4. 되돌리기

외부 주입에 문제가 생기면 먼저 배포를 중지하고 외부 인증서 디렉터리의 승인된 백업을 복원한다. 경로 주입 변경이 이미 구현된 경우 이전 Compose·preflight 커밋으로 되돌린 뒤 파일 존재·키 일치·HTTPS handshake를 다시 확인한다.

긴급한 개발 복구에 한해 현재 공개 Git 이력의 기존 파일을 별도 비공개 작업 트리에 복원할 수 있다. 이는 공개된 키를 폐기하거나 회전한 것이 아니므로 임시 복구일 뿐이며, 운영·외부 공유에는 사용하지 않는다. 복구 후에는 외부 주입 경로를 다시 검증하고 사용자 결정에 따라 개발 키를 교체한다.

## 현재 준비의 한계와 다음 담당

- 외부 디렉터리 생성과 인증서 발급은 아직 실행하지 않았다.
- Compose source 경로의 환경변수화와 clone 초기화 코드는 아직 구현하지 않았다. 현재 고정 source 상태에서 파일을 삭제하면 의도적으로 Compose가 실패한다.
- 새 인증서 발급, 기존 공개 키 폐기, `.gitignore`, 저장소 이력·공개 설정 변경은 사용자 결정 후 별도 작업으로 진행한다.
