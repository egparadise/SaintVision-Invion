## 새 지적

- **B8-M1 (MEDIUM, Rev7부터 유지된 결함, 97bb 검토가 놓침): TERMINAL_FRAME continuation의 liveness가 Node 단위다.**
  - `_legacy_parent_current`는 claimRights lease와 Node 전체 boolean인 `leaseActive`/`workloadActive`만 본다. matched claim이 아직 active인지, claim version, parent 상태는 보지 않는다.
  - release는 claimRights를 지우지 않는다. 다른 claim이 하나라도 있으면 boolean은 true로 남는다.
  - 반례: parent TERMINAL_CLEAN(claim release) 뒤 TERMINAL_FRAME의 register와 invoke가 성공한다. Rev7과 Rev8 모두 같다.
  - Rev8은 release 경로를 하나 더 만든다: CANCEL receipt가 claim을 release해도 parent는 PENDING으로 남는다.
  - 실제 72028 `terminal.py:_current`(65-93)는 해당 run의 lease가 미해제이고 미만료일 것을 요구한다. 따라서 제안은 현행 제품 guard보다 약하다.
  - 해결: per-claim liveness(release 시 tombstone, claim ∈ activeClaims, parent PENDING+LIVE cap), BUILD_CLEANUP_READ에 대한 명시적 결정, 회귀 시험.
