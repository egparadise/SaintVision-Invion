### 1.2 잔여 (병합 전)
- **R1 `gitCommitSha`는 여전히 상수** — `subprocess.check_output(...)`을 쓰지만 스크립트에 `import subprocess`가 없어 항상 `except`로 떨어져 fallback `"39537173"`을 기록한다. 내 트리 HEAD `7586af6e`에서 돌린 JSON도 `39537173`이다. 커밋된 `Evidence/desktop_ui_invariants.json`의 SHA도 관측이 아니다. import 추가 + fallback 제거(실패 시 `null`).
- **R2 vault 증거를 매 실행 덮어쓰기 + 러너 HEAD 미대조** — 스크립트가 `--output-dir`와 무관하게 `docs/vault/.../desktop_ui_invariants.json`을 항상 다시 쓴다(내 3015 실행이 트리의 추적 파일을 port 3015로 바꿔 놓았다; `git checkout`으로 복구). `run_browser_smoke.mjs`는 그 JSON의 `verified/gitCommitSha 길이/passedChecks≥8/screenshots≥4`만 보고 4→0으로 뒤집으며 **현재 HEAD와 SHA를 대조하지 않는다** → 증거가 커밋된 지금은 UI가 회귀해도 영구히 0 unverified. 최소: 러너가 `gitCommitSha == git rev-parse HEAD`(또는 조상)일 때만 신뢰, 아니면 `[STALE-EVIDENCE]`로 unverified 유지; vault 덮어쓰기는 명시 플래그(`--commit-evidence`)로만.
- **R3 "Window Active Title Text"가 비활성 창** — `document.querySelector('div[id^="window-title-"]')`는 DOM 첫 창(최소화 안 된 첫 창)이라 측정값 `rgb(156,163,175)`(=`--color-text-muted`, 비활성 타이틀)이다. 활성 타이틀(`#f8fafc` on `#1e293b`)은 측정되지 않았다. 활성 창 id로 선택하고 라벨을 맞출 것. (#61 v1.2.0은 여전히 "창 타이틀바 13.98:1"을 적어 두 PR이 서로 다르다.)

관찰(비차단): INV-02 `or` 완화 · INV-09는 mock 데이터 변경으로 성립(정직 수치의 실제 검증은 실 백엔드 레인) · 커밋 JSON `screenshots`가 로컬 절대경로(`…\https-github.com-egparadise-SaintVision-Invion.git\scratch\…`)이고 파일은 Git 밖 · 화면의 상단 바 `5 Nodes (4 Schedulable)` vs 탐색기 `온라인 1/1` 모순은 그대로.
