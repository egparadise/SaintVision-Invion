# 독립 검토 — 운영자 발급 discovery 자격증명

오늘 우리가 닫은 신규-노드 온보딩(토큰 없는 기계 공지 불가)을 임시 경로로 여는 작업. 운영자가 `inv_discovery_issuer` 권한 로그인으로 CLI를 실행해 installation-바인딩·15분·회전폐기 자격증명을 발급.

## 검토 트리 못 박기
- **미병합**(origin/integration=`b0b94f1`, a533b4b·8b79382 모두 조상 아님). 브랜치 `agent/codex/terminal-pty-contract`, 코드 커밋 **`a533b4b`**, tip **`8b79382`**(로컬=origin 동일)에서 검토. integration 착지 후 그 SHA 재확인 권장.
- 인터프리터 `.venv` python 3.14.6. **PG 없음**(측정 `which psql` 부재) → 실 PG 시험 실행 불가. **worktree `codex-terminal-pty-contract`의 `tools/discovery_credential.py`가 dirty**(Codex가 발급 rate-limit 구현 중, 미커밋) — 되살림은 그 파일을 건드리지 않도록 **커밋본 복사본**에서 수행(Codex 미커밋 작업 보존).

## 직접 확인 (내 손: 실행 + 되살림)
### ① 발급 권한 강제 — 앵커가 무게를 진다 (최우선, 확증)
- CLI `_operator_role`: `pg_has_role(session_user,'inv_discovery_issuer','MEMBER')` → 아니면 `Refused`, 맞으면 `SET LOCAL ROLE inv_discovery_issuer`. **2중**: 앱-층 검사 + DB-층(마이그레이션 0045가 INSERT를 그 역할에만 부여, `inv_app`은 SELECT+제한 UPDATE만).
- **실행**: `tests/core/test_discovery_credentials.py` **9 passed**(fake conn, PG 불요) — 비-operator(`allowed:False`)면 `EXIT_REFUSED`·쓰기 전 거부(`calls==1`)·비밀 미노출.
- **되살림(내 손, 커밋본 복사본)**: 가드 `if not row or not row["allowed"]: raise Refused` 제거본으로 비-operator 시나리오 실행 → **거부 안 함(result≠REFUSED), calls 6(쓰기 진행), 비밀이 stdout에 노출됨**. 즉 가드가 정확히 거부·비밀-차단을 만든다. (커밋본은 거부·calls 1·비밀 없음.)
- **PG-층은 미검증(내가)**: `SET ROLE` + INSERT-grant-only-to-issuer의 실효는 실 PG integration 시험이 검증(아래 통합 목록). 앱-층은 확증, DB-층은 PG-대기.

### ② 비밀 취급 — 일회 노출, 오류·리다이렉트엔 없음 (확증)
- 커밋 후 stdout에만 1회 노출; 비-operator 거부 시 비밀 없음(①); **stdout이 TTY가 아니면(리다이렉트/파이프) 연결조차 안 하고 `EXIT_REFUSED`("interactive terminal")** — `test_cli_does_not_write_if_one_time_secret_would_be_redirected` 통과. 저장은 `token_sha256(secret)` digest만.
- Codex가 고친 구별(의도된 일회 공개는 허용, 오류·후속·리다이렉트엔 금지)이 **옳고, 시험이 실제로 강제**함. 확증.

### ③ 폐기·만료 — 공개 거부는 확증, 회전-쓰기는 PG-대기
- `test_cross_scope_expiry_and_revocation_are_the_same_public_denial` 5-parametrize(tenant/installation/scope 불일치·**expired·revoked**) 전부 **동일 공개 거부**로 통과(fake, PG 불요) — 만료·폐기된 자격증명은 검증에서 거부됨(확증).
- **회전 폐기의 실제 쓰기**(`_issue`가 기존 비폐기 건을 `FOR UPDATE`로 잡아 `revoked_at` UPDATE 후 신규 INSERT)와 admission-자동폐기·15분 TTL·announce-with-token(202)은 **실 PG integration 시험**만 검증 → PG 없어 미실행(통합 목록).

## ④ 발급 쿼터 — 구현됨(8b8ed81, 기록 cd2b8b1) 독립 검토 (a533b4b 뒤 추가; PG 없어 소스+Codex PG결과 분리)
검토 트리: 8b8ed81 **integration 병합됨**(tip 7711c8a 조상). 이 호스트 **PG 부재 → 트리거 실행 못 함**; SQL 소스 검토 + Codex 실-PG 시험 결과(내가 시험 코드는 읽음, 실행은 안 함) 분리.
- 심각도 판단(유지): 원 취약점=**익명** 후보 500 소진; 지금 발급자는 DBA-부여·인증·감사 **신뢰 주체**라 동일 심각도 아님. 쿼터는 타당한 심층방어. 차단 아님.
- **① 우회(최우선) — 소스 확증**: 트리거 `tr_discovery_issuer_budget`가 **`BEFORE INSERT ON discovery_machine_credentials FOR EACH ROW`** — 테이블 INSERT면 **직접 SQL도 발동**(주석 "including direct SQL"). INSERT 권한은 `inv_discovery_issuer`에게만(a533b4b) → 직접 SQL 발급도 `SET ROLE inv_discovery_issuer` 필요→트리거 걸림. **CLI 예절 아님.** [측정-소스] Codex PG 시험이 `SET ROLE` 후 직접 INSERT 11번째가 `P0001`로 거부됨을 단언(내가 시험 코드 확인, 실행은 Codex). **관찰(결함 아님)**: superuser/테이블 소유자 직접 INSERT는 `current_user='inv_discovery_issuer'`가 아니라 budget·트리거 미적용 — superuser는 위협모델 밖(어차피 전능)이라 수용, 다만 쿼터는 issuer-role 경로에 한정됨을 명시.
- **② 권한 설계 — 소스 확증**: 트리거는 **SECURITY INVOKER**(caller로 실행) — `NEW.issued_by <> session_user`로 **actor=실 로그인** 강제(SET ROLE 후에도 session_user는 원 로그인). helper `consume_discovery_issue_budget`는 **SECURITY DEFINER + `SET search_path=pg_catalog,public`(고정, 주입 방지)**, 소유자=`inv_discovery_issuer_guard`(NOLOGIN·budget 테이블 유일 접근; 발급자는 budget 테이블 REVOKE ALL). helper 내부에서도 `pg_has_role(session_user,'inv_discovery_issuer')` 재확인. NOLOGIN 가드 역할에 **멤버 0을 마이그레이션이 RAISE로 강제**. Codex가 잡았다는 "DEFINER 트리거가 superuser 시험 로그인을 발급자로 오인" 버그의 수정=**트리거를 INVOKER+`current_user='inv_discovery_issuer'` 게이트로** 바꾼 것 → superuser는 게이트 밖(위 관찰). 새 문제 없음(마이그레이션의 임시 `GRANT guard TO CURRENT_USER`→OWNER 지정→`REVOKE guard/CREATE`로 잔여 멤버·권한 없음, members-check RAISE가 이중 방어).
- **③ 원자성 — 소스 확증**: helper의 `INSERT ... ON CONFLICT (tenant_id) DO UPDATE SET issue_timestamps=array_append(24h-prune, clock_timestamp()) RETURNING cardinality`. tenant **PK 행잠금**(ON CONFLICT DO UPDATE)이 동시 발급을 tenant별 직렬화; 첫 INSERT 경쟁도 PK로 한쪽만, 나머지 DO UPDATE로 직렬화. `used>10`이면 RAISE→그 UPDATE(append) **롤백**→거부된 11번째가 슬롯을 영구 소비 안 함. [측정-소스] Codex PG 시험은 순차 10+1이고 최종 `issued==event==budget==10` 일관성 단언 — **병렬 동시성은 미시험**(아래).
- **판정**: 소스 상 **sound**(우회 차단·권한 분리·원자성 기제). CLI P0001→마스킹 거부도 커밋됨.
- **못 돌림/권고(PG-대기, 아래 통합 목록 5·6에 추가)**: (5) 쿼터 실-PG 시험 실행(내가 못 함, Codex 결과 수용). (6) **트리거 제거 되살림**(Codex는 한도값 100 변경 되살림만 함; **트리거 자체를 빼면 시험이 깨지는지**는 PG-시점에 확인 권장) + **병렬 동시성 시험**(원자성은 행잠금으로 소스-추론, 실 병렬 미시험).

## 미검증 통합 목록 (실-인프라 필요 — 한 곳에 모음, 이중 기록 금지)
Codex가 남긴 미검증(실 Go 바이너리·물리 Node 흐름·보호 전달 채널)과 내 Go 검증밀도 지도의 실-인프라 항목이 **겹친다**. "하나만 해소하고 끝난 줄" 방지로 여기 통합한다(Go 지도의 T3 및 실서버 e2e는 이 목록을 가리키게 이관):
1. **discovery 자격증명 실 PG integration**(`tests/integration/test_discovery_machine_credentials.py`): role grant·SET ROLE 실효·15분 TTL·회전폐기 쓰기·admission-자동폐기·revoke 멱등. PG 필요.
2. **Go inv-discover 바이너리**: 컴파일 + main.run() env 로직 + announce.go 헤더 주입 방지 분기(Go 지도 T1·T2). Go 툴체인 필요.
3. **교차언어 e2e**: inv-discover(Go, env의 Bearer)가 → Python 서버 공지 → tenant/자격증명 대조 → 후보 기록까지 **전 경로**. 실 서버+Go+PG 필요. (Go 지도 T3.)
4. **물리 Node 흐름 · 보호 전달 채널**: 운영자가 발급 비밀을 secret manager로 새 기계에 주입 → 기계가 announce. 실 배포 환경 필요.
5. **발급 쿼터 실-PG 시험**(`test_discovery_issuer_budget_blocks_cli_and_direct_sql_beyond_ten_per_tenant`): CLI 10+11번째 거부·직접 SQL 11번째 P0001·count 일관성. PG 필요(Codex 실-PG 결과 수용, 내 실행 아님).
6. **쿼터 트리거-제거 되살림 + 병렬 동시성**: 트리거 자체를 빼면 시험이 깨지는지(Codex는 값-100 변경만), 실 병렬 발급에서 11번째 누출 없는지(원자성은 행잠금 소스-추론). PG 필요.
- 소관: 전부 보안·분산·배포 경계 = **Codex + 운영자**. 시점: PG/Go 툴체인/CI/test-서버 가용 후. Go 지도(항목19)와 이 목록은 **상호 참조**로 단일화.

## 판정
