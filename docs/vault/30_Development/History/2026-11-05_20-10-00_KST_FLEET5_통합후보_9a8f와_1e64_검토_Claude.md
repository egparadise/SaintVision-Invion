## 5. 별도 미해결: Go Node의 정상 renewal policy floor (P0, native 증명으로 확인됨)

아래는 내가 source에서 직접 확인한 정적 사실이다. 이후 계약 owner의 실제 Linux Go 증명(`5023ce7d`, `native-go-result.json`: 시도 2 cycle, 완료 0, 같은 version final 모두 `NODE-0041`)이 같은 결론을 냈다. 그 증명과 수리 방향 판정은 별도 P0 문서에 있다.

1. `tools/lan_pilot.py:2030-2049`(같은 모양이 2151·3308행 근처에도 있다)는 overlap policy와 final policy를 **같은 `version`(target channel version)**으로 만든다. 둘은 `expiresAt`과 `clientFingerprints`가 달라 raw bytes가 다르다. 59f에도 같은 code가 있으므로 이번 후보가 새로 만든 문제가 아니다.
2. `worker_leaf_rotation._policy`(199행)는 overlap과 final 모두 `version == targetChannelVersion`을 요구한다. 그래서 Python 쪽에서는 이 모양이 계약이다.
3. Go `runtime/journal.go:341-366` `PinPeerPolicy`는 `version == prior.Version && hash != prior.Hash`를 `NODE-0041 rollback rejected`로 거부한다.
4. `transport/trust.go:67-93` `policy()`는 raw sha256을 만들고 **expiry 확인 전에** pin한다. `NewAuthority`(49-65)는 생성 시 `policy()`를 부르고, `Authorize`(103~)도 연결마다 `policy()`를 부른다.
5. `cmd/inv-node/main.go:88-108`은 `NewAuthority`를 TLS, storage, listener **보다 먼저** 부른다.

따라서 이렇게 될 것으로 보인다.

- install에서 overlap policy를 쓰고 restart하면 Go는 (V, overlap hash)를 pin한다.
- finalize가 같은 V의 final policy를 쓰면, 그다음 TLS 연결의 `Authorize`부터 실패한다. 실제 docker restart 뒤에는 `NewAuthority`가 실패해 listener가 뜨지 않는다.

이것은 consecutive rotation만의 문제가 아니라 **첫 정상 rotation의 finalize부터** 걸릴 수 있다.

Python fixture cycle(2fb5까지의 7→8→9→10)은 restart를 대체하고 Go journal을 쓰지 않는다. 그래서 이 문제를 증명하지도 반증하지도 않는다. native Go 증명이 이를 **확인했다.** 이제 P0는 후보가 아니라 확인된 기준선 결함이다.

- floor를 약하게 만들면 안 된다.
- 고치는 방향은 계약 owner(`ctx_6f0f8253b8a7`)가 실제 Linux Go Journal과 Authority, 정확한 Python policy bytes로 증명한 뒤 정한다. 예: final policy에 overlap보다 큰 별도 policy version을 주고 channel version과 분리한다.
- 그 증명과 수정 검토 전에는 Go NORMAL cycle과 plain runtime 전체를 받아들이지 않는다.
