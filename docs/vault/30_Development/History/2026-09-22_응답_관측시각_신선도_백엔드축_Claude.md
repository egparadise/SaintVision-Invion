# 응답의 관측 시각(신선도) 백엔드 축

Gemini의 3번째 축(시간): 화면이 보여주는 값이 **조회 시점**의 것인데 언제 조회했는지 말 안 하면 사용자가 현재로 읽는다. 화면 쪽은 **표시**의 문제, 백엔드 쪽은 **응답 자체**의 문제 — 응답에 **그 값이 언제 참이었는지(관측 시각)**가 들어 있는가. 없으면 화면은 자기 **조회 시각**밖에 못 쓰는데, 그건 "언제 물어봤나"이지 "언제 참이었나"가 아니다.

## ① 오늘 묶은 계약: 관측 시각 담음 / 안 담음 (소스 확인, tip `5eb30850`)
| 계약 | 시각 필드 | 그 시각의 의미 |
|---|---|---|
| RunResultView | `completedAt` | **종단 상태만**(succeeded/failed 완료 시각). 진행중(running)엔 as-of 없음 |
| RunAttemptList | 항목별 `startedAt` | 시도별 시작; 목록 자체 as-of 없음 |
| ModelCommitObservation | `committedAt` | 커밋 시각(불변 진실). 단 `currentAvailability`는 live-ish (별도 as-of 없음, 대신 `requiresExecutionRevalidation`로 재검증 요구 = 정직) |
| StorageObservationView | `createdAt`·`expiresAt` | 요청 생성/만료(요청 수명) |
| **NodeResponse**(노드 상태) | **`lastHeartbeatAt`** | 마지막 하트비트 = 라이브니스 진실-시각 ✓ |
| **ReplicaObservationResponse**(복제본 건강) | **`observedAt`** | 관측 시각 ✓ (+`currentAvailability:"unknown"`·`requiresExecutionRevalidation:true`로 **지금 건강하다고 단언 안 함** = 정직) |
| RunArtifactList | 없음 | (아티팩트는 산출 후 불변; 신선도 하위) |
| RunLogView | 없음 | (로그; 신선도 하위) |
| **ShardObservation** | **없음** | **라이브 shard/parent 실행 상태**(parentState·allPhysicallyStopped·allSucceeded)에 as-of 없음 |
| WorkspaceEditView | 없음 | 특정 revision 콘텐츠(revision별 불변) — 라이브 값 아님, 신선도 비대상 |

## ② 누락 중 신선도가 중요한 것 (사용자 지정: 노드 상태·복제본 건강·실행 상태)
- **노드 상태**: `lastHeartbeatAt` **있음** → 화면이 "N분 무하트비트=stale" 계산 가능. 갭 아님.
- **복제본 건강**: `observedAt` **있음** + 라이브 건강 단언을 스스로 유보 → 갭 아님(오히려 모범).
- **실행 상태**: **여기가 갭.**
  - **ShardObservation** — 라이브 shard/실행 상태, **as-of 없음** ★ (신선도 갭 1순위)
  - **RunResultView(비종단)** — running/queued에 as-of 없음(completedAt은 종단만) (갭 2순위)

## ③ 알고 있는데 안 주나, 아예 기록을 안 하나 (오늘의 구별)
**전부 "알고 있는데 안 준다" = 작은 수정. "미기록"인 신선도-중요분은 없음.**
- ShardObservation·RunResultView(라이브)의 상태는 **`inv.runs`에서 나오고, `inv.runs.updated_at`는 트리거(`NEW.updated_at := clock_timestamp()`)로 상태 변경마다 갱신**된다(0001_core.sql). 즉 상태-진실-시각이 **기록돼 있다.** shards.py 쿼리는 `inv.runs u`/`r`를 JOIN하면서 `updated_at`을 **select/serve만 안 한다.** → **계약에 `observedAt`(또는 `stateAsOf`) 추가 = 작은 일**(select 추가 + 스키마 필드 + validate).
- 노드·복제본은 이미 시각을 기록·노출(lastHeartbeatAt·observedAt).
- **미기록(더 큰 일, 별도 결정)에 해당하는 신선도-중요 계약은 발견되지 않음.** 실행 상태의 진실-시각은 이미 `updated_at`으로 있다.

## 권고
- **ShardObservation에 `observedAt` 추가**(1순위): 서빙 쿼리가 `max(inv.runs.updated_at)`(parent+shards) 또는 관측 조립 시각을 담게. **커널 계약·서빙 = Codex 레인** → 소스 상 작은 추가임을 근거로 Codex에 인계(내가 커널 계약을 직접 안 바꿈).
- **RunResultView 비종단 as-of**(2순위): 진행중 상태에 `stateAsOf`(=run.updated_at). 동일 Codex 레인.
- RunArtifactList/RunLogView: 신선도 하위, 필요 시 산출/기록 시각 추가 검토(선택).
- saintvision(노드/복제본)은 이미 충분 — 추가 불요.

## Gemini에 전할 것 (화면이 지금 쓸 수 있는 것)
- **지금 신선도 표시 가능(백엔드가 진실-시각 제공)**: 노드 상태=`lastHeartbeatAt`, 복제본 건강=`observedAt`(단 "지금 건강"이 아니라 "재검증 필요"로 표기 — 계약이 그렇게 말함), 실행 **결과(종단)**=`completedAt`, 모델 커밋=`committedAt`, 스토리지 관측=`createdAt`, 실행 시도=항목별 `startedAt`.
- **아직 불가(백엔드가 진실-시각 미제공, 화면엔 조회 시각뿐)**: **라이브 실행 상태(RunResultView 진행중), ShardObservation(shard 상태)**, RunArtifactList/RunLogView. → **이 값들에 조회 시각을 진실-시각인 것처럼 붙이지 말 것**(이 축이 경계하는 바로 그 혼동). "조회 시점 기준"으로 정직히 표기하거나, 백엔드 `observedAt` 추가(작음, Codex 대기)를 기다린다. 실행 상태 신선도는 백엔드 추가 후 열린다.
