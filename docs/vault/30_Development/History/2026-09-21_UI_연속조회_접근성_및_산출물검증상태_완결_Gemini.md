# UI 연속 재조회 전이 회귀·접근성 role=alert·산출물 무결성 검증 엄격 분리 완결 보고

## 1. 개요 및 배경

Codex의 검증 경계 감사([[2026-09-21_UI_FB_contract_readiness_review_Codex]])에서 지적된 3대 핵심 미결 사항을 완전히 해소했다:
1. **연속 재조회 전이 회귀 시험 3종 구축 및 돌연변이 대조 실증**:
   - 단일 최초 조회가 아닌, 기존 후보가 존재하는 상태에서 2차 재조회(`refresh`)가 실행되는 실 사용자 수명주기 경로를 검증.
   - 3개 돌연변이(Mutant 1, Mutant 2, Mutant 3)를 실제 주입하여 각각 대응하는 DOM 테스트가 즉시 **FAIL**로 회귀를 정확히 포착함을 실증.
2. **접근성 `role="alert"` 전면 적용**:
   - `ResourceExplorer.tsx`, `PlacementSimulator.tsx`, `DeveloperStudio.tsx` 내 8개 오류 배너에 스크린 리더와 보조공학 기술이 즉각 감지할 수 있도록 `role="alert"` 표준 속성을 탑재.
3. **산출물 무결성 검증 완료 뱃지 엄격 분리 (`DeveloperStudio.tsx`)**:
   - 단순히 `currentRun?.state === 'succeeded'`인 것만으로 "산출물 검증 완료 (Output Verified)"를 주장하던 결함을 제거.
   - 실제 암호학적 증거 ID(`verifiedEvidenceId`)가 존재하고 폴백이 아닐 때만 `✓ 산출물 검증 완료 (Output Verified)`로 표시하고, 폴백은 `⚠️ 산출물 아티팩트 폴백 (Artifact Fallback / UNVERIFIED)`, 미검증 성공은 `⚠️ 실행 완료 · 출력 무결성 미검증 (Completed / UNVERIFIED)`으로 정직하게 분리.

## 2. 작업 내용 및 돌연변이 대조 실측

### 2.1 연속 재조회 및 에러 억제 DOM 테스트 3종 신설 (`resource-explorer-dom.test.tsx`)

| 시나리오 | 검증 내용 및 단언 | 주입된 Mutant | Mutant 주입 시 실측 결과 |
| :--- | :--- | :--- | :--- |
| **후보 있음 → 정상 빈 응답** | 1차 GET에서 `Node-01-Candidate` 표시 확인 → `discovery-refresh-btn` 클릭 → 2차 GET 빈 배열(`{ items: [] }`) → 기존 row/승인 버튼 완전 소멸 및 `discovery-empty-state` 표시 | `setCandidates` 갱신을 `if (items.length > 0)` 조건 안으로 되돌림 | **FAIL** (`AssertionError: expected '...' not to contain 'Node-01-Candidate'`) 포착 실증 |
| **후보 있음 → 재조회 오류** | 1차 GET 후보 확인 → 새로고침 클릭 → 2차 GET 500 오류 → `role="alert"` 에러 배너 노출, 기존 후보 및 승인/거절 버튼 완전 초기화(`setCandidates([])`) 확인 → 재시도(Retry) 클릭 시 로딩 중에도 과거 후보 플래시 노출 차단 확인 | catch 블록에서 `setCandidates([])` 제거 | **FAIL** (`AssertionError: expected '...' not to contain 'Node-02-Candidate'`) 포착 실증 |
| **Error 상태 + 후보 데이터** | `initialCandidatesState="error"` 상태에서 후보 데이터가 주입되어도 에러 가드(`candidatesState !== 'error'`)에 의해 운영 버튼 및 후보 카드가 완전 차단됨을 단언 | `candidatesState !== 'error'` 렌더 가드 제거 | **FAIL** (`AssertionError: expected '...' not to contain '승인 & 토큰 발급'`) 포착 실증 |

*모든 돌연변이 테스트 후 코드는 정상 상태로 원복되어 8/8 통과함을 확인.*

### 2.3 실행 성공과 산출물 무결성 검증의 엄격 분리 ([`DeveloperStudio.tsx`](file:///C:/Project/SaintVision-Invion/apps/web/src/features/studio/DeveloperStudio.tsx#L2009-L2035))
- `isOutputVerified = currentRun?.state === 'succeeded' && Boolean(artifactData?.verifiedEvidenceId) && !artifactData?.fallbackUsed`
- `isOutputVerified === true`: `✓ 산출물 검증 완료 (Output Verified)` (초록)
- `artifactData?.fallbackUsed === true`: `⚠️ 산출물 아티팩트 폴백 (Artifact Fallback / UNVERIFIED)` (노랑)
- `currentRun?.state === 'succeeded'` (증거 미발급): `⚠️ 실행 완료 · 출력 무결성 미검증 (Completed / UNVERIFIED)` (노랑)
