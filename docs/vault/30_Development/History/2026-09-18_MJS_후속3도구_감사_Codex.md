## 실행과 범위

세 파일 전문을 읽고 PASS 입력·실제 I/O·합격 종료 경로를 추적했다. 2-PC 및 reconciliation의 실제 runner 소스에서 crypto import만 제거해 Node VM에 같은 crypto와 합성 fetch를 주입했다. 실제 서버·브라우저·PC·GPU·Docker·PG는 사용하지 않았다. 수정한 제품 함수를 복제해 시험하지 않았고 process.exit는 결과 수집을 위해 가로챘다. 합성 응답은 일부러 새 dispatch와 다른 run/node의 receipt 및 잘못된 digest를 제공했다.

명령 `node docs/vault/30_Development/Evidence/verification-boundary-audit/mjs-observation-audit.mjs . docs/vault/30_Development/Evidence/verification-boundary-audit/mjs-observation-results.json` exit0. 스크립트의 exit0 자체는 감사 실행 종료일 뿐 제품 합격이 아니다. JSON에 대상 소스hash·요청목록·각 종료코드·실제 runner summary를 보존했다.

## VB-MJS-03 / P1 — 새 실행·receipt·output 결속 없이 실제2PC/GPU 검증 선언

2-PC 도구 :267의 receipt는 새 dispatch runId로 찾지 않고 고정 rcp_01JSHARD_03을 읽는다. receipt.runId/nodeId/attempt/epoch와 방금 실행한 요청 사이의 결속 검사가 없다. :225는 outputHash 접두사만, :274 부근은 receipt.output.sha256 존재만 확인한다. bytes 다운로드 후 해시 재계산은 없고 GPU 작업·학습 결과를 관측하는 실행 증거도 없다. pool telemetry/응답 boolean을 읽는 것이 실제 GPU 실행 검증은 아니다. FRONTEND_URL은 출력만 하며 브라우저 접근도 없다.

실측: run_synthetic_new_dispatch를 dispatch했지만 receipt는 UNRELATED_RUN/UNRELATED_NODE이고 outputHash는 sha256:not-a-digest였다.67/67 exit0. 따라서 실제 실행·결과 결속의 반증 조건이 빠졌다. reconciliation도 shard.receiptId=UNRELATED_RECEIPT와 successReceipt 간 실제 참조/hash 대조 없이59/59 exit0이었다.

수정 조건: 현 도구를 응답 필드 smoke로 정확히 표시하고 실2PC/GPU/화면 인수 인증에서 제외하거나, 실제 dispatch identity→claim/node/attempt/epoch→서명/stop receipt→artifact bytes/digest를 연결하고 다른 run/node/오래된 receipt/손상bytes를 거부하는 대조군을 추가한다. 실제 장비 인수는 별도 권한/환경 조건 후 수행한다. 수정 owner Gemini(현 runner), 계약 reviewer Codex. 미수정 finding.

## VB-MJS-04 / P2 — 로컬 상수 해시 비교를 Workspace frozen snapshot 대조로 표시

reconcile_receipts_evidence.mjs:152~156의 서로 다른 두 상수 문자열을 Node crypto로 해시한 뒤 origHash!==modHash를 'Working copy content edit yields different hash than frozen snapshot' PASS로 보고한다. 현재 조회한 currentResume.inputHash나 실제 편집기/서버 snapshot bytes와 이 두 해시는 연결되지 않는다. 위59/59 실행에서는 currentResume.inputHash=sha256:not-a-digest여도 이 단언이 PASS였다.

이는 SHA256 라이브러리에 대한 작은 예시로는 의미가 있으나 제품의 편집/동결 무결성을 보증하지 않는다. 수정 조건: 실제 working bytes와 서버가 결속한 frozen bytes/digest를 각각 관측하고, 잘못된 snapshot/mismatched digest 음성 대조군을 만든다. 그 전에는 로컬 해시 예시로 분리하고 제품 인수 PASS에 합산하지 않는다. owner Gemini, reviewer Codex. 미수정.

## VB-MJS-05 / P2 — 실패 결과에서도 무조건 verified 최종 문구

수정 조건: 성공/실패/미검증을 구조화하고 최종 메시지를 실제 결과 및 실행범위와 일치시킨다. 숫자상 모든 응답 조건이 통과해도 UI/장비 관측이 없다면 그 scope는 미검증이다. owner Gemini, reviewer Codex. 미수정.

## reproduce_handoff_review.mjs 판정

이 도구는 지정 checkout의 ReleaseManager/recoveryEngine/DeploymentManager를 메모리에서 불러 관측 JSON을 쓰는 재현 도구다. scope에 browser/traffic/TLS/training/deployment 없음이 명시되고, passedChecks·합격 판정기가 없다. false/위험한 결과도 raw field로 보고하며 import/메서드 오류를 성공으로 감싸는 catch도 없다. 이번 소스 범위에서는 추가 false-PASS finding을 확인하지 않았다. exit0는 JSON 수집 완료이지 제품 합격이 아니다.

명시한 소스 검토만 수행했고 해당 도구의 타입스크립트 모듈 실행/브라우저 검증은 재실행하지 않았다. 출력 JSON을 다른 사람이 어떻게 합격에 사용하는지의 하류 감사는 별도 잔여다. 계산 contrast는 고정 색상 대조이며 실제 CSS/렌더링 측정이 아님도 유지한다.
