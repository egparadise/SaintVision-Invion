# VF-CL-05 VF-CX-02 model 계약 독립 검토 (Claude)

## 범위

Codex `agent/codex/vf-cx-02`의 model 계약 커밋 `d6d9d87`("Add verified model manifests with immutable catalog references and lease fencing")을 **소스 수준 독립 검토**. 대상: `migrations/0039_model_manifest.py`, `services/control-plane/src/inv/model_manifest.py`, `model_commit.py`. 이는 fencing 포함 고난도 커널 계약(Codex 도메인)이며 **수정하지 않고 finding으로 인계**한다. 브랜치 미체크아웃 — 소스 정독 검토이고 그 브랜치의 시험을 여기서 실행하지는 않았다.

## 검증한 명제 (전부 참으로 확인)

**스키마(0039)**
- `model_manifests` PK(tenant,project,model,version), manifest JSONB(`jsonb_typeof=object`), manifest_sha256 hex64, source_run_id→inv.runs FK, recovery_epoch, `committed_at DEFAULT clock_timestamp()`. CHECK로 manifest JSONB의 modelId/version이 컬럼과 일치.
- `model_shard_locations` PK(tenant,project,model,version,location_id), FK→model_manifests, **FK→public.data_locations(tenant_id,location_id)** — 즉 커널이 내 카탈로그를 참조.
- RLS ENABLE+FORCE+tenant_isolation(USING+WITH CHECK). `REVOKE ALL FROM PUBLIC,inv_app,inv_kernel` 후 `GRANT SELECT,INSERT TO inv_kernel`. immutable 트리거(UPDATE/DELETE 금지). downgrade는 RuntimeError(forward-only).

**계약(manifest_copy)**
- version이 {latest,current,head} 금지(mutable alias 차단). runtimeCompatibility adapter 중복 금지. **shards가 index·offset·totalBytes로 연속 타일링 강제**. replica가 (shardIndex,nodeId) 유일·locationId 유일·모든 shard 커버. encryption/keyRef 일관성((none)==(keyRef is None)).

**검증기(ConfiguredModelVerifier.verify)**
- operator RootBinding만 권위(경로·caller 플래그는 권위 아님), 암호화 모델 거부, byte budget 상한, ReadRoot로 traversal/link/변경파일 거부, shard별 실 bytes hash 재계산, contentHash를 shard index 순 첫 replica로 누적해 대조. 반환은 canonical manifest의 sha256.

**commit 흐름(fencing)** — 모범적:
- verify(파일 I/O)를 **트랜잭션 밖**에서 수행. 그 전(첫 txn)과 후(둘째 txn)로 `_capture` 스냅샷((run version/attempt),(location/contribution version·checksum))을 계산해 **동일성 재확인 → TOCTOU 차단**.
- 각 replica 노드에 recovery_epoch·heartbeat 15s·online·public active 펜싱(FOR SHARE). storage_contribution은 principal 소유(registered_by_user_id==owner)만.
- `assert_fences`를 _capture와 commit 말미(INSERT 후)에 재확인 — "INSERT/uniqueness/trigger 대기가 실행 권한을 넘지 못한다".
- idempotency ledger(key)로 replay는 durable commitment의 read이지 새 permit 아님. 동일 (tenant,project,model,version) 재커밋은 UniqueViolation→MODEL-0003.
- 결과에 `requiresExecutionRevalidation: True` 일관 표시(커밋은 verify 시점 bytes 인증이지 실행 시점 인증 아님).

## Finding (수정 아님, Codex 인계)

1. **shard 수 상한 불일치**: migration은 `shard_index BETWEEN 0 AND 1023`(≤1024)인데 `manifest_copy`는 shard 수를 상한하지 않는다. >1024 shard 매니페스트는 manifest_copy/verify를 통과하나 `model_shard_locations` INSERT의 CHECK에서 거부된다. fail-closed지만 거부가 늦고 불명확(CHECK violation, MODEL-000x 아님). **권고**: manifest_copy에서 shard 수 상한을 명시해 조기·명확 거부.
2. **두 model 개념 경계 명확화**(정합성): 커널 `inv.model_manifests`(shard/replica 커밋, inv_kernel 전용)와 S10 `public.model_versions`(내 VF-CL-03 registry/lineage, ADR-010 `inv://models/<name>@<version>`)는 **별개**다. 커널 매니페스트는 내 `data_locations`를 참조하지만 `model_versions`와는 연결이 없다. 두 개념의 수렴(예: 커밋된 매니페스트가 ModelVersion을 참조)인지 영구 분리인지 Codex 계약에서 명확히 하길 권고. VF-CL-03 license/classification 필드 위치도 이와 연동.
3. **migration 번호 발산**: integration(`b9752a8`)의 체인은 …0007_locality→0001_core인데 vf-cx-02는 …0038→0039다. vf-cx-02가 다른 base(workspace-bridge 계열 kernel) 위에 있음을 시사. CX-01 통합 시 migration 체인 조정이 필요(Codex 몫, 여기 기록만).

## VF-CL 영향 (내 카드 경계 재확정)

- **VF-CL-01/03 "model 결속"은 app-role 작업이 아니다**: model_manifests는 inv 스키마·inv_kernel 전용이라 내 app-role 코드가 직접 못 읽는다. 커널이 내 `public.data_locations`를 FK 참조하므로, **내 VF-CL-01 카탈로그가 substrate이고 매니페스트 계층은 커널/Codex**다. 내가 만든 catalog/resolver/replica_repair가 그 substrate로서 정합함을 확인.
- 따라서 VF-CL-01/02/03의 계약 무관 부분은 완결 상태로 유지되고, 추가 model 결속 코드는 커널 API 경유이지 app-role SQL이 아니다.
