# 2026-11-04 Node 인증서 관측 검증 오류와 해결

카드 `PROJECT-NODE-CERTIFICATE-OBSERVATION`, owner Codex, reviewer Claude pending. 코드/환경/최종 명령은 [[2026-11-04_Project_Node_인증서_관측_계약_Codex]]에 결속한다. 이 페이지는 실패를 성공 합계에서 숨기지 않기 위한 별도 기록이다.

1. 최초 disposable PG 실행은 실제 0 passed / 5 setup errors, exit 1이었다. 재사용한 `usage_api` fixture가 의존하는 `approval`을 새 test module에 명시적으로 import하지 않은 원인이었다. transitive import가 pytest fixture 등록까지 전파한다고 가정하지 않고 prerequisite를 명시했다.
2. 두 번째는 2 passed / 3 failed, exit 1이었다. 시험이 channel expiry/enabled/epoch를 직접 바꾸며 version을 증가시키지 않아 기존 `inv.channel_monotonic`가 `23514`로 거부했다. 제품 trigger를 바꾸지 않고 소유 fixture의 update에 `version=version+1`을 적용했다.
3. 최종은 실제 PG/HTTP 6 passed, exit 0, skip/error/failure 0, 소유 컨테이너 제거 확인이다. XML/proof SHA와 KST는 위 구현 History에 보존했다. 앞선 invocation의 unique `.work/vf-runs` 기록은 그대로 남기며 같은 prefix의 마지막 요약을 이전 성공처럼 읽지 않는다.

소유 disposable DB만 사용했고 운영 DB·channel·인증서·Node를 바꾸지 않았다. 제품 browser/5노드 운영 인수는 여전히 별도 검증 대상이다.

4. Hosted Frontend `41774468131`의 Portal Container Build는 `nodeCertificateObservation.ts`의 root schema import를 찾지 못해 TS2307로 실패했다. 일반 frontend job과 local workspace build는 전체 repo를 보므로 이 누락을 드러내지 못했다. 원인은 portal Dockerfile의 COPY와 전용 Dockerfile.dockerignore 양쪽의 context 누락이다. 정본 한 파일만 명시적으로 포함한 뒤 실제 Docker/Node 22 container build exit 0을 확인했다. 검토 판정과 이미지 ID는 구현 History의 13:52 KST 절에 결속한다. 로컬 성공을 hosted 재검증이나 runtime 인수로 대신 쓰지 않는다.
