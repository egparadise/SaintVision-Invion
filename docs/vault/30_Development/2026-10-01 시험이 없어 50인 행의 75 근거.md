# 2026-10-01 시험이 없어 50인 행의 75 근거

## 0. 한 줄 답

| 행 | v1.6 | 이 카드 뒤 | 근거 |
|---|---:|---:|---|
| **S02-ST** | 50 | **75** | **이미 있었다** — `tests/core/test_storage_list_response_contract.py` |
| **S09-ST** | 50 | **75** | **이미 있었다** — `tests/test_context_eval.py`의 **artifact-pin 3건** |

**두 행은 시험이 없던 것이 아니라 제가 찾지 못한 것이었다. 한 행은 시험이 없던 것이 아니라 구현이 없던 것이었다.** 그 두 사실과 원인이 이 문서의 절반이다.

> **r2 변경**: v1.0은 S08-BE를 50 → 75로 올리겠다고 적었다. 독립 검토(#261)가 두 가지를 짚었고 **둘 다 맞다** — 새 시험이 실제 제품 경로(`RunStore.create`)를 부르지 않았고, §5-1의 ROOF 구현 근거가 **`grep -i roof`가 `proof`를 잡은 결과**였다. 시험은 제품 경로로 고쳤고(§5-3), 점수는 **50으로 되돌렸다**(§5-1·§5-5). S09-ST는 지적대로 **3건으로 좁혔다**(§4).

## 1. 정정 — [[2026-09-28 48 task 진행률 재채점]] v1.6의 검색이 **파일명만** 봤다

v1.6 §4-3-5는 세 행을 "task 고유 시험 없음"으로 50에 두었고, 그 판단의 근거는 이것이었다.

```
git ls-tree -r --name-only <tree> -- tests/ | grep -icE "storage_policy|contribution"   -> 0
git ls-tree -r --name-only <tree> -- tests/ | grep -icE "kill|switch|gpu|buildkit|roof" -> 0
```

**`git ls-tree --name-only`는 파일 이름만 돌려준다.** 그래서 `storage-contributions-response.json`을 **내용으로** 다루는 `test_storage_list_response_contract.py`가 검색에 걸리지 않았다. 이름에 `contribution`이 없기 때문이다.

내용으로 다시 검색하자 두 행의 시험이 나왔다.

```
grep -rln -iE "storage/locations|DataLocationPage|data_locations" tests/
  -> tests/core/test_storage_list_response_contract.py
grep -rln -iE "trace.*artifact|artifact.*trace|eval.*artifact" tests/
  -> tests/test_context_eval.py
```

**이것은 v1.2가 고친 것과 같은 실수다.** 그때는 `2,775`를 markdown에서만 검색해 "task별 baseline이 없다"고 단언했고, baseline은 Evidence 디렉터리의 JSON에 있었다. v1.2는 그 교훈을 "**결론을 검색 범위 하나로 내린 것이 잘못이었다**"라고 적었다. v1.6에서 같은 형태로 다시 틀렸다 — 이번에는 범위가 **파일명**이었다.

### 1-1. r2 — 같은 실수의 **세 번째** 판: 이번에는 **일치한 문자열을 보지 않았다**

v1.0의 §5-1은 S08-BE의 네 낱말 모두 "코드가 있다"고 적었고, ROOF의 위치로 `src/saintvision/adapters/cli.py`·`src/saintvision/services/pilot.py`·`src/saintvision/services/replica_observation.py`를 들었다. **셋 다 틀렸다.** 근거가 `grep -i roof`였고, 그것이 잡은 것은 `proof`였다.

낱말 경계로 다시 세면 이렇다.

```
grep -rnwi 'roof' --include=*.py --include=*.go --include=*.ts --include=*.tsx services/ src/
  -> 1건. services/node-agent/runtime/permit_test.go:26 의 PolicyVersion: "roof:test:1"
     (Go 시험 안의 문자열 상수다. 구현이 아니다.)

세 파일 각각:  roof(낱말) 0건 / proof 2건·1건·1건
```

`-i`는 켰고 `-w`는 켜지 않았다. v1.2는 "범위"였고 v1.6은 "파일명"이었고 이번은 "**일치 자체를 확인하지 않은 것**"이다. 세 번 모두 같은 형태 — **한 번의 검색 결과를 읽지 않고 결론으로 썼다.** 그래서 이 문서는 아래의 모든 존재/부재 주장에 **실행한 명령과 건수**를 같이 적는다.

## 2. 방법 — 행마다 "무엇을 관측하면 75인가"를 먼저 적는다

[[2026-09-18_Codex_진척률재채점]] rubric의 75는 **"상당한 구현과 관련 로컬/고정 SHA 시험 확보"** 다. v1.6이 표 전체에 적용한 규칙을 그대로 쓴다.

1. **시험 건수는 점수가 아니다.** 48건을 더했다는 것이 75의 근거가 아니고, 그 시험이 **이 행의 수용 기준을 관측한다**는 것이 근거다.
2. **한 시험이 두 행을 funding하지 않는다.** 후보마다 재채점 문서에서 인용 횟수를 세어 **0인 것만** 썼다.
3. **75의 천장 사유는 유지된다.** 세 행 모두 100은 외부 전제·운영 인수를 기다리고, 이 카드는 그것을 건드리지 않는다.
4. **없는 것을 있다고 적지 않는다.** 하드웨어가 필요한 관측은 시험으로 흉내내지 않는다. **r2 추가**: 구현이 없는 축은 **거부 시험으로 대체하지 않는다.** 거부는 지원이 아니다.
5. **r2 추가 — 시험은 제품 경로를 부른다.** helper를 직접 부르는 시험은 그 helper가 **아무 경로에서도 불리지 않게 되는** 변이를 보지 못한다. 그런 시험은 guard가 컴파일된다는 것만 증명한다.

## 5. S08-BE — ROOF·kill switch·BuildKit·단일 GPU → **50 유지**

### 5-1. 네 낱말 중 **구현이 있는 것은 하나**다

v1.0의 이 절은 네 낱말 모두 "코드가 있다"고 적었다. 낱말 경계 검색으로 다시 세면 다르다.

| 낱말 | 실제 | 명령과 건수 |
|---|---|---|
| **ROOF** | **없다** | `grep -rnwi roof --include=*.py --include=*.go --include=*.ts --include=*.tsx services/ src/` → **1건**, 그것도 Go 시험 안의 문자열 `"roof:test:1"`. v1.0이 든 세 파일은 `roof` **0건** / `proof` 1~2건 |
| **kill switch** | **있다** | `services/control-plane/src/inv/containment.py:15 require_execution()`. `runs.py:46 RunStore.create()`·`runs.py:72 _transition()`이 부른다 |
| **BuildKit** | **없다** | `grep -rni buildkit ... services/ src/` → **1건**, `workspace_api.py:36`의 **docstring 낱말**. daemon·socket·privileged·host access·build 경계 **0건** |
| **단일 GPU** | **지원 아님** | `sandbox.py:117`이 `resources["gpuCount"] != 0`을 **거부**하고, `placement.py:58-64`는 측정된 GPU provider가 없으면 **fail closed**. `scheduler.py`에 device·VRAM 선택 코드는 있으나 실행 경로가 닫혀 있다 |

**그래서 75가 되지 않는다.** rubric의 75는 "상당한 구현과 관련 시험"이고, 이 행의 scope 네 축 중 **셋에 구현이 없다.** 거부 시험을 모아서 지원을 증명할 수는 없다 — ROOF 한계를 거부로 바꿔 적을 수도, BuildKit daemon 경계를 docstring으로 대체할 수도, GPU 지원을 GPU 거부로 대체할 수도 없다.

### 5-2. 그래도 시험은 고쳤다 — **helper가 아니라 제품 경로**

v1.0의 시험은 `require_execution(conn)`을 **직접** 불렀다. 검토가 그 결함을 정확히 짚었다 — `runs.py`의 `require_execution(conn)` **호출을 지워도 48건이 전부 통과**했다. helper는 물으면 여전히 거부했고, **아무도 묻지 않게 된 것**을 시험이 보지 못했다.

이것은 §2-5가 된 교훈이다. 고친 방식:

| 새 시험 | 관측 |
|---|---|
| `test_run_creation_is_stopped_by_the_gate_before_anything_is_written` | `RunStore.create()`를 부른다. 닫힌 gate에서 **`inv.runs` 쓰기 문장이 하나도 실행되지 않는다** |
| `test_run_creation_reads_the_gate_before_it_inserts` | 양성 대조 + **문장 순서** — gate 질의가 INSERT보다 **앞**이다. 뒤에 읽는 gate는 gate가 아니다 |
| `test_a_state_change_into_execution_is_stopped_by_the_gate` | `RunStore.transition(..., "scheduled")`. `FOR UPDATE` lock은 일어나고 `UPDATE inv.runs`는 일어나지 않는다 |
| `test_a_state_change_passes_a_cleared_gate` | 위의 대조 |

문장 단위로 답하는 연결 stub(`ScriptedConnection`)이 **질문의 순서를 기록**하므로, PostgreSQL 없이 "무엇이 먼저 실행됐는가"를 관측한다.

### 5-3. 시험 파일 — 이름도 고쳤다

`test_s08_be_kill_switch_buildkit_gpu_refusals.py`(엷 이름) → **`tests/core/test_s08_be_kill_switch_execution_gate.py`**.

v1.0은 "파일명 검색으로도 찾히도록 `buildkit`·`gpu`를 이름에 넣었다"고 적었다. 그 두 낱말의 제품 경로가 없다는 것이 §5-1이므로, 그 이름은 **없는 것을 광고하는 이름**이었다. 파일이 실제로 관측하는 것은 kill-switch 실행 gate와 containment 인자 guard, 그리고 운영자 Workspace config 거부다.

**54 passed.** PostgreSQL·Docker·GPU **모두 필요 없다** — 이 거부들은 DB 앞에서, 또는 transaction 안의 첫 문장에서 결정된다.

### 5-4. 변이 — 9종 중 8종 사망, 1종은 **다른 파일이 죽인다**

| 변이 | 대상 | 결과 |
|---|---|---|
| **`RunStore.create()`가 `require_execution`을 부르지 않는다** | 이 파일 | **사망** (v1.0에서는 생존했다) |
| 제어 행이 없으면 kill switch가 **열린다**(fail-open) | 이 파일 | **사망** |
| 활성 kill switch가 실행을 멈추지 않는다 | 이 파일 | **사망** |
| 아무 operation 이름이나 받아들인다 | 이 파일 | **사망** |
| 범위가 operation과 무관해진다 | 이 파일 | **사망** |
| idempotency key가 필요 없어진다 | 이 파일 | **사망** |
| 알 수 없는 할당 key를 받아들인다 | 이 파일 | **사망** |
| cpu와 memory가 같아도 된다 | 이 파일 | **사망** |
| **`compile_launch`가 GPU workload를 허용한다** | 이 파일 | **생존** — 이 파일은 더 이상 GPU 경로를 주장하지 않는다 |
| 같은 변이 | `tests/core/test_sandbox_contracts.py` | **사망** (`test_profile_limits_block_unapproved_execution[gpu]`) |

마지막 두 줄이 중요하다. GPU 거부 경로에는 **이미 제품 경로 시험이 있다** — 그러나 그 파일은 재채점 문서에서 **`S03-BE`를 funding하고 있고**, 한 시험을 두 행에 두 번 세지 않는다(§2-2). 그 파일을 복제해 S08-BE에 붙이는 것은 **시험 수로 점수를 올리는 일**이므로 하지 않았다.

### 5-5. 그래서 이 행의 점수는 **50**이다

| | |
|---|---|
| 지금 묶인 것 | kill switch 축 — 실행 gate가 **Run 생성과 상태 전이 경로에** 결속됐다 |
| 열리지 않은 것 | ROOF(구현 없음) · BuildKit(docstring 1건) · 단일 GPU 지원(실행 경로 닫힘) |
| 50 → 75 조건 | 위 셋 중 최소한 **구현이 생기는 것**. 시험이 아니라 구현이 선행 조건이다 |
| 100 조건 | 실 단일 GPU 장비와 보안 시나리오·복원 보고의 운영 인수(`G-19`) |

새 시험은 재채점 문서에 **점수 근거가 아니라 부분 증거**로 기록한다 — "kill-switch 실행 gate가 `RunStore` 경로에 결속됨".

## 6. 하지 않은 것

- **점수를 올리지 않았다.** [[2026-09-28 48 task 진행률 재채점]]은 **#258에서 검토 중**이고, 두 branch에서 같은 문서를 고치면 충돌한다. #258이 착지한 뒤 v1.7에서 **S02-ST·S09-ST 두 행만** 50 → 75로 옮기고, `S08-BE`는 **50에 두되 §4-3-5의 근거 문장을 정정**한다(지금 문장은 "그 이름의 시험 파일이 없다"인데, 실제 사유는 "**네 축 중 셋에 구현이 없다**"다).
