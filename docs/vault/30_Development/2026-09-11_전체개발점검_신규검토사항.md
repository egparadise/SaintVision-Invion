# 전체 개발 점검 신규 검토 사항

검토 대상: Gemini `268b4008a8380854b812834738305d463867c3e1`, Claude `6a11a036ffa0f35e472500cc5aa2e18f0bac5a20`; 정본 결과/준비 계약은 Codex `f4fe37e`/ADR-070. 이번 검토는 코드·기존 기록을 읽은 정적 검토다. 새 브라우저·복원·물리 장비 시험을 수행했다고 주장하지 않는다. 판정은 아래 수정 및 검증이 필요한 상태다.

## Gemini — 아직 실제 결과와 준비 상태를 보장하지 않는 경로

1. **P1, 준비 API 실패를 충족 상태로 바꿈.** `apps/web/src/features/studio/DeveloperStudio.tsx:203`의 catch는 계정·역할·Workspace·도구 체크를 true로 만들어 `executable: isLinked`를 반환한다. API 장애/401/403이면 미확인 또는 권한 오류로 남기고 다음 실행 단계 진입을 막아야 한다. 최신 정본은 checks 7개(입력 준비 포함), executable=false, admissionRequired=true이며 배열과 개별 사유를 그대로 표시해야 한다. 이 지적은 UI의 허위 준비 상태이며 실제 커널 승인 우회가 재현됐다는 뜻은 아니다.
2. **P1, 결과가 없는 Evidence/receipt를 만들어 표시.** 같은 파일 `:355`는 `evi_${runId}`와 exitCode 0을 생성하고 `:519`의 다운로드도 succeeded만으로 physicallyStopped/verified/resourceReclaimed를 true로 만든다. 응답의 null/부재를 보존하고 실제 receipt·Evidence·미반납 lease 상태만 보여야 한다.
3. **P1, 실제 파일 다운로드 미연결.** `:497`은 옛 `/artifacts/download`를 호출한 뒤 메모리에서 JSON 요약을 만들며, 정본 `/artifacts`와 `/artifacts/content?path=...`의 검증된 파일 바이트를 받지 않는다. 결과 envelope hash와 각 파일 hash도 구분해야 한다. 실제 파일 저장 후 해당 파일 SHA-256을 대조하는 브라우저 검증이 합격 증거다.
4. **P1, 정본 URL을 흉내 낸 별도 서버.** `src/saintvision/server.py:1864`의 새 result/attempt/artifact route는 전역 RUNS/RECEIPTS와 고정 크기·생성 ID를 읽고 `source=execution-kernel`이라 응답한다. URL 이름이 같은 것으로 정본이 되지 않는다. 개발 fixture는 분리·명시하고 운영 `/v1`는 실제 `inv.app` 조합으로 연결해야 한다. 파일 헤더의 Production 문구와 시험 수로 운영 완료를 증명할 수 없다.
5. **P2, 자원/관측 표시 일부 잔존.** `NodeDetail.tsx:190`의 Workspace ID는 고정값이며 `:191`의 물리 총량−allocatable은 실제 lease 점유량이 아니다(제공하지 않은 자원까지 포함). `:203`은 stale/offline 분기 없이 Heartbeat OK로 출력한다. 원본 freshness/lease/offer 각 의미대로 표시해야 한다.
6. **P1, AI 평가·모델 계보가 예시임을 명시.** `agent/agentEngine.ts:127`은 Prompt 99/100·coding 24/30·누출 0을 상수로 반환한다. `mlops/mlopsEngine.ts:4`의 학습·배포 계보도 예시 목록이다. 실제 평가/MLflow/모델 조회 전에는 미측정으로 표시하고 AC-09/10 인수 수치로 사용하지 않는다.

## Claude — 새 복원 도구는 진척이지만 전체 복원 합격은 아님

6a11a03 작성자 보고에는 590,148 byte DB, RTO 6.5~12.1초, 오래된 backup의 fencing 역행 거부가 기록되어 있다. 따라서 과거의 '리허설 한번도 안 함'은 최신 상태가 아니다. 이번 감사에서는 이 측정을 다시 실행하거나 원본 실행 JSON을 독립 확인하지 않았으므로 **작성자 로컬 실측 보고**로 표시한다.

1. **P1, 검사 실패를 0으로 바꿔 fencing을 통과시킬 수 있음.** `tools/recovery_drill.py:170,177`에서 sequence/lease 조회 실패를 issued=0/held=0으로 바꾸고 `:332`는 advance==0이면 verified로 계산한다. 조회 실패/권한 부족/관계 부재는 unknown 또는 실패로 끝내고 통과 기록을 거부해야 한다.
2. **P1, 복원 무결성 범위가 public 일부에 한정.** `:59,126,146`은 public ORM 테이블 개수와 public 4개 테이블 digest를 검사한다. 정본 `inv.evidence`, `inv.run_attempts`, checkpoint/outbox/lease의 내용과 실제 object 바이트, Node journal, key 참조, 역할/ACL은 전체 복원 검사에 포함되지 않는다. 양쪽에 같은 테이블이 없으면 -1/absent가 같아 통과하는 경로도 막아야 한다. `--no-owner --no-privileges` 리허설을 운영 권한 복원 검증으로 표시하지 않는다.
3. **P2, RPO/RTO 측정 경계 보완.** `:226,307`은 파일 mtime 또는 dump 완료 시점부터 검사 시점의 시간 차이를 RPO로 쓴다. 이것은 복구한 마지막 커밋/LSN과 장애 시점의 차이를 확인한 값이 아니다. 원본 변화와 일관된 snapshot의 비교, WAL/PITR, 복원 후 fencing 재설정·앱 기동·실제 안전 작업 재개까지 별도 측정해야 한다. RTO 현재 값은 DB 복원/일부 검사 범위로 남긴다.

## 다음 소유자와 합격 증거

Gemini는 위 6개 UI/API 경로를 정본 계약으로 고치고 실제 인증 앱을 대상으로 실패·누락·바이트 다운로드 브라우저 증거를 남긴다. Claude는 복원 도구의 실패 기본 거부·전체 데이터/권한 검사·시간 지표를 보완한다. Codex는 fencing/결과 계약과 보완 코드를 재검토한다. 이번 문서는 수정 코드도, 저자 대신 수행한 시험 기록도, 독립 승인도 아니다. 운영 서버/DB/Node 설정은 바꾸지 않았다.
