# S01-BE · S01-ST 잔여 합격 조건 표

registry `in_progress` 2건(owner Codex, reviewer Claude). 둘 다 **AC-01**(OUT-01 "완성 목표와 계약을 모든 Agent가 동일하게 해석한다"; 기준 "계약과 owner 누락 0, 5노드 조사표의 미확인 값 명시"), 요구 증거 **계약 검증 · 설계 검토 · 인벤토리 보고**. 아래는 증거 단위로 **충족 / 미충족(우리 몫) / 외부 대기(사용자 입력)**를 가르고, 외부 대기는 [[S02_선행입력_체크리스트_2026-09-22]]의 절 번호에 연결한다. 근거: [[2026-09-22_S01_기반셋_왜안닫혔나_검토_Claude]] · [[2026-09-22_Codex_registry_closure_candidate_audit]] · [[2026-09-22_Codex_user_input_impact_map]]. **이 표는 판정이 아니라 잔여 목록이다** — 닫힘은 owner Codex가 증거 대조 후 처리한다(self-close 금지).

## 1. S01-BE — 저장소·계약·개발 환경·권한 경계

| 요구 증거 | 세부 | 상태 | 근거 / 남은 일 |
|---|---|---|---|
| 계약 검증 | 정본 schema·계약 시험·export drift·contract bindings·contracts:check·CI 백엔드 스위트 | **충족(기록 갱신 필요)** | 실측은 있음(migration head 0045, 게이트 GREEN, hosted backend 2645 passed). 합격증거 기록의 "0001~0006"이 stale → **owner가 기록 갱신**(우리 몫) |
| 설계 검토 | Codex 기반물 독립 검토(쓰기응답·contribution·artifact-content·discovery tenant/자격증명·migration head·retry) | **충족(consolidate 됨)** | [[2026-09-22_S01_소프트웨어_peer_review_통합_Claude]]로 묶임(소프트웨어 범위) |
| 인벤토리 보고 — 개발 환경 | 로컬 개발환경 구성·검증 | **충족** | [[2026-09-11_DEV-ENV_Codex_로컬개발환경구성과검증]] |
| 인벤토리 보고 — 권한 경계(소프트웨어) | RLS·NOLOGIN·tenant 격리·운영자 자격증명 발급 | **충족** | 독립 검토 완료([[2026-09-21_운영자자격증명발급_독립검토_Claude]]) |
| 권한 경계 — **실제 IdP 연결** | 실 issuer/JWKS로 `/readyz` ready·`/v1/session` 200/401 | **외부 대기 U2·U4** | 체크리스트 §1·§3 성공 신호 |
| 권한 경계 — **실제 CA 연결** | `INV_NODE_MTLS_CA_BUNDLE` 채움·잘못된 CA 거부 실측 | **외부 대기 U3** | §2; `/v1/health.unresolvedSettings`에서 사라져야 함 |
| 5노드 조사표의 미확인 값 명시(AC-01) | 조사표에 "시각 동기화 소스·현재 스큐" 등 미확인 항목 표기 | **미충족(우리 몫, 작음)** | U5 입력 전이라도 **미확인 값 목록**은 지금 작성 가능 — S01-ST 인벤토리 표 초안에 포함 |

**S01-BE 닫힘 조건 요약**: (우리) 계약 증거 기록 갱신 + 미확인 값 목록 → (사용자) U2·U3·U4 → (검증) §1~§3 성공 신호 실측 → owner 대조 후 done.

## 2. S01-ST — URI·보존·제품 검증·장비 인벤토리

| 요구 증거 | 세부 | 상태 | 근거 / 남은 일 |
|---|---|---|---|
| 계약 검증 | Contribution/DataLocation/StorageObservation 결속·시험, artifact-content `X-Content-SHA256` | **충족** | 계약 좁힘·실 PG 증거([[2026-09-22_S03_DB_실PG증거_및_ST_정본결정게이트_Claude]] 등) |
| 설계 검토 — URI | `inv://` 리졸버 | **충족** | 코드·시험 존재, 검토 문서 있음 |
| 설계 검토 — 보존 | retention_pinned_until·GC eligibility(CR-07) | **부분 충족** | 정책 완성도(90일/1년 pin/35일) 문서화는 [[Codex 운영 자격증명과 Storage 계약]]; **자동 정리 실측 없음** → 우리 몫(작음) |
| 제품 검증 | Storage 제품(MinIO/S3 호환) 실제 계정·버킷·왕복 SHA-256 | **외부 대기 U6** | §5; `INV_OBJECT_STORE_ENDPOINT` 채워져야 `unresolvedSettings` 비움 |
| 인벤토리 보고 — 장비 5대 | IP·OS·역할·CPU/RAM/GPU·디스크·허용 자원/폴더·NTP | **외부 대기 U1·U5** | §0·§4; 개발 PC를 제품 Node로 임의 등록 금지 |
| 인벤토리 보고 — 허용 폴더/자원 | Node offer + storage-policy | **외부 대기 U5** | §4; 등록 후 `NodeResourceUsage`·`/v1/storage/locations`로 대조 |
| 5노드 조사표의 미확인 값 명시(AC-01) | 위 표에 "미확인" 열 | **미충족(우리 몫, 작음)** | 인벤토리 **표 양식**(열: 장비·값·출처·미확인 여부)을 지금 만들어 U5 입력 시 채움 |

**S01-ST 닫힘 조건 요약**: (우리) 인벤토리 표 양식 + 보존 정리 실측 → (사용자) U1·U5·U6 → (검증) §4·§5 성공 신호 실측 → owner 대조 후 done. **S01-ST가 하드 블로커**(장비+제품)를 안고 있어 사용자 없이는 닫히지 않는다.

## 3. 지금 가능한 우리 몫 (사용자 입력 없이)

1. S01 합격증거 기록의 stale 값 갱신(0001~0006 → 0045, hosted CI 결과 첨부) — **Codex(owner)**.
2. 5노드 인벤토리 **표 양식 + 미확인 값 열** 초안 — **Claude**(다음 카드 후보, 작음).
3. 보존 정리(retention/GC) 실측 1건 — **Claude**(실 PG, 작음).

## 4. 열리는 것

U1~U6이 오면 S01-BE·S01-ST가 후보가 되고, 둘이 닫히면 S02~S12 44개가 의존성상 후보가 된다([[2026-09-22_Codex_user_input_impact_map]]). 입력이 와도 **자동 done은 없다** — 해당 범위 증거를 다시 대조한다.
