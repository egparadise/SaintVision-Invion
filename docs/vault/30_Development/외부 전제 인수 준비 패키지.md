# 외부 전제 인수 준비 패키지

48 task 진행률 재채점(PR **#220**, `docs/vault/30_Development/2026-09-28 48 task 진행률 재채점.md`) v1.3이 보인 결론은 **48개 중 34개가 75점 천장**이고 그 천장을 만드는 것이 **우리 코드가 아니라 `G-15`~`G-26`과 `U1`~`U6`** 이라는 것이다. 이 문서는 그 18개 전제를 **사용자가 가장 빨리 제공할 수 있는 형태**로 정리한다.

분석 tree는 **`9f1c2be4`**(`origin/coord/train-ci-2207`)이고, 인용한 환경변수·경로·명령은 그 tree에서 `git grep`·`git show`로 **실재를 확인**했다. 재채점 문서는 아직 병합 대기이므로 **평문(PR 번호·파일 경로)으로** 인용한다.

이 카드는 **docs-only**다 — 코드 변경 0, 그리고 §4의 LAN pilot 정리는 **읽기 전용**이다(ssh·서비스 재시작·Docker 조작 0건, 상태 파일과 문서만 읽었다).

## 0. 먼저 — 전제를 주는 것이 곧 점수가 되지는 않는다

정직하게 적는다. 전제가 도착하면 **막혀 있던 관측이 열리고**, 그 관측을 **실행해 기록한 뒤에** 점수가 오른다. 그래서 각 항목의 마지막 열은 "**올라가는 점수**"가 아니라 "**열리는 관측과 그때 올라갈 수 있는 task**"다.

각 항목은 여섯 가지를 갖는다.

1. **사용자가 줄 것** — 값·파일·계정·결정 중 무엇인지
2. **양식** — 어떤 형태로 주면 바로 꽂히는지(§5의 템플릿)
3. **꽂히는 곳** — 환경변수·설정·파일 경로(실재 확인)
4. **직후 명령·lane** — 도착하면 바로 돌릴 것
5. **기대 증거** — 그 명령이 남겨야 하는 것
6. **열리는 것** — 어느 task의 어떤 관측이 풀리는지

## 4. `G-19`·`G-24` — 2026-09-23 LAN pilot이 이미 덮은 것 (읽기 전용 정리)

**읽기만 했다** — `ssh` 0건, 서비스 재시작 0건, Docker 조작 0건. 아래는 상태 파일과 병합된 PR 문서에서 읽은 것이다.

상태 경로: `D:/Project/SaintVisionI-Invion/.work/lan-5node/node1`

### 4-1. 이미 덮인 것

| 항목 | 상태 파일에서 읽은 것 |
|---|---|
| **Node 3대 provisioning** | `private-state.json`의 `nodes` 배열에 **3개 항목이 모두 `provisioned: true`** 다 |
| tenant·epoch 고정 | `tenantId`·`epoch`(`recovery_epoch`) 값이 있다 |
| **PKI** | `ca.pem`·`ca-key.pem`·`control-cert.pem`·`control-key.pem`·`signer.pub`·`peer-policy.json`이 있고, node별 CSR(`node1.csr`·`node3.csr`)과 `public/node-cert.pem`이 있다 |
| **node agent 이미지** | `agentImage` digest가 고정돼 있고 `node-agent.tar`(약 13MB)가 있다 |
| **worker 배포물** | `public/worker.zip` + `public/worker.sha256` |
| DB | pilot 전용 PostgreSQL 컨테이너와 migration이 `head`까지 적용된 흔적(`lan_pilot.py:372-374`) |
| 실행 기록 | `serve*.stdout.log`·`observe.stdout.log`가 남아 있다 |
| 병합된 코드 | PR **#89**·**#95** |

**즉 3대까지는 "등록·mTLS enroll·agent 배포"가 실제로 된 적이 있다.** `G-19`가 요구하는 5대 중 3대의 경로는 이미 걸어 본 길이다.

### 4-2. 남은 것

| 남은 것 | 무엇이 필요한가 |
|---|---|
| **4번째·5번째 PC** | 상태 파일의 `nodes`는 **3개**다. 4번째 PC는 당시 **미확인**이었다 — `U5` 인벤토리가 그것을 정한다 |
| **이 PC의 CP 동거 worker** | 당시 **Docker Desktop API 1.41** 제약으로 막혔다. ADR-100이 이 구성을 "CP 겸임 Node 1대"로 분류하고 **timed 분모에서 제외**하므로, 이것이 풀리지 않아도 **all-five smoke의 5번째**는 채울 수 있으나 **eligible 4대**에는 들어가지 않는다 |
| **재현 가능한 실행** | 상태 파일은 **2026-09-23**이고 그 뒤 tree가 크게 바뀌었다(migration 33→70 등). `baseSHA`가 `d01c931a`이므로 **현재 release SHA에서 다시 세워야** 증거가 된다 |
| **비밀 값 재발급** | `private-state.json`에 **DSN 비밀번호가 평문으로** 있다. 이 문서는 그것을 옮겨 적지 않았고, 재사용하지 말고 **재발급**하는 것이 맞다 |

### 4-3. 그래서 `G-19`에 실제로 필요한 것

- **PC 2대 추가**(4번째·5번째) 또는 4번째 1대 + CP 동거를 5번째로 쓰는 결정(`U1`)
- 각 PC의 **계정·허용 폴더·NTP**(`U5`)
- Docker Desktop API 제약을 피할 수 있는 경우 **CP 동거 worker의 eligible 편입 여부 재판단**(ADR-100은 편입하지 않는 쪽이다)

## 6. 이 문서가 확인하지 않은 것

- **명령의 인자 전체를 검증하지 않았다.** `lan_pilot.py`의 `--state`·`--server-ip`·`--node-ip`(`:660-666`)와 `pitr_readiness.py --dsn-env`는 읽었으나, 나머지 도구는 **존재와 목적**을 확인했고 전체 CLI를 실행해 보지 않았다.
- **점수 상승을 약속하지 않는다**(§0). 전제 도착은 관측을 열고, 점수는 그 관측을 기록한 뒤에 오른다.
- **LAN pilot 상태는 2026-09-23의 것**이다(§4-2). 현재 release SHA에서 다시 세워야 증거가 된다.
- **비밀 값을 옮겨 적지 않았다** — pilot 상태 파일의 DSN·비밀번호, node IP, 인증서 내용은 이 문서에 없다. 경로만 적었다.
- **읽기 전용이었다** — `ssh`·서비스 재시작·Docker 조작을 하지 않았고, `G-19`·`G-24`의 현재 장비 상태를 **지금 다시 측정하지 않았다.**
- 실행하지 않았다: 로컬 실 PG·Docker·전체 suite.
