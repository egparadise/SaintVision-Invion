# 외부 전제 인수 준비 패키지

48 task 진행률 재채점(PR **#220**, `docs/vault/30_Development/2026-09-28 48 task 진행률 재채점.md`) v1.3이 보인 결론은 **48개 중 34개가 75점 천장**이고 그 천장을 만드는 것이 **우리 코드가 아니라 `G-15`~`G-26`과 `U1`~`U6`** 이라는 것이다. 이 문서는 그 18개 전제를 **사용자가 가장 빨리 제공할 수 있는 형태**로 정리한다.

분석 tree는 **`9f1c2be4`**(`origin/coord/train-ci-2207`)이고, 인용한 환경변수·경로·명령·argparse 계약은 그 tree에서 `git show`·`git grep`으로 **실재를 확인**했다. 재채점 문서는 아직 병합 대기이므로 **평문(PR 번호·파일 경로)으로** 인용한다.

이 카드는 **docs-only**다 — 코드 변경 0, 그리고 §4의 LAN pilot 정리는 **읽기 전용**이다(ssh·서비스 재시작·Docker 조작 0건, 상태 파일과 로그만 읽었다).

## 0. 이 문서를 지배하는 두 규칙

### 0-1. 전제를 주는 것이 곧 점수가 되지는 않는다

전제가 도착하면 **막혀 있던 관측이 열리고**, 그 관측을 **실행해 기록한 뒤에** 점수가 오른다. 그래서 각 항목의 마지막 칸은 "올라가는 점수"가 아니라 "**열리는 관측과 그때 올라갈 수 있는 task**"다.

### 0-2. "직후 명령"은 그 입력을 **실제로 소비하는** 명령이어야 한다

v1.0의 가장 큰 결함이 여기였다. 여러 항목의 직후 명령이 **합성·dev·hosted 전용 도구**여서, 사용자가 실 운영 값을 줘도 그 도구는 그것을 **읽지 않는다.** 예를 들어 `tools/run_s02_real_api_acceptance.py`는 `start_dev_idp(...)`로 **자기 dev IdP를 띄우고**(`:114`, `:303`) issuer·JWKS 인자가 **아예 없으며**, `tools/collect_s02_acceptance_evidence.py`는 `U2`~`U5`를 **항상 `UNMEASURED`**, `acceptanceClaim`을 **항상 `false`** 로 고정한다(`:21-23`, `:297`, `:323`). 실 IdP를 줘도 이 둘은 `G-15`를 닫지 못한다.

그래서 v1.1은 항목마다 명령을 **세 칸으로 나눈다.**

| 칸 | 뜻 |
|---|---|
| **① 지금 실행 가능(입력 소비)** | 사용자가 준 값을 **실제로 읽는** 명령. 필수 인자를 모두 채운 **1줄**로 적는다 |
| **② 코드 선행(producer 없음)** | 그 전제를 증명할 운영 lane이 **아직 없다.** 우리 몫의 구현이고, 없는 것을 있는 것처럼 적지 않는다 |
| **③ 참고: 기존 축 재확인** | 돌려도 되지만 **외부 인수를 소비하지 않는** 기존 collector. 이 결과로 전제가 닫혔다고 말하면 안 된다 |

항목마다 갖는 것은 여섯 가지다: **사용자가 줄 것 · 양식 · 꽂히는 곳(실재 확인) · ①②③ · 기대 증거 · 열리는 것(직접/의존)**.

### 0-3. v1.1에서 고친 것

독립 검토가 지적한 일곱 가지를 **전부 코드에서 재확인했고 전부 맞았다.**

| # | v1.0의 잘못 | v1.1 |
|---|---|---|
| 1 | `G-15`·`G-23`·`G-25`·`G-26`의 직후 명령이 dev IdP·합성 token·`UNMEASURED` 고정 collector였다 | ①②③으로 분리했다. 네 항목 모두 **운영 producer가 없음**을 §6에 코드 선행으로 명시했다 |
| 2 | `G-17`에서 **Node private key를 중앙으로 받으라고 적었다** | **CSR만 받는다.** key는 각 Node가 로컬 생성·보관한다. `python tools/lan_pki.py`도 지웠다 — 그 파일은 `main`·`argparse`·`__main__`이 **하나도 없는 library**다 |
| 3 | `G-20`이 legacy env 3개만 적었다 | 운영 정본인 **`configurationReadiness.objectStore` 6-key 블록**과 `/run/saintvision/…` credential 파일 규칙으로 바꿨다(§2-6, §5-1) |
| 4 | `G-24`의 `lan_workspace.py`를 전송 실행기로 적었다 | **패키징 / 실행·receipt / 마운트**를 셋으로 분리했다. 마운트는 코드가 **명시적으로 배제**한다 |
| 5 | `G-16`·`G-21`의 명령이 disposable container·로컬 planner였다 | 소비 seam(`configurationReadiness.mlflow`, `record_backup(off_site=True)`)으로 바꾸고, 후자는 **노출 명령이 없음**을 적었다 |
| 6 | §4가 "3대 등록·mTLS enroll 완료"라고 적었다 | **2대는 지금도 heartbeat 중이고 3번째는 한 번도 관측된 적이 없다.** 숫자로 다시 썼다 |
| 7 | 명령에 필수 인자가 빠져 복사 실행이 불가능했다 | **필수 인자를 채운 1줄**로 바꾸거나 ②로 내렸다. "인자를 검증하지 않았다"는 포괄 면책은 삭제했다 |
| 8 | task 연결이 직접 증거와 의존 관계를 섞었다 | registry의 `next_handoff`로 **직접**을, `depends_on`으로 **의존**을 분리했다(§1, §3) |

## 1. 가장 빠른 순서

registry가 말하는 **직접 관계**부터 본다. `docs/task-registry.json`에서 두 task의 다음 행동이 곧 이 문서의 입력이다.

| task | `status` | `next_handoff` |
|---|---|---|
| `S01-BE` | `in_progress` | **`user-input:U2/U3/U4`** |
| `S01-ST` | `in_progress` | **`user-input:U1/U5/U6`** |

그리고 registry의 `depends_on`은 sprint 사슬이다 — `S02-*`의 `depends_on`이 `["S01-FE","S01-BE","S01-DB","S01-ST"]`이고 같은 모양이 `S03`→`S02`, `S05`→`S04`, `S07`→`S06`, `S11`→`S10`으로 이어진다. 즉 `U1`~`U6`는 **사슬의 머리**를 닫는다.

| 순 | 전제 | 직접 닫는 것 | 왜 먼저인가 |
|---:|---|---|---|
| 1 | **`U1`·`U5` + `G-19`** 물리 5대 | `S01-ST` `next_handoff`의 2/3 | 장비가 없으면 AC-11의 네 축(`S05` 배치 SLO, `S07` 장애·복구 SLO, `S06` remote PTY, `S11` long-soak)이 **모두** `NOT_OBSERVED`로 남는다. `G-24`도 같은 장비를 쓴다 |
| 2 | **`U2` + `G-15`** 실 IdP | `S01-BE` `next_handoff`의 1/3 | **값 5개**로 끝난다(§2-1). 실 로그인 여정 producer는 ②지만, 값 결속은 오늘 확인 가능하다 |
| 3 | **`U3` + `G-17`** CA 신뢰 bundle | `S01-BE`의 1/3 | `U1`·`U5`와 **같이 주면 한 번에** 끝난다. 필요한 것은 **bundle + Node별 CSR**이고 private key는 **주면 안 된다** |
| 4 | **`U6` + `G-20`** Storage 제품 | `S01-ST`의 1/3 | 값 6개 + credential 파일 1개. 운영 왕복 증거 경로가 **이미 있다**(§2-6 ①) |
| 5 | **`U4` + `G-18`** DNS·호스트명 | `S01-BE`의 1/3 | 결정만 있으면 되고 `#134` A2가 대기 중이다 |
| 6 | **`G-22`** 실 PITR | — | dry-run·readiness·retention은 이미 관측됐고 **실 복구만** 남았다. 도구가 다 있다 |
| 7 | **`G-24`** 실 Node 실행·전송 | — | `G-19` 장비 위에서 이어진다. 전송·receipt는 ①, **마운트는 ②** |
| 8 | **`G-21`**·**`G-23`**·**`G-25`**·**`G-26`**·**`G-16`** | — | 다섯 모두 **운영 producer가 먼저 필요하다**(§6). 값을 미리 받아 둘 수는 있으나 지금 돌릴 ①이 없다 |

## 2. 항목별 패키지

### 2-1. `G-15` + `U2` — 실 IdP

| | |
|---|---|
| **사용자가 줄 것** | **값 5개** — tenant id · issuer URL · audience · client id 목록 · **JWKS 파일**(URL이 아니다) |
| **양식** | §5-1의 설정 블록 + `jwks.json` 파일 1개 |
| **꽂히는 곳** | `INV_TENANT_ID` · `INV_OIDC_ISSUER` · `INV_OIDC_AUDIENCE` · `INV_OIDC_CLIENT_IDS`(쉼표 구분) · `INV_OIDC_JWKS_FILE` — `src/saintvision/config.py:142-149`. 다섯이 **모두** 있어야 `login_configured`가 참이 된다(`config.py:117-127`) |
| **① 지금 실행 가능** | 다섯 값을 넣고 control plane을 기동해 **`Settings.login_configured`가 참**이고 미해결 설정 보고(`unresolved_s01_settings()`, `config.py:154-156`)가 이 다섯을 더 부르지 않는지 본다. 검증기는 `src/saintvision/identity/oidc.py:76-89`에서 같은 다섯을 읽는다 |
| **② 코드 선행** | **실 issuer 경유 로그인 여정 lane이 없다.** `tools/run_s02_real_api_acceptance.py`는 `.work/dev/dev_idp.py`를 직접 띄우고(`:5`, `:114`, `:303`) issuer·JWKS 인자가 없다 |
| **③ 참고** | `python tools/collect_s02_acceptance_evidence.py` — `U2`~`U5`를 **항상 `UNMEASURED`**, `acceptanceClaim=false`로 낸다(`:21-23`, `:297`). **`G-15`를 닫지 않는다** |
| **기대 증거** | ①: 다섯 값 결속과 offline 검증기 구성. ② 뒤: 실 issuer 토큰 성공 1건 + **인증 실패 기록**(AC-02가 요구한다) |
| **열리는 것** | **직접**: `S01-BE`의 `user-input:U2`. **의존**: `S02-FE`·`S02-BE`·`S02-DB`·`S02-ST` |

**중요 — URL이 아니라 파일이다.** `config.py:17-23`이 그 결정을 기록한다: `INV_OIDC_JWKS_URL`은 **있다가 제거됐고**, 이유는 검증기가 설계상 offline(`inv.identity.AccessTokens`)이며 **운영자가 준 trust bundle 파일**을 쓰기 때문이다. 검증 시점에 키를 가져오면 **IdP의 가용성이 모든 요청의 의존성이 되고 그 DNS가 신뢰 경계가 된다.** 그래서 JWKS는 **파일로** 주셔야 한다.

### 2-2. `G-17` + `U3` — 운영 CA 신뢰 bundle과 Node 인증서

| | |
|---|---|
| **사용자가 줄 것** | **CA 신뢰 chain 파일(PEM) 1개** + Node별 **CSR**(또는 이미 발급된 leaf·fingerprint) |
| **양식** | §5-1의 `INV_NODE_MTLS_CA_BUNDLE` + Node별 `<node>.csr` |
| **꽂히는 곳** | `INV_NODE_MTLS_CA_BUNDLE` — `config.py:26`의 `S01_PENDING`에 **"S01이 소유하고 이 sprint가 발명하면 안 되는 설정"** 으로 있다 |
| **① 지금 실행 가능** | `python tools/lan_pilot.py --state <상태디렉터리> enroll --csr <node.csr>` (`lan_pilot.py:674-675`, `--csr` 필수) → `python tools/s01_readiness_preflight.py --inventory <인벤토리> --state <상태디렉터리> --ca-bundle <ca-chain.pem> --output dist/s01-readiness.json` (`:1252-1266`, `--output` 필수) |
| **② 코드 선행** | 없음 — 입력만 오면 ①로 끝난다 |
| **기대 증거** | Node 수만큼의 leaf chain·identity probe 통과 + **잘못된 cert의 enroll 거부** |
| **열리는 것** | **직접**: `S01-BE`의 `user-input:U3`. **의존**: `S02-BE` mTLS |

**private key를 주지 마십시오.** `tools/lan_pki.py`의 첫 문장이 계약이다 — *"Private pilot PKI. Enrollment accepts a public CSR, never a remote private key."* key는 각 Node가 로컬에서 만들어 로컬에 두고, 서버로 오는 것은 **CSR뿐**이다. 그리고 그 파일은 **library다** — `main`·`argparse`·`__main__`이 없어 `python tools/lan_pki.py`는 아무 증거도 만들지 않는다. v1.0이 적었던 그 명령은 삭제했다.

### 2-4. `G-19` + `U1`·`U5` — 물리 PC 5대 (가장 많은 축을 막는다)

| | |
|---|---|
| **사용자가 줄 것** | **토폴로지 결정**(`U1`) + **5대 인벤토리·계정·허용 폴더·NTP**(`U5`) |
| **양식** | §5-3의 인벤토리 표 — AC-01이 "5노드 조사표의 **미확인 값 명시**"를 요구하므로 **모르는 칸은 비우지 말고 "미확인"으로** 채우는 것이 정답이다 |
| **꽂히는 곳** | `tools/lan_pilot.py`의 `init --server-ip <CP> --node-ip <노드>`(`--node-ip`는 **Node마다 반복**, `lan_pilot.py:659-666`). CP 호스트에 Node를 겹치는 것은 `--allow-server-node-colocation`이 **명시적으로만** 허용하고, 되돌리는 명령이 `revoke-server-node-colocation`이다 |
| **① 지금 실행 가능** | `python tools/lan_pilot.py --state <경로> init --server-ip <CP> --node-ip <n1> --node-ip <n2> --node-ip <n3> --node-ip <n4> --node-ip <n5>` → Node마다 `enroll --csr <node.csr>` → `status` → `observe --once` |
| **② 코드 선행** | 없음 — pilot 도구가 이 경로를 갖고 있다. 다만 **현재 release SHA에서의 재수립**이 필요하다(§4-3) |
| **기대 증거** | 5대 등록·mTLS·heartbeat(all-five smoke) + **Ubuntu 4대 timed 분모**(ADR-100) |
| **열리는 것** | **직접**: `S01-ST`의 `user-input:U1/U5`. **의존**: AC-11의 네 축과 그것을 요구하는 `S05`·`S06`·`S07`·`S11` |

**이미 걸어 본 부분과 남은 부분은 §4에 숫자로 적었다.**

| **볼륨 마운트** | **② 코드 선행** | `lan_execution.py:132`가 **"Fixed modes only: no arbitrary command, mount, image tag or user data input."** 라고 적는다. 마운트 증거를 만드는 lane이 **없다** |

| | |
|---|---|
| **사용자가 줄 것** | `G-19`의 장비 + **쓰기 허용 폴더 결정** |

## 4. `G-19`·`G-24` — LAN pilot이 실제로 덮은 것 (읽기 전용 정리)

**읽기만 했다** — `ssh` 0건, 서비스 재시작 0건, Docker 조작 0건, DB 변경 0건. 상태 파일과 `observe.stdout.log`만 읽었다. IP·인증서 내용·DSN·Node ID는 **이 문서에 옮기지 않았다.**

상태 경로: `D:/Project/SaintVisionI-Invion/.work/lan-5node/node1`

### 4-1. `provisioned: true`는 "enroll 완료"가 아니다

v1.0은 `private-state.json`의 `nodes` 3개가 모두 `provisioned: true`라는 것을 근거로 "3대 등록·mTLS enroll·agent 배포가 됐다"고 적었다. **그것은 상태 파일의 의미보다 강한 주장이다.** `tools/lan_pilot.py:400-402`의 `init`은 DB 준비가 끝나면 **CSR·enroll 전에도** 모든 configured node에 `provisioned = True`를 넣고, 바로 다음 줄에서 출력하는 상태가 **`offline-awaiting-CSR`** 이다(`:407-410`). 즉 그 값의 뜻은 **"구성·identity 생성됨"** 이다.

### 4-2. 파일과 로그가 실제로 말하는 것

| 관측 | 값 |
|---|---|
| `nodes` 항목 수 / `provisioned: true` | 3 / 3 (= **구성 3대**) |
| **CSR 파일 수** | **2** |
| **발급된 leaf 수** | **2**(`public/node-cert.pem` 1장 + `public/nodes/<한 노드>/node-cert.pem` 1장) |
| `observe.stdout.log` 표본 수 | **93,665**(JSON 파싱 실패 0) |
| 관측 구간 | **2026-09-22T18:43:25Z → 2026-09-28T15:15:07Z = 5.86일**, **지금도 기록되고 있다** |
| 표본 간 최대 간격 | **11초**(300초 초과 0건, 3600초 초과 0건) |
| Node A | `online`·`observed` **93,665 / 93,665 = 100.0%**, agent `0.1.0`, `osType=linux` |
| Node B | `online`·`observed` **93,385 / 93,665 = 99.7%**, agent `0.1.0`, `osType=linux` |

**정정된 결론**: **2대**는 CSR → 발급 → mTLS enroll → agent 배포 → heartbeat까지 실제로 갔고 **5.86일 연속 관측**이 지금도 쌓이고 있다. **3번째는 구성만 됐고 한 번도 관측된 적이 없다**(CSR 없음, leaf 없음, snapshot 없음).

이것은 v1.0보다 약한 주장이면서 동시에 더 강한 사실이다 — 약한 쪽은 "3대"가 "2대"로 줄었다는 것이고, 강한 쪽은 그 2대가 **2026-09-23에 끝난 역사가 아니라 지금 살아 있는 5.86일 연속 heartbeat**라는 것이다. AC-11의 long-soak을 닫지는 못한다(ADR-100은 **5대 구성·4대 timed 분모**를 요구한다). 그러나 "물리 Node가 오래 붙어 있을 수 있는가"에는 실측이 있다.

## 7. 이 문서가 확인하지 않은 것

- **①의 명령은 argparse 계약까지 확인했고 실행하지 않았다.** 각 도구의 필수 인자·subcommand·`required=True`를 분석 tree에서 읽어 1줄을 구성했으나, 실제로 돌려 본 것은 **없다**(실 장비·실 계정·운영 DB가 필요하다).
- **②의 "없음"은 단정이다.** 근거는 해당 도구의 docstring·argparse·고정된 `UNMEASURED` 값이다. 저장소 전체를 읽어 "어디에도 없다"를 증명한 것은 아니므로, producer가 다른 이름으로 있다면 정정 대상이다.
- **점수 상승을 약속하지 않는다**(§0-1). 전제 도착은 관측을 열고, 점수는 그 관측을 기록한 뒤에 오른다.
- **LAN 관측은 상태 파일과 로그만 읽었다** — `ssh`·서비스 재시작·Docker 조작·DB 변경 0건. 5.86일 구간은 로그가 말하는 것이고 **장비의 현재 물리 상태를 지금 다시 측정하지 않았다.**
- **비밀 값을 옮겨 적지 않았다** — pilot 상태 파일의 DSN·비밀번호, node IP, 인증서 내용, Node ID는 이 문서에 없다. 경로와 개수만 적었다.
- 실행하지 않았다: 로컬 실 PG·Docker·전체 suite.
