# 외부 전제 인수 준비 패키지

48 task 진행률 재채점(PR **#220**, `docs/vault/30_Development/2026-09-28 48 task 진행률 재채점.md`) v1.3이 보인 결론은 **48개 중 34개가 75점 천장**이고 그 천장을 만드는 것이 **우리 코드가 아니라 `G-15`~`G-26`과 `U1`~`U6`** 이라는 것이다. 이 문서는 그 18개 전제를 **사용자가 가장 빨리 제공할 수 있는 형태**로 정리한다.

분석 tree는 **`9f1c2be4`**(`origin/coord/train-ci-2207`)이고, 인용한 환경변수·경로·route·argparse 계약과 **설정 파일의 검증 규칙**은 그 tree에서 `git show`·`git grep`으로 읽었다. 재채점 문서는 아직 병합 대기이므로 **평문(PR 번호·파일 경로)으로** 인용한다.

이 카드는 **docs-only**다 — 코드 변경 0, 그리고 §4의 LAN pilot 정리는 **읽기 전용**이다(ssh·서비스 재시작·Docker 조작 0건, 상태 파일과 로그만 읽었다).

## 0. 이 문서를 지배하는 세 규칙

### 0-1. 전제를 주는 것이 곧 점수가 되지는 않는다

전제가 도착하면 **막혀 있던 관측이 열리고**, 그 관측을 **실행해 기록한 뒤에** 점수가 오른다. 그래서 각 항목의 마지막 칸은 "올라가는 점수"가 아니라 "**열리는 관측과 그때 올라갈 수 있는 task**"다.

### 0-2. ①은 그 입력을 실제로 읽는 **완전한** 명령이어야 한다

| 칸 | 뜻 |
|---|---|
| **① 지금 실행 가능(입력 소비)** | 준 값을 **실제로 읽는** 명령. **필수 인자·필요한 토큰·올바른 route까지 갖춘** 형태로 적는다 |
| **② 코드 선행(producer 없음)** | 그 전제를 증명할 운영 lane이 **아직 없다.** 우리 몫이고 §6에 모았다 |
| **③ 참고** | 돌려도 되지만 **외부 인수를 소비하지 않는** 도구. 이 결과로 전제가 닫혔다고 말하면 안 된다 |

### 0-3. 기대 증거는 ①이 실제로 만드는 것만 적는다

"있으면 좋은 증거"를 기대 증거에 적으면 ①을 돌린 사람이 없는 것을 찾게 된다. 기존 제품 시험이 이미 지키는 것은 **기대 증거가 아니라 별도 칸**에 적는다.

### 0-4. v1.2에서 고친 것

| # | v1.1의 잘못 | v1.2 |
|---|---|---|
| 1 | `G-18`의 ①이 **틀린 route**(`/v1/settings`)를 쓰고 operator token·`--inventory`가 빠져 있어, 그대로 돌리면 두 설정 check는 `operator-token-missing`, DNS는 `inventory-input-missing`으로 **BLOCKED**가 된다 | 정본 route는 **`/v1/operations/configuration-readiness`**(`inv/app.py:331`)다. §2-0에 **입력을 다 넣은 하나의 canonical 명령**을 두고 각 항목은 그 명령의 **어느 check가 움직이는지**를 가리킨다 |

| 4 | `G-17`의 기대 증거에 ①이 만들지 않는 "잘못된 cert 거부"가 있었고, `G-19`의 ① 템플릿에 CP 겸임 시 필수인 플래그가 없었다 | 전자는 **기존 제품 시험 칸**으로 분리했다. 후자는 `--allow-server-node-colocation`과 **`topology` 값이 `role` 수와 일치해야 하는 규칙**을 함께 적었다 |
| 5 | §5-3의 인벤토리를 **markdown 표**로 주고 "모르는 칸은 '미확인'으로 채우라"고 했다 | 도구가 읽는 것은 **JSON 파일**이고, 문자열 "미확인"을 넣으면 타입 검사에서 **`invalid` → FAIL**이 된다. **키를 생략하거나 `null`** 로 두면 `missing` → **BLOCKED `inventory-values-missing`** 이다. 실제 스키마를 §5-3에 넣고 이 규칙을 적었다 |

v1.1에서 고친 것(합성·dev collector를 운영 producer로 오인, Node private key 요구, ObjectStore strict 설정, LAN 3대 과장)은 그대로 유지한다.

## 2-0. 먼저 — 하나의 canonical 명령이 `U3`·`U4`·`U5`·`U6`를 함께 관측한다

`tools/s01_readiness_preflight.py`는 **여러 입력을 한 번에 받아 하나의 보고서**를 낸다(`:1296-1336`). 항목마다 조각난 명령을 적는 것이 v1.0·v1.1이 틀린 이유였으므로, **완전한 형태를 한 번만** 적고 각 항목은 이 보고서의 **check 이름**을 가리킨다.

```
# operator token은 환경변수로만 전달한다 (명령줄에 두지 않는다)
export INV_S01_OPERATOR_TOKEN=<operator 토큰>
export INV_S01_ACCESS_TOKEN=<세션 토큰>

python tools/s01_readiness_preflight.py \
  --base-url      https://<확정 CP 호스트> \
  --settings-url  https://<확정 CP 호스트>/v1/operations/configuration-readiness \
  --http-ca-bundle <ca-chain.pem> \
  --inventory     <inventory.json> \
  --state         <LAN 상태 디렉터리> \
  --ca-bundle     <node-mtls-ca-chain.pem> \
  --storage-evidence    dist/s01-storage-roundtrip.json \
  --storage-attestation <storage-attestation.json> \
  --output        dist/s01-readiness.json
```

| 보고서 check | 무엇을 보는가 | 어느 전제 | 입력이 없으면 |
|---|---|---|---|
| `configuration-node-ca`·`configuration-object-store` | 운영 route가 미해결 설정을 어떻게 답하는가 | `G-17`·`G-20` | `--settings-url` 없으면 `settings-url-missing`, 토큰 없으면 **`operator-token-missing`**, https가 아니면 **FAIL `plaintext-operator-token-transport-rejected`** (`:422-462`) |
| `node-certificate-chain` | 등록·검증된 leaf 수(`registeredLeafCount`·`verifiedLeafCount`) | `G-17`/`U3` | `--state`나 `--inventory`가 없으면 `certificate-input-missing`(`:786-792`) |
| `dns-resolution` | 인벤토리의 `hostnames.{controlPlane,portal,idp}`와 `nodes[].dnsName` 해석 | `G-18`/`U4` | 인벤토리 없으면 `inventory-input-missing`, **lint가 PASS가 아니면 `inventory-not-ready`**(`:678-687`) |
| `inventory-lint` | 5노드 인벤토리의 필수 값·형식·topology 일치 | `U1`·`U5` | 값이 비면 BLOCKED `inventory-values-missing`, 형식이 틀리면 **FAIL `inventory-invalid`**(`:394-407`) |
| `pilot-capabilities` | LAN 상태와 인벤토리의 능력 대조 | `G-19` | `--state`·`--inventory` |
| `storage-evidence` | 운영 왕복 증거와 attestation의 신선도 결속 | `G-20`/`U6` | `--storage-evidence`·`--storage-attestation` |

**세 가지를 먼저 보셔야 한다.** (1) `--settings-url`은 **반드시 https**여야 하고 아니면 실패한다 — 토큰을 평문으로 보내지 않기 위해서다. (2) `operator_token`은 `INV_S01_OPERATOR_TOKEN`이 없으면 **세션 토큰으로 대체**된다(`:1294`). (3) `--output`은 **입력 파일을 덮어쓸 수 없다**(`:1290`).

## 2. 항목별 패키지

### 2-1. `G-15` + `U2` — 실 IdP

| | |
|---|---|
| **사용자가 줄 것** | **값 5개** — tenant id(UUID) · issuer URL(**`https://`로 시작해야 한다**) · audience · client id 목록 · **JWKS 신뢰 bundle 파일** |
| **양식** | §5-1의 `api.json` `identity` 블록 + `jwks.json` 1개. **bundle의 `expiresAt`은 최대 7일 뒤**여야 하므로 **주기적 재발급이 전제에 포함된다** |
| **꽂히는 곳** | 두 곳이고 서로 다르다. **control plane**: `INV_API_CONFIG`가 가리키는 `api.json`의 `identity`(`inv/app.py:1140-1158`, `AccessTokens(*, tenant_id, issuer, audience, client_ids, jwks_file)` `identity.py:69-82`). **saintvision API**: env `INV_TENANT_ID`·`INV_OIDC_ISSUER`·`INV_OIDC_AUDIENCE`·`INV_OIDC_CLIENT_IDS`·`INV_OIDC_JWKS_FILE`(`config.py:142-150`), 다섯이 모두 있어야 `login_configured`가 참(`config.py:117-127`) |
| **① 지금 실행 가능** | `python tools/prepare_server_config.py --directory <설정디렉터리> --volume <새 볼륨이름> --image <이미지>` — `api.json`을 읽어 `identity.jwks_file`이 **flat `/run/saintvision/<이름>` 참조**인지 검증하고 새 private 볼륨을 만든다(`:38-70`, `:204-212`). 거부되면 **기존 볼륨과 원본을 보존**한다. 이어서 control plane 기동 자체가 검증이다 — `AccessTokens.__init__`이 `self._keys()`를 호출해 **불완전한 신뢰 bundle이면 startup을 거부**한다(`identity.py:82`, *"no dev fallback"*) |
| **② 코드 선행** | **실 issuer 경유 로그인 여정 lane이 없다.** `tools/run_s02_real_api_acceptance.py`는 `.work/dev/dev_idp.py`를 직접 띄우고(`:5`, `:114`, `:303`) issuer·JWKS 인자가 없다 |
| **③ 참고** | `python tools/collect_s02_acceptance_evidence.py` — `U2`~`U5`를 **항상 `UNMEASURED`**, `acceptanceClaim=false`(`:21-23`, `:297`). **`G-15`를 닫지 않는다** |
| **기대 증거(①)** | 설정 검증 통과 + **불완전한 bundle에서의 startup 거부**. 즉 "구성됐다"와 "구성되지 않았다"가 **둘 다** 관측된다 |
| **열리는 것** | **직접**: `S01-BE`의 `user-input:U2`. **의존**: `S02-FE`·`S02-BE`·`S02-DB`·`S02-ST` |

**`/v1/health`를 OIDC 확인으로 쓰지 마십시오.** 그 route는 `unresolvedSettings: unresolved_s01_settings()`를 돌려주고 docstring이 "OIDC가 구성됐는지 추측하지 않아도 된다"고 적지만, `S01_PENDING`에는 **이름이 둘뿐**이다 — `INV_NODE_MTLS_CA_BUNDLE`과 `INV_OBJECT_STORE_ENDPOINT`(`config.py:24-28`). **OIDC 다섯 값은 그 목록에 없어서 이 route로는 보이지 않는다.** 그래서 ①을 설정 검증과 startup 거부로 잡았다.

**중요 — JWKS는 URL이 아니라 파일이다.** `config.py:17-23`이 그 결정을 기록한다: `INV_OIDC_JWKS_URL`은 **있다가 제거됐고**, 이유는 검증기가 설계상 offline이며 **운영자가 준 trust bundle 파일**을 쓰기 때문이다. 검증 시점에 키를 가져오면 **IdP의 가용성이 모든 요청의 의존성이 되고 그 DNS가 신뢰 경계가 된다.**

### 2-2. `G-17` + `U3` — 운영 CA 신뢰 bundle과 Node 인증서

| | |
|---|---|
| **사용자가 줄 것** | **CA 신뢰 chain 파일(PEM) 1개** + Node별 **CSR**(또는 발급된 leaf의 SHA-256 fingerprint) |
| **양식** | §5-1의 `INV_NODE_MTLS_CA_BUNDLE` + Node별 `<node>.csr`. fingerprint를 인벤토리에 넣을 때는 `certificateSHA256`이 **64자 hex이고 노드 간 중복이 없어야** 한다(§5-3) |
| **꽂히는 곳** | `INV_NODE_MTLS_CA_BUNDLE` — `config.py:26`의 `S01_PENDING`에 **"S01이 소유하고 이 sprint가 발명하면 안 되는 설정"** 으로 있다. control plane 쪽은 `configurationReadiness.nodeMtlsCaBundle`(`configuration_readiness.py:28`) |
| **① 지금 실행 가능** | Node마다 `python tools/lan_pilot.py --state <경로> enroll --csr <node.csr>`(`:674-675`, `--csr` 필수) → **§2-0의 canonical 명령** 1회. 움직이는 check는 `node-certificate-chain`(`registeredLeafCount`·`verifiedLeafCount`)과 `configuration-node-ca`다 |
| **② 코드 선행** | 없음 |
| **기대 증거(①)** | 인벤토리가 선언한 leaf 수와 **등록·검증된 leaf 수의 일치**, 그리고 운영 route가 `nodeMtlsCaBundle`을 미해결로 부르지 않는 것 |
| **이미 제품 시험이 지키는 것(기대 증거 아님)** | **잘못된 cert의 enroll 거부**는 기존 시험의 몫이다. §2-0의 어떤 check도 음성 경로를 새로 만들지 않으므로 ①의 기대 증거에 넣지 않는다 |
| **열리는 것** | **직접**: `S01-BE`의 `user-input:U3`. **의존**: `S02-BE` mTLS |

**private key를 주지 마십시오.** `tools/lan_pki.py`의 첫 문장이 계약이다 — *"Private pilot PKI. Enrollment accepts a public CSR, never a remote private key."* key는 각 Node가 로컬에서 만들어 로컬에 두고, 서버로 오는 것은 **CSR뿐**이다. 그리고 그 파일은 **library다** — `main`·`argparse`·`__main__`이 없어 `python tools/lan_pki.py`는 아무 증거도 만들지 않는다.

### 2-3. `G-18` + `U4` — DNS·호스트명

| | |
|---|---|

### 4-1. `provisioned: true`는 "enroll 완료"가 아니다

`tools/lan_pilot.py:400-402`의 `init`은 DB 준비가 끝나면 **CSR·enroll 전에도** 모든 configured node에 `provisioned = True`를 넣고, 바로 다음 줄에서 출력하는 상태가 **`offline-awaiting-CSR`** 이다(`:407-410`). 즉 그 값의 뜻은 **"구성·identity 생성됨"** 이다.

### 4-2. 파일과 로그가 말하는 것 (2026-09-29 작성 시점의 snapshot)

| 관측 | 값 |
|---|---|
| `nodes` 항목 수 / `provisioned: true` | 3 / 3 (= **구성 3대**) |
| **CSR 파일 수** | **2** |
| **발급된 leaf 수** | **2** |
| `observe.stdout.log` 표본 수 | **93,665**(JSON 파싱 실패 0) |
| 기록 구간 | **2026-09-22T18:43:25Z → 2026-09-28T15:15:07Z = 5.86일**, 마지막 표본이 이 문서 작성 시점의 끝이다 |
| 표본 간 최대 간격 | **11초**(300초 초과 0건, 3600초 초과 0건) |
| Node A | `online`·`observed` **93,665 / 93,665 = 100.0%**, agent `0.1.0`, `osType=linux` |
| Node B | `online`·`observed` **93,385 / 93,665 = 99.7%**, agent `0.1.0`, `osType=linux` |
| **Node C** | `online` **0 / 93,665**, `observed` **0 / 93,665**, snapshot 없음. 마지막 heartbeat는 **2026-09-22T18:22Z** |
| 기타 자산 | `ca.pem`·`control-cert.pem`·`signer.pub`·`peer-policy.json`, `agentImage` digest 고정 + `node-agent.tar`, node별 `worker.zip`+`worker.sha256`, pilot 전용 PostgreSQL container와 migration `head`(`lan_pilot.py:372-374`), `serve*`·`observe` 로그 |
| 병합된 코드 | PR **#89**·**#95** |

**정정된 결론**: **2대**는 CSR → 발급 → mTLS enroll → agent 배포 → heartbeat까지 실제로 갔고 **마지막 관측 시각(2026-09-28T15:15:07Z)까지 5.86일 연속으로 기록**됐다. **3번째는 구성만 됐고 한 번도 관측된 적이 없다**(CSR 없음, leaf 없음, snapshot 없음).

**이 표는 작성 시점의 로그 snapshot이고 장비의 현재 상태가 아니다.** 이 문서를 나중에 읽는 사람은 그 사이의 변화를 알 수 없다. AC-11의 long-soak을 닫지도 못한다 — ADR-100은 **5대 구성·4대 timed 분모**를 요구한다. 그러나 "물리 Node가 오래 붙어 있을 수 있는가"에는 실측이 있다.

### 4-3. 남은 것

| 남은 것 | 무엇이 필요한가 |
|---|---|
| **3번째 Node의 enroll** | CSR 1장이면 §2-2의 ①로 진행된다 |
| **4번째·5번째 PC** | `U5` 인벤토리가 정한다. 4번째는 2026-09-23 시점에 **미확인**이었다 |
| **이 PC의 CP 동거 worker** | **Docker Desktop API 1.41** 제약으로 막혔다. ADR-100이 이 구성을 "CP 겸임 Node 1대"로 분류하고 **timed 분모에서 제외**하므로, 풀리지 않아도 **all-five smoke의 5번째**는 채울 수 있으나 **eligible 4대**에는 들어가지 않는다. 인벤토리에서는 `topology: "cp-colocated-plus-four-workers"` + `role: "cp-colocated"` 1개로 표현되고, 명령에는 `--allow-server-node-colocation`이 필요하다 |
| **현재 release SHA에서의 재수립** | 상태 파일의 `baseSHA`가 **`d01c931a`** 이고 그 뒤 tree가 크게 바뀌었다(migration 33→70 등). 기록된 heartbeat도 **그 SHA의 agent**가 만든 것이므로, 현재 release에서 다시 세워야 증거가 된다 |
| **비밀 값 재발급** | `private-state.json`에 **DSN 비밀번호가 평문으로** 있다. 이 문서는 그것을 옮겨 적지 않았고, 재사용하지 말고 **재발급**하는 것이 맞다 |

## 5. 양식 (템플릿)

### 5-1. 설정

**`G-15` / `U2` — control plane의 `api.json`(`INV_API_CONFIG`가 가리키는 파일). `identity`는 필수이고 키는 다섯입니다.**

```json
{
  "identity": {
    "tenant_id": "<UUID>",
    "issuer": "https://<idp 호스트>/<발급자 경로>",
    "audience": "<audience>",
    "client_ids": ["<client-id-1>", "<client-id-2>"],
    "jwks_file": "/run/saintvision/<jwks 파일이름>"
  }
}
```

`issuer`는 **`https://`로 시작**해야 하고 `audience`·`client_ids`는 비어 있을 수 없습니다(`identity.py:70-80`).

**JWKS 신뢰 bundle(`jwks_file`이 가리키는 파일) — 키는 정확히 셋입니다.**

```json
{
  "issuer": "<위 identity.issuer와 글자까지 같아야 합니다>",
  "expiresAt": 0,
  "keys": [
    {"kty": "RSA", "alg": "RS256", "use": "sig", "kid": "<1~128자, 중복 금지>",
     "n": "<modulus base64url>", "e": "AQAB"}
  ]
}
```

- `expiresAt`은 **정수(Unix 초)이고 지금부터 최대 7일 뒤**여야 합니다 — 그러므로 **주 1회 재발급이 운영 전제에 포함됩니다**(`identity.py:84-94`).
- 키는 **1~8개**, 각각 `kty=RSA`·`alg=RS256`·`use=sig`이고 **private 성분 `d`가 있으면 거부**됩니다. RSA 크기는 **2048~4096**입니다.
- 불완전하면 **startup이 거부**됩니다(dev fallback 없음).

**saintvision API 쪽(같은 값을 env로)**

```
INV_TENANT_ID=
INV_OIDC_ISSUER=              # https://...
INV_OIDC_AUDIENCE=
INV_OIDC_CLIENT_IDS=          # 쉼표로 구분
INV_OIDC_JWKS_FILE=           # 파일 경로 (URL 아님)
```

**`G-17` / `U3` — 운영 CA. bundle은 서버로, private key는 각 Node에만.**

```
INV_NODE_MTLS_CA_BUNDLE=      # PEM 체인 파일 경로
```

Node마다 `<node>.csr` 1장. **private key는 보내지 마십시오**(§2-2).

**`G-20` / `U6` — Storage 제품. `api.json`의 `configurationReadiness`에 넣습니다. 키는 정확히 6개입니다.**

```json
{
  "configurationReadiness": {
    "objectStore": {
      "providerId": "소문자·숫자·.·- / local-bounded-v1 금지",
      "endpoint": "https://<호스트>[:포트]",
      "bucket": "소문자 bucket 이름",
      "region": "소문자 region",
      "credentialFile": "/run/saintvision/<파일이름>",
      "prefix": "앞뒤 / 없는 경로 또는 빈 문자열"
    }
  }
}
```

`credentialFile`이 가리키는 파일 — 키는 정확히 둘:

```json
{"accessKeyId": "1~128자", "secretAccessKey": "1~256자"}
```

파일 조건: `/run/saintvision/` 아래, 일반 파일, hard link 1개, 4096 byte 이하, POSIX에서 group/other 권한 비트 0, symlink 아님. legacy `objectStoreEndpoint`와 **같이 쓰면 거부**됩니다.

**`G-22` — PITR·복구 (§2-8: DSN이 하나가 아닙니다)**

```
INV_PITR_DSN=                 # pitr_readiness.py (설정 관측 전용)
INV_RECOVERY_SOURCE_DSN=      # recovery_drill.py: 신뢰된 quiescent source
INV_RECOVERY_ADMIN_DSN=       # recovery_drill.py: CREATE DATABASE 권한
```

**`G-16` — 실 MLflow (§2-12: 지금은 관측할 명령이 없습니다)**

```
INV_MLFLOW_TRACKING_URI=
INV_MLFLOW_DESTINATION=       # ^[a-z][a-z0-9-]{0,63}$
INV_MLFLOW_EXPERIMENT_PREFIX= # ^[a-z0-9-]{1,32}$
INV_MLFLOW_TIMEOUT_SECONDS=
```

**주의**: 이 블록들을 저장소에 commit하지 않습니다. 값은 운영 호스트의 설정 파일·볼륨으로 주시고, 이 문서에는 **채운 값을 적지 않습니다.**

### 5-2. 호스트명 (`U4`)

호스트명은 별도 표가 아니라 **§5-3 인벤토리의 `hostnames`와 `nodes[].dnsName`** 에 들어갑니다. `hostnames`의 세 키는 각각 **list**이고 **값이 중복되면 안 됩니다**.

### 5-3. 5노드 인벤토리 (`U5`·`U1`) — 도구가 읽는 것은 **JSON 파일**입니다

`schemaVersion`은 **`s01-readiness-inventory:1`**, `nodes`는 **정확히 5개**입니다.

```json
{
  "schemaVersion": "s01-readiness-inventory:1",
  "topology": "five-workers-dedicated-cp",
  "hostnames": {
    "controlPlane": ["<cp 호스트명>"],
    "portal": ["<portal 호스트명>"],
    "idp": ["<idp 호스트명>"]
  },
  "nodes": [
    {
      "nodeId": "nod_<영숫자·_·->",
      "hostname": "<호스트명>",
      "dnsName": "<DNS 이름>",
      "ip": "<사설 IPv4, loopback 금지, 중복 금지>",
      "installationId": "<설치 식별자>",
      "os": {"family": "", "version": "", "containerRuntime": ""},
      "role": "worker",
      "certificateSHA256": "<64자 hex>",
      "profile": "lan-workspace-v1",
      "hardware": {
        "cpuModel": "", "physicalCoreCount": 0, "logicalThreadCount": 0,
        "gpus": [{"model": "", "vramBytes": 0, "driver": ""}],
        "storageDevice": "", "networkInterface": ""
      },
      "capacity": {"cpuMillis": 0, "memoryBytes": 0, "gpuDevices": 0,
                   "storageBytes": 0, "networkBitsPerSecond": 0},
      "allowedResources": {"cpuMillis": 0, "memoryBytes": 0, "gpuDevices": 0, "storageBytes": 0},
      "allowedFolders": ["<절대 경로>"],
      "ntp": {"configured": true, "source": "<NTP 서버>", "maxSkewSeconds": 0},
      "storageRole": "none"
    }
  ]
}
```

**모르는 값은 "미확인"이라고 쓰지 마십시오.** 문자열을 넣으면 타입 검사에서 **`invalid` → FAIL `inventory-invalid`** 가 됩니다. **키를 생략하거나 `null`** 로 두면 **`missing` → BLOCKED `inventory-values-missing`** 이고, 이것이 AC-01이 요구하는 "미확인 값 명시"에 해당하는 정직한 상태입니다(`s01_readiness_preflight.py:94-97`, `:394-407`).

지켜야 하는 것 몇 가지:

- `topology`는 `five-workers-dedicated-cp` 또는 `cp-colocated-plus-four-workers`이고, **후자는 `role: "cp-colocated"`가 정확히 1개**, 전자는 **0개**여야 합니다.
- `role`은 `worker` 또는 `cp-colocated`, `profile`은 `lan-workspace-v1` 또는 `lan-observe-v1`, `storageRole`은 `provider`·`archive`·`none` 중 하나입니다.
- `nodeId`·`hostname`·`dnsName`·`ip`·`installationId`·`certificateSHA256`은 **노드 간 중복 금지**이고, `nodeId`는 `nod_`로 시작합니다.
- `ip`는 **사설 IPv4**여야 하고 loopback은 거부됩니다.
- `logicalThreadCount`는 `physicalCoreCount`보다 작을 수 없고, `hardware.gpus`의 개수는 `capacity.gpuDevices`와 같아야 합니다.
- `allowedResources`의 각 값은 같은 이름의 `capacity` 값을 **넘을 수 없습니다**.
- `allowedFolders`는 **절대 경로**여야 하고, `storageRole`이 `none`이 아니면 **비어 있을 수 없습니다**.
- `ntp.configured`는 **`true`여야** 하고 `maxSkewSeconds`는 **0~5**입니다.
- 정의되지 않은 키를 추가하면 **`invalid`** 로 셉니다.

## 7. 이 문서가 확인하지 않은 것

- **①의 명령은 인자·route·토큰 분기까지 코드에서 확인했고 실행하지 않았다.** 실 장비·실 계정·운영 DB·운영 볼륨이 필요하다.
- **②의 "없음"은 단정이다.** 근거는 해당 도구의 docstring·argparse·고정된 `UNMEASURED` 값·route 목록이다. 저장소 전체를 읽어 "어디에도 없다"를 증명한 것은 아니므로, producer가 다른 이름으로 있다면 정정 대상이다.
- **점수 상승을 약속하지 않는다**(§0-1).
- **LAN 관측은 작성 시점의 로그 snapshot이다**(§4-2). 장비의 현재 상태를 지금 다시 측정하지 않았고, `ssh`·서비스 재시작·Docker 조작·DB 변경 0건이다.
- **인벤토리 스키마는 lint 규칙에서 읽은 것**이고, 실제 파일로 lint를 통과시켜 본 것은 아니다.
- **비밀 값을 옮겨 적지 않았다** — pilot 상태 파일의 DSN·비밀번호, node IP, 인증서 내용, Node ID는 이 문서에 없다.
- 실행하지 않았다: 로컬 실 PG·Docker·전체 suite.
