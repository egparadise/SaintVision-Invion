# PR14 통합 선행 검토

SHARD-RECOVERY 작업 중 [Claude PR #14](https://github.com/egparadise/SaintVision-Invion/pull/14)가 갱신되어 `44756e1247600aa5fb2e294eeed16c90632ea6f9`를 읽었다. 이는 #11/#12의 독립 검토와 업무 연결 코드이며, #13의 Workspace 공개 API/DB 역할과 #15의 샤드 복구까지 포함한 검토는 아니다. 다음 내용은 Codex의 제한된 정적 호환성 검토다. PR14 전체를 실행 검증하거나 병합한 결과로 표현하지 않는다.

## 병합 전 해결할 사항

1. **Migration 이력의 두 대안이 공존한다.** PR14는 기존 0008_node_certificate_lookup·0009_idempotency_and_inbox_scope·0010_canonical_resource_units를 0019·0020·0021로 재명명하고 0018 뒤로 옮긴다. PR13의 ADR-047은 기존 revision ID/부모를 보존하고 0019_workspace_api_integration에서 두 head를 합친다. PR15의 0020_shard_recovery는 후자 위에 있다. 두 경로를 모두 실행하면 같은 업무 DDL을 다시 적용할 수 있다. 기존 공개 head를 보존하는 합류/forward 계획, 이미 적용된 DB 업그레이드 시험이 선행해야 한다. 기존 history의 일괄 재명명은 수용하지 않는다.

2. **DB 역할과 production 진입점을 맞춰야 한다.** PR14의 0022는 `inv_app`에 inv 권한을 부여한다. PR13은 `inv_kernel` NOLOGIN 그룹과 제한 권한을 실제 migration에 두고 production factory를 설정 필수로 전환했다. PR14가 보고한 “inv 권한 없음/모의 server 진입점”은 #13에서 수정됐다. 현재 tree에 통합할 때 이 수정이 되돌아가면 안 된다. public 업무 연결에 필요한 역할과 0020의 불변 테이블 권한까지 명시적으로 검토해야 한다.

3. **업무 binding 상태를 실제 실행 증거에 연결해야 한다.** `src/saintvision/api/v1/execution.py`의 `POST /bindings/{binding_id}/state`는 인증된 사용자의 `payload.state`를 서비스 `advance()`로 전달한다. `services/handoff.py`의 advance는 public binding 상태를 바꾸고 settled/abandoned 때 편집 lock을 해제한다. 이 경로에서는 inv의 실제 delivery·stop receipt·Evidence 확인을 찾지 못했다. attach_approval도 inv ApprovalStore/quorum을 읽는 대신 `apr_` 접두와 업무 permission을 확인한다. 현재 확인한 inv 연계 SQL은 control_epoch 읽기다. 이 metadata를 실제 queued/executing/settled 증거로 사용하면 안 된다. 권한 있는 kernel outbox 소비 또는 같은 트랜잭션의 실행 결과 조회로 바꾸고 client state 제출은 실행 권위에서 제거해야 한다.

4. **동일 tenant의 다른 project/lock 접근을 막아야 한다.** edit-lock 해제 route와 binding 상태 route는 principal의 tenant를 전달하지만 해당 경로에서 현재 project permission을 확인하지 않는다. `resume_editing()`과 `_load()`도 tenant만 확인한다. stop_editing route는 payload의 project 권한을 확인한 뒤 Workspace를 tenant 기준으로 읽으므로 실제 Workspace/Run의 project와 대조해야 한다. 현재 정적 검토에서 확인한 누락이며, 다른 project 사용자·권한 철회·다른 lock 소유자의 HTTP/DB 거부 시험과 수정이 필요하다.

## 다음 작업 계약

Codex의 다음 최우선은 PR14 업무 연결을 PR13/15 실행 커널에 통합하는 작업이다. 기존 revision ID 유지, 역할 최소 권한, 실제 kernel 승인/출력/Evidence 기반 상태, 현재 project 권한·lock/Run/Workspace scope를 함께 확인한다. Claude의 업무 CRUD 구현을 이 계약에 맞춰 연결하고 실제 PostgreSQL/JWT/Node 통합 시험으로 증명한다. 이후 kill switch/drain·주기 reconciliation을 진행한다.

Claude는 새 recovery 공개 route·운영 설정·준비 레코드 보존 및 업무 연결 보완, Gemini는 실제 project API의 승인/복구 화면과 브라우저 검증을 맡는다. PR14는 이 문서 작성 시 이번 branch에 병합하지 않았으며 다른 Agent 코드·공용 worktree를 수정하지 않았다. PR15의 독립 reviewer Claude 상태는 별도로 pending이다.
