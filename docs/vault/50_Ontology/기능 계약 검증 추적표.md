# 기능 계약 검증 추적표


예상된 증거 요구와 실제 증거를 분리한다. 아래는 전부 예정 상태이며 실제 Evidence는 실행 페이지에서 연결한다. 기계 검증 원본은 `docs/task-registry.json`이다.

| Outcome | 완성 기능 | 합격 조건 | 작업 | 필요한 증거 | 상태 |
|---|---|---|---|---|---|
| OUT-01 | 완성 목표와 계약을 모든 Agent가 동일하게 해석한다 | AC-01: 계약과 owner 누락 0, 5노드 조사표의 미확인 값 명시 | S01-FE/BE/DB/ST | 계약 검증·설계 검토·인벤토리 보고 | planned |
| OUT-02 | 로그인한 사용자가 등록 Node와 제공 자원을 본다 | AC-02: 허용 Node 등록·조회 성공, 토큰 재사용 차단, 다른 project 정보 접근 차단 | S02-FE/BE/DB/ST | 실제 API·브라우저 여정·인증 실패 기록 | planned |
| OUT-03 | Workspace에서 허용 작업이 실행되고 증거가 남는다 | AC-03: 허용 실행 성공, 금지 경로/명령 차단, 종료 후 자원 회수 | S03-FE/BE/DB/ST | 허용·거부 로그·exit code·증거 ID | planned |
| OUT-04 | 승인·취소·결과 확인의 단일 노드 여정을 완료한다 | AC-04: 승인 전 실행 0, 중복 요청 부수 효과 0, 전송 재개 hash 일치 | S04-FE/BE/DB/ST | 만료 승인·취소·중복 요청·재전송 통합 결과 | planned |
| OUT-05 | 5노드 자원을 초과 예약 없이 설명 가능하게 배치한다 | AC-05: 동일 입력 배치 동일, 50개 동시 예약 초과 0, P95 2초 목표 실측 | S05-FE/BE/DB/ST | 경합 테스트·snapshot/weight/policy 버전·Explain | planned |
| OUT-06 | 편집·터미널·Git 작업이 재시작 후 안전하게 재개된다 | AC-06: 허용 범위 편집·Git 성공, CP 재시작 뒤 중복 실행 0, 복원 hash 일치 | S06-FE/BE/DB/ST | 소스 commit·WS/PTY·restart·restore 결과 | planned |
| OUT-07 | Node 손실과 분할 상황에서 낡은 실행을 차단한다 | AC-07: 이탈 감지 60초 이내, 오래된 토큰 쓰기 0, 복구 성공률 목표 95% | S07-FE/BE/DB/ST | Node 중단·분할·late result·cache 경합 결과 | planned |
| OUT-08 | 격리된 Build·GPU 작업을 정책과 복구 아래 수행한다 | AC-08: Docker socket 미노출, 승인 우회 0, 합성 GPU 실행 성공, backup 복원 | S08-FE/BE/DB/ST | 보안 시나리오·GPU capability·복원 보고 | planned |
| OUT-09 | Agent가 근거 있는 Context와 제한된 수정 루프로 일한다 | AC-09: Prompt 100건 유효율 99%, 코딩 과제 30건 성공률 70% 목표, 누출 0 | S09-FE/BE/DB/ST | golden eval·분류별 성적·금지 행동 시험 | planned |
| OUT-10 | 서로 다른 AI 도구와 모델 계보를 공통 계약으로 추적한다 | AC-10: Codex/Claude 계약 동일, 모델의 데이터·코드·평가·승인 역추적 | S10-FE/BE/DB/ST | Adapter conformance·lineage query·배포 digest | planned |
| OUT-11 | 기능·보안·성능·복원이 검증된 내부망 후보를 만든다 | AC-11: 주요 SLO와 실제값 보고, critical/high 미완화 0, rollback 검증 | S11-FE/BE/DB/ST | E2E·부하·복원·보안·접근성 결과 | planned |
| OUT-12 | 5대 PC에서 개발부터 배포·장애 복구까지 완료한다 | AC-12: 5노드 전체 여정·정량 목표·알려진 제한·인수 확인 모두 기록 | S12-FE/BE/DB/ST | Release manifest·사용자 인수·웹 smoke·복구 Evidence | planned |

기능에서 역으로 추적해 owner·reviewer 없는 작업, 증거 요구가 없는 합격 조건, 목표 없는 구현을 `tools/check_docs.py`에서 차단한다. 실행 결과가 생기면 실제 commit/build/Evidence 참조를 추가하며 단순 모델 완료 문구를 증거로 사용하지 않는다.
