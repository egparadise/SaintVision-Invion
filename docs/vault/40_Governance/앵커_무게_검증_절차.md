# 앵커 무게 검증 절차

"앵커가 있다 ≠ 앵커가 지킨다(무게)"를 상시로 다룬다. 2026-09-22 변이 감사에서 서빙 앵커 무게가 **스펙트럼**임을 확인했다: 완전 무게(무효 응답을 서빙 경로에서 거부하는 시험 있음) → 호출만 검증(시험이 validator를 레코더로 대체해 "불렸다"만 봄) → 전무(앵커는 있으나 시험 0). 근거: [[2026-09-22_서빙앵커_무게_전수변이_부류확장_Claude]].

## 두 층으로 다룬다

### 1) 정적 신호 (싸고 상시·CI 가능) — `tools/check_anchor_weight.py`
각 커널 서빙 앵커 타입을 **rejection-tested / called-only / named-only / no-serving-test**로 분류한다. **report-only**(게이트 아님) — `called-only`가 곧 결함은 아니다(스키마 계약 시험이 거부를 덮을 수 있음). 사람이 읽고 "서빙 경로 거부 시험을 더할지"를 판단한다.
- 실행: `python tools/check_anchor_weight.py` (opt-in `--strict`는 비-rejection이 있으면 exit 1).
- 자기 시험: `tests/test_check_anchor_weight.py` — 무게 없는 앵커를 일부러 심고, rejection 시험을 레코더로 망가뜨렸을 때 도구가 `called-only`로 잡는지 확인한다(병 심기). 도구를 고칠 때 이 시험이 도구가 여전히 판별하는지 지킨다.
- 한계(정직): 정적 proxy다. 런타임 무게를 **증명하지 못한다**. 타입 이름을 안 부르는 rejection 시험은 놓친다(false-negative). `check_contract_bindings.py`의 (2)(2b)와 **보완 관계** — 그 도구는 앵커·replay 가드의 *존재*를, 이 도구는 시험의 *거부 검증 여부*를 본다.

### 2) 변이 ground truth (비싸고 on-demand) — 정적 신호가 애매하거나 확증이 필요할 때
정적 도구가 `called-only`/`no-serving-test`로 짚은 것을 실제로 확인하거나, 주기 감사로 전수 확인할 때 쓴다. **런타임 무게는 이 방법으로만 증명된다.**

**반드시 격리 워크트리에서.** 제품/공유 트리에서 변이하면 실수 시 제품 코드에 변이가 남는다(3 agent 공용).
1. `git worktree add --detach <scratch> <origin tip SHA>`; `git status --porcelain` 빈 것 확인; SHA 고정.
2. **baseline**: 대상 suite를 돌려 passed/skipped 기록.
3. **변이는 "검증 효과만 중화, 호출은 유지"**: `validate_contract`(그리고 `_checked`) 정의를 passthrough(즉시 return)로. **호출 줄을 지우지 마라** — 호출 제거는 (a)이름-레코더 시험이 잡아버려 "거부 무게 없음"을 놓친다(2026-09-22 실측: result_view가 호출-제거판에선 안 죽고 검증-중화판에서야 called-only로 드러남).
4. **대조군 필수**: 무게 아는 앵커 하나(예: `control.create`의 fresh `ControlRunView`)를 함께 중화해 **반드시 죽는지** 확인한다. 안 죽으면 변이 harness가 안 먹은 것이니 결과 전체를 폐기한다.
5. baseline과 diff: 안 죽은 앵커 = 무게 없음. 한꺼번에 제거→적게 죽으면 그 차이가 후보→좁힘.
6. 끝나면 워크트리 제거(`git worktree remove --force`). 제품 트리 무변경 확인.

## 결과의 귀속

발견하면 **자리만 짚고 소유자가 고친다**(커널/v1 계약 = Codex). 무게 없는 앵커가 전부 결함은 아니다 — replay 가드는 계약 이전 저장 prior에 대한 정당한 방어이고, 문제는 앵커의 존재가 아니라 **거부 시험의 부재**다. 그 구분을 보고에 적는다(있는 것은 맞고, 시험이 없는 것이 결함).

## 상시화

- 화면·계약 변경 PR에서 `check_anchor_weight.py`를 report-only로 본다(신선한 called-only 유입 감시).
- 새 서빙 앵커 추가 시 rejection 시험(무효 응답→거부)을 함께 넣는다. 안 넣으면 이 도구가 called-only로 드러낸다.
- 주기(예: 릴리스 전) 또는 정적 신호가 애매할 때 §2 변이로 확증한다.
