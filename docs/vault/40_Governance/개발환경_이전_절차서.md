# 개발 환경 이전 절차서 — 새 PC(192.168.45.74)

사람이 순서대로 따라 하는 문서다. 각 단계에 **명령 → 성공 신호 → 실패 신호**를 적는다. 실측은 2026-09-22 이 기계(`C:\Project\SaintVision-Invion`, 사용자 `egpar`) 기준이며 SHA·워크트리는 이후 이동한다.

## 0. 원칙 (먼저 읽는다)

- **폴더 통째 복사 금지, clone 한다.** `.venv`·`node_modules`에 절대경로가 박혀 있고 `.git/`의 상태 파일이 옛 vault를 가리켜 sync를 막는다. 코드는 origin에서 clone하고 파생물은 새로 만든다.
- **비밀 값 복사 금지.** DSN·자격증명은 새 PC에서 재발급한다(§4).
- **보호 컨테이너 4개는 이 기계에 남긴다.** 옮기지도 지우지도 않는다(§6).
- 이동 목적지: 프로그램 `D:\Project\SaintVision-Invion`, vault `C:\Users\inviz\OneDrive - Inviz (1)\15.Vibe Cording\Obsidian\SaintVision-Invion`. 현재는 `C:\Project\SaintVision-Invion`, `C:\Users\egpar\OneDrive - Inviz\15.Vibe Cording\Obsidian\SaintVision-Invion`. **사용자명(egpar→inviz)과 OneDrive 폴더명(OneDrive - Inviz→OneDrive - Inviz (1))이 둘 다 다르다.**

## 1. 옮기기 전 — 이 기계에서 확인 (데이터 손실 방지)

clone은 **origin에 있는 것만** 가져온다. 미커밋 변경·미푸시 커밋·stash는 안 따라온다. 이동 전에 이 셋을 없애거나(=올리거나) 의도적으로 버린다.

### 1-1. 미커밋 워크트리
```
git worktree list --porcelain | awk '/^worktree /{w=$2} /^$/{if(w)print w; w=""}' \
  | while read wt; do d=$(git -C "$wt" status --porcelain | wc -l); [ "$d" -gt 0 ] && echo "DIRTY($d): $wt"; done
```
- **성공 신호**: 출력이 비어 있다(모든 워크트리 clean).
- **실패 신호(현재 실측 3곳, 이동 시 유실)**: `C:/Project/SaintVision-Invion`(2), `.worktrees/codex-write-response-contract`(12, Codex 활성 작업), `C:/vw`(4, detached 측정 트리). 각 워크트리의 **소유자**가 commit+push하거나 버릴지 결정해야 한다. 남의 워크트리를 대신 커밋하지 않는다.

### 1-2. origin보다 앞선 브랜치 (미푸시 커밋)
```
for b in $(git for-each-ref --format='%(refname:short)' refs/heads/); do
  git show-ref --verify --quiet "refs/remotes/origin/$b" || continue
  a=$(git rev-list --count "origin/$b..$b"); [ "$a" -gt 0 ] && echo "AHEAD $a: $b"
done
```
- **성공 신호**: 출력 비어 있음.
- **실패 신호(현재 실측)**: `agent/codex/cross-lane-test-inventory`(+7), `agent/codex/terminal-pty-contract`(+24), `codex/integration-merge`(+32). 각 소유자가 `git push origin <branch>`로 올려야 clone에 포함된다. origin에 전혀 없는 로컬 브랜치는 현재 없음(있으면 이 목록에 함께 나오도록 `refs/remotes/origin/$b` 없는 경우도 확인).

### 1-3. stash (clone·push 안 됨)
```
git stash list
```
- **성공 신호**: 비어 있음.
- **실패 신호(현재 실측 10개)**: `pre-s01`·`pre-s02-pg`·`pre-ruleR2`·`pre-clobberfix` 등. 필요한 것은 브랜치로 살려 push(`git stash branch <name> stash@{n}` → commit → push), 불필요하면 명시적으로 버린다. 안 올리면 새 PC에 없다.

### 1-4. 이 기계 baseline 기록 (§5 비교용)
이동 후 "같은 결과인지" 볼 기준을 지금 남긴다.
```
# exit를 함께 기록 — 파이프(`| tail`)에 넘기면 검사의 exit를 잃고 tail의 exit를 읽는다 (R2-b)
.venv/Scripts/python.exe -m pytest tests/core -q -p no:cacheprovider; echo "pytest exit=$?"
.venv/Scripts/python.exe tools/check_contract_bindings.py; echo "bindings exit=$?"
```
- 이 두 줄의 숫자(예: `tests/core = NNN passed / M skipped`, `fixtures F / anchors A`)를 적어 둔다. 새 PC에서 같아야 한다.

## 3. 경로 바꾸기 (세 곳 + sync 확인)

vault 경로가 세 곳에 박혀 있다. **표기 주의**: JSON 두 곳은 이중 백슬래시(`\\`), 마크다운은 단일(`\`).

| # | 파일 | 위치 | clone에 오나 | 조치 |
|---|---|---|---|---|
| 1 | `docs/source-manifest.json` | `"vault"` (JSON) | **온다**(tracked) | **반드시 수정** |
| 2 | `AGENTS.md` | 45줄 텍스트 | **온다**(tracked) | **반드시 수정** |
| 3 | `.git/obsidian-sync-state.json` | `"vault"` (JSON) | **안 온다**(`.git/` 안) | clone-fresh면 없음 → sync가 destination으로 새로 생성. 있으면(폴더 복사 시) 삭제하거나 수정 |

옛값 → 새값:
- JSON(`\\`): `C:\\Users\\egpar\\OneDrive - Inviz\\15.Vibe Cording\\Obsidian\\SaintVision-Invion` → `C:\\Users\\inviz\\OneDrive - Inviz (1)\\15.Vibe Cording\\Obsidian\\SaintVision-Invion`
- 마크다운(`\`): `C:\Users\egpar\OneDrive - Inviz\...` → `C:\Users\inviz\OneDrive - Inviz (1)\...`

sync 도구는 destination을 `docs/source-manifest.json`의 `vault`(또는 `--vault`)에서 읽고, 상태 파일(`.git/obsidian-sync-state.json`)의 `vault`가 destination과 다르면 **중단**한다(`State belongs to another vault`). clone-fresh면 상태 파일이 없어 destination으로 새로 초기화되므로 #1만 고치면 맞는다.

### 3-1. 상태 파일 처리
```
# clone-fresh면 없음(정상). 폴더를 복사했다면 옛 vault를 담고 있으니 삭제(sync가 새로 만든다):
del ".git\obsidian-sync-state.json"   # 있을 때만
```

### 3-2. sync 확인 — check 먼저, apply 나중
```

```
- **성공 신호**: exit 0(또는 pending만 보고). `State belongs to another vault` 오류가 **없어야** 한다.
- **실패 신호**: `State belongs to another vault` → #1 미수정이거나 옛 상태 파일 잔존(3-1 실행). vault 폴더 경로가 실제로 없으면 OneDrive 폴더명(`OneDrive - Inviz (1)`) 오타 확인.
```

```
- **성공 신호**: exit 0, 새 vault 폴더에 문서가 채워짐.
- **실패 신호**: 권한/경로 오류 → vault 상위 폴더 존재·쓰기 권한 확인.

## 4. 비밀 값 (목록만 — 값은 절대 적지 않는다, 새 PC에서 재발급)

복사 금지. 새 PC에서 재발급·재설정한다. **DSN은 새 PC의 PostgreSQL을 가리켜야 하고, 옛 비밀번호를 재사용하지 않는다.**

**A. 자격증명·DSN (반드시 재발급)**
- `INV_TEST_ADMIN_DSN` — disposable PostgreSQL 16+ admin DSN(통합 시험 필수)
- `INV_AUDIT_DSN`
- `INV_DATABASE_URL`
- `INV_RECOVERY_ADMIN_DSN`, `INV_RECOVERY_CONTAINER_DSN`, `INV_RECOVERY_RECORD_DSN`, `INV_RECOVERY_SOURCE_DSN` (복구 드릴 넷)
- `INV_OIDC_ISSUER`, `INV_OIDC_AUDIENCE`, `INV_OIDC_CLIENT_IDS`, `INV_OIDC_JWKS_FILE` (인증; issuer/jwks는 새 환경 값·경로)

**B. 기계·환경 식별 (새 PC 값으로 새로)**
- `INV_ENV`, `INV_TENANT_ID`
- `CX01_CONTAINER` — 보호 컨테이너는 이 기계에 남으므로(§6) 새 PC에선 새 컨테이너가 생기기 전까지 **미설정**. 미설정이면 관련 복구-드릴 시험은 정직히 skip된다.
- `SV_OUTPUT_DIR`, `INV_TEST_EVIDENCE_DIR`, `INV_STORAGE_SOURCE_ROOT`, `SAINTVISION_DEV_CERT_DIR` (경로 — 새 PC 경로로)

**C. 시험 레인 토글·이미지·포트 (기본값 있음; 해당 레인 돌릴 때만)**

- `INV_BROWSER_TEST`, `INV_BROWSER_SMOKE_INTEGRATION`, `INV_RUN_NODE_TESTS`, `INV_TEST_SYMLINKS`, `INV_CANDIDATE_ADDED`
- 이미지: `INV_NODE_IMAGE`, `INV_PYTHON_NODE_IMAGE`, `INV_NODE_BINARY`, `INV_STORAGE_AGENT_IMAGE`, `INV_UPGRADE_AGENT_IMAGE`, `INV_WEB_IMAGE`, `INV_TEST_CONFIG_IMAGE`, `INV_TEST_ROLE_GUARD_IMAGE`, `INV_TEST_SERVER_IMAGE`, `INV_WEB_NGINX_CONFIG`

- **실패 신호**: 연결 거부 → 새 PC PostgreSQL 미기동/포트/비밀번호. 값을 문서·git에 적지 않았는지 확인(적었으면 회전).

## 5. 옮긴 뒤 검증 (도는지 확인 — 규칙 8 전수 검증)

옮겼다고 되는 게 아니다. **마지막 상태에서 전부 돌려** 이 기계와 같은 결과가 나오는지 본다(규칙 8: [[검증규칙과_세축_canon]] "여러 착지 후 전수 검증"). 다른 결과 = 환경 차이.

```
git rev-parse HEAD                     # 이 기계 baseline과 같은 SHA인지
.venv\Scripts\python -m pytest tests/core -q -p no:cacheprovider | tail -1
$env:INV_TEST_ADMIN_DSN="<재발급값>"; .venv\Scripts\python -m pytest tests/integration -q -p no:cacheprovider | tail -1
.venv\Scripts\python tools\check_contract_bindings.py | tail -1
cd apps\web && npx tsc -b && npm run build; cd ..\..
```
- **성공 신호**: `tests/core` passed/skipped 수가 §1-4에 적은 이 기계 값과 **같다**. contract binding fixtures/anchors 수 같음. tsc/build exit 0.
- **실패 신호(그리고 해석)**:
  - core 수치가 **다르다** → 환경 차이(의존성 버전·인터프리터). 어느 시험이 늘거나 죽었는지 이름으로 대조.
  - integration에서 이 기계보다 **skip이 늘었다** → 새 PC에 없는 자원(Linux 스토리지·CX01 컨테이너 등)이라 정직한 게이팅. 늘어난 skip이 §4에서 의도적으로 미설정한 것과 일치하는지 확인.
  - **Go**: `go build ./...`(inv-discover)가 이 기계엔 없어 **처음 컴파일**된다 → 여기서 처음 실패가 나오면 그것이 발견이다(옮김 실패가 아니라 미검증이 검증되는 순간). 결과를 별도 기록.
- **못 도는 것 분리**: 실 PostgreSQL·Docker·물리 노드가 준비되기 전 통합/컨테이너 시험은 정직히 skip. skip을 통과로 세지 않는다.

## 6. 이 기계에 남길 것

- **보호 컨테이너 4개는 별도 프로젝트다. 옮기지도 지우지도 않는다.** 새 PC의 복구/컨테이너 시험은 새 PC 자원을 쓰며, `CX01_CONTAINER` 미설정이면 관련 시험은 skip된다(정상).
- 이 기계의 `.venv`·`node_modules`·`.git/obsidian-sync-state.json`·stash는 옮기지 않는다(파생물·로컬 상태).

## 기준선 (이 기계, 이전 전 측정 — 새 PC 대조용)

규칙 8 전수 검증. **측정 SHA `47b0d2de`** (clean detach 워크트리에서 측정, `git status --porcelain` 빈 것 확인 후 SHA 고정). 인터프리터 `.venv/Scripts/python.exe`(py3.14.6, pytest 9.1.1), 실 PG 없음(통합 skip 고정). 새 PC에서 §5를 돌려 이 표와 대조한다.

| 항목 | 결과 (SHA 47b0d2de) |
|---|---|
| 백엔드 게이트 | check_docs PASS(758 docs) · check_contract_bindings PASS(48 fixture·14 anchor·12 replay guard) · check_frontend_integrity PASS(0 위반) · check_doc_single_source --ratchet PASS(18 pair) · check_response_freshness PASS(report-only) · **check_ontology RED (exit 1)** ← 아래 |

| contracts:check | PASS (16 API 응답 타입 ↔ JSON Schema 일치) |

**RED 1건 — check_ontology (귀속 Codex, 소유 Reverse-Ontology):** registry가 S01-DB·S01-FE를 `done`으로 닫았으나 `ontology/example.ttl`이 재생성되지 않아 stale하다(S01-DB=`in_progress`, S01-FE=`review`로 남음). check_ontology가 registry↔ontology 일치를 강제하므로 exit 1. 격리 워크트리에서 `python tools/generate_ontology.py`를 돌리면 **정확히 그 2줄만** `done`으로 바뀌고 check_ontology exit 0이 됨을 비파괴로 확인했다(확인 후 revert, 착지 안 함). 생성물이자 Reverse-Ontology 영역이라 내가 고치지 않았다 — 소유자가 재생성·착지해야 한다. **CI 개방 상태라 다음 CI 실행에서 이 게이트가 실패한다(우선).**

**not_run (이 기계엔 없음 — 새 PC서 처음 돌거나 인프라가 붙으면 달라진다. 이 목록이 "새로 도는 것"과 "회귀"를 가른다):**
- **Go**: 이 기계에 Go 없음 → `inv-discover` 0 컴파일. 새 PC에서 **처음** 컴파일·실행(T1/T2/T3 교차언어). 새로 도는 것이지 회귀 아님.
- **PG 통합**: 위 1039 skip의 다수. 새 PC CI엔 `postgres:16` 서비스가 있어 skip이 크게 줄고 passed로 전환된다. (참고: 이 기계에서도 로컬 PG(55440)로 개별 실행은 됐다 — 오늘 S09 76·S10 228·경합/복구 166 등. 단 CI-스코프 기준선은 DSN 없이 재서 skip으로 고정했다.)
- **실 브라우저 인수**: 미실행(Chrome/Playwright 실측은 별도 도구·Gemini 레인).
- **hosted CI**: gh 인증·결제 후. 위 수치는 전부 로컬 실측이며 CI 통과와 동등하지 않다.

**예상 차이 (새 PC서 다르게 나올 것 — 미리 적어 그날 놀라지 않고 예상 밖에 집중):**
- Go가 처음 돈다 → Go 항목이 0에서 실제 숫자로. 첫 red는 미검증→검증의 순간이지 이동 실패가 아니다.
- PG가 CI에 있으면 **1039 skip이 크게 감소**(통합 passed 증가). skip 감소는 정상 신호.
- worker 5대가 붙으면 `--ignore`했던 node-dependent 24파일이 실제로 돈다.
- check_ontology는 소유자가 재생성·착지하면 GREEN이 된다(위 RED 해소 후).
- **위 넷 외에 게이트/core passed·vitest·tsc·build 숫자가 이 표와 다르면 그것이 환경 차이 또는 회귀다** — 어느 시험이 늘거나 죽었는지 이름으로 대조한다.
