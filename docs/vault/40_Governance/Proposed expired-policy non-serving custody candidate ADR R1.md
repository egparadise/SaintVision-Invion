## Scope and terminal boundaries

The candidate supports an expired peer policy while the same pinned CA, retained Node leaf and CP-client leaf are presently valid. It checks real wall time; there is no clock override/backdating. Leaf expiry returns RECOVERY_TERMINAL_LEAF_EXPIRED and CA expiry RECOVERY_TERMINAL_CA_EXPIRED. A not-yet-expired policy is refused. More than candidate completion budget plus630s safety plus30s skew must remain on each leaf. Signed challenges live at most120s, tolerate at most30s future issue time, and candidate execution budget is bounded1..60s. These fixture/component budgets are not production B_Rpolicy. Production B_Rpolicy must include its own serving-binary/container migration and all remaining steps; it remains null/HOLD. No normal adapter release exists. After the production CA terminal11-14 16:15:30KST, same-CA recovery is impossible; authority replacement is a distinct unimplemented workflow. Leaf-expired recovery is also a separate unimplemented card.

Production policy expires11-08 16:15:30KST, leaves11-09 16:15:30KST. These are metadata, never CI actors or test certificates. The unchanged serving implementation rejects expired policy at NewAuthority and every subsequent connection, so after expiry Root must preserve keys/journals/floors and avoid current Node restart/reboot/migration until a reviewed recovery release exists. See [unchanged serving authority](https://github.com/egparadise/SaintVision-Invion/blob/1efea494f026e932360c35ae811b6423d874a2e7/services/node-agent/transport/trust.go#L52-L107). ## Contract and domains

Proposed schema ID urn:saintvision:proposed:expired-policy-custody:1 describes authorization, operator attestation, non-serving proof, checkpoint request, checkpoint and signed envelope. The source-map JSON lists exact component paths and hashes. No change is made to the canonical core schema or normal M2:2. Five distinct signature domains end with NUL and use Ed25519, lowercase64-byte signature hex, and base64 of exact canonical payload bytes. Canonical JSON is a bounded ASCII/integer subset: maximum65536 bytes per object; no floats, unsafe integers, duplicate keys, unknown keys, noncanonical wire, unbounded arrays or deep nesting. Existing journal bytes are parsed strictly and hashed as-is, without rewriting historical ordering.

Authorization binds exact original operation bytes/digest, fresh operation ID and nonce, sequence counter, tenant/epoch, sorted exact3member cohort, independent expectedC/targetC=C+1 and priorP/targetP=P+1, old floor/identity/policy/config hashes, prior policy expiry, sameCA/CP/Node DER pins, retained-key continuity, revocation set, context generation and all5site inventory digest. The proposal does not publish a new policy, certificate or generation. Production current P/C, private handles, releases and times of actual future operations remain null/HOLD; request values are test scope or future authenticated bindings, never inferred from a new untrusted request.

A distinct recovery-authorizer key signs authorization and checkpoint requests. A separate operator-custody key signs the operation, actual helper executable SHA, CID/image, UID1000, original journal lock device/inode and inventory. Neither private key nor CA/CP private key enters Node config/trust mounts. The Node's retained private key is read locally and must match the exact pinned Node certificate; it never leaves the Node/helper. Go public role pins and cohort digest are explicit out-of-band CLI bindings, not discovered from an unsigned request. The CP verifier additionally checks all role keys are different from one another, CA, CP TLS and every Node key.

## Custody threat model and refusal

The assurance is trusted-operator custody plus actual exclusive flock, not TPM/kernel attestation of physical quiescence. CID/image metadata is a trusted operator claim; no boolean or PID0 proves the absence of another physical process or malicious privileged actor. Root/operator integrity, reviewed out-of-band trust/pins and exclusive custody of the host/mount namespace are required integration assumptions. The helper never labels itself a live serving binary, never forges os.SameFile and never emits normal M2. The [existing live observer](https://github.com/egparadise/SaintVision-Invion/blob/1efea494f026e932360c35ae811b6423d874a2e7/services/node-agent/runtime/peer_floor_linux.go#L45-L188) remains unchanged.

Go runs only UID1000 with fixed /config and /trust read-only and /state and /custody writable. All directories must be owned private directories, no symlink roots. Read files use O_NOFOLLOW/nonblocking, regular single-link bounded files, same UID/private mode and stable descriptor metadata/size. The existing journal flock and the separate candidate namespace flock are acquired nonblocking and held through the signed checkpoint; there is no OpenJournal/init/create-floor/reset operation. Only the idle identity/.peer-policy/.lock journal layout is supported. Unknown jobs or partial/foreign files return HOLD. Fixed container bind mount roots plus trusted operator custody prevent an untrusted same-UID actor from replacing roots; this is an assumption to be proved by a future restricted adapter, not hardware attestation. Exact config and journal bytes and locked inode are rechecked while locks remain held.

The producer checks actual public policy bytes/scope/version/expiry and floor hash against the independently authorized proposal, matching retained key and same pinned CA. Single-CA validity, signature, Ed25519, EKU, SPIFFE tenant/epoch/Node URI, Node IP, time bounds and revocation constraints remain strict. This does not relax the [generic normal trust path](https://github.com/egparadise/SaintVision-Invion/blob/96afd799d49717fd40e4ddabd538d82accbe1958/services/control-plane/src/inv/node_transport.py#L1-L130).

Never-started recovery can reach a candidate checkpoint. Partial serving migration and partial normal publication are explicitly recognized but return RECOVERY_HOLD_PARTIAL_RECONCILIATION_NOT_BOUND before any proof write. Their real multi-file migration/publication inventory and forward reconciliation adapters are not implemented. Candidate checkpoint partial writes use a different namespace: .next is created exclusive, fsynced, linked without replacement, directory fsynced, and only the just-created temporary file is removed. A crash residue, foreign file, chain gap or conflicting immutable checkpoint is HOLD, never deleted/reinitialized by the component. Recovery of an actual in-flight production publication is not claimed by the candidate's own checkpoint reconciliation.

## Candidate state machine and uncertain delivery

1. Explicit reference bootstrap is allowed only in an owned isolated scope. It is not authenticated production enrollment. A real adapter must supply independently authenticated initial C/P and custody authority, or HOLD.
2. The Go helper acquires both actual locks, verifies request/keys/files/bounds and emits a Node-signed non-serving proof. It waits with those locks held for a CP-signed checkpoint request, bounded by deadline. No listener is started.
3. CP verifies all3 Node proofs, all3 independently signed operator attestations, the exact cohort and all5 context inventory. A durable SQLite reference transaction records PREPARED with exact proposal/nonce/counter/batch proof digest and expected C/P. A changed retry, reused nonce/counter or conflicting current state is refused.
4. Only after all3 proofs verify does CP sign per-Node checkpoint requests bound to the entire batch and exact proof. Nodes recheck files under locks and durably write a chained retained-key signed candidate checkpoint. They then release locks; the checkpoint states custody held through signing, not indefinite quiescence or readiness to serve.
5. CP verifies all3 immutable checkpoints and performs one expectedC/P CAS transaction with3 audit rows and a durable CANDIDATE_COMMITTED reference receipt. A late conflict rolls back all rows. Concurrent identical retries return the same receipt without another audit/advance. No external transport/publisher/DB is called.
6. Read-only reconcile requires exact operation ID/proposal digest and reports historical PREPARED/COMMITTED or unknown outcome; it never upgrades stale authority to fresh success. A completed Node retry returns the existing record with a distinct historical replay kind. It is not a fresh custody proof. Missing checkpoint/bad phase/batch/deadline remains a visible refusal. Activation always returns RECOVERY_HOLD_INTEGRATION_NOT_BOUND.

A local privileged attacker can tamper with a reference ledger or bypass a trusted operator; the component does not claim to defend a hostile Root. Reference ledger private-file checks and CAS serialization detect ordinary races/conflicts, while real restricted production custody/DB authorization and authenticated floor provenance are mandatory later gates.
