# 있다 vs 작동한다 — 규칙을 검사로

오늘 닫은 여섯 층은 전부 **"있다"와 "작동한다"를 가르는** 한 질문의 변형이다:
1. 초록인데 단언 도달 안 함, 2. 배선됐는데 CI에서 안 돌아 통과 미확인, 3. 통과했는데 다른 이유로(bare raises가 원인 뭉갬), 4. 방어가 엉뚱한 것을 지킴, 5. 계약이 있는데 서빙이 안 지킴(앵커 없음), 6. 앵커가 있는데 제거해도 안 깨짐(무게 없음).
지금은 **사람이 매번 찾았다**. 계약이 28개로 늘었고 더 늘 것이라 사람 훑기는 오래 못 간다. **구조가 질문을 던지게** 바꾼다. 전부 자동화되진 않는다 — 자동화 가능한 것과 사람이 봐야 하는 것을 가른다.

## 자동화 가능 (구조적, 판단 불요)
- **[제작함] 계약 결속 형식성** — `tools/check_contract_bindings.py`:
  - (1) fixture 커버리지: `contracts/fixtures/*.json` 전부가 어떤 시험에서 참조되는가(참조 없는 fixture=이름뿐인 결속). ← 층5의 형식 갈래.
  - (2) 서빙-앵커 커버리지: bound(fixture+계약시험) ∩ 커널 서빙 앵커(`_checked("X",…)`/`validate_contract("X", <응답인자>)`)인 응답 전부가, **그 서빙 모듈을 import하고 그 계약명을 참조하는 시험**을 갖는가. ← 층6의 형식 갈래. 새 커널 응답이 서빙-앵커 시험 없이 묶이면 검사가 잡는다(버킷2 재축적 방지). 현재 11개 bound 커널 응답 전부 통과, 검사 자체가 회귀를 잡음도 음성대조로 확인.
  - (3) **죽은-계약 탐지(보고-전용·별도 등급)**: bound(fixture+계약시험)이고 실제 계약 타입(pydantic 스키마 클래스 또는 커널 $def)인데 **그 응답을 서빙하는 코드 경로가 어디에도 없는** 것(서빙 참조 0 + 다른 스키마의 필드로 합성되지도 않음). 있다≠작동한다의 가장 순수한 사례를 잡는다 — 스키마·fixture·초록 시험이 다 있는데 그 응답을 만드는 코드가 없음(예: `LegacyProjectCatalogResponse`).
  - **한계(명시)**:
    - (2)는 서빙-앵커 시험이 **존재**하는지만 본다. 앵커 제거 시 실제로 깨지는지(무게)는 안 본다 — 판단/변형(아래).
    - (3) 서빙 탐지는 **패턴/grep 기반**이라, 타입 이름을 전혀 명시하지 않는 **완전 동적 구성**으로만 서빙되는 계약은 죽었다고 오보할 수 있다(오탐). **늑대소년 방지**로: (a) 보수적 — 이름 언급·중첩 필드 참조가 하나라도 있으면 alive, (b) 실제 계약 타입에만 적용, (c) **보고-전용**(게이트를 실패시키지 않음) — 해결이 사람 결정(엔드포인트 배선 vs 계약 제거)이라. **양쪽 검증함**: LegacyProjectCatalogResponse는 잡고, 산 계약·중첩 아이템 타입(DiscoveryCandidateResponse 등)은 안 잡음.
- **[목록] 자리표시자 식별자 린트**: 프런트 프로덕션 요청 경로의 하드코딩 자리표시자(`11111111-…`, `01JABCDE`, `saint-pilot`, `_DEMO`) 경고. 값의 존재·전달은 자동, **위험 분류(표시/요청/인가)는 판단**.
- **[목록] fixture↔스키마 유효성**: 각 fixture가 자기 `$def`에 validate되는지 독립 검사(계약시험이 이미 하지만 스탠드얼론 게이트화 가능) — fixture 드리프트 포착.
- **[목록] saintvision response_model 커버리지**: `src/saintvision/api/v1/*` 응답 라우트가 `response_model=`를 갖는지(프레임워크 앵커 누락 포착).
- **[목록] 검사의 CI 배선(층2)**: `check_contract_bindings` 등이 CI에서 실제로 돌아 초록인지(존재≠실행).

## 사람 판단 필요 (의미론 — 자동화 부적합)
- **무게(층6 심층)**: 앵커/가드를 제거하면 시험이 깨지는가. 변형(mutation) 테스트로 부분 자동화 가능하나 무거움 — 오늘은 표본 되살림(사람).
- **앵커 위치(층5 심층)**: 앵커가 **서빙 응답**에 걸렸나, 아니면 인입/검증워커에 걸렸나(ModelManifest=검증워커, NodeStopReceipt=이름충돌). 이름 유사에 속지 않는 판단.
- **도달(층1)**: 단언에 실제 도달하는가. 커버리지로 힌트는 되나 "의미 있는 도달"은 사람.
- **원인 뭉갬(층3)**: bare `raises(DomainError)`가 인가·리스·멤버십을 뭉개 다른 이유로 초록인가 — per-case match 필요, 의미론.
- **엉뚱한 방어(층4)**: 방어가 지키려던 실체를 실제로 지키는가.
- **가짜 값이 실체를 가리키나**: 모양 유효한 값이 실존을 가리키는가. 백엔드 fail-closed가 일부 잡지만 "옳은 실체인가"는 판단.

## 지금 만든 것 / 남긴 것
- **만듦**: `tools/check_contract_bindings.py` — (1) fixture 커버리지 + (2) 서빙-앵커 커버리지(층5·6 형식 갈래, 하드 게이트) + (3) 죽은-계약 탐지(보고-전용). 자기검증 완료: (2) 회귀 포착 음성대조, (3) 양쪽(Legacy 잡음·산 계약 안 잡음, 중첩-타입 오탐도 수정). 현재 (3)이 `LegacyProjectCatalogResponse` 1건을 죽은 계약으로 보고 → **Codex 결정 대기**(엔드포인트 배선 vs 계약 제거; 내가 지우지 않음).
- **남김(우선순위순)**: 자리표시자 린트 → fixture↔스키마 게이트 → saintvision response_model 커버리지 → 검사 CI 배선. 각각 자동화 가능, 위 한계 밖은 사람 판단.
- **원칙**: 자동 검사는 "형식이 갖춰졌나"까지만 보증한다. "작동하나"의 심층(무게·위치·의미)은 여전히 독립 검토가 진다 — 검사는 사람이 매번 처음부터 찾지 않게 **바닥을 올린다**.
