# 외부 인계 제안 수신과 정본 동기화 복구

Tool admission 개발 중 Obsidian의 일부 관리 문서가 현재 Codex Git보다 이전 ADR·진행·인계 기록으로 돌아간 것을 확인했다. shared sync state도 다른 브랜치의 export hash로 바뀌어 기본 --check가 이를 conflict 대신 pending export로 계산했다. Git의 기존 코어/승인 검증 증거는 그대로 보존돼 있어 정본 손실은 없었다.

현재 ADR-019~026·검증 보고·회신은 유지하고, 새 Claude/Gemini 인계 문서를 저자·doc ID를 보존한 제안으로 Git에 수용했다. 공백만 정규화했으며 받은 bytes/hash는 로컬 `.work/tool-external-snapshot`에 보존했다. 새 인계 링크·행을 기존 이력에 더했고 Ontology는 현재 task registry projection을 유지했다.

각 외부 문서의 test count·build·시각은 작성자의 주장이다. 이 작업에서 다른 Agent 코드/CI/브라우저 검증을 실행하거나 독립 검토를 완료하지 않았다. 일부 보고의 시각이 수신 당시 미래 시각이므로 실제 실행 시각은 해당 원시 로그로 별도 확인해야 한다. S03/S04 Frontend의 exit 0→성공, 취소→자원 해제, 사용자 전환→독립 승인, evi_ ID 주장은 core 계약과 같다고 승인하지 않는다. 생성 ID는 evd_, 성공은 검증 Evidence와 동일 txn, 물리 반환은 Node stop ACK, 승인은 서버 인증 actor/nonce/quorum 기준이다.

이번 이후의 export는 `.work/tool-obsidian-sync-state.json`의 작업별 snapshot을 사용한다. 확인 후 다른 브랜치가 Obsidian을 바꾸면 이 state에 없는 hash가 되어 export가 중단된다. 다른 브랜치가 쓴 shared state를 다시 읽어 무검토로 변경을 인수하지 않는다. 원문 docs/sources 및 다른 Agent의 업무 코드는 수정하지 않았다.
