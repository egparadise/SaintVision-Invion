# 검증 검사 도구 목록

새로 온 사람이 **여기 하나만** 보면 저장소의 검증 도구가 무엇이고 어떻게 돌리고 실패하면 뭘 하는지 안다. (AGENTS.md `## 검증`에서 이 문서를 가리킨다.) 등급 기준은 [[검사_게이트승격_기준과_5검사_분류_Claude]]: 백로그0·오탐낮음·대응명확 셋 다면 게이트, 아니면 ratchet/report-only.

## 문서·온톨로지 (기존)
| 도구 | 무엇 | 등급 | 실행 | 실패 시 |
|---|---|---|---|---|
| `tools/check_docs.py` | 원본해시·비밀DSN·위키링크·프런트매터·task-registry 무결성 | 게이트 | `python tools/check_docs.py` | 메시지가 어느 문서/필드/링크인지 지목 — 그것을 고침 |
| `tools/check_ontology.py` | RDF/SHACL·task 매핑(48행 registry 유도)·per-task realizes 집합 | 게이트 | `python tools/check_ontology.py`(requirements-docs 환경) | 어느 query/task가 불일치인지 지목 |
| `tools/sync_obsidian.py` | vault↔공유 미러 동기 | 확인 후 `--apply` | `--check` 후 권한 내 `--apply` | pending/conflict 목록 확인 |

## 계약·화면·신선도 (오늘 밤 신규 5)

|---|---|---|---|---|
| `tools/check_contract_bindings.py` | ①fixture-무-시험 ②bound 커널응답-무-서빙앵커시험 (③dead-contract=내부 report-only) | **게이트**(①②) | `python tools/check_contract_bindings.py`(docs.yml) | "fixture X에 시험 없음"→그 fixture 참조 시험 추가; "응답 X 서빙앵커 시험 없음"→X를 명명하고 `inv.<module>`를 import하는 시험 추가 |
| `tools/check_anchor_weight.py` | 서빙 앵커의 **거부-커버리지 tier**(rejection-tested/called-only/no-serving-test) 정적 분류 — check_contract_bindings(존재)의 보완(시험이 거부를 검증하나) | **report-only** | `python tools/check_anchor_weight.py`(opt-in `--strict`); 자기시험 `pytest tests/test_check_anchor_weight.py` | called-only=서빙 거부 시험 추가 또는 계약시험이 덮는지 확인; no-serving-test=사각지대. 런타임 무게 확증은 변이 절차([[앵커_무게_검증_절차]]) |
| `tools/check_frontend_integrity.py` | 프런트 무결성(가짜 id·조기성공·tri-state 등) | **게이트** | `python tools/check_frontend_integrity.py`(docs.yml) | 위반 파일·지문 목록 → 해당 코드 정정(Gemini 소관) |
| `tests/core/test_serving_anchors.py` | 커널 응답의 서빙 함수가 실제로 validate_contract 호출(앵커 무게) | **게이트**(pytest 스위트) | backend/core pytest가 수집 | 어느 응답 앵커가 안 불렸는지 → 서빙 경로에 앵커 복구 |
| `tools/check_doc_single_source.py` | 살아있는 문서 간 실질 라인 중복(rule5 분기면) | **ratchet**(`--ratchet`) / 기본 report-only | 게이트: `python tools/check_doc_single_source.py --ratchet`; 가시화: 기본 실행→`$GITHUB_STEP_SUMMARY` | 새 doc-pair→통합 or `tools/baselines/doc_single_source_pairs.txt`에 명명 줄 추가; stale→그 줄 삭제(하향). | `npx tsc -b` / `npm run build` | 프런트엔드 TypeScript 정적 타입 무결성 및 프로덕션 번들 빌드 검증 (Vitest의 타입 strip 한계 보완) | **게이트** | `cd apps/web && npx tsc -b && npm run build` | 타입 에러(TS2304 등) 및 번들링 실패 정정 (Gemini 소관) |

- **report-only 가시성**: report-only는 로그에 묻히면 무시되므로 CI에서 `$GITHUB_STEP_SUMMARY`로 뽑는다([[검사도구_CI배선과_리포트가시성_Claude]]). 미배선 2개(doc_single_source·response_freshness) 배선 문안은 그 문서에.
- **배선 현황**(2026-09-22): check_docs/ontology/contract_bindings/frontend_integrity=docs.yml, serving_anchors=pytest 스위트. doc_single_source·response_freshness=배선 대기(문안 Codex 인계, YAML 소관 Codex).
