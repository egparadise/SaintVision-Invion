# Saint Vision INV 시스템 스키마

## 목적

이 문서는 Control Plane, Node Agent, Workspace, Scheduler, Runtime와 MLOps가 공유하는 핵심 Entity와 계약을 정의한다. 구현 언어와 Framework가 달라도 ID, 상태, 관계와 Event 의미는 이 기준을 따라야 한다.

## 1. Domain 경계

| Domain | 주요 Entity | 소유 서비스 |
|---|---|---|
| Identity | User, Role, CredentialRef | Identity and Access |
| Project | Project, Repository, Workspace, Template | Workspace Service |
| Infrastructure | Cluster, Node, Capability, ResourceSnapshot | Node and Resource Service |
| Scheduling | Workload, ResourceRequest, Lease, PlacementPlan | Scheduler |
| Execution | Run, Task, TerminalSession, ToolInvocation | RunGraph and Tool Gateway |
| Data | Dataset, DataLocation, Artifact, StorageVolume | Storage and Artifact Service |
| AI and MLOps | AITool, Experiment, Model, ModelVersion, Deployment | AI CLI Hub and MLOps |
| Governance | Policy, PolicyDecision, Approval, AuditEvent | Policy and Audit |

## 3. 공통 ID와 Metadata

모든 주요 Entity는 다음 필드를 가진다.

| 필드 | 형식 | 설명 |
|---|---|---|
| id | UUID 또는 Prefix UUID | 전역 유일 ID |
| tenant_id | UUID | 배포 단위가 단일 조직이어도 예약 |
| version | Integer 또는 SemVer | 계약 또는 Resource Version |
| created_at | RFC 3339 UTC | 생성 시각 |
| updated_at | RFC 3339 UTC | 변경 시각 |
| labels | Map String String | 검색과 배치용 제한된 Metadata |
| annotations | Map String String | 비식별 설명 Metadata |
| correlation_id | UUID | 요청과 Run 전 구간 추적 |

권장 Prefix는 usr, prj, wsp, nod, wld, run, tsk, lse, plc, dat, art, mdl, dep, pol, apr와 evt다.

## 4. 핵심 Entity

### Node

| 필드 | 설명 |
|---|---|
| node_id | 안정적인 Node 식별자 |
| cluster_id | 소속 Cluster |
| hostname | 표시용 이름이며 ID로 사용하지 않음 |
| os_family, os_version | Windows 또는 Linux와 버전 |
| architecture | amd64, arm64 등 |
| agent_version | Node Agent 버전 |
| status | registering, online, draining, offline, quarantined |
| trust_level | attested, managed, untrusted 등 |
| provider_policy_id | Host 소유자가 설정한 제공 정책 |
| last_heartbeat_at | 마지막 생존 신호 |

### Capability

CPU Architecture, GPU Vendor와 Compute Capability, Driver, CUDA, Container Runtime, Shell, Filesystem, Network Interface와 보안 기능을 표현한다. Capability는 현재 남은 양이 아니라 **가능 여부와 호환성**을 나타낸다.

### ResourceSnapshot

현재 총량, 제공 한도, 이미 Lease된 양, 실제 사용량, 온도, 전력, Host 사용자 부하와 측정 시각을 포함한다. Snapshot은 불변 Event로 저장하고 최신 Projection을 별도 유지한다.

### Workload

원하는 결과와 제약을 표현한다. 실제 Node 명령이나 Provider 전용 옵션을 직접 넣지 않고 Runtime Adapter가 해석할 수 있는 중립 계약을 사용한다.

### Lease

Scheduler가 특정 Node 자원을 일정 시간 예약했다는 권한이다. Lease에는 만료 시각, Resource Slice, Fencing Token과 Run ID가 반드시 있어야 한다.

### Run

Workload의 한 번의 실행 시도다. 상태는 requested, validating, awaiting_approval, scheduled, starting, running, verifying, succeeded, failed, cancelled, timed_out와 lost를 기본으로 한다.

## 5. WorkloadSpec 초안

~~~yaml
apiVersion: inv.saintvision.ai/v1alpha1
kind: Workload
metadata:
  name: echo-evaluation
  projectId: prj_echo
  workspaceId: wsp_echo_dev
spec:
  workloadType: ai.evaluation
  runtime:
    type: container
    image: registry.local/echo-ai:0.4.0
    command:
      - python
      - evaluate.py
  resources:
    cpu: 8
    memory: 32Gi
    gpu:
      count: 1
      minVram: 16Gi
      vendor: nvidia
  data:
    mounts:
      - source: inv://datasets/echo-v3
        target: /inv/datasets/echo
        mode: readOnly
  placement:
    preferDataLocality: true
    maxHostLoad: 0.40
    networkClass: lan10g
  policy:
    riskLevel: L1
    internetAccess: restricted
    timeout: 2h
~~~

## 7. API 초안

| Method | Path | 목적 |
|---|---|---|
| POST | /v1/nodes/register | Node Bootstrap와 등록 |
| POST | /v1/nodes/{id}/heartbeat | 상태와 최신 Snapshot 보고 |
| GET | /v1/resource-graph | 논리 자원과 Topology 조회 |
| POST | /v1/workloads | Workload 제출 |

| POST | /v1/runs/{id}/cancel | 취소 요청 |

| POST | /v1/workspaces/{id}/terminals | TerminalSession 생성 |
| POST | /v1/approvals/{id}/decision | 승인 또는 거부 |
| GET | /v1/artifacts/{id} | Artifact Metadata와 접근 |

## 9. 저장소 매핑

| 데이터 | 권장 저장소 | 이유 |
|---|---|---|
| 사용자, Project, Workload, Lease, Run | PostgreSQL | Transaction과 관계 무결성 |
| 짧은 Queue와 Cache | Redis | 일시 상태와 낮은 지연 |
| Dataset, Model, Build Artifact와 Log Bundle | S3 호환 Object Storage | 대용량, Version과 수명주기 |
| Metrics | Prometheus 호환 TSDB | 시계열 집계 |
| Trace와 구조화 Log | OpenTelemetry Backend | Correlation과 분산 추적 |
| Ontology와 Knowledge 관계 | RDF Store 또는 PostgreSQL Projection | 표준 교환과 단계적 도입 |

## 10. 불변 조건

- 하나의 활성 Resource Slice에는 하나의 유효한 Fencing Token만 존재한다.
- succeeded Run은 검증 결과와 최소 하나의 Evidence Envelope을 가진다.
- 모든 ToolInvocation은 호출자, PolicyDecision과 Workspace 경계를 가진다.
- Credential 원문은 WorkloadSpec, Event, Log와 Artifact Metadata에 저장하지 않는다.
- Node가 offline 또는 quarantined면 새 Lease를 발급하지 않는다.
- Dataset의 DataLocation은 Checksum과 접근 정책 없이 active가 될 수 없다.
- Deployment는 승인된 ModelVersion 또는 Container Image Digest를 참조한다.

## 11. 버전 전략

- 외부 계약은 apiVersion과 kind를 사용한다.
- 호환 가능한 필드는 추가만 하고 삭제와 의미 변경은 새 Major Version에서 수행한다.
- Database Migration, JSON Schema, OpenAPI, Event Schema와 Ontology Version을 같은 Release Manifest에서 연결한다.
- TTL과 JSON-LD는 [[Ontology 설계]], [[saintvision-inv.ttl]], [[saintvision-inv.example.jsonld]]를 기준으로 한다.
