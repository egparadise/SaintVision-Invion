## 2. Workload 실행 흐름

~~~mermaid
sequenceDiagram
    actor User
    participant Portal
    participant Workspace
    participant Policy
    participant Scheduler
    participant ResourceGraph
    participant NodeAgent
    participant Runtime
    participant Evidence

    User->>Portal: Run 제출
    Portal->>Workspace: Project와 Workspace 확인
    Workspace->>Policy: Workload와 호출자 평가
    Policy-->>Workspace: 허용 또는 승인 필요
    Workspace->>Scheduler: 검증된 WorkloadSpec
    Scheduler->>ResourceGraph: Node와 DataLocation 조회
    ResourceGraph-->>Scheduler: Snapshot과 Topology
    Scheduler->>Scheduler: Hard filter와 scoring
    Scheduler->>ResourceGraph: Lease 생성
    Scheduler->>NodeAgent: PlacementPlan과 Fencing Token
    NodeAgent->>Runtime: Container 또는 Process 시작
    Runtime-->>NodeAgent: Logs Metrics Artifacts
    NodeAgent-->>Evidence: 상태와 증거 기록
    Evidence-->>Portal: Run 결과와 Explain
    Portal-->>User: 결과 표시
~~~

## 3. Scheduler 결정 그래프

~~~mermaid
flowchart TD
    W[WorkloadSpec] --> V[Schema Validation]
    V --> P[Policy Evaluation]
    P -->|deny| D[Rejected]
    P -->|approval| A[Awaiting Approval]
    P -->|allow| H[Hard Constraints]
    A -->|approved| H
    A -->|rejected| D

    H --> O[Online and Trust]
    O --> C[Capability Match]
    C --> R[Resource Availability]
    R --> S[Storage Access]
    S --> N[Network Requirement]
    N --> L[Data Locality]
    L --> SCORE[Candidate Scoring]
    SCORE --> RESERVE[Atomic Lease]
    RESERVE -->|conflict| REFRESH[Refresh Snapshot]
    REFRESH --> H
    RESERVE --> PLAN[PlacementPlan]
    PLAN --> EXPLAIN[Explain Record]
    PLAN --> EXECUTE[RunGraph Execute]
~~~
